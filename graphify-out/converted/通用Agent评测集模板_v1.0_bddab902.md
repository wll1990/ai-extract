## Sheet: 使用说明
| 通用 Agent 评测集模板 |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- |
| 版本 v1.0 · 2026-11-04 · 适用于任何 LLM / Agent 项目（工具无关） |  |  |  |  |  |
| 一、这是什么 |  |  |  |  |  |
| 一句话：一行一道题，写清输入、金标、评分和门禁；专家按同一套标准出题、复核、冻结、跑分。 |  |  |  |  |  |
| 与具体框架无关：Excel 用于出题与评审；确认后按列导出 JSONL / CSV，即可接入 promptfoo、LangSmith、OpenAI Evals、DeepEval 等。 |  |  |  |  |  |
| 二、专家怎么做（七步） |  |  |  |  |  |
| 1. 定目标：先写“上线必须保证什么”，再拆能力矩阵，不先写题。 |  |  |  |  |  |
| 2. 拆矩阵：能力 × 难度 × 场景；同一考点不重复出题，避免“看起来很多、其实在测同一件事”。 |  |  |  |  |  |
| 3. 写金标：答案必须可追溯到文档 / 工单 / 专家结论；真实 PII 一律脱敏。 |  |  |  |  |  |
| 4. 定评分：客观项用 exact / contains；主观项用 rubric + 裁判模型，人工抽检 ≥10%。 |  |  |  |  |  |
| 5. 交叉复核：出题人之外至少一人独立评分，分歧超过 1 档由第三人裁决。 |  |  |  |  |  |
| 6. 冻结与版本：holdout 不参与调参；变更写“变更记录”；检查训练数据污染。 |  |  |  |  |  |
| 7. 设门禁：关键题 100% 通过；总分 ≥0.80；分项不低于基线 2 个百分点；安全题一票否决。 |  |  |  |  |  |
| 三、样本量与比例（建议） |  |  |  |  |  |
| 冒烟集 50–100 题；发布集 200+ 题。负例/对抗 ≥20%；多轮 ≥15%；L3+L4 ≥30%；holdout ≥20%；关键题 ≥10%。 |  |  |  |  |  |
| 小团队可从 30 题起步，但安全题、回归题必须齐全——这两类不能“以后补”。 |  |  |  |  |  |
| 四、使用流程 |  |  |  |  |  |
| 1) 在“评测集”页按示例填写；19 条示例用于演示写法，正式使用前可保留参考或删除。 |  |  |  |  |  |
| 2) 打开“覆盖检查”页，公式会自动统计分布，确认是否达标。 |  |  |  |  |  |
| 3) 组织专家按“评分规则”页复核金标与权重，至少两人独立评审。 |  |  |  |  |  |
| 4) 冻结 holdout，导出 JSONL 跑基线，记录版本号与日期。 |  |  |  |  |  |
| 5) 每次发版跑全量；失败按“失败分类”归因，回归题必须全过。 |  |  |  |  |  |
| 五、红线 |  |  |  |  |  |
| · 不得写入真实客户姓名、手机号、身份证、订单号等 PII。 |  |  |  |  |  |
| · holdout 不得用于提示词调参或微调；冻结后只能追加新版本。 |  |  |  |  |  |
| · 不允许只有“好题”没有负例；不允许没有“设计理由”的题。 |  |  |  |  |  |
| · 关键题失败不得用“平均分还行”解释；安全题 0 分即阻断发布。 |  |  |  |  |  |
| 六、页签说明 |  |  |  |  |  |
| 评测集：主表，一行一题。字段定义：36 列的填写规范。评分规则：维度、阈值、失败分类。覆盖检查：自动统计。变更记录：版本留痕。评审与运行记录：评审结论与基线分数。 |  |  |  |  |  |
| 填写提示：带 * 的列为必填；下拉列请勿手填其它值；评分权重合计必须等于 1（表格会自动标红）。 |  |  |  |  |  |
