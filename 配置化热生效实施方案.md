# 配置化热生效实施方案

> 核心目标：**改配置 → 自动生效 → 零重启**。运营可自助调参数，开发者可零代码扩领域。

---

## 一、现状诊断

### 1.1 当前热加载能力矩阵

| 配置类型 | 加载器 | 缓存策略 | 热加载 | 失效机制 |
|---------|--------|---------|--------|---------|
| Domain YAML | DomainConfigLoader | ConcurrentHashMap 永驻 | ❌ 无 | clearCache() 从未被调用 |
| Prompt 文件 | PromptLoader | ConcurrentHashMap + mtime | ✅ 外部目录模式 | mtime变化自动重读 |
| 场景关键词 | 随Domain YAML | 同上 | ❌ 无 | 同上 |
| 管道参数 | 随Domain YAML | 同上 | ❌ 无 | 同上 |
| Chat模式 | 随Domain YAML | 同上 | ❌ 无 | 同上 |
| application.yml | Spring Boot | Spring机制 | ❌ 需重启 | 无 |
| 领域树 _tree.json | DomainController | 读文件返回 | ❌ 无 | 无 |

### 1.2 关键瓶颈

**DomainConfigLoader.load() 第69-92行**：
```java
DomainConfig cached = cache.get(key);
if (cached != null) return cached;  // ← 命缓存直接返回，不看文件变化
```

一旦加载就永驻内存。**所有7个服务**（ChatStreamService / MaterialCleaningService / MaterialPreChecker / InterviewService / BusinessNoiseFilter / InterviewTranscriptExtractor / DomainController）都通过这个 Loader 获取配置，改了YAML文件，这些服务永远拿到旧值。

**PromptLoader** 的做法是对的——每次 load 都检查 mtime。DomainConfigLoader 需要照抄这个机制。

---

## 二、方案设计：三层热生效体系

### 2.0 整体架构

```
配置写入方式 (3种入口):
  ① 改YAML文件 → WatchService 检测 → 缓存失效 → 下次请求生效
  ② Admin API修改 → 写DB + 写YAML → Redis Pub/Sub通知 → 缓存失效 → 即时生效
  ③ 配置管理界面 → 调Admin API → 同②

生效路径 (统一):
  所有服务 → ConfigHub → 检查缓存键(mtime/version) → 返回最新值
```

### 2.1 第一层：DomainConfigLoader 热加载改造

#### 改造方案：照抄 PromptLoader 的 mtime 机制

```java
// DomainConfigLoader.java — 改造版

@Slf4j
@Component
public class DomainConfigLoader {

    // 改造1: 缓存结构从 DomainConfig 升级为 CacheEntry（带mtime）
    private final Map<String, CacheEntry> cache = new ConcurrentHashMap<>();

    private record CacheEntry(long mtime, DomainConfig config) {}

    @Value("${app.domain.scan-interval:5000}")  // 新增: 扫描间隔，默认5秒
    private long scanInterval;

    private Path externalDir;  // 外部目录路径

    @PostConstruct
    public void init() {
        String dir = System.getenv("PROMPTS_DIR");
        if (dir != null) {
            externalDir = Path.of(dir, "domain");
        }
    }

    // 改造2: load() 方法加入mtime检查
    public DomainConfig load(String domainId) {
        if (domainId == null || domainId.isBlank()) return null;

        String key = domainId;
        CacheEntry entry = cache.get(key);

        // 外部目录模式: 检查mtime
        if (externalDir != null) {
            Path yamlPath = resolveYamlPath(domainId);
            try {
                if (Files.exists(yamlPath)) {
                    long mtime = Files.getLastModifiedTime(yamlPath).toMillis();
                    if (entry == null || entry.mtime != mtime) {
                        // mtime变了 → 重新加载
                        DomainConfig config = loadAndMerge(domainId);
                        cache.put(key, new CacheEntry(mtime, config));
                        log.info("领域配置热加载: {} (mtime={})", domainId, mtime);
                        return config;
                    }
                    return entry.config;  // mtime没变 → 返回缓存
                }
            } catch (IOException e) {
                log.warn("领域配置mtime检查失败: {}", domainId, e);
            }
        }

        // 无外部目录 或 文件不存在 → classpath模式（永久缓存）
        if (entry != null) return entry.config;

        DomainConfig config = loadAndMerge(domainId);
        cache.put(key, new CacheEntry(System.currentTimeMillis(), config));
        return config;
    }

    // 改造3: 继承链mtime也需要检查
    private DomainConfig loadAndMerge(String domainId) {
        DomainConfig config = loadFile(domainId);
        if (config.getDomainExtends() != null) {
            DomainConfig parent = load(config.getDomainExtends());  // 递归，也会检查mtime
            config = deepMerge(parent, config);
        }
        return config;
    }

    // 改造4: 保留 clearCache()，现在Admin API会调用它
    public void clearCache() {
        cache.clear();
        log.info("领域配置缓存已清除");
    }

    // 改造5: 按需清除某个领域的缓存
    public void clearCache(String domainId) {
        cache.remove(domainId);
        log.info("领域配置缓存已清除: {}", domainId);
    }

    private Path resolveYamlPath(String domainId) {
        // "finance.secondary_market" → "finance/secondary_market.yml"
        String[] parts = domainId.split("\\.");
        if (parts.length == 1) {
            return externalDir.resolve(parts[0] + ".yml");
        }
        Path path = externalDir.resolve(parts[0]);
        for (int i = 1; i < parts.length; i++) {
            path = path.resolve(parts[i]);
        }
        return path.resolve(parts[parts.length - 1] + ".yml");
    }
}
```

#### 生效机制

**下次请求即生效**——不需要主动推送。每个服务每次请求都走 `domainConfigLoader.load()`，mtime变了就重新读取文件，mtime没变就返回缓存。这是最简单的"惰性热加载"模式：

- 性能无损：mtime检查是纳秒级操作（stat系统调用）
- 一致性保证：mtime变了必然重读，mtime没变必然返回缓存
- 零代码侵入：所有7个服务不需要改动任何代码，它们已经在每次请求调用 `domainConfigLoader.load()`

### 2.2 第二层：ConfigHub 统一配置管理

#### 新增 ConfigHub 组件

```java
/**
 * 配置中心 — 统一管理所有可热生效的配置
 * 提供: 配置查询/修改/发布/回滚/强制刷新
 * 支持: 文件源 + DB源 双写一致性
 */
@Slf4j
@RestController
@RequestMapping("/api/admin/config")
@RequiredArgsConstructor
public class ConfigHubController {

    private final DomainConfigLoader domainConfigLoader;
    private final PromptLoader promptLoader;
    private final DomainRegistryService domainRegistryService;
    private final ConfigAuditService configAuditService;

    // ========== 题域配置管理 ==========

    // 查询领域配置（当前生效的）
    @GetMapping("/domain/{domainId}")
    public DomainConfig getDomainConfig(@PathVariable String domainId) {
        return domainConfigLoader.load(domainId);
    }

    // 修改领域配置（在线编辑）
    @PutMapping("/domain/{domainId}")
    public DomainConfig updateDomainConfig(
            @PathVariable String domainId,
            @RequestBody DomainConfigUpdateRequest req) {

        // 1. 校验配置
        ValidationResult validation = domainConfigValidator.validate(req.getConfig());
        if (!validation.isValid()) {
            throw new ConfigValidationException(validation);
        }

        // 2. 双写: 写DB + 写YAML文件
        domainRegistryService.save(domainId, req.getConfig(), req.getChangeNote());
        domainYamlWriter.write(domainId, req.getConfig());  // 写外部YAML文件

        // 3. 清除缓存（让mtime机制下次请求时重读）
        domainConfigLoader.clearCache(domainId);

        // 4. Redis通知其他实例
        configEventPublisher.publish(domainId, "domain_config_updated");

        // 5. 审计日志
        configAuditService.log(domainId, "UPDATE", req.getChangeNote(), req.getOperator());

        return domainConfigLoader.load(domainId);  // 返回生效后的最新值
    }

    // 强制刷新所有配置缓存
    @PostMapping("/refresh")
    public RefreshResult refreshAll() {
        domainConfigLoader.clearCache();
        promptLoader.clearCache();
        domainRegistryService.refreshTree();

        configEventPublisher.publish("ALL", "config_refreshed");
        configAuditService.log("ALL", "REFRESH", "手动刷新全部配置", "admin");

        return RefreshResult.success();
    }

    // 强制刷新某个领域的配置缓存
    @PostMapping("/refresh/{domainId}")
    public RefreshResult refreshDomain(@PathVariable String domainId) {
        domainConfigLoader.clearCache(domainId);
        return RefreshResult.success(domainId);
    }

    // ========== 题域版本管理 ==========

    // 配置版本历史
    @GetMapping("/domain/{domainId}/versions")
    public List<DomainVersion> getVersions(@PathVariable String domainId) {
        return domainRegistryService.getVersions(domainId);
    }

    // 回滚到指定版本
    @PostMapping("/domain/{domainId}/rollback/{version}")
    public DomainConfig rollback(
            @PathVariable String domainId,
            @PathVariable int version) {
        DomainConfig config = domainRegistryService.rollback(domainId, version);
        domainYamlWriter.write(domainId, config);
        domainConfigLoader.clearCache(domainId);
        configEventPublisher.publish(domainId, "domain_config_rollback");
        configAuditService.log(domainId, "ROLLBACK", "回滚到版本" + version, "admin");
        return config;
    }

    // ========== 题域树管理 ==========

    // 动态领域树（替代 _tree.json）
    @GetMapping("/domain-tree")
    public List<DomainTreeNode> getDomainTree() {
        return domainRegistryService.getTree();
    }

    // 新增领域节点
    @PostMapping("/domain-tree")
    public DomainTreeNode addDomainNode(@RequestBody DomainTreeNode node) {
        DomainTreeNode created = domainRegistryService.addNode(node);
        configEventPublisher.publish("ALL", "domain_tree_updated");
        return created;
    }

    // ========== 题域场景关键词管理 ==========

    // 获取领域场景关键词
    @GetMapping("/domain/{domainId}/scene-mapping")
    public List<SceneMapping> getSceneMapping(@PathVariable String domainId) {
        DomainConfig config = domainConfigLoader.load(domainId);
        return config.getPrecheck().getSceneMapping();
    }

    // 修改领域场景关键词
    @PutMapping("/domain/{domainId}/scene-mapping")
    public List<SceneMapping> updateSceneMapping(
            @PathVariable String domainId,
            @RequestBody List<SceneMapping> mappings) {
        DomainConfig config = domainConfigLoader.load(domainId);
        config.getPrecheck().setSceneMapping(mappings);
        return updateDomainConfigInternal(domainId, config, "更新场景关键词");
    }

    // ========== 题域关键词组管理 ==========

    @GetMapping("/domain/{domainId}/keyword-groups")
    public List<KeywordGroup> getKeywordGroups(@PathVariable String domainId) {
        DomainConfig config = domainConfigLoader.load(domainId);
        return config.getPrecheck().getKeywordGroups();
    }

    @PutMapping("/domain/{domainId}/keyword-groups")
    public List<KeywordGroup> updateKeywordGroups(
            @PathVariable String domainId,
            @RequestBody List<KeywordGroup> groups) {
        DomainConfig config = domainConfigLoader.load(domainId);
        config.getPrecheck().setKeywordGroups(groups);
        return updateDomainConfigInternal(domainId, config, "更新关键词组");
    }

    // ========== 配置审计日志 ==========

    @GetMapping("/audit-log")
    public List<ConfigAuditLog> getAuditLog(
            @RequestParam(required = false) String domainId,
            @RequestParam(defaultValue = "50") int limit) {
        return configAuditService.query(domainId, limit);
    }

    // ========== 内部方法 ==========

    private <T> T updateDomainConfigInternal(String domainId, DomainConfig config, String note) {
        domainRegistryService.save(domainId, config, note);
        domainYamlWriter.write(domainId, config);
        domainConfigLoader.clearCache(domainId);
        configEventPublisher.publish(domainId, "domain_config_updated");
        configAuditService.log(domainId, "UPDATE", note, "admin");
        return (T) domainConfigLoader.load(domainId);
    }
}
```

#### DomainRegistryService

```java
@Service
@RequiredArgsConstructor
public class DomainRegistryService {
    private final DomainRegistryRepository repo;
    private final DomainVersionRepository versionRepo;
    private final ObjectMapper yamlMapper;

    // 获取领域树（动态构建，替代 _tree.json）
    public List<DomainTreeNode> getTree() {
        List<DomainRegistry> allDomains = repo.findByStatusNot("deprecated");
        return buildTree(allDomains);
    }

    // 保存配置（双写: DB + YAML文件）
    public void save(String domainId, DomainConfig config, String changeNote) {
        String yamlContent = yamlMapper.writeValueAsString(config);

        // DB写入
        DomainRegistry registry = repo.findById(domainId)
            .orElse(new DomainRegistry(domainId));
        registry.setConfigYaml(yamlContent);
        registry.setConfigVersion(registry.getConfigVersion() + 1);
        registry.setUpdatedAt(Instant.now());
        repo.save(registry);

        // 版本记录
        DomainVersionHistory version = new DomainVersionHistory();
        version.setDomainId(domainId);
        version.setVersion(registry.getConfigVersion());
        version.setConfigYaml(yamlContent);
        version.setChangeNote(changeNote);
        versionRepo.save(version);
    }

    // 回滚到指定版本
    public DomainConfig rollback(String domainId, int version) {
        DomainVersionHistory vh = versionRepo.findByDomainIdAndVersion(domainId, version);
        return yamlMapper.readValue(vh.getConfigYaml(), DomainConfig.class);
    }

    // 构建领域树
    private List<DomainTreeNode> buildTree(List<DomainRegistry> domains) {
        Map<String, DomainTreeNode> nodeMap = new LinkedHashMap<>();
        List<DomainTreeNode> roots = new ArrayList<>();

        for (DomainRegistry d : domains) {
            DomainTreeNode node = new DomainTreeNode(d.getId(), d.getName());
            nodeMap.put(d.getId(), node);
        }

        for (DomainRegistry d : domains) {
            if (d.getParentId() == null) {
                roots.add(nodeMap.get(d.getId()));
            } else {
                DomainTreeNode parent = nodeMap.get(d.getParentId());
                if (parent != null) parent.addChild(nodeMap.get(d.getId()));
            }
        }
        return roots;
    }
}
```

### 2.4 第二层补充：Redis Pub/Sub 多实例通知

```java
/**
 * 配置变更事件发布器
 * 当一个实例修改了配置，通过Redis通知其他实例清除缓存
 */
@Component
@RequiredArgsConstructor
public class ConfigEventPublisher {

    private final RedisTemplate<String, String> redisTemplate;
    private static final String CHANNEL = "ai-extract:config-events";

    public void publish(String domainId, String action) {
        ConfigEvent event = new ConfigEvent(domainId, action, Instant.now());
        redisTemplate.convertAndSend(CHANNEL, event.toJson());
    }
}

@Component
@RequiredArgsConstructor
public class ConfigEventSubscriber {

    private final DomainConfigLoader domainConfigLoader;
    private final PromptLoader promptLoader;

    @RedisListener(channel = "ai-extract:config-events")
    public void onEvent(String message) {
        ConfigEvent event = ConfigEvent.fromJson(message);

        if ("config_refreshed".equals(event.getAction()) || "ALL".equals(event.getDomainId())) {
            domainConfigLoader.clearCache();
            promptLoader.clearCache();
        } else {
            domainConfigLoader.clearCache(event.getDomainId());
        }

        log.info("收到配置变更通知: domainId={}, action={}", event.getDomainId(), event.getAction());
    }
}
```

**效果**：3个后端实例部署时，改配置只需在一个实例操作，Redis通知另外2个实例清缓存，1秒内全集群生效。

### 2.7 WatchService 文件监听（可选增强）

mtime检查是"下次请求时检查"的惰性模式。如果想做到"文件改了立刻主动清除缓存"，可以加WatchService：

```java
@Component
public class DomainConfigWatcher {

    private final DomainConfigLoader domainConfigLoader;
    private WatchService watchService;
    private Path watchDir;

    @PostConstruct
    public void startWatching() throws IOException {
        String dir = System.getenv("PROMPTS_DIR");
        if (dir == null) return;  // 无外部目录则不启动监听

        watchDir = Path.of(dir, "domain");
        if (!Files.exists(watchDir)) return;

        watchService = FileSystems.getDefault().newWatchService();
        watchDir.register(watchService,
            StandardWatchEventKinds.ENTRY_MODIFY,
            StandardWatchEventKinds.ENTRY_CREATE);

        // 递归注册子目录
        registerSubDirectories(watchDir);

        Thread watcherThread = new Thread(this::watchLoop, "domain-config-watcher");
        watcherThread.setDaemon(true);
        watcherThread.start();

        log.info("领域配置文件监听已启动: {}", watchDir);
    }

    private void watchLoop() {
        try {
            while (true) {
                WatchKey key = watchService.take();
                for (WatchEvent<?> event : key.pollEvents()) {
                    Path changed = (Path) event.context();
                    String domainId = extractDomainId(changed);
                    if (domainId != null) {
                        log.info("领域配置文件变更: {} → 清除缓存", domainId);
                        domainConfigLoader.clearCache(domainId);
                    }
                }
                key.reset();
            }
        } catch (InterruptedException e) {
            log.info("领域配置文件监听停止");
        }
    }

    private String extractDomainId(Path changedPath) {
        String name = changedPath.getFileName().toString();
        if (!name.endsWith(".yml")) return null;
        return name.replace(".yml", "");
    }

    @PreDestroy
    public void stopWatching() throws IOException {
        if (watchService != null) watchService.close();
    }
}
```

**选择建议**：
- **Phase 1**：只用mtime检查（最简单，零额外线程，已有PromptLoader验证可行）
- **Phase 2**：加WatchService（主动感知，改了文件1秒内清缓存，适合多实例场景）
- 两层可以共存：mtime是保底安全网，WatchService是加速触发器

## 三、各配置项的热生效路径

| 配置项 | 改什么 | 怎么生效 | 生效延迟 |
|-------|--------|---------|---------|
| 题域基本信息(role_label等) | YAML文件 或 Admin API | mtime检查/缓存清除 | 下次请求(~0ms) |
| 准入参数(min_text_length等) | YAML文件 或 Admin API | mtime检查/缓存清除 | 下次请求(~0ms) |
| 场景关键词 | YAML文件 或 场景编辑器 | mtime检查/缓存清除 | 下次请求(~0ms) |
| 业务白名单 | YAML文件 或 Admin API | mtime检查/缓存清除 | 下次请求(~0ms) |
| 萃取管道参数 | YAML文件 或 Admin API | mtime检查/缓存清除 | 下次请求(~0ms) |
| Prompt模板 | md文件 | PromptLoader已有mtime检查 | 下次请求(~0ms) |
| 题域树(新增/删除领域) | DB domain_registry | DomainRegistryService动态构建 | 即时(API调用时) |
| 配置版本 | Admin API保存时自动递增 | DB记录 | 即时 |

**关键**：所有配置项的生效延迟都是"下次请求"，不需要重启应用。mtime检查在每次load()调用时执行，是纳秒级的stat系统调用，对性能零影响。

## 六、技术保障

### 6.1 并发安全

- `ConcurrentHashMap` 本身线程安全
- mtime检查在load()内原子判断：`entry == null || entry.mtime != mtime`
- 缓存清除用 `cache.remove(key)` 原子操作
- 没有锁、没有竞态条件

### 6.2 性能影响

- mtime检查：stat系统调用，约0.01ms
- 每次请求额外0.01ms，完全可忽略
- WatchService：daemon线程，零CPU占用（阻塞在take()上）

### 6.3 多实例一致性

- Redis Pub/Sub广播缓存清除事件
- 最坏情况：某实例Redis消息延迟 → 额外5秒内mtime检查兜底生效
- 不存在"部分实例用旧配置"的持久性问题

### 6.4 文件+DB双写一致性

- Admin API修改时：先写DB → 再写YAML → 再清缓存
- 如果写YAML失败：DB有最新值，下次mtime检查会用classpath兜底
- 如果写DB失败：不写YAML、不清缓存，保持旧配置
- 极端情况：YAML和DB不一致 → DB是权威源，mtime检查兜底保证最终一致

## 七、与多领域架构方案的衔接

本方案是之前"多领域架构设计方案"的基础设施层。配置化热生效解决的是**如何让配置变更即时生效**，多领域架构解决的是**如何设计领域配置的结构**。两者结合：

```
多领域架构 (领域元模型/继承/Prompt模板) — 定义配置的结构
  ↓
配置化热生效 (mtime/WatchService/Admin API/DB双写) — 让配置变更即时生效
  ↓
配置管理界面 (可视化编辑/版本管理/审计) — 让运营自助操作
```

**核心交付链**：
1. 先做配置化热生效（Phase 1-2） → 改配置即时生效的基础能力
2. 再做多领域架构 → 扩领域配置的结构优化
3. 最后做配置管理界面 → 运营自助调参

这样运营和开发者都能做到：**改配置 → 自动生效 → 零重启 → 零代码改动**。
