## 1. 问题与实测证据（不是推测）

### 1.1 现状实现

`EvaluationGenerationService.runGeneration` 当前三层去重：

1. 精确：`normalizeQuestion` 去空白转小写后比对题干（挡一字不差）。
2. 语义：题干 embedding 余弦 ≥ `app.evaluation.dedup-sim-threshold`（默认 0.90）(挡换说法)。
3. 接受后把题干/向量追加进基线，供同批次后续素材比对。

### 1.2 实机结果（2026-10-28 14:13，jobId `ec93b6d8`）

对题集 `a7624dcc`（5 题基线）用同一素材再生成一次：`producedCount=5`，日志无 `候选生成去重` 行（`skippedExact=0, skippedSemantic=0`）。产出的 6–10 题逐条是 1–5 题的复述。

真实余弦（DashScope `text-embedding-v4` 1024 维，逐题计算）：

## 2. 设计目标与非目标

### 目标
1. 「同一素材的同一事实」在题集内**至多一题**，判等依据是事实标识而非题干文本。
2. 事实标识**必须可复现**：同一素材重复出题，两轮得到相同的标识（不依赖模型措辞稳定）。
3. 零新增 AI 调用、零新增外部依赖；事实标识计算在生成任务线程内，不进事务。
4. 失效可解释：每个被丢弃的候选都归入明确计数，日志可追溯。

### 非目标（本批次不做，避免过度设计）
- 不做跨素材的「同事实不同措辞」合并（属知识库自身去重问题，见 docs/39 §2.4 的 5 组重名）。
- 不回溯补齐历史题目（39 条既有 `fact_key` 为 NULL，保持原样）。
- 不改前端、不改 API 契约、不改 `evaluation_item` 之外的任何表。

## 3. 核心机制：以「素材句子」为事实单元

### 3.1 为什么不用模型生成的 factKey

若让模型自己输出「事实编号」，两轮生成会给出不同编号/不同措辞 → 标识不稳定，等于把去重失效换个地方重演。

### 3.2 事实单元 = 素材中的一句话（服务端切分，确定性）

- `factKey = SHA-256(normalize(句子))`，句子由**服务端从素材原文切分**得到，模型不参与。
- 模型只承担两件事：① 引用它出题所依据的**素材原文片段**（verbatim，不生成）；② 编写题干。
- 服务端把模型引用的片段**吸附到所在句子**（`quote ⊆ sentence`），标识落在句子上。

这样：
- 模型引用「第21类客户场景下的关键动作」或「提升成交转化率」——两者同句 → 同一 `factKey` → 第二轮被判重。
- 标识只取决于素材原文与切分规则，**与模型措辞无关**，可复现。

### 3.3 切分与归一化规则（精确）

```java
/** 句子边界：中文/英文句末与换行。半角/全角都要，素材来自多格式解析。 */
private static final char[] SENTENCE_DELIMS = {'。', '！', '？', '；', '!', '?', ';', '\n'};

/** 归一化：只保留字母/数字/汉字并转小写（Character.isLetterOrDigit 对汉字返回 true）。 */
private String normalizeForMatch(String text) {
    if (text == null) {
        return "";
    }
    StringBuilder sb = new StringBuilder(text.length());
    for (int i = 0; i < text.length(); i++) {
        char c = text.charAt(i);
        if (Character.isLetterOrDigit(c)) {
            sb.append(Character.toLowerCase(c));
        }
    }
    return sb.toString();
}
```

归一化同时抹掉空白与全部标点，因此 `，`/`,`、全角括号等排版差异不影响判等，也不需要维护一张标点表。

```java
/** 按句末符与换行切分，丢弃归一化后长度 < 6 的碎片（"分类：methodology" 这类字段头）。 */
private List<String> splitSentences(String content) { ... }

/** 把模型引用片段吸附到素材句子；找不到返回 null（该候选作废）。 */
private String resolveFactSentence(String sourceContent, String quote) {
    String q = normalizeForMatch(quote);
    if (q.length() < FACT_QUOTE_MIN_MATCH) {   // = 6
        return null;
    }
    for (String sentence : splitSentences(sourceContent)) {
        if (normalizeForMatch(sentence).contains(q)) {
            return sentence;
        }
    }
    return null;
}

/** factKey = SHA-256(归一化句子) 的 64 位小写十六进制。 */
private String factKeyOf(String sentence) { ... }
```

## 5. Prompt 变更：`prompts/eval_generate_item.md`

新增变量 `{exclude_facts}`，输出 JSON 增加必填字段 `factQuote`。完整模板：

```markdown
# 变量: {source_type}, {source_content}, {purpose}, {exclude_questions}, {exclude_facts}

你是销售经验萃取平台的评测题目生成专家。请严格依据下面的{source_type}素材，生成候选评测题目，
用于检验 AI 销售分身是否真正掌握并正确应用该素材。

## 素材类型
{source_type}

## 题集用途
{purpose}
- regression（研发回归）：检验检索召回，重点给出 retrievalExpected（期望命中的知识/案例标题或场景标签）
- acceptance（分身验收）/ training（培训考试）：检验回答质量，重点给出 expectedPoints（金标要点）

## 素材内容
{source_content}

## 本题集已有题目（严禁重复）
{exclude_questions}

## 本题集已覆盖的事实（严禁再出题）
{exclude_facts}

## 生成要求
1. 只从素材中提炼真实存在的信息，不要编造、不要引申素材之外的内容。
2. 一道题只检验一个事实；同一事实只出一题。
3. factQuote 必须从「素材内容」中**逐字连续摘抄** 1 段（10~80 字），代表该题所检验的事实。
   不允许改写、拼接、跨句摘抄；摘抄不到就说明素材没有可用事实，此时不要为该事实出题。
4. 已有题目与已覆盖事实都不得重复，也不得只是换个说法复述其中任何一条。
5. 每题包含：
   - question：题干，模拟真实客户提问或业务场景
   - factQuote：逐字摘抄的事实片段（见要求 3，必填）
   - context：可选固定上下文，没有则为空字符串
   - expectedPoints：预期要点数组（金标，验收/考试用）
   - forbiddenPoints：禁止项数组（红线，命中即失败，没有则为空数组）
   - citationRequirement：引用要求，没有则为 null
   - sceneTag：场景标签
   - goldBasis：金标依据，即素材标题
   - retrievalExpected：检索期望数组（研发回归用，期望命中的知识/案例标题或场景标签）
6. 每份素材生成 1~3 题；素材不足以出题时输出 []。
7. 严格输出纯 JSON 数组，不要 markdown 代码块，不要任何额外说明文字：
[{"question":"...","factQuote":"...","context":"","expectedPoints":["..."],"forbiddenPoints":[],"citationRequirement":null,"sceneTag":"...","goldBasis":"...","retrievalExpected":["..."]}]
```

`{exclude_facts}` 由 `buildFactBlock` 生成（新增方法，复用 `buildExcludeBlock` 的形状）：

```java
/** 拼「已覆盖事实」避让清单；上限 PROMPT_EXCLUDE_MAX 条、单条截断 PROMPT_QUESTION_MAX_CHARS。 */
private String buildFactBlock(List<String> coveredFacts) {
    if (coveredFacts.isEmpty()) {
        return "（本题集暂无已覆盖事实）";
    }
    int limit = Math.min(coveredFacts.size(), PROMPT_EXCLUDE_MAX);
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < limit; i++) {
        String f = coveredFacts.get(i);
        if (f != null && f.length() > PROMPT_QUESTION_MAX_CHARS) {
            f = f.substring(0, PROMPT_QUESTION_MAX_CHARS) + "…";
        }
        sb.append(i + 1).append(". ").append(f).append('\n');
    }
    if (coveredFacts.size() > limit) {
        sb.append("（其余 ").append(coveredFacts.size() - limit).append(" 条略）\n");
    }
    return sb.toString();
}
```

## 6. 生成流程变更（`runGeneration` 精确改写）

### 6.1 新增常量

```java
/** 事实引用片段的最短归一化长度：过短（如"话术"）无法定位唯一句子，一律作废 */
private static final int FACT_QUOTE_MIN_MATCH = 6;

/** fact_quote 落库截断长度，与 DDL varchar(200) 对齐 */
private static final int FACT_QUOTE_MAX_CHARS = 200;
```

### 6.2 删除的成员（语义去重整条链路移除，理由见 §1.2）

| 成员 | 处理 |
|---|---|
| `DEDUP_BASELINE_MAX` | 删除 |
| `dedupSimThreshold`（`@Value`） | 删除，并从 `application.yml` 移除 `app.evaluation.dedup-sim-threshold` |
| `embeddingService`（构造注入） | 删除该字段与 import（类本身仍被知识/案例审批使用，不删） |
| `embedExistingQuestions` / `embedQuestionsOf` / `embedQuestions` | 删除 |
| `isSemanticDuplicate` / `cosine` | 删除 |

保留 `normalizeQuestion`（精确去重）与 `buildExcludeBlock`（题干避让）。

### 6.3 改写后的循环（可直接编译）

```java
int nextOrderNo = itemRepository.findMaxOrderNo(ds.getId(), ds.getCurrentVersion());
List<String> existingQuestions = new ArrayList<>(itemRepository
        .findQuestionsByDatasetIdAndVersionAndStatus(
                ds.getId(), ds.getCurrentVersion(), EvaluationItem.STATUS_ACTIVE));
Set<String> seenQuestions = new HashSet<>();
existingQuestions.forEach(q -> seenQuestions.add(normalizeQuestion(q)));

// 事实级去重基线：已有题目的 fact_key（手工题为 NULL，不参与）+ 已有事实原文（喂 prompt）
Set<String> seenFactKeys = new HashSet<>(itemRepository
        .findFactKeysByDatasetIdAndVersionAndStatus(
                ds.getId(), ds.getCurrentVersion(), EvaluationItem.STATUS_ACTIVE));
List<String> coveredFacts = new ArrayList<>(itemRepository
        .findFactQuotesByDatasetIdAndVersionAndStatus(
                ds.getId(), ds.getCurrentVersion(), EvaluationItem.STATUS_ACTIVE));

List<EvaluationItem> items = new ArrayList<>();
int skippedExact = 0;
int skippedFact = 0;
int rejectedNoFact = 0;

for (UUID sourceId : sourceIds) {
    SourceText source = loadSource(sourceType, sourceId);
    if (source == null) {
        log.warn("来源条目不存在，跳过 sourceType={}, sourceId={}", sourceType, sourceId);
        continue;
    }
    List<FactCandidate> generated = generateFromSource(ds, sourceType, source, existingQuestions, coveredFacts);
    for (FactCandidate candidate : generated) {
        EvaluationItem item = candidate.item();
        String sentence = resolveFactSentence(source.content(), candidate.factQuote());
        if (sentence == null) {
            // 没有可定位的事实引用 → 该题没有去重依据，宁可丢弃也不能让题集里出现无法判重的题
            rejectedNoFact++;
            log.warn("候选题事实引用无法定位，已丢弃 datasetId={}, sourceId={}, factQuote={}, question={}",
                    ds.getId(), sourceId, candidate.factQuote(), item.getQuestion());
            continue;
        }
        String factKey = factKeyOf(sentence);
        if (!seenQuestions.add(normalizeQuestion(item.getQuestion()))) {
            skippedExact++;
            continue;
        }
        if (!seenFactKeys.add(factKey)) {
            skippedFact++;
            continue;
        }
        item.setFactKey(factKey);
        item.setFactQuote(truncate(sentence, FACT_QUOTE_MAX_CHARS));
        item.setOrderNo(++nextOrderNo);
        items.add(item);
        existingQuestions.add(item.getQuestion());
        coveredFacts.add(item.getFactQuote());
    }
}

if (skippedExact > 0 || skippedFact > 0 || rejectedNoFact > 0) {
    log.info("候选生成去重 jobId={}, skippedExact={}, skippedFact={}, rejectedNoFact={}, kept={}",
            jobId, skippedExact, skippedFact, rejectedNoFact, items.size());
}
self.persistItems(jobId, items);
```

判等顺序固定：**事实可定位 → 精确重复 → 事实重复 → 接受**。`seenFactKeys.add` 只在接受后调用，保证同批次内同事实只留一题。

## 7. 计数语义与日志（验收依据）

| 计数 | 含义 | 是否算 `producedCount` |
|---|---|---|
| `skippedExact` | 题干归一化后与已有/本批题目相同 | 否 |
| `skippedFact` | 事实标识已存在于本题集本版本（含本批已接受） | 否 |
| `rejectedNoFact` | 模型未给 factQuote，或片段在素材中定位不到 | 否 |
| `kept` | 实际入库题数 = `job.producedCount` | 是 |

三类丢弃**互斥且穷尽**：任一候选必落入其中之一或被接受，无静默丢弃。

## 8. 风险与已知限制（必读，不得在验收时隐瞒）

| # | 限制 | 影响 | 处置 |
|---|---|---|---|
| R1 | 句子是最小事实单元，单句含多个独立事实时只能出一题 | 长句素材出题数偏少 | 切分已含 `；`/换行细分；后续可改「原子结论」标注 |
| R2 | 两轮生成若引用**不同句子**来考同一事实，fact_key 不同 → 漏检 | 仍可能出重复题 | prompt 已把「已覆盖事实」原文喂给模型避让；剩余靠人工审核 |
| R3 | 历史 39 题 `fact_key` 为 NULL，不参与事实判重 | 老题集重跑仍可能被复述 | 本次不回溯（见 §2 非目标）；旧题仍有精确比对兜底 |
| R4 | 模型可能引用与题干无关的合法句子骗过定位 | 标识失真 | 定位只保证「引用真实存在」，语义相关性属出题质量，由审核环节把关 |
| R5 | 移除 embedding 语义去重后，对无 fact_key 的历史题不再有任何语义兜底 | 老题集回归能力下降 | 实测该兜底本身无效（§1.2），保留即为死代码 |
