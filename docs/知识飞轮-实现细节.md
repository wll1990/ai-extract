## 一、数据根基：一条颗粒长什么样

[ExperienceGrain.java](backend/src/main/java/com/aiextract/model/ExperienceGrain.java) — 4 个业务字段是飞轮的调整对象：

| 字段 | 含义 | 示例 | 谁改 |
|------|------|------|------|
| `expert_thought` | 专家的思考逻辑 | "不能直接降价，先量化客户的损失感知..." | 管理员/分身主 |
| `standard_script` | 实战原话 | "王总我理解，咱们算一笔账..." | 管理员/分身主 |
| `common_mistakes` | 常犯错误 | "新人直接报折扣价，没问客户对比的是哪个版本" | 管理员/分身主 |
| `applicable_condition` | 适用条件 | "确认竞品是相同功能级别时有效" | 管理员/分身主 |

3 个统计字段是飞轮的判断依据：

| 字段 | 含义 | 谁更新 |
|------|------|--------|
| `helpful_count` | 👍 次数 | `SkillService.submitFeedback()` 原子递增 |
| `unhelpful_count` | 👎 次数 | 同上 |
| `quality_score` | AI 验证综合分(0-5) | `MaterialCleaningScheduler` 萃取时写入 |
| `status` | active / deprecated | 管理员标记废弃 |
| `edited_content` | 管理员编辑后的 JSON | 管理员在线编辑时写入 |

还有两个表需要新建：

```
feedback_log   — 每次打分的完整记录（给飞轮看趋势）
knowledge_gap  — RAG 0 结果时记录（给飞轮找缺失）
```

## 二、飞轮四步，每一步的具体代码

### 第 1 步：用户打分 — 飞轮的数据来源

**触发**：用户点 👍 或 👎

**前端** [page.tsx:264-273](frontend/src/app/skill/%5BskillId%5D/page.tsx#L264-L273)：
```tsx
{/* 👍 按钮 */}
onClick={() => qa.handleFeedback(msg.id, msg.grainId || '', true)}
{/* 👎 按钮 */}
onClick={() => qa.handleFeedback(msg.id, msg.grainId || '', false)}
```

**前端** `useQaChat.ts` — `handleFeedback` 调用 `submitFeedback` API，更新本地 `feedbackState`。

**后端** [SkillService.java:162-175](backend/src/main/java/com/aiextract/service/SkillService.java#L162-L175) — 当前实现：
```java
public void submitFeedback(String skillId, FeedbackRequest request) {
    if (request.getGrainId() == null || request.getGrainId().isBlank()) return;
    UUID grainId = UUID.fromString(request.getGrainId());
    if (Boolean.TRUE.equals(request.getHelpful())) {
        grainRepository.incrementHelpful(grainId);
    } else {
        grainRepository.incrementUnhelpful(grainId);
    }
}
```

**需要增强**：
- 写入 `feedback_log` 表（记录完整上下文：当时 RAG 分数、用户问题原文、时间）
- 这样后续管理员可以看到"被踩的回答长什么样"，而不是只知道计数

```java
// 增强后的 submitFeedback
feedbackLogRepository.save(FeedbackLog.builder()
    .skillId(UUID.fromString(skillId))
    .grainId(grainId)
    .rating(request.getHelpful() ? "up" : "down")
    .query(request.getQuery())        // 新增：用户当时的提问
    .ragScore(request.getRagScore())  // 新增：当时的 RAG 匹配度
    .createdAt(LocalDateTime.now())
    .build());
```

### 第 2 步：知识缺口收集 — 发现"用户想知道但我们没有的"

**触发**：RAG 检索 0 结果

**后端** [ChatStreamService.java:401-405](backend/src/main/java/com/aiextract/service/ChatStreamService.java#L401-L405) — 当前：
```java
if (scored.isEmpty()) {
    List<ExperienceGrain> fallback = grainRepository.findBySpaceId(spaceId)
        .stream().limit(20).collect(Collectors.toList());
    return new GrainResult(fallback, Map.of(), Map.of());
}
```

**改为**：
```java
if (scored.isEmpty()) {
    // 1. 记录知识缺口
    knowledgeGapRepository.upsert(
        skill.getId(), skill.getSpaceId(), request.getMessage(),
        guessSceneTags(request.getMessage()));

    // 2. 返回空颗粒，不硬塞
    return new GrainResult(List.of(), Map.of(), Map.of());
}
```

`guessSceneTags` 逻辑：用现有的 `classify_scenes.md` prompt 快速标注问题属于哪个场景。即使没匹配到颗粒，也能告诉管理员"这个问题大概是关于 '价格谈判' 的"。

### 第 3 步：管理员审查 — 发现问题后怎么改

**入口**：Admin 后台 → 分身调优

**三个数据源**：

| 数据源 | 查询 | 展示 |
|--------|------|------|
| 低质量颗粒 | `SELECT * FROM experience_grain WHERE unhelpful_count > 0 ORDER BY unhelpful_count DESC LIMIT 20` | 列表，每行显示颗粒文本 + 👎次数 + 最近一条反馈时间 |
| 知识缺口 | `SELECT * FROM knowledge_gap WHERE skill_id=? AND status='open' ORDER BY count DESC` | 列表，每行显示问题原文 + 出现次数 + 推测场景 |
| 对话抽样 | `SELECT * FROM feedback_log WHERE skill_id=? ORDER BY RANDOM() LIMIT 20` | 20 条随机真实问答，手动标注"通过/需改进" |

**管理员可以做的操作**：

```
看到一条低质量颗粒 "客户砍价怎么应对？"
  │
  ├─ [查看对话]  → 展开看到用户问什么、AI 答了什么、用户为什么 👎
  │
  ├─ [编辑颗粒]  → 弹出编辑框，修改 expert_thought / standard_script / common_mistakes
  │                保存 → UPDATE experience_grain SET expert_thought=?, standard_script=?
  │                重新计算 embedding → UPDATE embedding column
  │
  ├─ [标记废弃]  → UPDATE experience_grain SET status='deprecated'
  │
  └─ [补充新颗粒] → 手动填写 4 个字段 → INSERT INTO experience_grain
                     → 生成 embedding
```

**关键**：编辑颗粒文本后**必须重新生成向量**，否则 RAG 检索不到修改后的内容：

```java
// 颗粒编辑保存后
grainRepository.save(grain);                         // ① 保存文本
float[] vec = embeddingService.embed(grain.getExpertThought()
    + " " + grain.getStandardScript());              // ② 重新向量化
jdbc.update("UPDATE experience_grain SET embedding=?::vector WHERE id=?",
    arrayToPgVector(vec), grain.getId());            // ③ 更新 embedding
promptLoader.invalidate(name, domain);               // ④ 失效相关 prompt 缓存
```

### 第 4 步：分身更新 — 改完后怎么生效

**路径 1**：改颗粒文本 → 重新 embedding → **下次 RAG 检索自动生效**（无需重启）

**路径 2**：改画像参数（personality/speaking_style）→ 更新 `skill_profile` 表 → **下次对话自动用新画像**（System Prompt 每次从 DB 读）

**路径 3**：改提示词模板 → Admin 编辑 → 发布 → `promptLoader.invalidate()` → **下次 prompt 加载从 DB 读新版本**

三种修改都不需要重启服务，下次用户对话立即生效。

## 三、具体示例：一条颗粒的完整优化过程

```
第 1 天
  用户 A 问: "客户说你们比竞品贵 30%，怎么办？"
  RAG 匹配到颗粒 #G-042，专家回答用了这条颗粒
  用户 A 点 👎 — 因为标准话术里说"不降价、算总账"，但用户觉得太生硬
  ↓
  feedback_log 写入: {grain_id: G-042, rating: "down", query: "客户说贵30%", rag_score: 0.68}

第 3 天
  G-042 累计被 👎 了 3 次，管理员在"反馈审查"列表看到它排在前面
  管理员点 [查看对话] → 看到 3 条真实对话
  发现共同问题: 话术确实太生硬，用户反馈"客户听了反而更生气"

第 4 天
  管理员点 [编辑颗粒] → 修改 standard_script:
    改前: "不降价、算总账。您算一笔账..."
    改后: "我理解您这个顾虑特别真实。咱们换个角度看——您比较的是现在
           的价格还是三年总成本？我有个客户算了笔账，发现..."
  保存 → embedding 自动重算 → 颗粒更新完成

第 5 天
  用户 B 问: "你们价格比竞品高怎么解释？"
  RAG 匹配到 G-042（已更新）→ AI 用新话术回答
  用户 B 点 👍
  ↓
  G-042 的 helpful_count 开始上升，飞轮转动
```

## 五、飞轮的"飞"体现在哪里

```
初始状态: 100 条颗粒，5 个场景，满意度 70%

Week 1:
  用户提问 → 500 条反馈 → 发现 12 个缺口 → 管理员补充 8 条颗粒
  → 满意度 72%

Week 2:
  用户提问 → 800 条反馈 → 发现 5 条低质量颗粒 → 编辑优化
  → 满意度 76%

Week 4:
  用户提问 → 2000 条反馈 → 缺口开始收敛（常见问题已覆盖）
  → 满意度 82%

Week 8:
  用户提问 → 5000 条反馈 → 缺口稀少，主要是"长尾罕见问题"
  → 满意度 88%

Week 12:
  新客户上线 → 直接复用同行业已优化的颗粒模板
  → 冷启动满意度从 70% 提升到 80%
```

关键：**每次不满意都是一个改进信号，每次改进都让下一次更准。** 这就是飞轮。
