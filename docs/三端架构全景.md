## 一、三端概览

| 端 | 本地端口 | 目录 | 用户角色 | 说明 |

| **B 端** | 3000 | `frontend/` | super_admin / company_admin / employee | 管理后台 + 分身广场 |

## 三、核心组件依赖

```
SkillChatView (B端共享)
  ├── VoiceRecorder      ← 语音输入
  ├── ThinkingCard       ← 等待 AI 回复动画 (@aiextract/shared-ui)
  └── useQaChat          ← QA/Talk 聊天状态 hook

SalesInterviewChat (B端 + H5 共用)
  ├── VoiceRecorder
  ├── ThinkingCard       ← (@aiextract/shared-ui)
  └── useInterviewSession ← 访谈状态 hook

ExpertInterviewChat (B端独立)
  ├── VoiceRecorder
  ├── PhaseProgressBar    ← 四阶段进度
  └── useInterviewSession

MobileChatShell (C端分享独立)
  ├── VoiceRecorder
  ├── ThinkingCard       ← (@aiextract/shared-ui)
  └── useQaChat

ChatView → ChatActive (平台端独立)
  ├── VoiceRecorder       ← 拷贝自 frontend
  ├── ThinkingCard        ← (@aiextract/shared-ui)
  └── useChat             ← 平台端自有 hook

PracticeView (平台端独立)
  └── VoiceRecorder       ← 拷贝自 frontend
```

## 四、共用 vs 独立汇总

### 同一份代码（共享）

| 组件/Hook | 使用者 |
|------|------|
| `SkillChatView` | B端分身 QA/Talk + B端对练 |
| `SalesInterviewChat` | B端销售访谈 + H5 移动端访谈 |
| `ThinkingCard` | `@aiextract/shared-ui` → SkillChatView + MobileChatShell + SalesInterviewChat + ChatActive |
| `useQaChat` | B端分身 + C端分享 + 对内分享 |
| `useInterviewSession` | ExpertInterviewChat + SalesInterviewChat |

### 各自独立实现（不共享）

| 页面 | 原因 |
|------|------|
| `ExpertInterviewChat` | 四阶段推进、萃取进度面板，逻辑特殊 |
| `MobileChatShell` | 游客体系、注册抽屉、手机布局 |
| `ChatView` / `ChatActive` | 平台端自有 hooks、inline styles、不同 UI 风格 |
| `PracticeView` | 平台端自有对练逻辑、逐轮评价 |

### 拷贝（两端各一份）

| 文件 | 原因 |
|------|------|
| `VoiceRecorder` | `frontend/` 和 `platform/` 各一份，两个独立的 Next.js 项目 |

## 六、数据流 & 状态管理

| 端 | Hook | 管理内容 |
|------|------|------|
| B端分身 | `useQaChat` | messages / inputValue / isStreaming / qaStreamText / currentConvId / feedbackState |
| B端访谈 | `useInterviewSession` | session / messages / inputValue / isStreaming / phases / collectStatus |
| C端分享 | `useQaChat` + `useGuestSession` | 同上 + 游客身份 / remaining / ensuring |
| 平台端 | `useChat`（自有） | messages / streamText / phase / currentConvId |

### 流式消息状态机

```
entry → streaming（首 chunk 前: ThinkingCard）→ streaming（首 chunk 后: 文本流）→ idle
```
