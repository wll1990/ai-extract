## 二、依赖关系地狱清单

### 2.1 环境变量缺失/错误（最易导致启动失败）

| 变量名 | 使用位置 | 缺失后果 | 必查文件 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | 根目录 `.env` | AI 服务全部不可用，访谈/分身/报告生成全部报错 10001/10002 | [.env.example](/.env.example) |
| `JWT_SECRET` | 根目录 `.env` → `application.yml` jwt.secret | 启动不报错但所有 Token 无法验证，登录后任何请求返回 401 | [application.yml](backend/src/main/resources/application.yml) :42 |
| `LLM_API_KEY` | `ai-service/.env` | Python AI 服务无法调用大模型 | [ai-service/.env.example](ai-service/.env.example) |
| `LLM_API_BASE` | `ai-service/.env` | 默认 `https://api.deepseek.com`，错误则 SSE 流无响应 | [ai-service/.env.example](ai-service/.env.example) |

**修复 SOP**：
1. 检查根目录 `.env` 和 `ai-service/.env` 两个文件是否都存在
2. 两个文件中的 API Key 必须一致
3. 若 `JWT_SECRET` 未设置，使用默认值 `ec86ce46-f6f3-4075-8114-7dad9bc3b08e`（仅开发环境）
