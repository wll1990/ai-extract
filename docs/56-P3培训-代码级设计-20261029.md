### 4.2 `TrainingRemediationService`（新）

```java
public record RemediationResult(TrainingTaskRecord record, TrainingAssignment assignment, int roundNo) {}

@Transactional(rollbackFor = Exception.class)
public RemediationResult create(UUID assignmentId, UUID recordId, String reason, LocalDateTime deadline);

@Transactional
public void applyDeadlineIfNeeded(TrainingAssignment lockedAssignment, LocalDateTime newDeadline, String reason);
```

事务顺序（写死）：
1. 无锁读 assignment → `accessService.assertCanReview(cohortId)`；
2. `findByIdForUpdate(assignmentId)` 锁分配；
3. 校验：状态 ∈ `{not_started,in_progress,pending_certification}`；`learner != token` 或超管；目标 record 属于该 assignment；目标 record 是该 task 的 `max(round_no)`；状态 `failed`；任务非 reading；`round+1 <= app.training.remediation.max-rounds`；
4. 若 assignment 已过截止且 `deadline == null` → 409 `REMEDIATION_DEADLINE_REQUIRED`；带 deadline 则先延期（规则 C）；
5. 插入新 record：`status=available`、`roundNo=old+1`、`remediationOfRecordId=recordId`、`remediationReason`、`remediationCreatedBy`；
6. 调用 `progressService.reevaluateCertificationState(assignmentId)` 统一判定：
   有新补训轮未出结论 → `pending_certification → in_progress`；不再硬编码降级顺序；
7. 审计 `training.remediation.create`；事务提交后通知学员。

唯一键冲突 `DataIntegrityViolationException` → 409 `REMEDIATION_STATE_CHANGED`。

### 4.3 `TrainingProgressService`（改造）

```java
@Transactional public void applyRecordResult(UUID recordId, boolean passed);
@Transactional public void recomputeCounters(UUID assignmentId); // 锁 assignment 后绝对写回
@Transactional public void reevaluateCertificationState(UUID assignmentId);
```

- `roundNo == 1`：保持现有 delta 逻辑；`failed` 时同样调用 `reevaluateCertificationState`。
- `roundNo > 1`：条件迁移 record 后调用 `recomputeCounters`：
  ```java
  assignmentRepository.findByIdForUpdate(assignmentId);
  List<TrainingTaskRecord> all = recordRepository.findByAssignmentIdOrderByCreatedAtAsc(assignmentId);
  List<TrainingTask> tasks = taskRepository.findByPlanIdAndVersion...(cohort.planId, cohort.planVersion);
  Counters c = aggregator.count(all, tasks);
  assignmentRepository.setCounters(assignmentId, c.completed(), c.passed(), c.requiredPassed());
  ```
  再执行解锁后继与待认证判定（`afterTaskPassed` 改用 `aggregator.passedTaskIds`）；补训轮**失败**时也调用 `reevaluateCertificationState`。
- **待认证判定（评审后修正，唯一入口）**：
  ```java
  ready = 必修（无必修则全部任务）按「任一 passed/waived」全部满足;
  blocked = aggregator.hasUnfinishedRemediation(records); // round>1 且非终态
  if (ready && !blocked) markPendingCertification();
  else if (状态 == pending_certification) updateStatus(pending_certification -> in_progress);
  ```
  修复「待认证 → 补训 → 补训失败」永久停在 in_progress、认证接口永不接受的状态机死锁。
- `afterTaskPassed` 内解锁只对**有效轮次**的 locked 记录操作；补训轮创建时直接 `available`，但仍检查前置。
- `markPendingReview` 不变（不计数）。

### 4.4 `TrainingCertificationService`（改造）

```java
public record RevocationResult(TrainingAssignment assignment, TrainingCertification revoked,
                               String revokedByName, String learnerName) {}

@Transactional(rollbackFor = Exception.class)
public RevocationResult revoke(UUID assignmentId, String reason);

@Transactional(rollbackFor = Exception.class)
public CertificationResult certify(UUID assignmentId, String note);
```

`certify` 变更：
- 幂等判定改 `findByAssignmentIdAndStatus(assignmentId, "confirmed")`；
- assignment 已 `certified` 但无 confirmed → 409 `CERT_RECORD_MISSING`；
- 重算通过集合改用 `aggregator.passedTaskIds`（含补训轮）；
- 已有 revoked 历史时**插入新行**，不 update 旧行；
- 捕获 `DataIntegrityViolationException` → 409 `CERT_STATE_CHANGED`。

`revoke` 顺序：
1. 无锁读 + `assertCanReview`；不能撤销自己（超管例外）；
2. `findByIdForUpdate` 锁 assignment；
3. 必须 `status='certified'` 且存在 confirmed 认证，否则 409 `CERT_NOT_CONFIRMED`；
4. 该 confirmed 行改 `revoked`，写 `revokedBy/revokedAt/revokeReason`（保留 confirmed 字段）；
5. `revokeCertified(assignmentId)` 条件更新 `certified → pending_certification`，0 行 → 409 `CERT_STATE_CHANGED`；
6. 审计 + 通知学员。

`CertificationView` 增加 `revokedBy/revokedByName/revokedAt/revokeReason`；`of()` 取传入记录；新增 `CertificationHistoryRow` 列表。

### 4.5 `TrainingDeadlineExtensionService`（新）

```java
public record ExtensionResult(TrainingAssignment assignment, LocalDateTime oldDeadline,
                              LocalDateTime newDeadline, int updatedAttempts) {}

@Transactional(rollbackFor = Exception.class)
public ExtensionResult extend(UUID assignmentId, LocalDateTime newDeadline, String reason);

@Transactional
public ExtensionResult applyLocked(TrainingAssignment locked, LocalDateTime newDeadline, String reason);

/** 补训附带的截止：允许 pending_certification（已认证/已取消仍拒绝） */
@Transactional
public ExtensionResult applyForRemediation(TrainingAssignment locked, LocalDateTime newDeadline, String reason);
```

规则：
- 新截止必须晚于 `now`；若有旧截止必须晚于旧截止，否则 409 `DEADLINE_NOT_FORWARD`；
- 手工延期只允许 `not_started/in_progress`，否则 409 `DEADLINE_NOT_EXTENDABLE`；
- 补训延期走 `applyForRemediation`，额外允许 `pending_certification`（补训本身允许落在该状态）；
- 不能操作自己（超管例外）：分配 `learner_id == 操作人` → 403；
- 进行中考试：`newAttemptDeadline = min(startedAt + duration, newDeadline)`；仅当 `> oldAttemptDeadline` 时才条件更新；
- 陪练只改 assignment；
- `extendDeadline` 写 `original_deadline=coalesce(original_deadline, oldDeadline)`；
- 审计 + 通知。

```java
public Download download(UUID id);  // done 才可；审计 training.export.download；OSS 短 TTL 预签名
public ProcessOutcome process(UUID jobId, String owner); // 非事务：查询 + 生成 + 存储
public void complete(UUID jobId, String owner, ProcessOutcome outcome); // 短事务写 done + 通知
public void fail(UUID jobId, String owner, String reason); // REQUIRES_NEW：状态 + 通知
```

- `export_job.source_type='training_cohort'`，`file_path` 存存储 key；`row_count` 记录行数。
- **事务边界（评审后修正）**：`process` 故意不加 `@Transactional`——CSV 构建与本地写盘/OSS 上传属于文件/网络 IO，不能进事务；`complete` / `fail` 各自短事务落状态。`fail` 必须 `REQUIRES_NEW`（Spring Data `@Modifying` 不自带事务，Worker 调用时无外层事务）。
- Worker：`lockClaimableIds` + `claim`（lease 15 分钟，owner 默认「主机名+pid」保证多实例唯一）；`process` 校验租约未过期、`attempts > max-attempts(3)` 直接失败；单条异常 → `fail`。
- CSV 列（一行 = 学员 × 任务 × 轮次）：
  `批次,计划,学员姓名,账号,分配状态,截止,是否逾期,阶段号,阶段名,任务标题,类型,必修,轮次,记录状态,尝试次数,最新结论,总分,提交时间,认证状态,确认人,确认时间,撤销人,撤销时间,撤销理由,补训原因`
- `CsvWriter`：UTF-8 BOM、RFC4180、公式注入防护；上限 `app.training.export.max-rows=100000`。
- 存储：`ExportStorage` 接口；`LocalExportStorage`（`app.training.export.dir`，默认 `./data/exports`）、`OssExportStorage`（`OssService.upload` + `generatePresignedUrl(key, app.training.export.presign-seconds=900)`）；`app.training.export.storage=local|oss`。
- 下载：`GET /exports/{id}/download` 需要 `Authorization`（浏览器 `<a href>` 不带 header），前端改为 fetch+blob；OSS 模式返回短时效预签名地址。

### 4.12 `TrainingRateLimiter.tryConsumePracticeMessage`

```java
public boolean tryConsumePracticeMessage(UUID attemptId, long persistedCount, int limit);
```

Lua：
```lua
local k = KEYS[1]
local init = tonumber(ARGV[1])
local limit = tonumber(ARGV[2])
if redis.call('EXISTS', k) == 0 and init > 0 then
  redis.call('SET', k, init)
end
local n = redis.call('INCR', k)
if n == 1 then redis.call('EXPIRE', k, 86400) end
return n <= limit and 1 or 0
```
Redis 异常回退 `persistedCount < limit` 并 warn。`TrainingAttemptService.messages` 保留一次 DB count 作为初始化值与降级依据，替换 `count-then-send`。

## 9. 迁移与回滚

1. 备份 → `psql -f scripts/training-schema.sql`（可重复）→ 预检查重复 confirmed → 重启（`validate`）。
2. 功能开关：`app.training.remediation.enabled`、`app.training.pending-review.enabled`、`app.training.export.enabled`、`app.auth.query-token.mode`。

4. 发布门禁：docs/54 人工清单 + Playwright + PG 集成 + 五方评审全部通过。
