# 共享知识与Skill平台：首版技术决策

> 后续定案：真实Skill使用独立agent-runtime执行，详见42号文档。原业务backend不以整体升级作为前置；本文件中的“模型编排放Java”细化为“放独立Java Runtime”，不是塞进旧backend。真实Skill与数字分身Skill严格分离。

2026-11-13。基于40号方案收敛；这是设计决策稿，不代表已实现或用户已经验收。

## 1. 定下来的边界

以现有ai-extract作为底座，服务内部团队：标准收文件→共享知识检索→导入并迁通真实Skill→真实任务打磨输入输出→飞书文字查询。
保留知识库、案例库作为内容业务视图；新增统一资料原件和能力包管理，不重建用户体系，不把Skill强塞进现有销售分身Skill表。
不做通用编排画布、任意桌面Agent远程接管、自动多Agent协作、IM上传审批、实时多人编辑。
第一条实际能力链路：给定客户需求和资料范围，使用一个现有课程设计Skill产出课程大纲草稿和引用。

## 2. 组件选择

| 组件 | 职责 |
|---|---|
| frontend Next.js | 资料库、共享问答、能力库及执行结果 |
| backend Java | 认证权限、资料登记、版本、检索、模型调用、执行编排与任务记录 |
| PostgreSQL/pgvector | 业务记录、文档章节块与向量；关键词+向量组合检索 |
| OSS | 原件、不可变版本的Skill包、生成文件 |
| ai-service | 复用文件解析，不承担新增业务编排 |
| 独立脚本Worker | 经适配批准的Python/Node脚本，隔离目录执行，不能在backend宿主目录执行上传命令 |
| feishu-bot | 后续文字入口，调用同一问答服务 |

模型编排先放Java，脚本执行与业务进程隔离；不新增第二套后端业务模型。
首版用数据库任务表和轮询，不引入新消息中间件。Redis只做短期缓存/限流，不作为唯一任务账本。

## 3. 数据对象

### 资料线

- SourceAsset：资料标题、类型、企业、作者/提交人、来源项目、适用场景、可见范围、性质、当前版本。
- SourceAssetVersion：OSS原件key、hash、解析状态、正文引用、版本号、创建时间；旧版不可覆盖。
- SourceChunk：资料版本、章节路径、顺序、原文、embedding；原件不能定位页码时不伪造页码。
- 已有KnowledgeEntry/IndustryCase：经过整理的知识与案例，逐步补sourceAssetVersionId回到原件；历史数据保留原来源，不造假关联。

同一资产可带多个标签；最低必填为标题、类型、来源、范围与内容性质，AI建议摘要由人核对。
原件解析→全文索引与结构化萃取是不同任务：不能要求先萃取成知识卡才允许查原文，也不能同样命中重复计数。

### 能力线

- Capability：用途、类型、负责人、企业与可见范围。
- CapabilityVersion：原包key/hash、入口、适配配置、输入输出Schema、声明依赖、批准工具、试运行状态。
- CapabilityRun：发起人、企业、固定能力版本、输入、资料范围/快照、模型配置版本、执行状态、预算、重试关联。
- RunEvent/RunArtifact：步骤/工具调用/错误与产物；日志脱敏，不要求存模型隐式思维过程。

ToolRegistry首版后端配置/代码注册即可，不做工具市场或任意URL执行配置。
问答会话使用独立用途标识和受控上下文，避免沿用销售人设；复用底层模型客户端而不是复制RAG。

## 4. 资料处理与检索

网页上传→先存原件与待处理记录→异步解析正文→按章节分块→索引→显示可检索状态。
内容共享必须显式确认，默认范围明确；索引查询在SQL层限定企业和可见范围后再排序。
检索先做类型/场景过滤与关键词召回、语义召回，合并去重；优先返回相关材料和原文引用，答案是附加解释。
命中片段可回看完整文档，链接通过后端鉴权获取短期访问，不把原件设为永久公开。
旧知识案例检索可复用；统一QueryService需要合并完整资料命中与结构化知识案例，避免丢失历史方案上下文。

## 5. 本地Skill导入与兼容

首版支持zip包上传，完整保留SKILL.md、references/、templates/、scripts/相对结构。
检查解压路径、数量、大小、软链接和缺失入口；禁止包中秘密随发布进入共享。
平台补一份适配配置，不要求用户改写原Skill：输入/输出Schema、运行类型、已批准工具、固定脚本入口、超时/轮数/用量限制。
依赖扫描只提供候选，人工试运行验证；不能凭自动扫描就标可运行。

状态：imported→needs_adaptation或ready_for_test→tested→published；新版从导入开始，不覆盖当前发布版。

| 类型 | 首版执行方式 |
|---|---|
| prompt | 加载模板、授权资料及参数，调用模型 |
| agent_skill | 模型加载原Skill指令，按结构化工具调用使用已注册工具，保留消息角色与工具结果 |
| script | 固定批准入口交独立Worker执行，依赖固定，不执行任意用户shell |

不能照搬桌面Agent内部工具名。每个Skill列出工具映射；缺浏览器、外部登录、系统依赖时标需适配，不静默忽略。
Java新增独立ModelGateway，提供带角色消息与结构化工具调用能力；现有把全部消息拼成字符串的适配器不能直接作为SkillRunner。
使用现有模型供应商的协议实现Gateway，先验证所选模型工具调用；不在本轮设计中假定当前Spring AI版本已经满足所有适配需求。

## 6. 最小工具与执行流程

首批工具：search_knowledge（授权检索）、read_asset（受控读取原文）、read_package_file（读固定包内参考/模板）、run_approved_script（固定脚本）、save_output（保存文本/文件）。
模型声明要读什么不等于授权；每次工具调用重新验证企业、用户、运行资料范围和路径。

用户选能力并填写输入/指定资料→POST创建run→固定版本与范围→立即返回runId。
后台领取run→组装需求与Skill入口→调用模型→校验工具调用→执行工具并追加结果→迭代至产物或预算上限。
完成后校验约定输出结构、文件存在、引用可解析；质量由专家对照历史样本审核，不以Schema通过当专业质量通过。
允许按需读包内references，避免把所有参考资料一次塞满上下文。
独立Worker按运行创建隔离目录、CPU/内存/时间限制，默认无外网；必要网络单独批准。不得暴露Docker宿主控制接口给上传包。

## 7. 任务可靠性与模型配置

queued→running→succeeded/failed；取消cancel_requested→cancelled。
租约、心跳、原子领取、幂等创建、超时释放与新尝试记录；重启后恢复待执行任务，执行中任务超时标失败/待重试，不承诺任意脚本无副作用续跑。
每次执行保留已产生工具结果与产物。外部副作用工具首版不开放；重试不覆盖旧结果。
前端轮询可恢复进度，SSE仅用于问答/可选文本展示，不作为任务完成的唯一依据。
模型配置由后端按企业/用途选择，异步任务记录配置引用；不共享个人登录态，不把Key打包。
内部单团队试点可显式使用团队配置；没有完成企业Key路由前，不宣称能交付企业自带Key隔离。

## 8. 首版页面、接口职责

| 入口 | 操作 | 后端接口草案 |
|---|---|---|
| 资料库 | 上传、查看状态、确认共享、打开原件 | POST/GET /assets；GET /assets/{id}；POST /assets/{id}/share；GET /asset-versions/{id}/download |
| 团队问答 | 提问、补充背景、查看引用 | POST /knowledge-query（SSE），返回会话ID与结构化引用 |
| 能力库 | 导入、查看依赖、补配置、试运行、发布 | POST /capabilities/import；GET /capabilities/{id}；PUT /capability-versions/{id}/adapter；POST /capability-versions/{id}/publish |
| 执行页 | 创建运行、进度、取消、重试、下载 | POST /capability-runs；GET /capability-runs/{id}；POST /capability-runs/{id}/cancel或retry；GET /run-artifacts/{id}/download |

全部路径以/api/v1开头；试运行也是run，发布校验至少有本版本已通过的试运行与人工确认。
按钮必须有真实动作、权限、状态和错误反馈；没有实现的适配类型只显示兼容报告，不展示可点击运行。

## 9. 实施工作包与验收

| 顺序 | 工作包 | 验收 |
|---|---|---|
| A | 原件登记、解析索引、来源定位，复用现有知识案例 | 3—5个历史项目资料可查，20个真实问题逐项核对 |
| B | 能力导入、版本、依赖报告与执行协议；拿真实Skill做适配 | 包结构完整，缺依赖明确；一个真实Skill可执行 |
| C | 最少工具、任务、产物与输入表单 | 非原作者用3份历史需求产出可评审大纲与引用 |
| D | 输入/结果体验与专业质量调整 | 专家记录修改原因，完善方法、模板、工具，而不是盲目换模型 |
| E | 飞书身份绑定与共享QueryService | 私聊提问、文字补背景、可打开引用；不做IM上传和写操作 |

各工作包均检查跨范围访问、失败重试和刷新恢复。执行器具体适配取决于真实Skill，不能先按未知工具承诺工期。
第一轮只接一个模型提供方、一个代表Skill、一个IM渠道；架构保留扩展，不实现没有样本的所有兼容层。
