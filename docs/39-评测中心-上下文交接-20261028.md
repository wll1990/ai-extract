## 6. 环境与操作约定（照做，不要试错）

### 启动 / 登录
- 后端：8080，context-path `/api/v1`
- 登录 DTO 字段是 **`account`**（不是 `username`）+ `password` + `companyCode`
- 分页 **1-based**（`page=0` 报错）
- 开发账号：`admin/123456/DEFAULT01`、`weida/123456/JCLWM5YL`
- DB：`psql -U wanglei -d aiextract -h localhost`（密码从 `.env` 的 `PG_PASSWORD` 取，**不得回显**）；`"user"` 表名需加引号

### 编译 / 测试
- 后端测试编译**必须 `clean`**：`mvn -f backend/pom.xml clean test`（增量编译会出现 `Flexible Constructor Bodies ... source level 25` 的假错误）
- 编译：`mvn -f backend/pom.xml -q clean compile`

### 契约细节（踩过坑）
- `EvaluationItemRequest` 的 JSONB 字段（`expectedPoints`/`forbiddenPoints`/`citationRequirement`/`scoringRule`/`retrievalExpected`）是 **JSON 编码的 String**，不是数组（跟 `IndustryCaseRequest` 一致）。前端必须 `JSON.stringify(array)` 再传
- 计划 §五 把它们写成数组，属于文档与实现的偏差，以代码为准
- SSE 统一走 `frontend/src/lib/sse.ts`，禁止内联 fetch 手写解析

### 代码红线（CLAUDE.md）
- SQL 只在 Repository（pgvector 的特例走 Service 的 `jdbcTemplate`），禁止 Service 拼 raw SQL
- 禁止 `findAll()` + 内存过滤、N+1、无 LIMIT 查询
- 事务内禁止 AI / HTTP / 文件 IO，事务持有 < 100ms
- 分页响应必须 `PageResponse.of()`
- 零 Mock、零假数据（AI 失败抛异常，不造假）

### 工具
- 任何代码检索前先跑 `graphify query "<问题>"`；改完代码跑 `graphify update .`（约 2 分钟，超时可放后台）
- 后端进程不得自行重启
