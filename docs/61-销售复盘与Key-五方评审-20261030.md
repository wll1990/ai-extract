## 四、中危（6 条已改/加约束，4 条接受）

已改/加约束：

1. **任务同名并发**：`exists` 预检挡不住并发，唯一索引会抛 500。首版接受「极低概率 500」，实现时在 Service 外层捕获 `DataIntegrityViolationException` 转 409；不要在同一事务里 catch 后继续。
2. **企业 Key 首次保存并发**：`(company_id, provider)` 唯一键同样可能 500。首版接受，前端串行保存；后续改 upsert。
3. **旧 Key 永不清理**：`old_api_key_cipher` 设计保留 24 小时，但没有清理任务，密文会一直躺着。实现时加每日清理（`old_key_expires_at < now()` 置空），或干脆去掉旧 Key 字段。
4. **测试连通接口同步调 AI**：`POST /admin/company/ai-model/test` 在 HTTP 线程打 LLM，违反「HTTP 线程不调 AI」红线。接受理由：管理员手动诊断、单次 `maxTokens=1`、10 秒超时、不参与业务链路；已在 60 标注为唯一例外。
5. **台账 N+1**：每行查一次最新报告，20 条/页可接受；超过 50 条/页要改成批量查。
6. **跨员工查重可见性**：转线索时查重返回全公司同名/同电话线索的候选（含负责人姓名）。这是防重的必要信息，但普通员工能看到同事的客户名。首版接受，后续按「仅返回本人 + 未分配」收窄。

接受（不影响上线）：

7. **无创建/生成频率限制**：登录用户可反复建会话/点生成，刷 LLM 成本。首版靠登录 + 报告排队；P1 加每日配额。
8. **报告条目偏多**：strengths/weaknesses/risks 各 8 条，页面很长。用户已确认「按细的来」，接受。
9. **`closed` 状态不可达**：DDL 有、没有关闭接口。接受：P0 不做关闭；状态列留着不写。
10. **线索/任务不能编辑/换负责人**：产品已确认首版最小记录，接受。

## 五、口径确认结果

已确认（2026-10-30）：

1. **主复盘是 AI 分身，真人教练可以被请求补充。** 设计见 58 §3.12.1 与 60 D 部分：请求 → 通知教练 → 教练看报告/授权原文 → 追加补充 → 通知发起人。补充不写回 AI 报告，不参与后续重生成。
2. **company_admin / super_admin 是最大权限**，可以看全公司复盘原文；普通员工只能看自己的。`SALES_REVIEW_VIEW_ALL` 保持当前设计。
3. **复盘内容按记录长期保留**，不做自动清理、不设保留期；`review_session/segment/message/coach_note` 都是记录表。
4. **`closed` 本轮不做**：状态列保留但不提供关闭接口，P0 不引入「关闭复盘」这个动作。

已确认（2026-10-30，补充）：

5. **「线索人工接收」= 人确认才创建，不做认领。** 重复候选由发起人拍板；线索建好后负责人就是发起人，本轮不做线索池、公海、主管分配。`lead.status` 保持 `new/following/converted/invalid`，不引入 `pending_accept`。

## 六、已核实的代码事实（评审依据）

- `PageResponse.of` 返回 `Map<String,Object>`，不是泛型类。
- `connectSse` 不拼 `API_BASE`；现有 SSE 调用全部显式拼。
- `PromptLoader` 从 `prompts/` 加载，模板名必须带 `.md`；`backend/src/main/resources/prompts` 是指向仓库根 `prompts/` 的软链。
- `COMPANY_MANAGE` 只授予 super_admin；company_admin 没有。
- `Skill.companyId` 对历史 individual 分身为空，现有 picker 已用 `space`/`user` 联表解析企业。
- `storage.getUser()` 返回类型只声明 `name/role`，`permissions` 是运行时字段。
- `TrainingNotificationService.notifyUser(...)` 的签名与设计一致，事务提交后投递、失败不影响主流程。
- `GrainRetriever.retrieveHybrid(question, spaceId, topK)` 返回 `List<GrainResult>`，`GrainResult` 含 `grain/similarity/weightedScore`。
- `application.yml` 当前 `temperature=0.1`、`max-tokens=8192`、模型 `deepseek-chat`，企业 Key 工厂的默认值不会覆盖它。

未核实（L1 编译时必须验）：

- Spring AI `1.0.0-M5` 的 `OpenAiApi` / `OpenAiChatModel` 构造器形态；若 M5 只提供 builder，`CompanyChatClientFactory` 要改成 builder。
- `ChatClient` 的 JDK 动态代理对默认方法的调用行为；当前实现只代理接口方法，若遇到 `default` 方法需单独处理。
- 新增 DDL 在现有库上跑两遍是否幂等（`uq_rrp_session_active`、`company_ai_config`）。

## 七、结论

- 阻断项清零，设计可以照着写。
- 高危项已落到 58/60 的具体代码，不再靠口头约定。
- 真人教练、管理员权限、保留期已定；只剩「线索接收」一处口径。
- L1 企业 Key 可以先做；L2 复盘可以按「建会话 → 报告 → 追问 → 请教练补充」推进。转线索是否加「认领」等口径确认后再动，不影响前面。
