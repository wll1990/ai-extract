## Phase 1：飞轮启动（本周，6-8 小时）

### 1.1 数据表建立

| # | 表名 | 用途 | 关键字段 | 索引 |
|---|------|------|---------|------|
| 1.1.1 | `knowledge_gap` | 知识缺口记录 | skill_id, space_id, query, scene_tag, count, status | (skill_id, status) |
| 1.1.2 | `feedback_log` | 每次打分记录 | skill_id, conversation_id, grain_id(NULL允许), rating, query, rag_score, ai_response(截500字) | (skill_id, created_at), (grain_id) |
| 1.1.3 | `conversation_stats` | 每轮对话统计 | skill_id, conversation_id, user_id, mode, total_rounds, rag_high/ref/none_count, error_type, is_test | (skill_id, created_at) |
| 1.1.4 | `grain_retrieve_log` | RAG检索日志 | skill_id, conversation_id, original_query, rewritten_query, grain_id, similarity, tier | (skill_id, created_at), (grain_id) |
| 1.1.5 | `analytics_event` | 前端埋点 | skill_id, event_type, event_data(JSONB) | (skill_id, created_at) |
| 1.1.6 | `admin_audit_log` | 管理员操作审计 | admin_id, action, target_type, target_id, detail | (admin_id, created_at) |

**说明**：
- `feedback_log.grain_id` 允许 NULL——RAG=0 时 AI 回答不引用颗粒，用户仍可打分
- `conversation_stats.is_test` 标记 Admin 测试对话，统计时过滤
- `grain_retrieve_log` 保留 30 天，定时清理，避免数据爆炸
- `admin_audit_log` 为 Phase 3 预建表，Phase 1 可不写入

**建表文件**: Flyway migration V2~V7
**JPA 实体**: 6 个新文件
**Repository**: 6 个新文件

## 数据流全景

```
用户发消息
  │
  ├─→ rewriteQuery → (日志) JSON log
  │
  ├─→ retrieveGrainsWithScores
  │     ├─ scored > 0 → grain_retrieve_log (5 行)
  │     └─ scored = 0 → knowledge_gap (upsert)
  │
  ├─→ AI 流式回答
  │     │
  │     ├─ doFinally → conversation_stats (1 行)
  │     │
  │     └─ 前端展示
  │           ├─ 有匹配 → 溯源面板 + 👍👎
  │           └─ 无匹配 → 推荐问题卡片
  │
  ├─→ 用户 👍👎 → feedback_log (1 行)
  │
  └─→ 前端埋点 → analytics_event
```
