## 一、使用行为层

### 1.1 对话量

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 今日对话量 | `COUNT(*) FROM skill_message WHERE role='user' AND date=今天` | `skill_message` | 实时监控 |
| 本周/本月对话量 | 同上，时间窗口扩大 | 同上 | 周报月报 |
| 对话趋势 | 按天聚合，画折线图 | 同上 | 发现异常波动 |
| 人均对话量 | 对话量 / 活跃用户数 | 同上 | 用户粘性 |

### 1.2 活跃用户

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| DAU/WAU/MAU | 当天/当周/当月有对话的 distinct user_id | `skill_message` join `skill_conversation` | 用户规模 |
| 新用户数 | 首次在本分身对话的用户 | 同上 | 获客效果 |
| 回访用户数 | 之前有过对话记录的 | 同上 | 留存效果 |
| 7日留存率 | 7天前首次使用的用户，7天后还在用 / 总数 | 同上 | 粘性核心指标 |
| 30日留存率 | 同上，30天窗口 | 同上 | 长期价值 |

### 1.3 对话深度

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 人均对话轮数 | avg(每 conversation 的 message 数) | `skill_message` group by conversation_id | 对话质量 |
| 对话轮数分布 | 1轮 / 2-5轮 / 6-10轮 / 10+轮 占比 | 同上 | 用户体验曲线 |
| 单轮流失率 | 只有 1 轮就结束的 conversation 占比 | 同上 | 首答不满意就走了 |
| 平均对话时长 | 首条消息到最后一条消息的时间差 | 同上 | 沉浸度 |

### 1.4 模式偏好

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| QA 占比 | `mode='qa'` 或 `mode='discuss'` 的 conversation / 总数 | `skill_conversation.mode` | 功能偏好 |
| Talk 占比 | `mode='talk'` / 总数 | 同上 | 社交属性需求 |
| Practice 占比 | `mode='practice'` / 总数 | 同上 | 培训需求 |
| 模式切换率 | 同一用户在不同模式间的切换 | 同上 | 用户探索行为 |
| 各模式人均轮数 | 按 mode 分组的平均轮数 | 同上 | 哪种模式粘性最高 |

### 1.5 时段分析

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 小时级热度分布 | 按小时聚合消息数 | `skill_message.created_at` | 运营推送时机 |
| 周几最活跃 | 按星期几聚合 | 同上 | 内容更新时机 |
| 工作日 vs 周末 | 工作日/周末分组 | 同上 | 使用场景判断 |

### 1.6 对练专项

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 对练场景选择 TOP10 | 按 practice 场景标签聚合 | practice session 数据 | 用户最想练什么 |
| 对练完成率 | 完成全部轮数 / 开始的总数 | 同上 | 练习体验 |
| 平均重试次数 | 每轮 retry 次数 | 同上 | 难度评估 |
| 对练平均分 | 评估分数分布 | 同上 | 用户水平画像 |
| 薄弱场景 TOP5 | 分数最低的场景 | 同上 | 培训重点 |

## 二、回答质量层

### 2.1 RAG 匹配分布

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 高匹配占比 | `tier='high'` 的对话轮次 / 总轮次 | `conversation_stats.rag_high_count` | 知识覆盖度 |
| 参考匹配占比 | `tier='ref'` 的对话轮次 / 总轮次 | `conversation_stats.rag_ref_count` | 知识延伸度 |
| 无匹配占比 | RAG 0 结果但未触发缺口的轮次 | `conversation_stats` | 需要关注 |
| 缺口触发率 | 触发 knowledge_gap 写入的轮次 | `knowledge_gap` | 知识盲区比例 |
| 各场景 RAG 平均分 | 按 `scene_tag` 分组 avg(similarity) | `grain_retrieve_log`（待建）| 场景级覆盖质量 |
| RAG 命中率趋势 | 按周聚合高匹配占比 | 同上 | 优化效果追踪 |

### 2.2 用户满意度

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 整体 👍 率 | `feedback_log.rating='up'` / 总数 | `feedback_log` | 整体满意 |
| 各场景 👍 率 | 按 grain.scene_tag 分组 | `feedback_log` join `experience_grain` | 场景级质量 |
| 👍 率趋势 | 按周聚合 | `feedback_log` | 优化效果 |
| 打分覆盖率 | 有打分的消息 / 总 AI 消息数 | `feedback_log` / `skill_message` | 数据充分度 |
| 沉默用户占比 | 从未打过分的用户 / 总用户 | 同上 | 反馈机制可见性 |

### 2.3 颗粒级质量

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| **👍 TOP20 颗粒** | `helpful_count DESC LIMIT 20` | `experience_grain` | 最佳实践 |
| **👎 TOP20 颗粒** | `unhelpful_count DESC LIMIT 20` | 同上 | 优先修复队列 |
| 点赞率 = 0 的颗粒 | `helpful_count=0 AND created_at < 30天前` | 同上 | 僵尸颗粒 |
| 从未被检索的颗粒 | 从未出现在任何 RAG 结果中 | `grain_retrieve_log`（待建）| 标签可能有误 |
| 颗粒质量分分布 | `quality_score` 直方图 | `experience_grain` | AI 萃取质量 |
| 颗粒被检索频率 | 每颗粒 30 天内被 RAG 命中的次数 | `grain_retrieve_log` | 实用性排序 |

### 2.4 推荐问题效果

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 推荐展示次数 | 无匹配时展示推荐的次数 | 前端埋点 | 曝光量 |
| 推荐点击率 | 点击次数 / 展示次数 | 前端埋点 | 推荐质量 |
| 推荐后满意度 | 点击推荐→对话→👍率 | 前端埋点 + `feedback_log` | 闭环验证 |

## 三、运营效率层

### 3.1 知识缺口管理

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 缺口总数 | `COUNT(*) FROM knowledge_gap WHERE status='open'` | `knowledge_gap` | 工作负载 |
| 本周新增缺口 | status='open' AND created_at in 本周 | 同上 | 发现速度 |
| 本周解决缺口 | status='resolved' AND resolved_at in 本周 | 同上 | 处理效率 |
| 缺口趋势 | 按周画新增 vs 解决折线 | 同上 | 是否在收敛 |
| 平均解决天数 | avg(resolved_at - created_at) WHERE status='resolved' | 同上 | 响应速度 |
| **高频缺口 TOP10** | `count DESC LIMIT 10 WHERE status='open'` | 同上 | 优先处理 |
| 缺口场景分布 | 按 `attempted_scene_tags` 分组 | 同上 | 哪个场景最缺 |

### 3.2 颗粒修复

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 待修复颗粒数 | `unhelpful_count >= 阈值` 的颗粒数 | `experience_grain` | 修复队列长度 |
| 平均修复耗时 | 从标记为需修复到 edited_content 更新的时间 | 同上 | 修复效率 |
| **修复效果验证** | 修复前 30 天 vs 修复后 30 天 👍 率对比 | `feedback_log` | ROI 证明 |
| 颗粒弃用率 | `status='deprecated'` 占比 | `experience_grain` | 内容健康度 |

### 3.3 管理员活跃度

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 管理员登录频率 | 登录 Admin 的次数 | Admin 日志 | 运营投入度 |
| 颗粒编辑次数 | 每周编辑颗粒的次数 | 操作日志 | 维护活跃度 |
| 缺口处理率 | 处理过的缺口 / 总缺口 | `knowledge_gap` | 团队效率 |

## 四、商业价值层

### 4.1 客户健康度

### 4.2 冷启动效果

|------|---------|---------|------|

### 4.3 网络效应

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|

| 模板贡献颗粒占比 | 来自模板的颗粒 / 客户总颗粒 | `experience_grain.source_type` | 模板价值 |
| 客户间颗粒重合度 | 跨客户场景标签分布对比 | `experience_grain.scene_tag` | 可复用性 |

### 4.4 ROI 指标

| 指标 | 计算方式 | 数据来源 | 用途 |
|------|---------|---------|------|
| 单次对话成本 | AI 调用成本 / 对话次数 | LLM API 账单 + `skill_message` | 成本控制 |

## 五、需要新建的数据表

### 5.1 conversation_stats（对话统计）

```sql
CREATE TABLE conversation_stats (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_id UUID NOT NULL,
    conversation_id UUID NOT NULL,
    user_id UUID,
    mode VARCHAR(20),
    total_rounds INT DEFAULT 0,
    rag_high_count INT DEFAULT 0,
    rag_ref_count INT DEFAULT 0,
    rag_none_count INT DEFAULT 0,
    feedback_up INT DEFAULT 0,
    feedback_down INT DEFAULT 0,
    recommended_clicked INT DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT now()
);
CREATE INDEX idx_cs_skill_created ON conversation_stats(skill_id, created_at);
```

### 5.2 grain_retrieve_log（RAG检索日志）

```sql
CREATE TABLE grain_retrieve_log (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    skill_id UUID NOT NULL,
    conversation_id UUID NOT NULL,
    query TEXT,
    rewritten_query TEXT,
    grain_id UUID,
    similarity DOUBLE PRECISION,
    tier VARCHAR(10),
    position INT,
    created_at TIMESTAMP NOT NULL DEFAULT now()
);
CREATE INDEX idx_grl_skill_created ON grain_retrieve_log(skill_id, created_at);
CREATE INDEX idx_grl_grain ON grain_retrieve_log(grain_id);
```

### 5.3 前端埋点事件

```
recommendation_show      — 推荐问题曝光
recommendation_click     — 推荐问题点击（含问题文本）
feedback_click           — 点赞/踩（含 grain_id, 当前 RAG tier）
mode_switch              — 模式切换（从哪个切到哪个）
conversation_end         — 对话结束（含轮数、时长）
```

## 六、报表节奏

| 频率 | 内容 | 受众 |
|------|------|------|
| **实时** | 对话量、在线用户数 | 运维 |
| **每日** | 昨日对话量、新增缺口数 | 运营 |
| **每周** | 周报：使用趋势 + RAG 分布 + 满意度 + TOP 问题 | 产品经理 + 客户成功 |
| **每月** | 月报：留存率 + 冷启动曲线 + 客户健康度 + ROI | 管理层 |
| **每季度** | 行业对比 + 网络效应 + 战略规划 | CEO/投资方 |
