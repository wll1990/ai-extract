# 技能生成与匹配技术详解

> 从素材上传 → 清洗提取 → 向量入库 → 对话匹配，完整技术链路。

---

## 概述

技能的生成不是 AI 凭空创造，而是从销冠的**真实对话记录/文档**中分层萃取的。每个颗粒都对应素材里的一段原文，有完整的溯源链。

```
素材上传 → 解析 → 11层清洗管道 → 颗粒入库 → pgvector向量化 → 对话时语义匹配 → AI回复
```

---

## 一、素材上传

管理员选择销冠空间，上传文件（txt/docx/pdf/图片），调用 `POST /admin/materials/upload`。

**`MaterialCleaningService.uploadMaterialToSpace()`**：
1. 根据 `spaceId` 查找已有空间
2. 找到或自动创建对应的 `Skill`（分身，status=`generating`）
3. 保存 `SkillMaterial`（素材文件，status=`uploaded`）
4. 文件落盘到本地目录

此时还没有做任何 AI 处理，仅是保存。

---

## 二、11层清洗管道

`MaterialCleaningScheduler` 每 30 秒扫描 `status=uploaded` 的素材，调用 `MaterialCleaningService.clean()`。

### 示例素材

```
周铭：那次招商银行的项目，对方上来就说"你们比XX贵了30%"。
我第一反应不是解释价格，而是问他们现在的技术架构。
他说用的是Oracle那一套，我就给他算了一笔账——
你们每次出报表要3天，我们的方案2天就出，一年省多少人力？
30%看着多，折算下来两个月就回本了。最后王行当场就说"你赢了"。
```

### Layer 0 — 情境标注（1次 AI 调用）

```json
{
  "buying_stage": "竞品对比PK",
  "buyer_persona": "技术决策者",
  "competitive_context": "价格敏感但重视效率",
  "industry_signals": "银行/金融"
}
```

### Layer 1+2+3 — 规则清洗（零 AI）

- **去格式噪音**：多余空格、换行统一、标点归一
- **去业务噪音**：删寒暄语（"你好""好的"）、重复段落
- **文本归一化**：别名统一（"王行"="王行长"，"XX"="某竞品"）、数字标准化

### Layer 4 — 语义分块（AI）

按对话回合切分独立段落：
```
块1: 客户质疑价格 → 周铭反问架构
块2: 周铭算账 → 客户被打动
```

### Layer 5 — AI 提取洞察（核心）

调用 DeepSeek，从文本块提取结构化颗粒：

```json
{
  "sceneTag": "异议处理",
  "sceneDescription": "客户用价格施压时的应对策略",
  "expertThought": "不急着解释价格，先反问技术架构，找对方的隐性成本，用数据让客户自己算账",
  "standardScript": "李总，在聊价格之前我想先了解一下你们现在的技术架构是什么样的？",
  "commonMistakes": "直接降价或解释'我们也值这个价'——这是新手会犯的错误",
  "applicableCondition": "客户横向比价、竞品报低价时适用，对方有一定技术背景效果更好"
}
```

### Layer 6 — 对抗验证（AI 自检）

五维评分（specificity/reproducibility/causality/distinctiveness/falsifiability）：
```
特异性 4.5  可复制性 4.2  因果性 4.0  差异性 4.8  可证伪性 3.5
→ qualityScore = 4.2，通过（≥3.0）
```

### Layer 7 — 同标签去重合并

同一 sceneTag 下的相似颗粒合并，避免冗余。

### Layer 8 — 模式发现

从所有颗粒中提炼核心心法（methodologyName/oneliner/coreHabits/differentiators）。

### Layer 9-11 — 附产物

- FAQ 提取（从原文提取客户异议+销售回应）
- 叙事重放（策略→颗粒关联）
- 画像自动生成（从颗粒+模式提炼 personality/speakingStyle/background 等）

## 三、审核仪表盘数据指标详解

审核页面"经验技能化"步骤展示的四个指标，全部来自 `AdminAuditController.getAuditDashboard()` 的实时计算：

### 3.1 五维评分

**数据来源**：`experience_grain.verificationNotes`（JSONB 列），由 Layer 6 对抗验证写入。

| 维度 | 含义 | 1分 | 5分 |
|------|------|-----|-----|
| specificity（特异性） | 是否具体可执行 | "深入了解需求"这种废话 | 新人拿着就知道说什么 |
| reproducibility（可复制性） | 3个月新人能否复制 | 依赖个人天赋/关系 | 有清晰步骤，人人可学 |
| causality（因果性） | 因果关系是否可信 | 看不出为什么客户被说服 | 行为→反应→结果链条清晰 |
| distinctiveness（差异性） | 和教科书有多不同 | 每本销售书上都有的 | 反直觉的、大多数人不会做的 |
| falsifiability（可证伪性） | 什么时候会失效 | 没讨论任何限制 | 清楚说明适用边界和失效条件 |

**AI 综合分公式**：
```
composite = specificity×0.25 + reproducibility×0.2 + causality×0.2 + distinctiveness×0.2 + falsifiability×0.15
composite ≥ 3.5 → APPROVE
specificity < 3 → 直接 REJECT
```

**前台展示**：所有已审核颗粒各维度取均值，保留1位小数。最低维度标红提示。

**存储格式**（`verificationNotes` 列）：
```json
{
  "scores": {
    "specificity": 4.5, "reproducibility": 4.2,
    "causality": 4.0, "distinctiveness": 4.8, "falsifiability": 3.5
  },
  "composite": 4.2, "verdict": "APPROVE",
  "reason": "话术具体可执行，反直觉技巧明显，但缺少失效条件说明"
}
```

### 3.2 场景覆盖

**纯 SQL GROUP BY**，不调 AI：

```java
grains.stream()
    .filter(g -> g.getSceneTag() != null)
    .collect(Collectors.groupingBy(ExperienceGrain::getSceneTag, Collectors.counting()));
// → { "异议处理": 8, "破冰": 5, "逼单": 3, "价格谈判": 2 }
```

每个 `sceneTag` 来自 Layer 5 AI 提取时做的**场景分类**——AI 读完文本后归类到具体业务场景。

### 3.3 质量分布

按 `quality_score` 分三档，纯代码计数：

```java
if (qualityScore >= 4.0) highQ++;       // ✅ 绿色：4-5分，直接可用
else if (qualityScore >= 3.0) midQ++;   // ⚠️ 黄色：3-4分，需人工复核
else lowQ++;                            // ❌ 红色：<3分，已剔除（但保留数据）
```

`qualityScore` 就是对抗验证的 composite 分。

### 3.4 颗粒明细

按 `sceneTag` 分组后逐条展示，供管理员逐条审核：

```java
// 每颗 active 颗粒按 sceneTag 分组
for (ExperienceGrain g : grains) {
    if (g.getSceneTag() == null || !"active".equals(g.getStatus())) continue;
    scenarioGrains.computeIfAbsent(g.getSceneTag(), k -> new ArrayList<>()).add(g);
}
```

前台"技能场景化"步骤：左侧场景标签导航，右侧展示该场景下每条颗粒的"使用销冠技能 vs 常见错误做法"对比卡片，含 qualityScore 徽章。

### 3.5 对抗验证（Layer 6）

这是五维评分、质量分布的数据源头。Prompt 嵌入在 `MaterialCleaningService.java` 第 235 行：

```
你是一位严格的销售培训质量审核官，你的职责是找出"听起来对但实际无法落地"的技能描述。

审核维度（每个维度打分1-5，并给出具体理由）：

1. specificity（特异性）
   - 5分 = 新人拿着这段话就知道具体说什么做什么
   - 1分 = "建立信任""深入挖掘需求"这种万能答案

2. reproducibility（可复制性）
   - 5分 = 一个3个月经验的销售能否复制？完全可复制，有清晰步骤
   - 1分 = 严重依赖个人天赋或特定关系

3. causality（因果性）
   - 5分 = 行为→买方反应→结果，链条清晰
   - 1分 = 只有销售做了什么，看不出买方为什么被说服

4. distinctiveness（差异性）
   - 5分 = 反直觉的、大多数销售不会这样做但效果好的
   - 1分 = 每本销售书上都有的标准操作

5. falsifiability（可证伪性）
   - 5分 = 清楚说明了适用边界和失效条件
   - 1分 = 没有讨论任何限制条件

判定规则：
- specificity < 3 → 直接 REJECT
- 综合分 = specificity×0.25 + reproducibility×0.2 + causality×0.2 + distinctiveness×0.2 + falsifiability×0.15
- 综合分 >= 3.5 → APPROVE
- 综合分 < 3.5 → REJECT

输出纯JSON，不要markdown代码块：
{"results":[{"index":0,"scores":{...},"composite":4.3,"verdict":"APPROVE","reason":"..."}]}
```

**批量执行**：每次发 10 条颗粒给 AI，逐批审核：

```java
for (int start = 0; start < candidates.size(); start += 10) {
    // 构建批次摘要
    // 调 AI 审核 → APPROVE 留下，REJECT 丢弃
}
```

**实际输出示例**：
```json
{
  "results": [
    {
      "index": 0,
      "scores": { "specificity": 5, "reproducibility": 4, "causality": 4, "distinctiveness": 5, "falsifiability": 3 },
      "composite": 4.3, "verdict": "APPROVE",
      "reason": "具体话术可执行，反问技术架构是反直觉操作，但未说明低端客户场景是否适用"
    },
    {
      "index": 1,
      "scores": { "specificity": 2, "reproducibility": 3, "causality": 2, "distinctiveness": 2, "falsifiability": 1 },
      "composite": 2.05, "verdict": "REJECT",
      "reason": "'深入了解客户需求'过于模糊，新人无法执行，缺乏具体行为和因果关系"
    }
  ]
}
```

**设计理念**：AI 自我对抗——同一个 DeepSeek 模型，用不同角色 prompt，先萃取再审核。不需要第二个模型，不需要人工介入。

## 四、颗粒入库

`MaterialCleaningScheduler.tryCleanOne()` 逐条写入数据库：

### experience_grain 表

| 列 | 值 | 说明 |
|----|-----|------|
| `id` | UUID | 颗粒唯一ID |
| `space_id` | UUID | 所属空间 |
| `source_material_id` | UUID | 来源素材ID（溯源用） |
| `scene_tag` | "异议处理" | 场景分类标签 |
| `scene_description` | "客户用价格施压..." | 场景描述 |
| `expert_thought` | "不急着解释价格..." | 销冠的思维过程 |
| `standard_script` | "李总，在聊价格之前..." | 标准话术 |
| `common_mistakes` | "直接降价或解释..." | 常见错误做法 |
| `applicable_condition` | "客户横向比价..." | 适用条件 |
| `quality_score` | 4.2 | 5维综合质量分 |
| `weight` | 1.0 | 权重（0.1-2.0） |
| `embedding` | [0.023, -0.451, ...] | 1024维 pgvector |
| `status` | "active" | 活跃/废弃 |

### 向量化

```
DashScopeEmbeddingService.embed(grainToText(grain))
  → 阿里 text-embedding-v4 API
  → 1024维 float 数组
  → JDBC 原生 SQL 写入 pgvector:
    UPDATE experience_grain SET embedding = ?::vector WHERE id = ?::uuid
```

所有颗粒入库后，Skill 的 status 从 `generating` → `reviewing`。

## 五、对话匹配（运行时）

用户问：**"客户说我们比竞品贵，怎么回？"**

### 步骤 1：向量化问题

```java
float[] queryVector = embeddingService.embed("客户说我们比竞品贵，怎么回？");
// → [0.031, -0.442, 0.098, ...] 1024维
```

### 步骤 2：pgvector 语义检索

```sql
SELECT g.*, (1.0 - (g.embedding <=> ?::vector)) * COALESCE(g.weight, 1.0) AS relevance
FROM experience_grain g
WHERE g.space_id = ?
  AND g.status = 'active'
  AND g.embedding IS NOT NULL
ORDER BY relevance DESC
LIMIT 5
```

`<=>` 是 pgvector 的 cosine_distance 算子，`(1 - cosine_distance) × weight` = 综合相关度。

返回 top-5：

| 排名 | sceneTag | relevance |
|------|----------|-----------|
| 1 | 异议处理 | 0.92 |
| 2 | 付款条件异议 | 0.78 |
| 3 | 逼单技巧 | 0.65 |
| 4 | 价格谈判 | 0.58 |
| 5 | 竞品PK | 0.51 |

### 步骤 3：注入 System Prompt

```
你是周铭本人。10年金融科技销售，风格：先挖痛点再给方案。

## 异议处理
- 我的思考：不急着解释价格，先反问技术架构，找对方的隐性成本
- 我说过的话："李总，在聊价格之前我想先了解一下你们现在的技术架构"
- 我见过的坑：直接降价或解释"我们也值这个价"

## 付款条件异议
...

用户问：客户说我们比竞品贵，怎么回？
```

### 步骤 4：DeepSeek 回复

灌入颗粒上下文的 System Prompt + 用户问题 → DeepSeek chat API → 流式返回：

> "李总，先别急着聊价格。你们现在用的什么系统？出报表要多久？
> 我之前一个银行客户也是先比价，算完他们的隐性成本，发现自己一年浪费了十几万，
> 30%的差价一个月就回来了。你要不要也看看你们的隐性成本数据？"

## 六、关键技术组件

| 组件 | 技术 | 用途 |
|------|------|------|
| 文件解析 | Python AI 服务 `/internal/parse-file` | 提取纯文本 |
| 规则清洗 | Java 规则引擎（零AI） | 去噪/过滤/归一 |
| AI 提取 | DeepSeek chat API + JSON prompt | 结构化颗粒 |
| 向量生成 | DashScope text-embedding-v4 | 1024维 embedding |
| 向量存储 | PostgreSQL + pgvector 扩展 | cosine 相似检索 |
| 语义检索 | `GrainRetriever.retrieve()` | 对话时匹配 top-K 颗粒 |
| AI 回复 | DeepSeek chat API（灌入颗粒上下文） | 分身自然语言回复 |
| 降级兜底 | 关键词滑窗匹配 | embedding 不可用时回退 |
