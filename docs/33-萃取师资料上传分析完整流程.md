# 萃取师资料上传分析完整流程

> 2026-07-01 · 从上传到激活的完整链路

---

## 全流程总览

```
上传 → 调度扫描 → 文件解析 → AI分析(analyzing) → 提取法则 → 审核激活
  │        │          │               │              │          │
  │        │          ├─ 自动（文档类）│              │          │
  │        │          └─ 人工（图片/音频）           │          │
  │        │                         │              │          │
  │        └─ 30秒轮询 + 乐观锁      │              │          │
  │                    ↓             │              │          │
  └─ 新建/选择已有 → 多文件上传      │              │          │
                       ↓             ↓              ↓          ↓
                    待分析 → 分析中... → 待审核 → 已激活
                    
  核心原则：传了就分析，每次全量重新提取
  今天传3个 → 分析 → 提取3条法则                        
  明天又传3个 → 分析 → 删旧法则 → 从6份报告全量提取6条    
```

---

## ① 上传

| 操作 | 结果 |
|------|------|
| 输入萃取师信息（姓名、风格、行业、资历） | `expert_skill` 记录，status=pending |
| 选择文件（支持多文件、多格式） | `expert_document` 记录，parsedContent=null |
| 选择"已有萃取师" → 文件归入已有记录 | expertId 复用 |
| 选择"新建萃取师" → 同时创建记录和文件 | 新 expertId |

**支持格式**：txt, md, csv, html, docx, pdf, pptx, xlsx, png, jpg, mp3, wav, m4a

---

## ② 调度扫描

```
ExpertAnalysisScheduler.scanAndProcess()   每 30 秒执行

  查询: findPendingTasks()
    WHERE status = 'pending'
    AND (locked_by IS NULL OR locked_at < NOW() - 5分钟)

  乐观锁: tryLock(id, workerId)
    UPDATE expert_skill SET locked_by=?, locked_at=NOW()
    WHERE id=? AND locked_by IS NULL

  抢到锁 → 状态改为 "analyzing" → analyzeMaterials() → 处理完释放锁
  没抢到 → 跳过（其他 worker 在处理）
```

## ③ 文件解析

### 自动解析（文档类）

| 格式 | 解析方式 | 依赖 |
|------|---------|------|
| `.txt .md .csv` | 直接读文本 | 内置 |
| `.docx` | python-docx 提取段落 | python-docx |
| `.pdf` | PyPDF2 提取页面文本 | PyPDF2 |
| `.pptx` | python-pptx 提取幻灯片文字 | python-pptx |
| `.xlsx` | openpyxl 提取表格数据 | openpyxl |
| `.html` | BeautifulSoup 提取纯文本 | beautifulsoup4 |

→ 解析成功 → `status = "parsed"` ✅

### 人工处理（图片/音频）

| 格式 | 处理方式 |
|------|---------|
| `.png .jpg .jpeg .gif .bmp .webp` | 返回提示词，推荐用 ChatGPT Vision / Claude 提取文字 |
| `.mp3 .wav .m4a .ogg .flac .aac` | 返回提示词，推荐用 Whisper / 讯飞听见 转写 |

→ `status = "pending_manual"` ⚠️

**提示词示例**：
```
📷 图片文件待处理（.png格式）

推荐工具：ChatGPT（GPT-4o Vision）、Claude
提示词：请详细提取这张图片中的所有文字内容。如果是截图，逐段提取。
处理完成后，请将结果粘贴到输入框中。
```

## ④ AI 分析

**触发条件**：萃取师下所有文件的 status 都是 "parsed"（无 pending_manual）

**分析流程**：
```
分析开始 → expert_skill.status = "analyzing"（前端显示"分析中..."）

1. 拼入萃取师信息：姓名、风格标签、行业标签、资历
2. 拼入全部文件的 parsedContent
3. 加载 Prompt：expert_document_extraction.md
4. 调 AI 生成七章《萃取师经验报告》JSON
5. structureExpertReport() 二次格式化为六章标准 JSON
6. 存入 report 表 → 追加 reportId 到 skillFile 历史列表
7. expert_skill.status = "extracting"（待审核）
```

## ⑤ 人工处理（图片/音频未完成时）

```
用户在萃取师详情页看到"待手动处理"文件
  → 复制提示词模板
  → 把文件给 ChatGPT/Claude/Whisper 处理
  → 复制 AI 返回的结果
  → 粘贴到系统中
  
  PUT /admin/experts/documents/{docId}
  { "parsedContent": "手动处理后的文字", "status": "parsed" }
  
  → 下次调度器扫描时，全部文件 parsed → AI 分析继续
```

## ⑥ 提取法则 + 激活

```
analyzeMaterials 完成后 status=extracting，需管理员手动调用 POST /admin/experts/{id}/extract 触发 extractGrains()

extractGrains():
  1. 删除该萃取师全部旧法则（deleteAll）
  2. 从 skillFile 读取全部历史报告ID列表
  3. 逐个加载报告 contentJson
  4. 调用 expert_grain_extraction.md → AI 从全部报告拆解法则
  5. 降级：generateDefaultExpertGrains() 生成基础法则
  
  → expert_grain 表（status=under_review）

管理员审核 → 点击"激活"
  → expert_grain.status = "active"
  → expert_skill.status = "active"

激活后：
  → 法则注入 interview_system.md 的 {expert_knowledge}
  → 后续所有访谈中，AI 按萃取师的法则追问
```

**关键设计**：
- 报告ID通过 `appendReportIdToHistory()` 追加到 `skillFile` 字段（JSON数组）
- 每次提取前先清空旧法则，再从**全部历史报告**重新提取
- 用户传多少次都不影响，每次都是全量重提

## 关键状态机

### expert_skill 状态

```
pending（待分析）→ scheduler扫描（每30秒）
  ├─ 全部文件 parsed → analyzing（分析中...）
  │    → AI生成报告 → extracting（待审核）
  │    → extractGrains → 法则提取完成
  ├─ 有文件 pending_manual → 保持 pending（等人工处理）
  └─ 异常 → failed（可重试）

extracting → 管理员审核 → active（已激活）
```

### expert_document 状态

```
null/初始 → parsed（自动解析完成）
          → pending_manual（图片/音频，等待人工）
          → parsed（人工填写完成 → PUT /admin/experts/documents/{id} → 下次调度继续）
```
