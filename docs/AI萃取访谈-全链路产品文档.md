# AI 萃取访谈 — 全链路产品文档

> 2026-07-27 · 基于最新代码梳理 · 供产品、运营、商业化团队审阅

## 一、用户角色体系

| 角色 | 存储表 | 说明 | 典型场景 |
|------|--------|------|---------|
| **super_admin** | user | 平台超级管理员 | 管理所有企业、审核颗粒、发布分身 |
| **company_admin** | user | 企业管理员 | 管理本企业员工、审核颗粒 |
| **employee** | user | 企业员工（销冠） | 被访谈对象，提供销售经验 |
| **c_user** | app_user | C 端注册用户 | 通过邀请链接注册，做访谈 |
| **c_partner** | app_user | 合作方嵌入用户 | 通过 `?token=` 参数自动登录 |
| **c_guest** | app_user | C 端游客（未注册） | 匿名访问分享页，**不能做访谈** |

## 二、访谈入口（按用户类型）

### 2.1 B 端员工（super_admin / company_admin / employee）

| 入口 | URL | 认证 | 说明 |
|------|-----|------|------|
| 管理后台创建 | `/interview/create` | cookie（middleware 拦截） | 选 space、填 topic、选萃取师，点"开始访谈" |
| 邀请销冠 | 管理员生成邀请链接并分享 | — | 管理员在创建页点"邀请销冠"，生成二维码/链接 |

**流程：**

```
登录管理后台 → 分身管理 → 开始访谈 → 填主题 → 创建会话 → 进入聊天
                                                      │
                                          邀请销冠 → 复制链接/二维码
```

### 2.2 C 端用户（c_user / c_partner）

| 入口 | URL | 认证 | 说明 |
|------|-----|------|------|
| H5 邀请链接 | `/h5/interview/m/{inviteCode}` | 页面内自检：`?token=` → `c_auth` → cookie | 扫码或点击链接进入 |
| H5 独立入口 | `/h5/interview/start` | `c_auth` localStorage | 无邀请码，C 端直接开始 |

**H5 邀请链接的认证分叉：**

```
打开 /h5/interview/m/{inviteCode}
  │
  ├─ URL 带 ?token=xxx（partner 嵌入）
  │   → 自动校验 → 登录成功 → 显示主题输入
  │
  ├─ 已有 c_auth localStorage（之前注册过）
  │   → 自动识别 → 显示主题输入
  │
  ├─ 已有 B 端 cookie（企业员工在手机上）
  │   → 自动识别 → 显示主题输入
  │
  └─ 都没有
      → 显示"企业登录" / "个人登录"按钮
      → 点击后展开内联登录/注册表单
          ├─ 企业 tab：填公司名(自动填入)+账号+密码 → 登录/注册
          └─ 个人 tab：填手机号/邮箱+密码 → 登录/注册
```

### 2.3 Partner 嵌入用户（c_partner）

Partner 在自己的 App/网页中嵌入 H5 页面，URL 带上 `?token={JWT}`。

- JWT 由 Partner 用自己的 `appId + SK` 签发
- 后端 `PartnerJwtFilter` 验证签名 → 自动创建/查找 `app_user` → 设置 `c_partner` 角色
- 用户无需手动登录，直接进入主题输入

## 三、访谈生命周期

```
┌──────────┐    ┌───────────┐    ┌──────────┐    ┌──────────┐
│ created   │───▶│in_progress│───▶│ completed │───▶│ 报告查看  │
│ （刚创建）│    │ （对话中） │    │ （已完成）│    │          │
└──────────┘    └───────────┘    └──────────┘    └──────────┘
                      │               ▲
                      ▼               │
                 ┌────────┐     ┌─────┴──────┐
                 │ paused │     │ supplement │  ← 颗粒不够→继续补充
                 └────────┘     └────────────┘
```

### 3.1 创建会话

1. 用户填主题 → 点"进入萃取"
2. 后端检查：
   - C 端用户：免费次数 ≤ 3 次
   - 是否有进行中的同类型访谈（有则 409）
3. 创建 Skill（如果 space 还没有）
4. 生成 AI 开场白

### 3.2 四阶段推进

| 阶段 | 标签 | 采集模块 | AI 行为 |
|------|------|---------|---------|
| opening | 开场定调 | 案例故事 | 引导用户介绍背景 |
| storytelling | 故事深描 | 核心步骤 + 关键决策 | 深挖具体案例细节 |
| modeling | 模型提炼 | 专家心法 + 适用边界 | 提炼方法论 |
| closing | 收网确认 | 行动清单 | 检查遗漏，准备收尾 |

阶段推进按钮在 AI 输出 `【建议推进】` 时点亮为蓝色，否则点击会提示建议先多聊。

### 3.3 完成访谈

**方式一：** 走完四个阶段 → closing → AI 自动触发完成

**方式二：** 用户随时点"结束访谈"→ 强制完成

完成后：
1. 后端：会话状态 → completed，异步触发颗粒萃取管道
2. 前端：显示完成卡片，按颗粒数分三档

### 3.4 完成卡片 — 颗粒分级展示

| 颗粒数 | 卡片样式 | 按钮 | 说明 |
|--------|---------|------|------|
| ≥10 条（达标） | 🎉 访谈完成！ | [查看萃取报告] | 报告异步生成中，可轮询等待 |
| 5-9 条（接近） | 📊 访谈完成 | [继续补充] [查看报告(等待中)] | 差几条到标准，建议补充 |
| <5 条（不足） | ⚠️ 内容还不丰富 | [继续补充] [下次再说] | 内容太少，引导继续聊 |

**B 端 vs H5 差异：**
- B 端：点击"查看报告"跳转 `/report/{reportId}/done`（桌面端报告页）
- H5：点击"查看报告"跳转 `/h5/report/{sessionId}`（H5 报告页，含轮询等待）

## 四、报告查看流程

### 4.1 B 端报告

```
聊天页 → 完成卡片 [查看萃取报告] → /report/{reportId}/done
                                            │
                                    报告详情页（含评分、章节、下载）
```

B 端报告页包含完整六章内容、评分、Word/PPT 下载。

### 4.2 H5 报告（C 端 + 移动端 B 端）

```
聊天页 → 完成卡片 [查看萃取报告] → /h5/report/{sessionId}
                                            │
                              ┌─────────────┴─────────────┐
                              ▼                           ▼
                         报告未就绪                    报告就绪
                    ┌─────────────────┐          ┌──────────────┐
                    │ 颗粒采集小结     │          │ 完整 HTML     │
                    │ ⏳ 报告生成中    │  每10秒   │ 报告内容      │
                    │ 流动动画        │  自动检查  │              │
                    │ 上次检查时间    │──────────▶│              │
                    │ [手动刷新]      │          │              │
                    └─────────────────┘          └──────────────┘
                         │
          ┌──────────────┴──────────────┐
          ▼                             ▼
    颗粒 >0 且 <5                    5 分钟后超时
    → 停止轮询                       → 停止轮询
    → "内容还不够丰富"               → "检查超时，建议返回补充"
```

H5 报告页底部统一显示：
```
💡 查看完整报告与审核进度
[platform.mindforce.com] [复制]
```

## 五、"继续补充"功能

用户完成访谈后颗粒不够 → 点"继续补充"：

```
completed → reopenForSupplement → in_progress (phase=modeling)
                                        │
                                   AI 收到指令：
                                   "已采集：案例故事、核心步骤"
                                   "还需深入：专家心法、适用边界、行动清单"
                                   "请自然地引导用户补充，不要重复已采集的内容"
                                        │
                                   用户继续聊天
                                        │
                                   再次完成 → 颗粒累计/新增
```

**不是从零开始** — 历史消息、采集状态全部保留，AI 知道聊了啥。

## 六、认证矩阵（完整版）

### 6.1 前端页面级

| 页面 | 未登录 | B 端 | C 端 | Partner | 说明 |
|------|--------|------|------|---------|------|
| `/interview/create` | → 跳转 `/login` | ✅ | ❌ | ❌ | middleware 拦截 |
| `/interview/{id}` | → 跳转 `/login` | ✅ | ❌ | ❌ | middleware 拦截 |
| `/h5/interview/m/{code}` | 显示登录表单 | ✅ | ✅ | ✅（?token=）| 页内自检认证 |
| `/h5/interview/start` | 显示登录链接 | ❌ | ✅ | ❌ | 只检 c_auth |
| `/h5/interview/chat/{id}` | API 报错→会话不存在 | ✅ | ✅ | ✅ | 无页面级检查 |
| `/h5/interview/done` | 可访问（静态页） | ✅ | ✅ | ✅ | 无 API 调用 |
| `/h5/report/{id}` | API 报错 | ✅ | ✅ | ✅ | 无页面级检查 |

### 6.2 API 级

所有 `/interviews/**` 端点：`hasAnyRole(SUPER_ADMIN, COMPANY_ADMIN, EMPLOYEE, C_USER, C_PARTNER)`

- **c_guest 不能做访谈** — 必须先注册为 c_user
- **每个端点都有属主校验** — 用户 A 不能操作用户 B 的会话

## 七、商业化关键指标

### 7.1 C 端免费萃取上限

- 默认 **3 次**
- 配置：`app.interview.c-user-free-limit=3`
- 超出时返回 402：`"免费萃取次数已用完，请升级会员"`
- 当前：**没有支付/升级入口**，402 之后用户无法继续

### 7.2 报告生成门槛

| 阈值 | 值 | 说明 |
|------|-----|------|
| 颗粒下限 | 10 条 | ≥10 条才触发 HTML 报告生成 |
| 建议补充线 | 5 条 | <5 条强烈引导继续补充 |
| 场景覆盖 | 3 个 | 至少 3 个不同场景标签 |

### 7.3 用户转化路径

```
c_guest（游客）
  → 查看分享页 → 注册 → c_user
  → 收到邀请链接 → 注册 → c_user → 做访谈（最多3次）

c_user（注册用户）
  → 3 次免费访谈
  → 第 4 次 → 402 → ? （当前无支付入口）

c_partner（合作方用户）
  → 无限访谈（由合作方承担成本）
```

## 八、已发现的产品缺口（供讨论）

### 🔴 商业化缺口

1. **C 端 402 之后没有转化路径** — 用户超额后看到"请升级会员"，但没有任何按钮或链接引导升级
2. **没有支付/订阅系统** — free limit 到了就是死胡同
3. **Partner 用户无限免费** — 需要与合作方的结算机制

### 🟡 体验缺口

4. **H5 报告页没有"继续补充"的快捷入口** — 颗粒不足时只能看到提示，要回到聊天页才能操作
5. **B 端报告页依赖 reportId，但 reportId 可能为 null** — forceComplete 返回的 reportId 不一定是真实 report UUID，可能 404
6. **被邀请的销冠不知道自己属于哪个企业** — H5 邀请页展示了公司名但登录后不可见

### 🟢 权限缺口（安全，非产品）

7. **Report API 大部分缺少属主校验** — 已记录为技术债，用户视角无影响
8. **`/auth/register/with-code` 可能 403** — SecurityConfig 未显式 allow

## 九、配置速查

```yaml
# application.yml
app:
  interview:
    c-user-free-limit: 3        # C端免费次数
    grain-enough: 10            # 报告达标颗粒数
    grain-suggest-more: 5       # 建议补充线
  report:
    min-grains: 10              # 报告生成最低颗粒数
    min-scenes: 3               # 报告生成最低场景数
```

前端阈值常量：`GRAIN_ENOUGH=10`、`GRAIN_SUGGEST_MORE=5`，与 yml 一致。
