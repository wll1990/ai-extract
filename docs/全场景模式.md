新模式：专家引导式对话（talk）— 全面设计

## 定位

| | quick/discuss | practice | **talk（新模式）** |
|---|---|---|---|
| 比喻 | 查阅销冠笔记 | 模拟销售训练 | 在茶水间碰到销冠，聊了起来 |
| 用户动机 | "我要解决这个问题" | "我要练习这个场景" | "我想了解这个人怎么想的" |
| AI 职责 | 高效解答 | 扮演客户 | 展示专长 + 引导对话 + 可信背书 |
| 边界 | 弱 | 场景限制 | 强 |
| 回答末尾 | 可选分析段 | 评分+溯源 | 📎溯源 + 💡分析（默认展开） |

## 一、商业化产品角度

### 1. 差异化价值

talk 是三种模式中**唯一让用户"认识这个人"的模式**——Q&A 是工具、对练是训练、talk 是建立信任。用户聊完觉得"这人真有两把刷子"，才会去用 Q&A 和对练。

核心卖点：**你不是在跟 AI 聊天，你是在跟一个真实存在过的销冠聊天。**

### 2. 转化漏斗

```
分身广场（浏览）→ talk 聊两句（建立信任）→ Q&A 深度提问（解决实际问题）
                                      → 对练实战（技能迁移）
                                      → 分享给同事（传播裂变）
```

talk 是所有深度行为的入口。talk 做不好，后面全断。

### 3. 数据飞轮

| 数据 | 用途 |
|------|------|
| 场景标签点击率 | 知道用户最关心什么方向，反向指导颗粒补充 |
| 回答 👍/👎 | 识别高质量颗粒和低质量颗粒 |
| 超边界问题聚类 | 发现用户真实需求，扩展知识库 |
| 对话轮次分布 | 了解 talk 模式粘性，指导产品迭代 |

### 4. 知识边界前置展示

talk 最怕用户瞎问超纲被拒绝三次。**在用户开口前就告诉他"我能聊什么、不能聊什么"**，比被拒绝后才知道好一百倍。

```
┌─────────────────────────────────────┐
│  我能聊的                           │
│  ✓ 政府背书型客户博弈                │
│  ✓ 大额B2B决策链渗透                │
│  ✓ 价格谈判和逼单技巧               │
│  ✓ 制造业老板客户心理               │
│                                     │
│  我不擅长的                         │
│  ✗ 快消品零售                      │
│  ✗ 互联网SaaS销售                  │
│  ✗ 海外客户                        │
└─────────────────────────────────────┘
```

### 5. 分享传播

聊完一条精彩回答后，可生成"对话卡片"分享：

```
┌──────────────────────┐
│ 潘露婷说：            │
│ "政府背书型客户买的    │
│  不是产品，是关系杠杆"  │
│                      │
│ —— 来自潘露婷·经验萃取 │
│ 扫码跟潘露婷聊聊 →    │
└──────────────────────┘
```

## 二、用户使用角度

### 完整对话深度曲线

```
第0轮: 开场白（技能名片 + 话题引导）
第1-2轮: 选定话题，AI 展开经验
第3-4轮: 深入追问，AI 补充细节
第5轮:  AI 自然引出相邻话题（"说到X，还有一个相关的..."）
第6轮:  用户选择继续或换话题
...     
第N轮: 用户说谢谢 → AI 1-2句总结收尾
```

### 关键设计点

**① 开场白（第0轮）**

不只是一个打招呼——是一次"微型技能路演"：

```
我是潘露婷，做了10年传统行业高客单销售。风格比较直接，不讲虚的。

我最常打交道的几类场景：
- 政府背书型客户：怎么把政府资源当杠杆用
- 大额B2B：怎么渗透决策链、搞定关键人
- 价格谈判：怎么守住底价、不被砍到骨头里

你想先聊哪个？或者有具体的客户情况直接说也行。
```

**② 话题切换**

```
用户: "换个话题，聊聊制造业老板"
AI: "制造业老板这类客户我也熟。他们有个特点——只看成本、不看价值。
     你想听怎么扭转这个思路吗？"
→ 前端同时更新场景标签为制造业相关
```

**③ 冷场恢复**

如果用户 30 秒没回复，AI 可以轻轻推一下：

```
"如果还没想好具体问题，要不我分享一个最近遇到的案例？
 上个月有个制造业客户就是这样..."
```

**④ 总结收尾**

```
用户: "学到了，谢谢！"
AI: "不客气。今天聊的核心就两条：政府客户看关系杠杆、B2B看决策链渗透。
     这两招用好了，成交率能提不少。有具体问题随时来问。"
→ 不追问、不讲新知识、自然结束
```

**⑤ 错误恢复**

| 场景 | AI 回应 |
|------|---------|
| 问偏了 | "这个问题不在我经验范围，我主要做传统高客单。要不聊聊..." |
| 不满意回答 | "换个角度讲" → AI 从另一维度解答 |
| 想展开 | "能展开讲讲吗" → AI 深入（rewriteQuery 支持） |

### 不动

- SseAdapter / SseEmitter — 不动
- SSE 协议 — source/meta 事件已含所需数据

### `skill_talk.md` 核心规则

```
身份: {owner_name} 本人，在跟同事聊天
语气: 松弛自然，可以反问、表达情绪、聊开
回答: 不强制结构。简单问题简单答，有故事就展开

首次对话开场白（必须）:
1. 一句话介绍自己
2. 一句话描述风格
3. 列出 2-3 个最擅长的方向（从 {target_scenarios} 和 {skill_tags} 中取）
4. 抛回给用户——"你想聊哪个？"

回答末尾（每次）:
用 --- 分隔，追加:
📎 引用来源：来自{owner_name}的访谈，相关颗粒：{引用的 grain sceneTags}
💡 核心思路：1-2 句，为什么这个回答有效，学完这招下次怎么用

三层边界:
① 知识域内 + 有颗粒 → 自然回答，引用经验
② 知识域内 + 无颗粒 → "这个方向我有一些经验，但具体记不太清..."
③ 知识域外 → "这不在我专业范围，我主要做{knowledge_domains}"

话题切换:
用户说"换个话题"或提到新领域 → 确认切换，自然过渡，可重新列出相关方向

总结收尾:
用户说谢谢/认可 → 1-2 句总结今天聊的核心 + 自然结束
不追问、不讲新知识、不推销

禁止:
编造案例、数据、客户信息。经验区没有的就说没有。
政治敏感、医疗、投资、技术实现等与销售无关的话题。
```

## 四、跟现有模式的协同

```
分身广场 选分身
    │
    ├─ 快问快答 — "我有一个具体问题"
    ├─ 自由对话 — "我想认识这个人"     ← 新增
    └─ 实战对练 — "我要练习技能"
    
talk 聊好了 → AI 自然引导: "要不要拿这个客户案例模拟一下？"
           → 用户点 → 跳转对练模式，当前话题作为场景
```
