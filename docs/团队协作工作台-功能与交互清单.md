> 当前方案讨论入口：[方案对比与选型](团队协作方案对比与选型.md)。本文保留自建工作台的产品目标；不表示已经选定自建、Pi或任何其他执行器。云端Harness＋IM或现成团队云产品可以先独立验证。

2026-11-13，V1.2讨论稿。本文保存完整产品目标；最近讨论已收敛首条实施链路，详见[《团队协作工作台-端到端流程与技术设计》](团队协作工作台-端到端流程与技术设计.md)。本文不是已实现功能说明。

> V1.2首条实施链路：共享资料上传和读取、限定范围搜索/RAG、指定方法生成固定成果、围绕当前成果多轮修改、版本保存与成员接续。先做内置固定步骤，不把用户自定义流程编辑器、跨项目自动记忆、自动历史摘要、多执行器切换和IM作为首条链路的前置。下文V1.1的完整功能和三批范围保留为后续目标；与新技术设计不一致时，以新文档的当前范围为准。技术细节是待逐项讨论的设计建议，不表示已批准全部实现。

> V1.1范围确认：通用共享工作台，课程是成果类型之一；文件全览、共享知识分类与版本、搜索、内部RAG、真实Skill执行、聊天式工作、用户定义流程、成果版本与修改均纳入目标范围。第12节补充本轮明确的完整需求，并调整旧文中“正文检索/流程全部延期”的表述：首版包含内部RAG和简单线性流程，多Agent并行/复杂流程画布仍延期。

## 1. 首版边界

三个人分别登录现有销冠平台，在“团队协作”菜单里共享工作区资料和真实Skill，发起Agent任务、看进度、接力修改并共享成果。
支持架构：平台Runtime+接入模型、Codex、Pi三类适配器；首版先实现并验证一个，Pi是当前候选。页面只允许选择已接通且与当前Skill兼容的执行器。
普通用户选任务、Skill与资料，使用默认配置；执行器/模型放“高级设置”。不强迫每次理解技术选项。
不做桌面APP远程接管、同时集成所有引擎、实时多人编辑、复杂工作流、首版IM上传审批。

## 2. 入口与页面

现有导航增加“团队协作”，进入/team-workspace；沿用现有登录与个人账号。

| 页面 | 建议路径 | 内容 |
|---|---|---|
| 工作区列表 | /team-workspace | 工作区、最近成果、最近活动、新建入口 |
| 工作区详情 | /team-workspace/[id] | 共同背景、共享文件、任务对话、执行进度、成果 |
| 团队Skill库 | /team-workspace/skills | 原包、版本、依赖、兼容执行器、试运行、发布 |
| 执行配置（管理员） | /team-workspace/settings | 引擎连接、模型凭证、依赖环境、默认值和并发限制 |

任务详情在工作区内，可通过/team-workspace/[id]?task=…定位；不额外建设重复任务系统首页。
详情布局：左侧文件/任务列表，中间任务对话和执行进度，右侧成果预览。窄屏改标签切换。

## 3. 角色与共享

首版owner/member两种工作区角色：owner管理背景、成员、归档；member查看资料、上传、发起任务、生成成果。
团队Skill发布和引擎凭证配置由管理员负责；成员可提交候选包、试运行其有权使用的包。
工作区内资料和对话默认对成员共享；创建时明确说明。个人密钥、隐藏模型推理和私有工具配置不共享。
同工作区一次只执行一个写入任务，其他成员可查看并提交待发送草稿，不能隐式插入运行指令。首版不做复杂排队编辑，忙碌时提示谁正在运行。
取消权限：发起人和owner；其他成员提示联系发起人。服务端校验，不靠隐藏按钮。

## 4. 工作区与文件交互

| 按钮/动作 | 用户交互 | 系统动作与结果 |
|---|---|---|
| 新建工作区 | 名称必填，背景选填，选择现有成员 | 创建并进入详情；不强制客户/项目复杂字段 |
| 邀请/移除成员 | owner选择成员并确认 | 记录成员关系；移除后接口与下载权限生效；运行中任务按策略停止后续读写 |
| 编辑共同背景 | 显示旧版、修改后保存 | 版本检查；仅影响新任务，当前运行使用快照 |
| 上传文件 | 选择/拖拽文件，标题默认文件名，类型选填 | 上传原件，显示传输和后处理状态，文件可选为输入 |
| 查看文件 | 点击列表项 | 可预览格式显示预览；不支持则显示元信息和下载，不展示空白 |
| 下载 | 点击文件/产物 | 后端校验成员再签发下载 |
| 更新文件 | 上传替代版本 | 保留旧版；不得覆盖已被运行引用的原件 |
| 搜索文件 | 文件名/标签，随后扩正文检索 | 返回工作区内获准文件，定位来源 |
| 选择参考资料 | 勾选文件/历史成果 | 显示本次输入列表，运行前固化版本；可以取消选择 |
| 移出工作区/归档 | 显示影响并确认 | 停止新任务选用；不因删除当前列表破坏历史产物记录 |
| 归档工作区 | owner确认 | 阻止新执行，历史按保留规则只读 |

文件状态分别显示上传中/已保存与解析中/就绪/需人工处理/失败。可读取原件的工具可使用已保存文件；全文检索只用已建好索引的内容。
版本数据是权威来源，容器工作目录是运行副本；Agent修改副本，成果自动发布为新版本。

## 5. Skill库交互

| 按钮/动作 | 用户交互 | 系统动作与结果 |
|---|---|---|
| 导入Skill | 上传zip，填写用途说明 | 保留SKILL.md/scripts/references/assets；校验包，列目录与依赖 |
| 查看说明 | 打开Skill详情 | 方法、输入输出、版本、负责人、依赖、验证样例 |
| 配置输入 | 管理者定义少量表单项/说明 | 首版支持文本、枚举、文件引用，不建通用表单设计器 |
| 配置执行器 | 选允许使用的已接通引擎及环境 | 检查工具/依赖；不可用组合显示具体原因 |
| 试运行 | 输入样例并选资料 | 创建test run，使用与正式运行相同链路，管理者查看真实产物 |
| 确认试运行通过 | 填评价/确认产物可用 | 记录对该Skill版本+执行配置的确认，不仅看程序退出码 |
| 发布 | 管理者确认 | 至少一个已验证组合才发布；团队可使用 |
| 上传新版 | 上传替换包 | 新增不可变版本，重新测试，不影响历史 |
| 停用 | 显示影响 | 阻止新运行，历史保留 |
| 使用Skill | 在库中点击 | 选择目标工作区，进入带该Skill的任务输入，不直接盲跑 |

Skill不是数字分身；不复用销售Skill表。原包不经知识萃取拆碎。
兼容性按Skill版本+执行器版本+工具环境记录；换模型至少做针对性验证，不声称跨引擎产物一致。

## 6. 新建任务与执行器选择

成员新建任务→填写需求→选择Skill（可选，首版重点支持明确选Skill）→勾选参考资料→检查输入摘要→发送。
无Skill模式为基础资料问答/文件处理，仅开放执行器真实支持的功能。
高级设置区分“执行器”和“模型”：平台Runtime选平台支持模型；Pi选其配置支持模型；Codex选其支持配置。三者不能共用一张任意组合菜单。
未配置、未验证、额度不可用或依赖缺失时禁用，并显示原因。不能点了以后才默默换其他引擎/模型。
首版默认不切换同一原生会话的执行器；切换须建新任务，带选定背景和成果引用，不承诺复制内部会话状态。

### 任务按钮

| 按钮 | 系统行为 | 前端反馈 |
|---|---|---|
| 发送/开始 | 校验成员、资料、Skill与配置；幂等建run | 显示配置摘要、发起人、运行状态 |
| 查看输入 | 读取固定输入快照 | 展示文件版本、Skill版本和公开执行配置 |
| 查看进度 | 接收/补取执行事件 | 准备资料、调用工具、处理文件、生成结果；不伪造思考过程 |
| 回答澄清 | 后端保存回答并交原会话 | 显示已提交；不支持暂停恢复的适配器先结束本轮并新建后续 |
| 确认工具操作 | 展示具体动作与影响 | 服务端鉴权，确认有效期/版本；拒绝也有终态 |
| 停止 | 标记取消并请求执行器中止 | 取消中→已取消/终止失败；保留已有产物 |
| 重试 | 创建新attempt，保留失败证据 | 提示可能重新执行，不覆盖原记录 |
| 刷新/返回 | 按ID重取会话、状态和事件 | 不丢进度、不重复发起任务 |
| 继续修改 | 指定成果版本和修改意见 | 沿用兼容会话或新建后续run，保存父任务关系 |
| 新开任务 | 保留工作区背景，自选文件 | 默认不带全部旧聊天，避免上下文混乱 |

run状态：queued/preparing/running/waiting_user/succeeded/failed/interrupted/cancel_requested/cancelled。不同适配器只声明已支持动作，不虚假承诺暂停和任意断点恢复。
多人查看同一任务；同一原生会话串行执行。并行任务是后续需求。

## 7. 成果与交接

| 按钮/动作 | 行为 |
|---|---|
| 查看成果 | 文本/Markdown预览；Word/PPT等首版允许下载，不承诺在线编辑所有格式 |
| 下载 | 直接取得已生成文件，不要求生成者再次人工上传 |
| 查看版本 | 显示来源任务、操作者、时间、修改说明和引用 |
| 提出修改 | 绑定指定版本发起后续任务，不覆盖旧成果 |
| 保存人工修改版 | 文本可编辑保存；二进制文件上传新版，标人工修改来源 |
| 确认最终稿 | owner或配置的确认人标记指定版本，保留可追溯记录 |
| 复制成果链接 | 生成需登录且校验工作区成员的页面链接，不自动公开给客户 |
| 存为团队资料 | 显式选择范围并确认；AI草稿不会自动变成可信案例 |

文字修改用乐观锁，冲突显示当前新版本与自己的内容，不能最后保存覆盖。
通知首版用页面状态和工作区最近活动；不以邮件/IM主动通知作为前置。

## 8. 设置与基础功能

管理员配置执行器连接、认证引用、模型、批准工具、运行镜像、超时/预算和默认值；Key不显示明文回读。
“测试连接”仅表示连通，“验证执行”需实际工具与文件样本，两者分别显示。
已有销售系统功能不依赖新Runner在线；Runner不可用只影响团队任务，文件仍可查看下载。
不同企业/工作区权限在每次文件读取、工具调用、产物下载和消息补取时检查。

## 9. MVP必做与延期

| 首版必须 | 后续扩展 |
|---|---|
| 现有平台团队协作菜单、个人登录 | IM查询/通知 |
| 工作区、成员、共同背景 | 部门、复杂审批、外部客户空间 |
| 文件上传读取、自动成果保存、版本 | 全格式在线编辑、实时多人编辑 |
| 真实Skill导入、依赖检查、试运行发布 | 自动发现复杂Skill组合、Skill市场 |
| 一个已验证执行器及模型配置 | 其他执行器、多模型策略和自动路由 |
| 执行进度、停止、错误、重试、刷新恢复 | 多Agent并行和工作流画布 |
| 后续修改、人工确认、接力 | 自动对外发送和业务系统写操作 |

首版模型和执行器仍待真实样本验收；Pi+DeepSeek为当前候选，不视为效果已验证。

## 10. 首条验收故事

A新建工作区、上传需求和参考资料→B选择真实课程Skill及可用执行配置→Agent读参考、执行脚本并生成文件→C打开任务结果、提出修改→Agent保存新版→A确认最终版。
要求：不手工转发生成文件；每步有真实记录；刷新不丢失；重复提交不重复运行；未授权用户不可访问；旧版保留。
另外覆盖依赖缺失、模型失败、工具失败、取消、服务重启、并发写冲突；不能只验理想路径。

## 11. 实施顺序

1. 一个真实Skill验证执行协议与文件产出。
2. 工作区/成员/文件和团队菜单。
3. 任务对话/事件/自动产物/继续修改。
4. Skill管理/发布、失败恢复与交互完善。
5. 用三人真实任务打磨，再接更多引擎和IM。

每步进入实现前固定接口、状态和验收；本文件先确认功能流程，不代表授权立即实现所有延期项。

## 12. V1.1通用工作台功能定义

### 12.1 产品对象与入口

统一对象：Workspace（共同背景和成员）、Asset（资料）、Conversation/Task（工作对话与执行）、Skill（真实方法包）、Workflow（流程定义）、Deliverable（成果）。
课程、方案、报告、研究、文案、代码等使用成果类型和模板区分，不各造一套版本/执行系统。
主菜单仍为“团队协作”；内部入口调整为工作区、共享知识库、Skill库、流程库；模型/执行器配置藏在管理员设置。
工作区保留对话、文件、成果三个核心区域；公共库选用的资料引用固定版本，不靠手工重复上传。

### 12.2 文件预览与全文阅读

- F01 文件名、格式、大小、作者、版本、处理状态、来源和共享范围。
- F02 点击快速预览；支持展开全屏、目录导航、正文搜索和回到引用片段。
- F03 PDF/图片原样查看；文本/Markdown正文；Office类保留原件并生成阅读用预览副本。
- F04 Word/PPT/表格的可视预览与解析正文分别提供；不能把抽取纯文本冒充原排版全览。
- F05 预览转换失败保留原件，提供下载与错误；扫描件标出是否OCR，不伪造完整可搜索状态。
- F06 修改/升级原件使预览副本和检索索引分别产生对应版本，不能展示旧预览配新正文。
- F07 预览、全文、下载与引用链接统一成员权限；复制网页链接不自动公开。

### 12.3 共享知识库、分类和版本

- K01 分团队共享库与工作区资料；首版简单文件夹/分类+多标签，不建设复杂知识图谱。
- K02 类型支持知识、案例、历史方案、课程材料、方法、模板、其他，允许后续配置。
- K03 分类/标签与权限分开；移动文件夹不默默改变共享范围。
- K04 原件不可变版本，当前有效版指针；更新说明、提交人、时间、来源可追溯。
- K05 版本查看、下载、选旧版重用；回退创建新当前版本引用，不能擦除历史。
- K06 可对文本做差异对比；二进制首版展示版本/预览对照，不承诺通用精准语义diff。
- K07 生效/归档/删除对检索与链接一致；被历史任务引用的版本按保留规则继续鉴权保存。
- K08 已确认知识、客户原始资料、AI草稿明确标识，不自动互相升级为可信资料。

### 12.4 搜索与内部RAG

- R01 文件名、正文关键词搜索；类型、分类、标签、时间、工作区过滤。
- R02 自然语言检索采用关键词+向量，结果显示相关原文、章节、版本及打开入口。
- R03 查资料和生成回答是两种界面状态：可以只返回文档列表，也可以基于命中内容回答。
- R04 检索范围由用户显式选团队共享库/当前工作区/指定文件，后端再限制权限；不混查销售资料。
- R05 回答必须关联实际命中文本；引用打开定位对应版本。信息不足明确说缺少依据。
- R06 原件保存/解析/索引状态分别显示；新版本索引完成后切换，不拼接不同版本。
- R07 问答可多轮补充条件，默认只是当前会话背景，不自动写正式知识。
- R08 真正使用新输入时可选“固定旧资料版本”或“按最新资料重跑”，不能静默更换依据。

### 12.5 类Codex的聊天式工作

- C01 对话为工作入口：输入目标、附文件、选Skill/流程、设置本次参考范围。
- C02 先展示理解/待澄清点，可在约束清楚后执行；不要求每项任务先填大表单。
- C03 真实流式文本、工具活动、文件产物、等待确认、错误与停止状态。
- C04 讨论与执行区分：用户可先问思路，再明确生成；外部副作用不靠猜测执行。
- C05 继续修改引用特定成果版本和修改范围；提供已处理/未处理说明，不能只回复“已完成”。
- C06 中途补充指令是否可steer取决于适配器；首版不支持时明确下一轮处理，不隐式打断。
- C07 重新打开任务恢复上下文和已保存事件；换执行器新建任务，不承诺内部状态无损迁移。
- C08 可见执行过程不等于展示模型隐藏思维链；展示操作、依据与结果即可。

### 12.6 自定义真实Skill

- S01 完整导入SKILL.md/脚本/参考/模板，已发布版本只读。
- S02 支持从平台创建“指令型Skill”草稿，编辑说明、上传依赖文件，保留与导入包一致的结构；不做首版在线任意代码IDE。
- S03 输入输出要求、执行器兼容性、工具依赖和批准运行环境可配置。
- S04 本人试运行→看产物→修订→管理员发布；模板与脚本依赖缺失要显示。
- S05 Skill版本与运行记录关联；知识和模型变更后的验证状态不能仍笼统显示“全部兼容”。

### 12.7 用户定义流程

- W01 首版提供步骤列表编辑器：新建、添加、删除、排序、保存、发布；不要求先做拖拽DAG画布。
- W02 步骤类型：资料检索、指定Skill执行、人工确认。每步有输入、输出、检查条件与失败处理。
- W03 步骤输入可引用用户输入、指定资料版本、上一步结果；界面选择引用，不能仅凭自由文本猜传参。
- W04 简单线性执行，例如需求整理→检索参考→生成大纲→人工确认→修改成稿。
- W05 流程定义保存版本，发布后修改产生新草稿；每次执行绑定流程版本和Skill版本。
- W06 运行视图显示步骤状态、输入、产物、错误；等待人工确认能关闭页面后返回继续。
- W07 同意/退回附意见，拒绝后按流程规则修改或停止；重试指定失败步骤及其受影响下游，不覆盖成功历史。
- W08 首版不做分支表达式、任意循环、并行多Agent或通用审批平台；后续通过相同步骤契约扩展。

### 12.8 通用成果、课程修改与版本

- D01 成果与文件关联，但另保存类型、状态、来源任务/流程、引用和基准版本。
- D02 课程、方案、报告、文案等都采用“草稿→修订→确认”的共同生命周期。
- D03 首版文本/Markdown可在线编辑，支持针对段落/模块提出AI修改；Word/PPT先下载或外部修改后上传新版。
- D04 课程特定交互作为扩展模板：受众、目标、时长、模块顺序和活动；不写死平台核心业务为课程。
- D05 部分修改明确目标模块和基准版本；保持未改部分，提供修改说明并防并发覆盖。
- D06 最终稿固定版本，可继续派生新草稿，不删除旧确认记录；成果不自动发布到公共知识。
- D07 引用旧成果继续工作时保留父版本关系；手动修改与Agent修改都可追溯。

## 13. V1.1交付切分

第一批：文件原件与预览/全览、分类版本、全文搜索和内部RAG。验收资料找得到、看得全、引用正确、权限一致。
第二批：聊天式目标执行、真实Skill创建/导入/试运行、一个执行适配器、真实文件产物和接力修改。
第三批：通用成果管理与课程模板、简单线性流程定义及人工确认，打通完整真实任务。
扩展批：更多执行器、IM、多Agent/复杂流程、Office在线编辑，依据真实需求另立验收。

第一至第三批组成目标MVP，不意味着必须一次开发完所有页面。先用同一真实业务样本纵向跑通，再逐项补齐。
