## 一、架构概览

```
新增一个领域:

  domain/_tree.json                           ← 加一个节点
  domain/xxx.yml                              ← 一级配置（通用）
  domain/xxx/sub.yml                          ← 二级配置（extends: xxx，只写差异）
  prompts/domain/xxx.sub/ 下 11 个 prompt      ← 领域专属

零 Java 代码。零数据库 migration。
```

### 领域配置驱动什么

| 功能 | 配置段 | 说明 |
|------|--------|------|
| 上传时准入检查 | `acceptance` | 关键词库、拒绝规则、业务白名单 |
| 上传后质量预检 | `precheck` | 关键词分组、异议信号、场景映射、反馈文案 |
| 萃取全部层级 | `pipeline` | 情境标注维度、场景分类体系、萃取角色、提取任务 |
| Chat 三种模式 | `chat.modes` | 模式标签、描述、placeholder、对练角色 |
| Prompt 变量注入 | `domain.*` | role_label、counterparty_label、skill_label、knowledge_unit |
| Java 代码反馈文案 | `precheck.labels` | 预检分析器的中文反馈措辞 |

## 二、扩展步骤

### Step 1：在 `_tree.json` 中注册

`domain/_tree.json`：

```json
[
  {
    "id": "medical",
    "name": "医疗",
    "children": [
      { "id": "medical.clinical", "name": "临床诊疗" }
    ]
  }
]
```

前端 `GET /api/domains` 直接返回此文件内容。

### Step 3：创建二级领域（可选）

`domain/medical/clinical.yml`：

```yaml
extends: medical
domain:
  id: medical.clinical
  name: 临床诊疗
```

> `extends: medical` — 继承一级的全部配置。二级只需写差异项。

### Step 4：创建领域 prompt 文件

`prompts/domain/medical.clinical/` 下新建 11 个文件：

| 文件 | 用途 | 编写要点 |
|------|------|---------|
| `material_context_tag.md` | 萃取 L0 情境标注 | 角色→临床场景分析，维度→clinical_stage/patient_type/department |
| `material_extract_full.md` | 萃取 L5 颗粒提取 | 角色→"临床思维分析专家"，任务→"诊断推理模式" |
| `material_extract_short.md` | 萃取 L5 精简版 | 同上 |
| `material_faq.md` | FAQ 提取 | 从医患对话提取 QA |
| `material_verify.md` | 对抗验证 | 审核临床经验质量（通用逻辑，通常无需大改） |
| `material_merge.md` | 合并去重 | 通用逻辑，通常无需大改 |
| `material_pattern.md` | 模式发现 | 提炼临床行为模式 |
| `material_profile.md` | 画像生成 | 医生画像配置 |
| `material_narrative.md` | 叙事重放 | 诊疗叙事 |
| `interview_system.md` | 访谈系统 | 策略→"医生讲病例→萃取诊疗过程→提炼临床路径" |
| `meta_interview_system.md` | 元访谈 | 目标→"萃取临床专家经验" |
| `classify_scenes.md` | 场景归类 | 角色→临床场景，"为以下{domain.name}场景分别起标签" |
| `skill_practice_customer.md` | 对练客户 | 角色→患者，"你是一位真实的{domain.counterparty_label}" |
| `skill_practice_opening.md` | 对练开场 | 患者主诉开场 |
| `skill_practice_angles.md` | 对练角度 | 从病例提取教学角度 |
| `skill_practice_evaluate_response.md` | 对练逐轮评价 | 角色→"临床带教老师"，评估→诊疗规范 |
| `skill_practice_full_answer.md` | 对练满分回答 | 角色→"主任医师"，输出→临床路径 |
| `practice_analyzer_intent.md` | 对练意图分类 | 6 意图→病史采集/体格检查/诊断推理/方案制定/患者教育/风险沟通 |

> **不需要全部 18 个都写**。很多文件（如 verify、merge、narrative）用通用逻辑即可。从已有领域（`sales.b2b_enterprise` 或 `finance.secondary_market`）复制改角色名是最快的方式。

### Step 5：验证

1. 重启后端，`DomainConfigLoader.load("medical.clinical")` 加载成功
2. 上传医患对话 → 预检用医疗关键词 → 检测到"诊断推理""治疗方案"
3. 萃取产出临床思维颗粒
4. Chat 模式标签显示"请教专家""病例对练"

## 四、Prompt 文件清单

### 通用 prompt（根目录，不改）

所有放到 `prompts/` 根目录的 prompt，已用 `{domain.xxx}` 变量化，自动适配任何领域。新增领域不需要动它们。

### 领域专属 prompt（需新建）

放在 `prompts/domain/{domain_id}/` 下，领域 ID 用点号分隔对应目录：`medical.clinical` → `prompts/domain/medical.clinical/`。

查找链：`domain/{domain_id}/{name}` → `domain/{一级}/{name}` → `{name}`（根目录通用版）。

## 五、常见问题

**Q: 加一个领域需要多长时间？**
A: 写 YAML 配置 1-2 小时 + 从已有领域复制并改 prompt 2-3 小时 + 测试 1 小时 ≈ 半天。

**Q: 二级领域必须创建吗？**
A: 不是。如果领域不需要细分（如心理咨询师），直接一个 `domain/psychology.yml` 即可，不需要 `psychology/xxx.yml`。此时领域 ID 就是 `psychology`，prompt 目录就是 `prompts/domain/psychology/`。

**Q: 如果 prompt 文件找不到会怎样？**
A: PromptLoader 返回 null，调用方收到空 prompt，不会 crash 但对应功能无输出。建议至少覆盖 11 个核心文件。

**Q: 领域配置写错了会 crash 吗？**
A: `DomainConfigLoader` 加载失败时返回兜底配置并打 error 日志。不会 crash，但行为可能不符合预期。
