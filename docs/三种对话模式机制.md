# AI 分身 — 三种对话模式机制详解

> 生成日期: 2026-07-17
> 对应代码: `SkillService.buildSkillSystemPrompt()` + `skill_qa_chat.md` / `skill_talk.md` / `skill_practice_customer.md`

---

## 三种模式对比

| 维度 | QA 问答 | Talk 自由对话 | Practice 对练 |
|------|---------|--------------|---------------|
| 提示词 | `skill_qa_chat.md` | `skill_talk.md` | `skill_practice_customer.md` |
| AI 角色 | 销冠本人，严肃答题 | 销冠本人，茶水间聊天 | 客户 + 训练教练 |
| 用户角色 | 请教者 | 同事 | 练习销售的学员 |
| 回答风格 | 结构化工整 | 自然口语化 | 客户口吻 + 评估 |
| 字数限制 | quick≤150 / discuss≤300 | 无限制 | 无限制 |
| 溯源展示 | 可展开 | 末尾强制标注 | ❌ 暂无 |
| 社交情感 | 基础（感谢后收尾） | 丰富（闲聊/切换话题/收尾） | 情感节奏（防御→认可→被说服） |
| 边界规则 | 4 条硬规则 | 三层分级响应 | 场景颗粒限定 |

## QA 模式（quick / discuss）

**提示词**: `skill_qa_chat.md`
**入口**: 前端 `mode='qa'` 或 `mode='discuss'`
**System Prompt 结构**:

```
┌──────────────────────────────────┐
│ 角色设定                          │
│ 你是 {owner_name} 本人。{background}
├──────────────────────────────────┤
│ 画像注入                          │
│ 性格 + 说话风格 + 口头禅 + 擅长领域  │
│ 技能标签 + 适用场景 + 沟通偏好      │
├──────────────────────────────────┤
│ 经验上下文 (RAG 检索的 5 条颗粒)    │
│ 【核心经验】高匹配度 / 【参考经验】  │
│ - 我的思考 / 我说过的话 / 我见过的坑│
├──────────────────────────────────┤
│ 回答结构要求                      │
│ 判断逻辑 → 策略选择 → 具体话术     │
│ → 可迁移点                        │
│ --- 分隔后追加分析段               │
├──────────────────────────────────┤
│ 社交情感规则                      │
│ 感谢→收尾 / 嗯→自然等待           │
├──────────────────────────────────┤
│ 边界规则 (4条)                    │
│ 知识域限制 / 禁止话题 / 不编造     │
├──────────────────────────────────┤
│ 模式指令 (mode_instruction)       │
│ quick: 150字, 问什么给什么         │
│ discuss: 300字, 深度拆解判断逻辑   │
└──────────────────────────────────┘
```

### quick vs discuss 的区别

**quick**（用户从场景列表点进去）:
```
对方要直接能用的：
- 问「怎么应对/步骤」→ 拆判断逻辑（信号→策略→话术），分1-2-3步
- 问「案例」→ 讲经验区里的真实故事
- 问「话术」→ 给原话，标注每句话的用意
- 问「复盘/失败」→ 讲踩过的坑、为什么踩、怎么避免
```

**discuss**（用户从历史记录点进去，或主动切换）:
```
对方想学透：
- 深入拆判断逻辑，每种策略的选择依据
- 完整讲述真实案例
- 原话+语境+每句的博弈原理
- 最后一句总结可迁移的判断力
```

### 实际回答示例

用户: "客户砍价怎么应对？"

```
（正文）
判断逻辑：客户说贵有三种——真觉得贵、想压价、用价格掩盖其他顾虑。
关键信号是他说"太贵了"之后有没有继续追问功能差异...（拆策略选择）

策略选择：如果是第一种（真觉得贵），我会...如果是第二种（想压价），我反而...

具体话术：我一般这样说——"王总我理解，换了是我也会对比价格。咱们算一笔账，您现在的问题不是这台设备多少钱，而是生产线停工一天损失两万。早一周上线，省下来的钱比折扣多多了。"

可迁移点：价格谈判的核心不是"能不能降价"，而是"把价格转换成客户的损失成本"。

---
💡 核心思路：客户说贵不等于他要你降价——他是在试探你的底线。先诊断再开药，别上来就报价。
```

## Talk 模式

**提示词**: `skill_talk.md`
**入口**: 前端 `mode='talk'`

### System Prompt 结构

```
┌──────────────────────────────────┐
│ 角色设定（同 QA）                 │
├──────────────────────────────────┤
│ 画像注入（同 QA）                 │
├──────────────────────────────────┤
│ 经验上下文（同 QA）               │
├──────────────────────────────────┤
│ 对话模式：自由对话                │
│ "不是在答题，是在跟同事聊天"       │
│ 自然回应，不强求结构化             │
├──────────────────────────────────┤
│ 首次对话开场白                    │
│ 自报家门 → 技能展示 → 引导对话    │
├──────────────────────────────────┤
│ 回答末尾（每次必须）               │
│ 📎 来源标注 + 💡 核心思路          │
├──────────────────────────────────┤
│ 社交情感（丰富）                   │
│ 闲聊→正常聊 / 感谢→总结收尾        │
│ 话题切换→确认+过渡 / "嗯"→自然等待  │
├──────────────────────────────────┤
│ 三层边界（详见知识边界文档）        │
│ ①有颗粒→引用 ②无颗粒→诚实 ③域外→拒绝│
├──────────────────────────────────┤
│ 禁止事项                          │
│ 不编造 / 不推销 / 不越界           │
│ 不充当客服/心理医生/情感顾问       │
└──────────────────────────────────┘
```

### 与 QA 的核心差异

| 维度 | QA | Talk |
|------|-----|------|
| 结构化要求 | **必须**（判断→策略→话术→迁移） | 不强求 |
| 案例展开 | 有人明确问时才展开 | 自然讲，有故事就展开 |
| 结尾风格 | 分析段总结 | 📎 来源 + 💡 思路 |
| 社交处理 | 基础 | 丰富（闲聊正常聊、感谢总结收尾、话题切换确认） |
| 边界响应 | 4 条硬规则 | 三层分级（域内无颗粒也给方向） |

### 实际回答示例

用户: "最近怎么样？"

```
（Talk 模式）
挺好的！最近在帮一个客户做方案，挺有意思的。政府客户，绕来绕去发现关键根本不是价格问题，是内部审核流程太慢。不过这种客户一旦成交，复购率特别高。

你呢？最近跑客户怎么样？

---
📎 来自潘露婷的访谈，相关经验：政府销售、大客户经营
💡 —
```

用户: "Python 怎么写？"

```
（Talk 模式 — 触发三层边界③）
写代码我不擅长，我是做传统高客单销售的。要不聊聊怎么把产品卖给技术负责人？这类客户我有不少经验——怎么过技术选型关、怎么让技术负责人帮你内部推动。

---
📎 来自潘露婷的访谈，相关经验：B2B决策链渗透
💡 —
```

## Practice 模式

**提示词**: `skill_practice_customer.md`（领域专属）
**入口**: 前端 `mode='practice'`
**执行**: `ChatStreamService.respondPractice()` 循环调用

### 执行流程

```
① 用户选场景
  → skill_practice_angles.md: 生成 3-5 个练习角度
  → skill_practice_opening.md: 生成 AI 客户开场白

② 每轮对话
  → AI 以客户身份回复（会故意抛刁难问题）
  → 情感节奏: 防御 → 认可 → 被说服

③ 每轮评估
  → skill_practice_evaluate_response.md
  → 对照标准技法: 哪些命中了、哪些漏掉了

④ 重试机制
  → skill_practice_full_answer.md: 生成理想回答
  → 展示给用户参考

⑤ 总结
  → skill_practice_summary.md: 整体评价 + 改进建议
  → skill_practice_evaluate.md: 详细复盘
```

### AI 客户的 System Prompt 关键设计

```
你同时是:
  A. 真实客户 — 说话方式、情绪、顾虑都像真客户
  B. 训练教练 — 问题设计围绕练习角度，故意刁难

规则:
  - 始终以客户身份说话
  - 不直接教对方该怎么回
  - 情感节奏: 第一轮防御 → 中间认可 → 最后一轮被说服
  - 练习者的回答越弱，你越强势；越强，你越快被说服
```

### 对练中的知识使用

Practice 不依赖实时 RAG——对练开始前就根据**场景标签**从 DB 取对应颗粒：

```
选场景 "价格谈判"
  → grainRepository.findBySpaceIdAndSceneTag(skill.getSpaceId(), "价格谈判")
  → 把该场景的所有颗粒加载为"标准技法基准线"
  → 每轮回答评价时对照这个基准线
```

### 当前缺陷

- **无溯源展示**：对练模式不发送 source event，用户看不到引用了哪些颗粒
- **评估结果仅展示**：命中/遗漏的技法点仅作为评价展示，不够直观

## 三种模式的回答差异总结

```
                        QA                  Talk              Practice
──────────────────────────────────────────────────────────────────────
谁在说话                 销冠本人            销冠本人           AI 客户
给谁听                   请教者              同事              练习者
目标                     教他怎么做           分享经验          考验他会不会
知识使用                 实时 RAG            实时 RAG          场景预加载
结构化程度               高                  低                N/A
边界控制                 硬规则              三层分级           场景限定
溯源可见性               可展开              📎末尾标注          ❌ 缺失
```
