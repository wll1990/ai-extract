## 三种模式对比

| 维度 | QA 经验请教 | Talk 轻松交流 | Practice 实战演练 |
|------|-----------|-------------|------------------|
| 提示词 | `skill_qa_chat.md` | `skill_talk.md` | `skill_practice_customer.md` |
| AI 角色 | 销冠本人，严肃答题 | 销冠本人，茶水间聊天 | 客户 + 训练教练 |
| 用户角色 | 请教者 | 同事 | 练习销售的学员 |
| 回答风格 | 结构化工整 | 自然口语化 | 客户口吻 + 评估 |
| 字数限制 | quick≤150 / discuss≤300 | 无限制 | 无限制 |
| 溯源展示 | 可展开（匹配度≥30%） | 可展开（同QA） | 客户消息有匹配度，评价含颗粒列表 |
| 社交情感 | 基础（感谢后收尾） | 丰富（闲聊/切换话题/收尾） | 情感节奏（防御→认可→被说服） |
| 边界规则 | 4 条硬规则 | 三层分级响应 | 场景颗粒限定 |
| 子模式 | quick（快捷）/ discuss（深度） | 无 | 逐轮评价+最终复盘 |
| 对话持久化 | 仅 published 分身 | 同左 | 同左 |
| 统计埋点 | `conversation_stats` | 同左 | 同左 |

## 模式解析机制

`SkillService.resolveMode(explicitMode, message)` — 前端传了 `chatMode` 就直接用，没传则基于消息内容推断：

```java
if (explicitMode != null) return explicitMode;
if (message.startsWith("/对练") || message.startsWith("/练习")) return "practice";
if (message.startsWith("/聊天") || message.startsWith("/talk")) return "talk";
if (message.startsWith("/讨论") || message.startsWith("/聊聊")) return "discuss";
return "quick";
```

> **当前事实：** 前端总是传 `chatMode` 参数（'qa'/'talk'/'practice'），基于消息前缀的推断路径是死代码。

`PromptAssemblyService.buildModeInstruction()` 进一步细化子模式：

| resolveMode 输出 | 模板 | modeInstruction |
|-----------------|------|-----------------|
| `"talk"` | `skill_talk.md` | 空（模板自带） |
| `"qa"` | `skill_qa_chat.md` | 空 |
| `"quick"` | `skill_qa_chat.md` | "快问快答：150字，直接可用" |
| `"discuss"` | `skill_qa_chat.md` | "深度探讨：300字，深入分析判断逻辑" |

## QA 模式（quick / discuss）

**提示词**: `skill_qa_chat.md`  
**入口**: 前端 `mode='qa'`  
**命名**: 用户可见 "经验请教"，副标题 "带着问题来，带着方法走"

### System Prompt 结构

```
┌──────────────────────────────────┐
│ 角色设定                          │
│ 你是 {owner_name} 本人。{background}
├──────────────────────────────────┤
│ 画像注入                          │
│ 性格 + 说话风格 + 口头禅 + 擅长领域  │
│ 技能标签 + 适用场景 + 沟通偏好      │
├──────────────────────────────────┤
│ 经验上下文 (RAG 检索的 5 条颗粒)    │
│ 按 tier 标记: high / ref / none    │
│ - 我的思考 / 我说过的话 / 我见过的坑│
├──────────────────────────────────┤
│ 回答结构要求                      │
│ 判断逻辑 → 策略选择 → 具体话术     │
│ → 可迁移点                        │
│ ━━━━━━ 分隔后追加分析段            │
├──────────────────────────────────┤
│ 社交情感规则                      │
│ 感谢→收尾 / 嗯→自然等待           │
├──────────────────────────────────┤
│ 边界规则 (4条)                    │
│ 知识域限制 / 禁止话题 / 不编造     │
├──────────────────────────────────┤
│ 模式指令 (mode_instruction)       │
│ quick: 150字, 问什么给什么         │
│ discuss: 300字, 深度拆解判断逻辑   │
└──────────────────────────────────┘
```

### 实际回答示例

用户: "客户砍价怎么应对？"

```
（正文）
判断逻辑：客户说贵有三种——真觉得贵、想压价、用价格掩盖其他顾虑。
关键信号是他说"太贵了"之后有没有继续追问功能差异...

策略选择：如果是第一种（真觉得贵），我会...如果是第二种（想压价），我反而...

具体话术：我一般这样说——"王总我理解，换了是我也会对比价格。咱们算一笔账，
您现在的问题不是这台设备多少钱，而是生产线停工一天损失两万。"

可迁移点：价格谈判的核心不是"能不能降价"，而是"把价格转换成客户的损失成本"。

━━━━━━
💡 核心思路：客户说贵不等于他要你降价——他是在试探你的底线。先诊断再开药。
```

## Talk 模式

**提示词**: `skill_talk.md`  
**入口**: 前端 `mode='talk'`  
**命名**: 用户可见 "轻松交流"，副标题 "像老同事一样自然对话"

### 与 QA 的核心差异

| 维度 | QA | Talk |
|------|-----|------|
| 结构化要求 | **必须**（判断→策略→话术→迁移） | 不强求 |
| 案例展开 | 有人明确问时才展开 | 自然讲，有故事就展开 |
| 结尾风格 | 分析段总结 | 📎 来源 + 💡 思路 |
| 社交处理 | 基础 | 丰富（闲聊正常聊、感谢总结收尾、话题切换确认） |
| 边界响应 | 4 条硬规则 | 三层分级（域内无颗粒也给方向） |
| 首次对话 | 1-2句自我介绍 | 2-3句自我介绍 + 邀请说出需求 |

### 实际回答示例

用户: "最近怎么样？"

```
挺好的！最近在帮一个客户做方案，挺有意思的。政府客户，绕来绕去发现关键
根本不是价格问题，是内部审核流程太慢。不过这种客户一旦成交，复购率特别高。

你呢？最近跑客户怎么样？

━━━━━━
📎 来自潘露婷的访谈，相关经验：政府销售、大客户经营
💡 —
```

## Practice 模式

**提示词**: `skill_practice_customer.md`（领域专属）  
**入口**: 前端 `mode='practice'`  
**命名**: 用户可见 "实战演练"，副标题 "在真实场景中刻意练习"

### 完整执行流程

```
① 用户选场景 → POST /skills/{id}/practice/start
  → 从颗粒加载场景信息 (title, setting, customerLine)
  → 创建 Conversation (mode='practice')
  → 返回 { practiceId, scene, angles }

② 每轮对话
  → 用户打字回应客户
  → POST /skills/{id}/practice/respond (SSE)
  → AI 以客户身份流式回复
  → 情感节奏: 防御 → 认可 → 被说服

③ 每轮评价（并行，非阻塞）
  → POST /skills/{id}/practice/evaluate-round
  → 返回 { championAnswer, hits, misses, technique, offTopic, matchLevel, grains }

④ 重试机制（最多2次）
  → 用户点"用技法再试一次"
  → 传入 previousChampionAnswer 和 retryCount
  → isLastRetry 时返回 fullAnswer

⑤ 角度推进
  → 用户点"继续下一轮"
  → 同一场景不同角度生成新客户消息

⑥ 最终复盘
  → 用户点"结束对练"
  → POST /skills/{id}/practice/evaluate (SSE)
  → 返回 { strengths, improvements, demo_script, next_advice }
  → 持久化到 skill_evaluation 表（四维评分）
```

### AI 客户的关键设计

```
你同时是:
  A. 真实客户 — 说话方式、情绪、顾虑都像真客户
  B. 训练教练 — 问题设计围绕练习角度，故意刁难

规则:
  - 始终以客户身份说话，不直接教对方该怎么回
  - 情感节奏: 第一轮防御 → 中间认可 → 最后一轮被说服
  - 练习者的回答越弱，你越强势；越强，你越快被说服
```

### 四维评价体系

| 维度 | 权重 | 评估内容 |
|------|------|---------|
| style_score | 30% | 语言风格匹配度 |
| consistency_score | 30% | 经验一致性 |
| behavior_score | 20% | 行为模式准确性 |
| script_reuse_score | 20% | 话术复用精准度 |

### 当前实现状态

- **三套独立实现**：前端 OSS（useReducer）、shared-ui 包（已抽取但 enterprise 未迁移）、enterprise（useState 自包含）
- **shared-ui 已创建**（2026-07-22）但 enterprise 未采用
- **溯源**：客户消息有匹配度标签（≥50%精准/≥30%关联/<30%综合），最终评价含颗粒列表
- **趋势**：`GET /skills/{id}/practice/trend` 返回历史评分序列

## RAG 检索管道（QA/Talk 共用）

```
用户消息
  │
  ├─ Phase 1: buildRagHistory()
  │   └─ 从 DB 加载最近 12 条消息作为上下文
  │
  ├─ Phase 2: rewriteQuery()
  │   └─ LLM 将代词/缩写扩展为完整查询（≤30 字）
  │   └─ 失败时优雅回退到原消息
  │
  └─ Phase 3: retrieveGrainsWithScores()
      └─ pgvector 语义检索 topK=5
      └─ 按阈值分层: high(≥0.50) / ref(≥0.30) / none(<0.30)
      └─ 写入 grain_retrieve_log 表
      └─ 无匹配→写入 knowledge_gap + SSE suggested 事件推回退问题
```

## 访客限制（H5 分享页）

| 层级 | 机制 | 默认值 | 配置 |
|------|------|--------|------|
| 速率限制 | Redis 计数器 | 6条/分钟 | `app.share.guest-msg-per-min` |
| 每日配额 | DB 计数 | 5条/天 | `app.share.guest-message-limit` |

超出限制 → SSE `limit` 事件 → 前端移除消息气泡 + 显示"注册解锁"按钮。

## 反馈系统

- **QA/Talk**：👍/👎 点赞，写入 `feedback_log` 表，含 query、AI 回复片段、RAG 分数
- **Practice**：四维 AI 自动评分，写入 `skill_evaluation` 表
- **统计**：每次 AI 回复写入 `conversation_stats` 表（RAG 分层计数、耗时、错误类型）

## 商业化备注（供产品和运营参考）

1. **访客→注册转化**：H5 游客 5 条/天后触发注册弹窗，是当前唯一转化入口
2. **对话统计飞轮**：`conversation_stats` 记录每次 AI 回复的 RAG 质量，可用于评估分身质量
3. **反馈数据**：`feedback_log` 可计算满意度，按 grain 聚合可发现高质量/低质量颗粒
4. **对练评分趋势**：Practice 评分趋势可用于展示用户进步，提高留存
5. **当前无支付系统**：游客超额后只能注册，无付费选项
