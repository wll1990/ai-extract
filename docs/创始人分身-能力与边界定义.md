# 创始人分身 · 能力与边界定义

> 本文档是创始人分身的**能力与边界总依据**，交互原型和技术方案都以此为准。
> 团队内部文档，用于对齐"分身能干什么、不能干什么、边界在哪"。

---

## 一、能力模型总览

创始人分身对外是**单一对话入口**——员工不问"我要用哪个模式"，直接提问，系统内部自动识别问题类型并路由。

问题类型最终收敛为**三种能力本质**：

| 能力 | 本质 | 回答形态 | 对应文龙模块 |
|------|------|---------|-------------|
| **判断** | 判断 | 判断卡片（原则→分析→结论→边界） | A 决策 + B 销售（合并） |
| **代笔** | 生成 | 草稿 + 强制标注 | C 内容代笔 |
| **百科** | 检索 | 标准答案 | D 公司百科 |

---

## 二、能力一：判断（核心，含决策 + 销售）

**本质**：员工问"这件事该怎么办/该不该做/怎么权衡"，分身给出老板的判断倾向和权衡逻辑。

**为什么决策和销售合并**：两者技术实现完全一致（检索判断原则 → 判断链生成），只是领域标签不同。合并为一个能力，内部按领域路由（战略 / 销售 / 组织 / 产品 / 资本 / 文化），对外是同一入口、同一套交互。

### 回答形态：判断卡片

```
原则：先看天花板，再看有没有结构性优势
分析：天花板 X 亿，但已红海，无独家壁垒
结论：暂不进入，观察 6 个月
边界：能并购拿到头部位置则另当别论
📎 来源：[1] 2024战略会纪要（可展开原文）
```

### 边界（三条，缺一不可）

1. **担责事项明示确认**：涉钱、合规、人事等担责类问题，回答末尾必须加"最终以老板本人确认为准"。
2. **信息不足反向追问**：当问题缺关键信息无法判断时，不硬下结论，而是反问"还缺哪些信息"（模拟老板"不拿信息不拍板"的习惯）。
3. **未覆盖诚实表态**：老板从没表态过的领域，明确说"老板未提过"，不瞎编。

### 触发识别（关键词）

"该不该 / 怎么办 / 怎么权衡 / 要不要 / 如何决策" → 判断能力。

---

## 三、能力二：代笔（生成）

**本质**：员工要写路演稿、融资叙事、行业观点短文等，分身按老板的口吻生成草稿。

**与判断的本质区别**：判断是"给倾向 + 边界"，代笔是"产出一篇新文本"。

### 回答形态：草稿 + 强制标注

```
【AI 草稿 · 需本人润色后对外】

[生成的草稿正文，保持老板口吻和商业认知]
```

### 边界（两条）

1. **强制标注**：每次代笔输出都强制带「AI 草稿，需本人润色后对外」标注，无论用途。
2. **不编造**：不编造老板没做过的业绩、没发表过的观点、没发生的事实。

### 依赖素材

老板的原话、口头禅、风格素材（对应素材标准的 D 级）+ 判断原则（保证商业认知一致）。

---

## 四、能力三：百科（检索）

**本质**：员工问制度、流程、静态信息，分身直接给标准答案。

**与判断的区别**：百科是"检索客观事实"，不需要判断，直接命中即答。

### 回答形态：标准答案

```
问：报销流程是什么？
答：[直接给制度原文/标准答案]
📎 来源：《报销制度》第 3 节
```

### 边界（两条）

1. **只答确认过的静态信息**：只回答老板/制度确认过的客观信息，不答未经确认的内容。
2. **动态信息标注时效**：融资阶段、团队规模等会变的信息，回答时带「截至 XX 时间」标注，并提示以最新为准。

### 依赖素材

公司制度文档（报销 / 人事 / 合伙人分工 / 产品参数），对应素材标准的"百科"类，直接入库供检索，不分级。

---

## 五、三种能力的统一边界（所有能力共同遵守）

| 边界 | 说明 |
|------|------|
| **敏感拦截** | 薪酬、具体人事、未公开交易、法律风险 → 转"建议直接问老板" |
| **诚实优先** | 三种能力都遵守"没覆盖就说没覆盖"，绝不硬答、绝不编造 |
| **溯源** | 判断和百科带来源引用；代笔带"草稿"标注 |

---

## 六、意图识别路由（技术落点）

```
用户提问
    │
    ├─ 命中敏感词（薪酬/人事/未公开交易/法律）→ 敏感拦截
    │
    ├─ 判断类（该不该/怎么办/要不要/怎么权衡）
    │    └─ 信息不足？→ 反向追问
    │        └─ 信息足 → 检索原则 → 判断卡片
    │
    ├─ 代笔类（帮我写/起草/生成 + 路演/融资/文章）
    │    └─ 生成草稿 + 强制标注
    │
    └─ 百科类（是什么/流程/参数/分工）
         └─ 检索事实 → 标准答案（动态信息标时效）
```

---

## 七、对应的交互原型改动

| 页面 | 改动 |
|------|------|
| 对话页 | 回答形态从 1 种（判断卡片）扩展为 3 种：判断卡片 / 代笔草稿（带标注）/ 百科答案（带来源+时效） |
| 对话页 | 新增"反向追问"状态（信息不足时不答，先问缺什么） |
| 老板端 | 新增"回填清单"界面（人设锚点 / 禁区 / 高频问题，高频问题按三种能力分类） |

## 八、对应的技术方案改动

| 点 | 改动 |
|---|---|
| 意图识别 | 从 judgment/fact 扩展为三路：judgment / generate / faq |
| 代笔 | 新增 prompt 模板（保持口吻 + 商业认知），输出强制带"草稿"标注 |
| 百科 | 事实层 chunk 直接检索，动态信息字段带时效标注 |
| 反向追问 | judgment 意图且信息不足时，先输出"需补充 X/Y/Z" |
