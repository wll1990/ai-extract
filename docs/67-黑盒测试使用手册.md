# 黑盒测试使用手册

> 目标：每次发版前用一套可重复的命令验证权限、核心闭环、历史回归与关键交互。
> 运行环境：线上（生产）。只写 QA 租户，默认只读、默认不跑 LLM。

## 一次性准备

```bash
npm run qa:setup
```

首次会生成 `.qa.env`（已 gitignore），填入密码后再次执行。setup 会：

1. 生成 bcrypt 密码哈希；
2. 在 QA 租户执行两次 seed（验证幂等）；
3. 空跑一次 cleanup（验证清理脚本可用）。

QA 租户固定信息：

| 项目 | 值 |
|---|---|
| 企业 | `0a000000-0000-0000-0000-000000000001`（QA 测试企业 · 勿删） |
| 注册码 | `QATEST01` |
| 账号 | `qa_super` / `qa_admin` / `qa_emp` / `qa_coach` |
| 密码 | `.qa.env` 中的 `QA_PASSWORD` |

## 每次发版

```bash
npm run qa:release
```

内部顺序：权限矩阵 → 黄金链路 → 回归集 → UI → Holdout（未配置自动 skip）。
控制台只输出一张表；退出码 `0` 可发，`1` 看报告，`2` 修环境。

报告位置：`reports/qa/<时间戳>/summary.md` 和 `result.json`（`reports/qa/` 已 gitignore，不会进仓库）。

- `summary.md`：给人看的。三张表——套件统计、失败用例、已知告警（`⚠ [known]`，含期望/实际和转正条件）。
- `result.json`：给机器看的。每条用例的 `id/suite/role/method/path/expected/actual/status/knownIssue`，可直接转研发工单。

## 常用命令

| 场景 | 命令 |
|---|---|
| 改完代码快速自检 | `npm run qa:quick` |
| 只跑权限矩阵 | `node scripts/qa/run.mjs --suite=permissions` |
| 只跑某条用例 | `node scripts/qa/run.mjs --suite=regression --case=REG-MAT-01` |
| 夜间带 LLM | `npm run qa:nightly` |
| 跑私有 Holdout | `QA_HOLDOUT_DIR=$HOME/qa-holdout npm run qa:nightly` |
| 发版门禁 | `bash scripts/qa/release-gate.sh` |

## 安全规则

- 默认只读；写操作需要 `QA_ALLOW_WRITE=1`，`qa:release` 内部已开启。
- 默认不跑 LLM；`QA_ALLOW_LLM=1` 才跑真实模型链路。
- **发版门禁例外**：`bash scripts/qa/release-gate.sh` 默认 `QA_ALLOW_LLM=1`，会真实调用模型验证「建知识/案例→分身聊天命中」「对练命中案例」等聊天链路，耗时与 token 成本明显高于权限/回归集。紧急情况下用 `QA_ALLOW_LLM=0 bash scripts/qa/release-gate.sh` 临时跳过。
- 所有测试对象名带 `QA-<runId>-`，清理按 runId，不按 companyId。
- 数据库断言通过 `ssh mindforge psql` 执行，本地不连生产库。
- 线上禁止执行 `demo-reset.sql`、`test-data.sql`、`*-reset.sql`、`clean-db.sql`。

## 新增用例

- 黄金链路：`scripts/qa/cases/golden/*.json`
- 回归集：`scripts/qa/cases/regression/*.json`，必须带 `sourceBug`
- 权限矩阵：`scripts/qa/cases/permissions.json`
- Holdout：不进仓库，放在 `QA_HOLDOUT_DIR` 指向的私有目录

用例格式见 `scripts/qa/cases/golden/` 下样板。断言只写行为、响应字段、DB 状态，不绑定源码行号。

步骤支持的可选字段：

| 字段 | 用途 |
|---|---|
| `as` / `asAccount` | 用角色或指定账号登录 |
| `companyId` / `companyCode` | B 端跨企业登录（不传用 `.qa.env` 的注册码） |
| `cEnd: true` | 走 `/c/auth/login`（C 端账号） |
| `token` / `tokenFrom` | 用固定 token 或上一步 `save` 下来的 token（游客会话用） |
| `await` | 执行本步前轮询 DB 到终态（等异步任务，如评测批次 / 报告生成） |
| `save` | 把响应字段存进上下文，后续用 `${var}` / DB 里的 `:var` 引用 |
| `expect.uniqueBy` | 列表按字段去重断言，如 `{"data.content":"id"}` |

`await` 与 `dbPoll` 的写法：

```json
"await": { "sql": "select status from evaluation_run where id=:runId",
           "until": ["done"], "maxAttempts": 36, "intervalMs": 5000 }
```

## 失败怎么处理

1. 打开 `summary.md`，看失败用例的期望/实际/证据；
2. 归类：产品 bug / 用例问题 / 环境问题；
3. 产品 bug 记 issue，修复后补一条 `REG-`；
4. 环境问题修环境后重跑，不计入内容失败。

## 代码审核（静态门禁）

`static` 套件在 `qa:quick` / `qa:release` / `qa:nightly` 都会跑，4 项全过才算通过：

| 检查 | 命令 | 抓什么 |
|---|---|---|
| 前端 lint | `npm run lint` | 未使用变量、hooks 依赖 |
| 类型 | `npx tsc --noEmit` | 前后端 DTO 字段错用 |
| 分层架构 | `scripts/check-architecture.sh` | Controller 写 SQL/事务、Service 直连 JDBC |
| 后端单测 | `mvn test`（517 个） | 状态机、权限映射、计分、聚合逻辑 |

发版构建仍是 `-DskipTests`（jar 体积/时长考虑），但**发布前必须过 `qa:release`**，等于把单测和静态检查前置为门禁。

## 已知边界

- 访谈、评测运行需要真实 LLM，默认不跑；`npm run qa:nightly` 会自动开启（不用再手动设 `QA_ALLOW_LLM=1`）。
- 访谈链路会创建真实素材/颗粒/报告，跑完按 runId 清理；单次耗时约 1–3 分钟（含报告合并）。
- 分享链路会创建游客账号，清理脚本按 `source_share_id` 精确删除，不影响真实访客。
- UI 交互用例会通过 API 造培训/知识数据，跑完同样按 runId 清理（`--suite=ui` 也会触发清理）。
- UI 套件依赖 Playwright 和线上账号；没有浏览器时自动 skip。
- AI 回答质量仍走评测中心黄金集，不在本手册范围。
- `qa:release` 默认不跑 LLM；需要完整链路用 `npm run qa:nightly`。
- 门禁目前是「发布前手动」，尚未接进 `deploy-all.sh`；接入前要先解决「不能测旧版本」的问题（见计划评审）。
