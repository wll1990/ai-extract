## 一、总览：一个萃取师的生命周期

```
D3页面[上传] → status=pending → Scheduler抢锁 → AI分析 → status=extracting
                                                              ↓
B2页面[创建访谈时选萃取师] ← status=active ← [激活] ← [提取法则]
```

5 个状态 (pipeline) + 1 个文档级状态 (pending_manual)：`pending` → `analyzing` → `extracting` → `active`（正常）；`failed`（异常可重试）；`pending_manual`（图片/音频待人工处理）（正常）；`failed`（异常可重试）

## 三、分步详解

### 步骤 1：上传

**触发**：D3 页 `UploadExpertModal` → 填写姓名、风格标签、行业标签、资历 → 选择文件 → 点"上传并开始分析"

**调用**：`POST /admin/experts/upload`

**ExpertService.uploadExpertMaterials** 做的事：

```
1. 创建 expert_skill 记录
   - id = UUID
   - name, description, styleTags(JSONB), industryTags(JSONB), seniority
   - status = "pending"          ← 等待调度器
   - locked_by = NULL, locked_at = NULL
   - grainCount = 0

2. 创建 expert_document 记录（每个文件一条）
   - fileUrl = "/data/files/experts/{expertId}/{安全文件名}"
   - 安全文件名规则：
     - 同批次同名 → 经验萃取.docx, 经验萃取_1.docx, 经验萃取_2.docx
     - 跨批次同名 → 磁盘已有则继续递增编号
   - status = "uploaded"
   - parsed_content = NULL       ← 待 AI 解析

3. 返回 expertId + status=pending
```

**不做的事**：不调 AI、不解析文件、不阻塞请求。上传即入库，耗时 < 100ms。

---

### 步骤 2：定时调度

**触发**：`ExpertAnalysisScheduler.scanAndProcess()` — `@Scheduled(fixedDelay=30_000)`，每 30 秒自动执行

**流程**：

```
1. findPendingTasks()
   SQL: SELECT * FROM expert_skill
        WHERE status='pending'
        AND (locked_by IS NULL OR locked_at < NOW() - 5分钟)

2. 逐条抢锁
   tryLock(id, workerId)
   SQL: UPDATE expert_skill SET locked_by=?, locked_at=NOW()
        WHERE id=? AND locked_by IS NULL
   → 返回 1 = 抢到，0 = 被其他 worker 抢走

3. 抢到后 → analyzeMaterials(id)

4. 释放锁
   releaseLock(id)
   SQL: UPDATE expert_skill SET locked_by=NULL, locked_at=NULL
```

**线程安全保证**：`UPDATE WHERE locked_by IS NULL` 是原子操作，多实例同时抢也只会有一个人拿到锁。锁超时 5 分钟自动释放防止死锁。

---

### 步骤 3：AI 分析

**ExpertService.analyzeMaterials(expertId)** 做的事：

```
阶段 A：文件解析
  for each expert_document:
    if parsed_content == NULL:
      调 Python POST /internal/parse-file
        → python-docx 提取 .docx 文本
        → 存回 expert_document.parsed_content
        → 失败则标记 "[文件解析失败: xxx]"

阶段 B：构建提示词
  萃取师元数据: name, description, seniority, styleTags, industryTags
  + 文件内容: 所有 parsed_content 拼接

阶段 C：调用 DeepSeek AI
  System Prompt: "你是萃取师经验分析专家。输出7章JSON报告..."
  120 秒超时

阶段 D：生成报告
  AI 返回内容 → 包装为合法 JSON → 存 report 表 (space_id=NULL)
  → expert.report_id = report.id

阶段 E：更新状态
  expert.status = "extracting"           ← AI 成功
  或 expert.status = "failed"            ← AI 失败（下次扫描重试）
```

**降级策略**：
- 文件解析失败 → 跳过该文件，继续用元数据生成报告
- AI 超时/报错 → status=failed，5 分钟后锁释放自动重试
- 整个方法异常 → status=failed，人工可手动重跑

---

### 步骤 4：提取法则

**触发**：D3 页点击"提取法则"

**调用**：`POST /admin/experts/{id}/extract`

**ExpertService.extractGrains** 做的事：

```
查找关联的 report.contentJson
  ↓
extractGrainsFromReportContent():
  按 7 个类别创建 expert_grain:
    typing_method       → 销冠分类方法
    judgment_intuition  → 追问判断直觉
    mental_model        → 心智模型
    failure_lesson      → 失败经验教训
    validation_method   → 验证方法
    metaphor_framework  → 隐喻框架
    rhythm_sense        → 对话节奏

  每条法则:
    status = "under_review"    ← 待管理员审核
    priority = 1-5
    consensus_type = "single"

  如果没有报告 → generateDefaultExpertGrains() 生成 3 条基础法则

更新 expert.grainCount
更新 expert.status = "extracting"
```

---

### 步骤 5：激活 Skill

**触发**：D3 页审核法则后点"确认入库，生成Skill"

**调用**：`POST /admin/experts/{id}/activate`

**ExpertService.activateExpert** 做的事：

```
1. under_review 法则 → active

2. expert.skill_file = "/prompts/experts/expert_{id前8位}.md"
   expert.status = "active"
   expert.grainCount = 实际法则数

3. @Async regenerateCompositeAsync():
   加载所有 active 萃取师的 active 法则
   → 按 category 分组
   → 比对 application_rule 语义相似度
     - 相似度 > 90% → consensus（共识，优先级+1）
     - 相似度 < 50% 且同场景 → conflict（矛盾，标记注意）
     - 唯一经验 → single（独家）
   → 生成 expert_composite.md
```

---

### 步骤 6：访谈注入

**触发**：B2 创建访谈时选择萃取风格

**注入路径**（`InterviewService.loadInterviewSystemPrompt`）：

| 选择 | 加载逻辑 |
|---|---|
| 综合（默认） | `loadCompositeExpertKnowledge()` → 查所有 active 萃取师 + active 法则 → 拼入 System Prompt |
| 指定萃取师 | `loadExpertKnowledge(expertSkillId)` → 查该萃取师的 active 法则 |
| 基础版 | 不加载任何萃取师经验 |

## 四、数据存储一览

| 数据 | 表/位置 | 关键字段 |
|---|---|---|
| 萃取师 | `expert_skill` | status, locked_by, locked_at, grainCount, reportId |
| 文件 | `expert_document` | fileUrl, parsed_content, status |
| 物理文件 | `/data/files/experts/{expertId}/{文件名}` | 按人分目录，同名 `_1` `_2` 编号 |
| AI 报告 | `report` | content_json(JSONB), space_id=NULL |
| 法则 | `expert_grain` | category(7类), knowledge_content, application_rule, status |
| 综合指令 | `prompts/experts/expert_composite.md` | 自动生成 |

## 五、文件管理操作

| 操作 | API | 效果 |
|---|---|---|
| 追加文件 | `POST /{id}/documents` | 新文件 → 重置 status=pending → 调度器重新处理（v3.4 修复） → 新报告覆盖旧报告 |
| 删除文件 | `DELETE /{id}/documents/{docId}` | 删文件记录 → under_review 法则废弃 → active 法则保留 |
| 替换文件 | `PUT /{id}/documents/{docId}` | 删旧文件+法则 → 上新文件 → 重新分析 |
