## 一、总体结论

P3 四条主链路（补训→重新达标→认证、撤销→重新认证、延期、导出）后端事务与状态机成立。五方问题表原始条目 116 条（同一缺陷常被多方同时点出），去重后 **65 条独立问题**，其中：

- **阻断/高危 7 条**：全部已修复（含 1 条补训永久锁死认证的状态机缺陷、1 条导出下载必然 403）。
- **中危 16 条**：13 条已修复，3 条接受（见第四节）。
- **低危/建议 42 条**：修复 16 条，其余记录为体验增强项或设计取舍。

上线判定：**可上线**（阻塞项清零，回归全绿）。遗留项不涉及数据正确性与权限边界。

## 二、阻断 / 高危（全部已修复）

| # | 来源 | 问题 | 处置 | 验证 |
|---|---|---|---|---|
| H1 | 产品/技术/安全 | 「待认证 → 对选修失败任务补训 → 补训轮再失败」后分配永久停在 `in_progress`，而 `certify` 只接受 `pending_certification`，学员**永久无法认证**，看板还误报必修未完成 | 新增 `TrainingProgressService.reevaluateCertificationState` 单一判定：必修（无必修则全部任务）按「任一通过/豁免」满足**且无未出结论的补训轮**才回待认证；补训创建、任一终态（含失败）都走该判定；`TrainingRecordAggregator.hasUnfinishedRemediation` 提供口径 | `TrainingProgressServiceTest` 新增 2 例；`TrainingRemediationServiceTest` 新增 1 例 |
| H2 | 用户/UI/技术 | 导出 CSV 用 `<a href>` 直连后端，浏览器不带 Bearer，后端也不读 Cookie → 下载**必然 403**，验收 G1/G2 无法完成 | 前端 `downloadExport()`：OSS 有 `downloadUrl` 时跳预签名地址，local 模式带 `Authorization` 取 blob 再保存；页面改为按钮调用 | 接口实测：带 Bearer 下载 200（见执行记录） |
| H3 | 技术/安全 | `TrainingExportService.fail()` 无事务，Worker 在事务外调用 `@Modifying` → `TransactionRequiredException`，失败状态永远写不进去，导出永久 `running` 被反复领取 | `fail` 改为 `REQUIRES_NEW` 独立事务 | `TrainingExportServiceTest` 断言 fail 落库 + 失败通知 |
| H4 | 技术/安全 | `markRead` / `markAllRead` 无事务 → 标记已读接口 500 | 两个方法加 `@Transactional` | 接口实测（见执行记录） |
| H5 | 技术/产品 | `process()` 在事务内先 `fail()` 再抛异常 → fail 随回滚；且 CSV 生成 + 本地写盘/OSS 上传在事务内，违反「事务内禁止文件 IO」红线 | `process` 去掉事务（只查询 + 生成 + 存储），新增 `complete()` 短事务落状态；失败交给 Worker 的 `fail()`（独立事务）；尝试次数上限 `max-attempts` | `TrainingExportServiceTest` 5 例（含租约过期跳过、超限不先 fail） |
| H6 | 产品/UI | 撤销认证后，批次表格与学员端仍渲染绿色「已认证 + 原确认人/时间」，与同页「待认证」自相矛盾 | 前端按 `certification.status` 分支：`confirmed` 绿、`revoked` 红（含撤销人/时间/原因）、其余待确认；学员端补「认证已撤销」说明 | `tsc` + 页面检查 |
| H7 | UI | 编辑任务时切换类型不清 `resourceId/resourceType` → 知识 ID 当分身保存必 404，反向必 400 | 切换类型时重置资源绑定与考试专属字段 | `tsc` + 手工检查 |

## 四、接受项（3 条中危，附理由）

| # | 问题 | 接受理由 |
|---|---|---|
| A1 | `super_admin` 无企业归属时访问培训接口 403 | 培训是**企业域**资源（批次/计划/学员都挂 company），无企业上下文无法做数据隔离；平台级跨企业运维不在本轮范围。评测域的「超管跳过」口径不适用于培训 |
| A2 | 合作方 JWT 的 `?token=` 在任意路径被接受（`query-token.mode` 不生效） | P1 既有设计（嵌入第三方 H5 的长效凭证），权限仅 `c_partner`，无法访问培训/管理接口。收窄需产品确认合作方入口形态，单独排期 |
| A3 | `?token=` 白名单未区分 HTTP 方法，`GET /me/training/attempts/{id}/messages` 历史接口也接受 query token | 历史接口与 SSE 同路径同方法，按方法无法区分；token 仅在本人尝试路径生效且有 `requireLearnerAttempt` 归属校验。后续可改为一次性 ticket |

## 五、低危/体验项处置

已修复：
- 延期弹层预填原截止（提交必 409）→ 默认留空 + 前置校验「晚于当前时间/晚于原截止」。
- 补训弹层未按逾期强制要求新截止、未显示任务标题 → 逾期校验 + 标题 + 红字提示。
- 已认证/已取消分配的「安排补训」按钮仍可点（必 409）→ 按分配状态隐藏。
- 弹层内校验/409 提示被遮罩压住 → Toast 提到 `z-[100]`。
- 学员端看不到补训原因 → 我的培训与任务页渲染 `remediationReason`。
- 成绩页次数用尽无指引 → 显示「次数已用尽，请联系主管安排补训」。
- 认证历史行不显示操作人 → 见 M8。
- 选择器当前绑定资源/导师不在首批选项时下拉空白 → 注入「当前已选」占位项。
- 通知面板只取 8 条、更早未读不可见 → 一次 20 条 +「加载更多」；已读后旧计数响应不再复活红点；点击通知先导航再异步标已读（慢网络不再卡跳转）。
- 阶段名改为空时后端忽略、前端仍提示「已保存」→ 前端拦截空名并提示。
- 筛选无结果仍提示「还没有学员」→ 区分「无匹配」。
- 分页加载中可连点 → 加载中禁用翻页。
- 滞留提醒按每条尝试 × 每个复核人发送（大班刷屏）→ 按批次聚合、同批次同日一条；已裁决的尝试不再提醒。
- 进度分页排序只按 `created_at`（批量分配同值会跨页重复/漏行）→ 补 `id` 兜底。
- 批次看板为取「最早待复核时间」全量加载 attempt 大 JSONB → 改为聚合投影 SQL。
- 滞留扫描 `COALESCE` 使部分索引失效 → 谓词拆分支 + 新增 error 行表达式索引。
- Redis 发言额度 Lua 初始化分支不设 TTL → 初始化带 `EX`，并在 TTL<0 时补设置。

接受/遗留（不影响正确性）：
- 导出 25 列基线未含「当前有效轮/复核人结论文本/原截止」等审计列（可按需追加）。
- 导出 CSV 在内存中构建（上限 10 万行，单实例 batch=3）；后续可改流式。
- 导出文件名使用 jobId 而非批次名。
- 批量分配/取消未写 `admin_audit_log`（docs/54 H6 未要求，建议后续补）。
- 选择器 UI 无「加载更多」，改为「最多 30 条 + 精确搜索」提示（后端已支持分页）。
- `completed` 口径为「任一终态」（设计口径 docs/56 §4.1）。
- 侧栏在窄屏不折叠（B 端管理台以桌面为主）。
- 复核与取消并发时计数可能写到已取消分配（仅数据一致性，低概率）。
- `training_certification.status='remediating'` 为历史设计死状态，无代码写入。
- 多处仍用 `window.confirm`（非本轮引入）。
- 通知列表未按 companyId 过滤（换企业可见历史通知，非越权）。

## 七、执行记录（关键实测）

1. **导出下载鉴权**：带 `Authorization: Bearer` → `200`、464 字节、首字节 `EF BB BF`（BOM）；无 token → `403`。
2. **导出列表隔离**：`GET /admin/training/exports` 只返回 `source_type=training_cohort`。
3. **通知已读**：`POST /me/notifications/{id}/read` → `200 {read:true}`；`POST /me/notifications/read-all` → `200 {updated:4}`（修复前 `TransactionRequiredException` 500）。
4. **认证历史姓名**：`GET /admin/training/assignments/{id}/attempts` 返回
   `confirmed: confirmedByName=P3验收导师`、`revoked: revokedByName=P3验收导师, revokeReason=P3验收：撤销认证验证`。
5. **选择器角色过滤**：默认只返回 `employee/company_admin/super_admin`；`keyword=adm` 正常命中；`role=c_user` → `400 不支持的角色筛选`。
6. **评审修复自身的回归**：首次实机验证发现「`role IN :roles` + 可空 keyword」导致 PostgreSQL 报
   `operator does not exist: character varying ~~ bytea`（JDBC 空参按 bytea 绑定），已用 `CAST(:keyword AS string)` 修复并复测通过 —— 该问题已并入 M7 处置记录。
