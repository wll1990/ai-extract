# 三库使用说明（知识库 / 案例库 / 评测中心）

> 面向：企业管理员、知识运营、销售管理者、一线销售。
> 口径与代码一致：只有「已生效」且未过期的内容会进入分身检索；评测集是尺子，本身不参与回答。

## 0. 三个库是什么关系

| 库 | 存什么 | 回答什么 | 何时被用 | 生效条件 |
|---|---|---|---|---|
| 知识库 | 事实（产品参数、价格政策、合规、竞品、术语、方法论） | 「是什么 / 规定是什么」 | 分身对话、对练之外的所有回答、评测答题 | 审批生效 + 未过期 |
| 案例库 | 一次真实客户推进（画像、异议、原话、动作、话术、结果） | 「这类客户怎么打」 | 同上，作为实战参考 | 审批生效 + 未过期 |
| 评测中心 | 题目 + 期望要点 + 评分规则 | 「分身答得好不好」 | 评测运行、培训考试 | 题集发布版本 |

数据流：

```
上传/录入 → 萃取草稿 → 人工采纳 → 待审核 → 审批生效 → 进入向量索引
                                                   ↓
                                        分身对话 / 评测答题时检索
                                                   ↓
                                        引用日志（被引用次数、最近时间）
```

一句话判断放哪：**能用一句陈述讲清、不随客户变化 → 知识；必须讲「某个客户身上发生了什么」→ 案例。**

### 0.1 不确定放哪时的判断顺序

1. **是事实/规则/参数吗**（价格、审批权限、产品参数、合规要求、行业常识）→ 知识库
2. **是一个客户的推进过程吗**（有对象、异议、动作、结果）→ 案例库
3. **两者都不是**（合同模板、组织架构、培训课件、竞品资料包）：
   - 系统**没有原始文档库**，不会保存「供人查阅的附件」。
   - 分身不需要回答相关内容 → **不要上传**。
   - 分身需要回答 → 只把其中「能独立讲清的事实/条款」拆成知识卡，走知识库上传或「外部提取导入」。
   - **不要走「分身素材上传」**：素材只收销冠的真实销售经历，合同/制度/产品说明/白皮书会被系统拒绝。
4. **行业知识**：分类选「行业介绍」。通用行业认知由平台放公共库；本企业自己的行业打法、客户结构放企业私有

判断不了就先放草稿，不要为了「放对」而卡住。草稿不参与检索，不会污染分身回答。

### 0.2 每个入口的标准与限制（一页看懂）

| 入口 | 收什么 | 不收什么 | 格式 | 单文件 / 正文上限 | 产出与生效 | 溯源 |
|---|---|---|---|---|---|---|
| 分身素材 | 销冠真实对话、心得、访谈、会议转写、CRM 记录 | 教材/书籍原文、产品白皮书、合同、制度、组织架构、广告、纯英文、AI 虚构对话 | pdf/docx/pptx/txt/md/csv/html、png/jpg/jpeg、mp3/wav | 20MB | 经验颗粒，萃取后进入该分身 | 素材文件名 + 上传人 + 时间 |
| 知识库 | 事实/规则/参数/合规/术语/方法论/行业介绍 | 整本书原文、客户故事、一句话便签、版权页/目录/序言 | pdf/docx/txt/md/pptx/csv/html | 20MB；解析后 50 万字；单卡 10–1500 字（书籍 60–600） | 知识卡草稿 → 采纳 → 审批生效 → 向量索引 | 来源文档/书名 + 章节 + 上传任务 + 卡片版本 |
| 案例库 | 一个客户的完整推进过程 | 无结果的片段、占位案例、整本产品说明 | pdf/docx/txt/md/pptx/csv/html | 20MB；解析后 30 万字 | 案例草稿/待审 → 审批生效 → 向量索引 | 来源文档/书名 + 章节 + 上传任务 + 卡片版本 |
| 评测中心 | 题目 + 期望要点 + 评分规则 | — | 手工 / AI 生成 / JSON 导入 | — | 题集发布即冻结版本 | 题集版本 + 依据知识/案例 |

**这不是 Dify 式原文切块 RAG**：上传的文档会被切成片段**仅作为模型输入**，模型产出结构化知识卡；原文分块不落库、不向量化、不参与检索。检索单位是「已审批生效的知识卡/案例卡」，不是原文 chunk。

## 1. 知识库

### 1.1 放什么

- 产品参数、报价政策、折扣审批规则、合同条款
- 合规红线、资质要求、招投标规则
- 竞品对比口径（客观参数，不写主观贬低）
- 术语定义、行业常识
- 方法论步骤（SPIN、BANT 等），一条一个方法

### 1.2 不放什么

- 整本书原文、整章制度原文（会命中不了，也会挤占审核）
- 客户故事、成交过程（放案例库）
- 一句话便签（正文 < 10 字直接拒绝）
- 版权页、目录、推荐序、作者简介
- 过期政策而不标注失效时间

### 1.3 准入标准（系统硬校验）

| 项 | 标准 |
|---|---|
| 标题 | 4–60 字；不能只是「第三章 异议处理」；书籍卡片至少 6 字 |
| 正文 | 普通 ≥10 字（建议 40 字以上）；书籍 60–600 字 |
| 上限 | 普通 ≤1500 字；书籍 ≤600 字（超过请拆条） |
| 分类 | 必须是：合规 / 价格 / 产品 / 政策 / 竞品 / 术语 / 方法论 / 行业介绍 |
| 出处 | 书籍来源必须填「书名 + 章节」 |
| 查重 | 同企业内标题完全相同会跳过（已下架的不算重复） |
| 书籍噪声 | 版权页、目录、序言等直接阻断 |

质量分规则：有具体数字 +10，有适用条件/边界 +10，标题含场景 +10。≥80 绿、60–79 黄、<60 红；有阻断项时不能采纳。

### 1.4 三种录入方式

**A. 手工新增**（少量、口径明确）

1. 知识库 →「＋ 新增知识」
2. 填标题、分类、来源类型、正文、失效时间（必填）
3. 保存为草稿或待审核；审批通过后生效

标题写法：`场景 + 对象 + 结论`，例如「制造业客户说预算未批时先确认决策链」，不要写「预算问题」。

**B. 上传文档萃取**（产品手册、制度文件）

1. 选「企业自有资料」，上传 pdf/docx/txt/md/pptx/csv/html
2. 系统按章节切片后交给模型提炼，逐条产出**知识卡草稿**；原文分块不落库、不参与检索（不会直接进库）
3. 在「萃取结果」里逐条看质量分：绿色可直接采纳；黄色建议补边界；红色有阻断项，必须点「补齐」改完才能采纳
4. 采纳后进入知识库「待审核」，审批生效

**C. 上传书籍 / 课程**

1. 选「书籍 / 课程」，勾选授权确认
2. 系统自动切「方法论卡片」模式：只保留可独立检索的观点，丢弃版权页/目录/序言/叙事段落，每条标 `《书名》 · 章节`
3. 送模型前做强脱敏（公司名/项目名/金额/政府机关一并替换）
4. 单次最多 200 条，超出会提示拆书上传

**D. 外部预提取导入**（想用自己的模型先处理）

1. 「新增知识」→「外部提取导入」，复制页面上的提示词
2. 把提示词和书本章节贴到任意大模型，得到 JSON 数组
3. 把 JSON 贴回页面（或上传 .json），先「校验预览」看每条是否合格，再「确认导入」
4. 导入不绕过审核：合格条目进「待审核」；书籍来源会做强脱敏

同一套规则也适用于案例：案例页的「外部提取导入」会按案例字段校验，书籍案例一律落草稿并标「二手」。

### 1.5 上传限制：几百兆的产品说明怎么处理

| 限制 | 值 | 超出后的行为 |
|---|---|---|
| 单个文件 | 20MB | 上传接口直接拒绝，并提示拆分 |
| 解析后正文（知识） | 50 万字（约 500 页） | 任务失败并给出实际字数和拆分建议 |
| 解析后正文（案例） | 30 万字 | 同上 |

**几百兆的产品说明书不能一次传**，原因不是存不下，而是会被解析成几十万字、触发上千次模型调用，既慢又贵，萃取质量还会下降。正确做法：

1. 按手册 / 产品线 / 章节拆成多个文件，每次传一部分；
2. 或者先在外部模型里按提示词提炼成知识卡片，再用「外部提取导入」批量导入；
3. 扫描版 PDF 如果没有文本层，需要先 OCR（当前解析不保证识别扫描件）。

### 1.6 审核、版本、过期

- **版本链**：已生效条目的每次 AI 改写都会生成新版本；详情页可看版本历史、逐行对比、以任意历史版本生成新草稿（回滚），审批前旧版一直生效
- **审批**：草稿/待审 →「审批」→ 选失效时间（批量审批默认 +1 年）
- **编辑**：草稿/待审可直接改；「AI 改写」按你的指令改内容——草稿/待审**直接覆盖当前条目**，已生效条目会**生成新版本草稿**，审批通过后旧版自动下线
- **AI 改写不是自动排版**：它按你写的修改要求（如「压缩到 300 字」「补充适用边界」）改写内容，不会自动帮你拆条或重新归类
- **过期**：过了失效时间自动停止引用；列表可用「已过期」筛选，续期需编辑失效时间后重新审批
- **下架**：错误或过期内容「下架」，立即停止引用；30 天内可「重新上架」，回到下架前状态
- **彻底删除**：仅草稿/待审/已下架条目可用；删除前校验「无派生版本、无培训任务引用」，通过后物理删除且不可恢复。下架是软状态，彻底删除才是真删除
- **公共库**：企业可「复制」公共知识到本企业再改；企业内容「提交到公共库」会生成公共待审候选（进入公共库前自动强脱敏）
- **溯源**：详情页显示来源文档/书名、卡片版本、创建时间；上传产生的条目可点「查看原始文档」打开 5 分钟有效的下载地址。手工录入、外部导入、公共库复制没有本企业上传任务，只能看到出处文本。

### 1.7 怎么知道有没有用

- 详情页「被引用」：哪些分身引用过、次数、最近时间
- 知识库列表页「检索测试」：输入客户问题，直接看命中的知识和案例、相似度；低于阈值（知识 0.35 / 案例 0.50）不会进入回答
- 检索阈值：知识 0.35、案例 0.50；每次每类最多取 3 条
- 如果一直没被引用：多半是标题太泛、正文没有具体名词/数字，或没有生效

## 2. 案例库

### 2.1 放什么

一条案例 = 一个客户的完整推进过程：

| 字段 | 写什么 | 用途 |
|---|---|---|
| 标题 | 「什么客户 + 什么场景」，如「制造业 500 人客户嫌贵，拆分总拥有成本后签约」 | 检索与列表识别 |
| 客户画像 | 行业 / 规模 / 关键角色 | 检索相似客户 |
| 漏斗阶段 | 线索/首触/需求/方案/异议/报价/追单/成交/复购 | 筛选与检索 |
| 场景标签 | 2–4 字，如「价格异议」「预算冻结」 | 检索加权 |
| 客户原话 | 每行一句真实表述 | 回答时可直接引用 |
| 核心异议 | 客户真正的顾虑 | 检索核心 |
| 情绪变化 | 如「戒备 → 认同」 | 判断推进节奏 |
| 关键动作 | 销售做了什么，分点写 | 可复用打法 |
| 关键话术 | 客户能听到的原句 | 直接复用 |
| 推进节点 | 按时间顺序 | 复盘与培训 |
| 结果 | 赢单 / 丢单 / 搁置（必填才能审批） | 区分打法有效性 |
| 可复用点 / 失败点 | 下次遇到同类客户怎么用 | 检索高频命中区 |

### 2.2 准入标准

阻断（不能审批生效）：

- 标题是「案例一」「示例」这类占位名
- 结果不是赢单/丢单/搁置
- 核心异议、关键动作、关键话术三者全空
- 书籍案例没有出处
- 标题为空或超过 60 字

提醒（可生效，建议补）：缺客户画像、缺客户原话、缺关键动作/话术。

### 2.3 三种录入方式

- **手工新增**：适合最近 3 个成交/丢单，10 分钟一条
- **上传文档萃取**：适合已整理好的案例集；信息不完整的候选会落草稿并标「需补齐」
- **书籍案例**：选「书籍 / 课程」，一律落草稿、标「书籍案例（二手）」、出处标书名章节；采信度低于内部实战案例，补齐后才能审批

### 2.4 审批、版本、检索

- 审批可设失效时间（可选，案例可长期有效）
- 已生效案例不能直接改：「AI 改写」会生成新版本草稿，审批后替换旧版；草稿/待审案例则直接覆盖
- 下架后 30 天内可重新上架；彻底删除不可恢复，且要求无派生版本、无培训引用
- 检索阈值 0.50（比知识更严）：宁可不用，也不要用错案例
- 案例命中时，会带异议/动作/话术/可复用点/失败点进入回答上下文

### 2.5 常见问题

- **案例写了很多但从不被检索**：没填客户画像或场景标签，或标题太泛
- **审批按钮不可用**：看详情顶部红色提示，按提示补齐后重新保存
- **结果选错**：搁置和丢单要分清，否则复盘口径会错

## 3. 评测中心

### 3.1 用途

| 用途 | 什么时候用 |
|---|---|
| 研发回归 | 模型/提示词/知识库变更后，确认老问题没退化 |
| 分身验收 | 新分身发布前，验证回答质量 |
| 培训考试 | 作为培训考核题（当前评测运行与培训任务是两套入口） |

### 3.2 题集生命周期

```
草稿 draft → 提交审核 in_review → 审核通过 approved → 发布 published
                                                        ↓
                                              版本冻结，不可改
                                                        ↓
                                         要改题 → 创建新版本（新草稿）
```

- 发布后生成冻结版本，运行只能选已发布版本
- 被退回时必须写理由，理由会显示在题集详情顶部
- 已退役 retired 用于下线不再使用的题集

### 3.3 不知道问什么？照这三类出题

| 类型 | 例子 | 看什么 |
|---|---|---|
| 事实类 | 「50 万以上报价需要谁审批？」 | 答案能在知识库核对，测事实召回 |
| 异议类 | 「客户说预算没批，这个季度签不了，怎么办？」 | 测分身会不会按案例打法回应 |
| 边界类 | 「能不能承诺 3 天上线并保证效果？」 | 测会不会乱承诺、编造 |

评测中心首页有「用示例题创建一个」按钮，会生成 3 道这类题目（草稿），可直接改完发布后试跑。

### 3.4 题目怎么写

| 字段 | 说明 |
|---|---|
| 问题 | 客户会真实问出口的话，不要写成考试题 |
| 期望要点 | 回答必须覆盖的 2–4 个点 |
| 禁止要点 | 出现即扣分的错误说法 |
| 引用要求 | 是否要求引用知识/案例来源（可空） |
| 评分规则 | 通过/部分通过/不通过的口径（可空） |
| 场景标签 | 便于按场景看短板 |
| 依据 | goldBasis：这条题的参考答案来自哪条知识/案例 |

**AI 生成候选**：可从知识库/案例库自动出题；生成结果会标「AI 生成」，必须人工检查后再发布。生成任务可回看；0 产出时会说明原因（重复/无事实/素材不足）。

### 3.5 跑一次评测

1. 进入「评测运行」→ 新建运行
2. 选题集（必须是已发布版本）、选已发布的分身
3. 后台逐题：生成回答 → 检索证据 → AI 评分 → 状态 `completed/error`
4. 支持取消；取消后未执行题目标记 `cancelled`，不能再用「重试失败题」复活整批
5. 部分题失败时可「重试失败题」，只重跑 `error` 的题

### 3.6 测试过程和结果在哪里看

- 快捷入口：题集详情页顶部「最近测试结果」，列出最近 3 次运行，点「看结果」直接进入
- 全量入口：**评测中心 → 运行与结果**，每一行是一次运行
- 点右侧「看结果」进入详情页，这一页就是完整的测试过程与结果：
  - 顶部计数卡：总题数 / 执行成功 / 执行错误 / 通过 / 未通过 / 未判定
  - 均分、检索指标（Recall@K、Precision@K、MRR）、token 用量
  - 逐题表：题目、执行态、结论、最终分
- 点单题「看回答」：AI 实际回答、检索到的知识/案例证据、AI 评分与理由、失败原因
- 执行中的运行每 3 秒自动刷新，可以离开页面稍后回来
- 定稿后的报告显示在详情页顶部，可导出 Markdown，刷新页面自动加载

### 3.7 复核与定稿

- 逐题看：问题、AI 回答、检索证据、AI 分、失败原因
- 复核动作：确认 / 调整分数 / 无法判断（必须写理由）
- **最终分 = 人工改分优先，否则取 AI 原分**；表格会标「人工」
- 全部复核完 → 定稿 → 生成报告（可导出 Markdown）
- 刷新页面会自动加载已定稿报告

### 3.8 对比与趋势

- 版本对比：同题集同版本可逐题比较分数与结论；版本不同只比较公共题目，不直接相减总分
- 对比页也显示最终分（人工优先）
- 同一题集多次运行可看均分与通过率变化；模型变更前后各跑一次即可对照

### 3.9 失败题 → 补内容

运行详情里失败/未通过的题可以直接「补知识 / 补案例」，系统会预填题干、AI 回答和引用证据，跳到新建页。补完生效后，重新跑一次同题集即可验证是否改善。

## 5. 问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 分身回答没有引用知识 | 知识未生效 / 已过期 / 相似度低于 0.35 | 检查状态与过期时间；标题补场景，正文补具体数字 |
| 案例从不被检索 | 相似度低于 0.50 / 缺画像与场景标签 | 补客户画像、场景标签、客户原话 |
| 审批按钮不可用 | 案例有准入阻断项 | 看详情红色提示，编辑补齐后保存 |
| 批量审批失败条目 | 失效时间为空（旧版问题） | 批量审批默认 +1 年；单条可手动设 |
| 上传后没有产出 | 全是版权页/目录/叙事段落，或与既有内容重复 | 看任务「已跳过 N 条」与处理说明；书籍建议按主题拆 |
| 草稿不能采纳 | 质量分低且有阻断项 | 点「补齐」修改标题/正文/分类/出处，保存后重试 |
| 评测运行没有题目 | 题集没有已发布版本 | 发布版本后再新建运行 |
| 复核后分数没变 | 看的是 AI 分列 | 看「最终分」列，人工改分优先 |
| 对比页不能相减总分 | 题集或版本不同 | 只比较公共题目，分别看各自均分 |

## 6. 一句话记住

- 知识回答「是什么」，案例回答「怎么打」，评测回答「打得好不好」。
- 只有生效且未过期，才会被分身看见。
- 标题写场景、正文给结论、案例留原话，命中率就上来了。
- 公共库和书籍内容会自动强脱敏；企业内部保留客户公司名与金额。
