# 知识 / 案例 / 评测 / 内容工厂 · 按钮级操作手册

> 面向：知识运营、销售管理者、企业管理员、平台超管。
> 目的：把每个按钮「点下去会发生什么、什么时候该用、有什么坑」讲清楚。
> 销售复盘/线索/跟进任务/教练台账/培训的按钮说明见 [74-销售模块按钮级操作手册](74-销售模块按钮级操作手册.md)。
> 依据：以当前代码为准（2026-11-17 核对），文末列出与旧文档不一致的地方。

---

## 0. 先读这 7 条

1. **AI 按钮只产草稿**：内容工厂/AI 改写生成的 Knowledge、Case 都是 `pending`，考题是 `draft`。草稿不参与检索、不能进考试，必须人工通过。
2. **审核 ≠ 立刻可检索**：审核只是把状态改为 `active`，向量化是异步的；要等详情页/列表的索引徽标变成 `indexed`，分身才可能命中。新版要等索引成功后才把旧版下线。
3. **下架不是删除**：下架只改状态，30 天内可恢复；彻底删除不可恢复，且有派生版本/培训引用时会被拒绝。
4. **同一个「生成」按钮有每日去重**：同企业 + 同场景 + 同信号当天只生成一次；失败可再点重试，成功要等第二天或换信号。
5. **权限决定你能看到哪些按钮**：知识/案例管理需要 `KNOWLEDGE_MANAGE`，评测管理需要 `EVAL_MANAGE`，复核/定稿需要 `EVAL_REVIEW`；员工只有提交权，看不到这些管理页。
6. **页面按流程组织**：知识库/案例库/评测中心顶部先是指标条（总数/待审/索引失败/公共库，或题集/已发布/待审/运行记录），点数字直接筛选；下面是一行四步流程（录入 → 审核 → 确认可检索 → 维护/运行），每一步直接可点；再下面是统一工具栏（搜索 + 筛选）。列表行内高频操作收进「更多」菜单，详情页按钮按「主操作 → 内容工具 → 生命周期」分组，不再是一排同权重按钮。检索测试仍是「诊断模式」：低于阈值的近失命中也会列出并标「未达阈值」。
7. **谁审核**：员工只能提交（`KNOWLEDGE_SUBMIT`）；企业管理员/平台超管（`KNOWLEDGE_MANAGE`）审核，允许审自己提交的内容，没有「指定审核人」。AI 待审视图不是第二套流程：它只筛出带生成任务的待审记录，通过/丢弃走同一条审核链路（考题需 `EVAL_MANAGE`）。

## 1. 知识库

### 1.1 列表页

页面从上到下：标题 + 右上角操作（使用说明 / 检索测试 / 上传文档萃取 / ＋新增知识）→ 指标条（知识总数 / 待审 / 索引失败 / 公共知识，点数字直接筛选）→ 四步流程 → 工具栏（搜索 + 筛选）→ 列表。行内只保留高频操作，其余收进「更多」。

勾选任意一条后，列表上方会出现**批量操作条**：已选 N 条 / 批量通过 / 批量重建索引 / 改分类为… + 应用 / 批量下架 / 取消选择。公共知识会提示只读并自动跳过；翻页或换筛选会清空选中，避免误操作上一页的行。

| 按钮 | 点下去发生什么 | 什么时候用 | 注意 |
|---|---|---|---|
| ＋ 新增知识 | 打开手工录入页 | 少量、口径明确的事实/规则 | 超管未切换企业视角时，创建的是**公共知识**（`company_id=NULL`） |
| 上传文档萃取 | 打开上传页签，按章节提炼知识卡 | 产品手册、制度、书籍 | 只产草稿，不会直接生效；原文分块不落库、不参与检索 |
| 检索测试 | 用一句话做向量检索，返回命中与相似度 | 排查「分身为什么没引用」 | **知识与案例各测各的**：知识库页只测知识，案例库页只测案例；只读，不写引用日志；**诊断模式**：低于线上阈值的近失命中也会列出并标记「未达阈值」；线上阈值知识 0.45、案例 0.50；向量服务不可用返回 503 |
| 企业私有 / 公共知识 | 切换列表范围 | 区分自有内容与平台公共库 | 公共内容只读，要改先「复制」到本企业 |
| 复选框 / 全选本页 | 进入批量模式 | 集中清理待审 | 只选当前页，不跨页 |
| 批量通过 | 逐条审核，返回成功/失败明细 | 集中清理待审 | 单条失败不中断整批；已有失效时间的会原样保留，可能「审核即过期」 |
| 批量重建索引 | 逐条异步重跑 embedding | 批量修复索引失败 | 只有 active 能成功，其余进失败列表 |
| 批量改分类 | 只改分类，不动标题/正文 | 历史分类纠偏 | 写编辑历史与审计 |
| 批量下架 | 逐条置 `deprecated` | 批量止损 | 30 天内可恢复 |
| 筛选（分类/来源/状态/关键词） | 重新拉列表 | 定位内容 | 「已生效」筛选会排除过期；「已过期」只看过期 |
| 「AI 生成」开关 | 只看 AI 生成的草稿/条目 | 集中处理 AI 产出 | 仅筛选 |
| 待我审 N | 切到 `pending` 筛选 | 快速进待审队列 | N 是当前范围 pending 总数，不是按审核人分配 |
| 行内「审核」 | 有失效时间直接审核；没有则弹日期对话框 | 让知识开始被检索 | 知识**必须**有失效时间；质量门禁不过会 400；通过后等索引 |
| 行内「复制」（公共 Tab） | 生成本企业 pending 副本 | 把平台公共知识本地化 | 后端只允许复制 active 公共内容；复制品不含原始上传任务，看不到原文 |
| 行内「重建索引」 | 异步重跑向量 | 修索引失败/换模型后 | 只有 active；不产生新版本 |
| 行内「AI 改写」 | 调模型改写；草稿/待审**原地覆盖**，已生效生成新版本草稿 | 压缩、补边界、改口径 | 同步等模型；新草稿不写向量，仍需审核；下架条目在详情页也能改写 |
| 行内「下架」 | 立即置 `deprecated`，分身立刻不再命中 | 错误/过期内容止损 | 30 天内可恢复；不删向量 |
| 行内「更多」 | 展开审核、AI 改写、重建索引、下架等低频操作 | 列表保持可读，避免一排按钮 | 与详情页动作一致，权限不足时不显示 |
| 公共 Tab 的写操作 | 企业账号不显示下架/AI 改写/审核 | 防止跨企业修改公共内容 | 后端同样 403；只能「复制到本企业」 |

### 1.2 新增页 / 上传 / 外部导入

| 入口 | 说明 | 注意 |
|---|---|---|
| 手工录入 → 保存 | 标题、正文、失效时间必填；按所选状态落库 | 状态下拉允许直接选「已生效」，等于绕过审核，谨慎授权 |
| 文档上传 → 企业自有资料 / 书籍课程 | 决定脱敏级别与卡片形态 | 书籍模式上限 200 条；书籍必须勾「授权确认」 |
| 开始萃取 | 立即返回 taskId，后台按章节提炼，前端每 3 秒轮询 | 文件本身只用于解析，不进库 |
| 上传任务进度 | 展示章节进度、失败章节数、跳过数 | 部分章节失败时任务仍可能 `done`，需要手工补录 |
| 续传 / 重试 | 从断点章节继续，不重做已完成章节 | 已完成任务、正在萃取、缺文件路径会被拒绝 |
| 采纳选中 / 全部采纳 | 把合格草稿转成 `pending` 知识 | 有准入阻断的草稿不能采纳，先「补齐」 |
| 拒绝选中 | 草稿置 `rejected`，不进知识库 | — |
| 补齐 / 编辑 → 保存 | 改标题/正文/分类/出处并重算质量分 | 已采纳/已拒绝不可改 |
| 外部导入 → 复制提示词 / 下载 .md | 把提示词拿去外部模型产出 JSON | — |
| 校验预览 | 只校验不落库，返回可导入/跳过原因 | 标题重复、缺正文/分类、未达准入会跳过 |
| 确认导入 | 逐条落库为 `pending` | 单次最多 200 条；仍需审核 |

### 1.3 详情页

| 按钮 | 点下去发生什么 | 注意 |
|---|---|---|
| 编辑 | 打开编辑页，全量替换字段 | 只有 draft/pending 能编辑；已生效要走「AI 改写→新版本」 |
| 通过并生效 | 置 active 并异步写向量 | 必须有失效时间；索引成功后才下线旧版 |
| AI 改写 | 生成/覆盖草稿并跳转 | 可先让 AI 给建议，再写修改指令 |
| AI 体检 | 确定性检查：重复标题、过短、过期、缺字段、不可检索，列相似条目 | 只读，不调模型、不落库 |
| AI 派生 | 点击先确认；知识生成评测题 + 场景微练，案例生成知识卡 + 评测题 + 场景微练 | **结果不自动入库**，只能在弹窗里按提示复制到对应页面；反复点会反复烧 token（无去重）。知识不再派生 FAQ 回知识库，避免重复条目 |
| 重建索引 | 异步重跑 embedding | 只有 active |
| 提交到公共库 | 新建 `company_id=NULL` 的 pending 候选，全部强脱敏；原条目不变 | 公共候选要平台超管审；候选继承原失效时间，可能提交即过期 |
| 放弃草稿 | 软丢弃为 deprecated；有原版则跳回原版 | 不是删除，30 天内可恢复 |
| 下架 | 停止检索，记录原状态 | 会提示引用数，便于评估影响 |
| 重新上架 | 恢复下架前状态；若同链已有 active 则回到 pending | 超过 30 天 409 |
| 彻底删除 | 物理删除 | 只有非 active 可删；有派生版本/培训引用会 409；不可恢复 |
| 查看原始文档 | 取 5 分钟预签名地址打开原文 | 手工录入/外部导入/公共复制的条目没有上传任务，会 404 |
| 版本历史 → 查看 | 打开历史版本 | 只读 |
| 版本历史 → 以此版本修改 | 以旧版为内容生成 `version+1` 的新草稿 | 不直接生效，需审核 |
| 查看原版本 / 差异对比 | 逐行 diff（绿增红删） | 纯展示 |
| 被引用 | 最近 30 天哪些分身引用、次数、最近时间 | 判断价值与下线影响 |

## 2. 案例库

与知识库基本同构，差异如下。案例列表同样有指标条（案例总数 / 待审 / 索引失败 / 公共案例）、四步流程、搜索+筛选工具栏；企业账号看公共案例只读，先「复制到本企业」再改。勾选案例后同样出现批量操作条（批量通过 / 批量重建索引 / 批量下架 / 取消选择），当前页最多 20 条，逐条执行并汇总失败原因。

| 场景 | 知识库 | 案例库 |
|---|---|---|
| 准入核心字段 | 标题、正文、分类、出处、失效时间 | 标题、结果（赢单/丢单/搁置）、核心异议、关键动作/话术、客户画像、客户原话 |
| 审核是否必须有失效时间 | **必须** | 不必须（案例可长期有效；前端默认给 12 个月） |
| 批量操作 | 有（通过/下架/改分类/重建索引） | 有（通过/下架/重建索引）；案例没有「改分类」，前端按当前页逐条调用，失败项会汇总 |
| 上传萃取产物 | 先落草稿，人工「采纳」后才进知识库 | 没有草稿预览：合格内部案例直接 pending；书籍/不达标直接 draft 待补齐 |
| 详情特有 | 分类、出处 | 客户画像、客户原话、情绪变化、推进节点、可复用点、失败点、二手标记 |

案例独有按钮/入口：

| 按钮 | 说明 | 注意 |
|---|---|---|
| 结果下拉（赢单/丢单/搁置） | 决定案例类型与准入 | 只接受 win/loss/delay |
| 客户画像三字段 | 行业/规模/关键角色，拼成 JSONB | 不填会降低检索命中率 |
| 客户原话 | 每行一句，拼成 JSON 数组 | 回答时可直接引用 |
| 去补齐 | 质量阻断项存在时跳到编辑页 | 不补齐不能审核通过 |
| 复制到本企业 | 公共案例生成本企业 pending 副本 | 后端只允许 active；超管需先切企业视角，否则目标企业为空会 400 |

## 3. 公共库与共享

| 机制 | 入口 | 发生什么 | 注意 |
|---|---|---|---|
| 企业内容提交公共库 | 知识/案例详情「提交到公共库」 | 新建公共 pending 候选，强脱敏，原条目不变 | 仅已生效内容可提交；平台超管通过后才生效 |

## 4. 评测中心

### 4.1 题集

评测中心列表：指标条（题集总数 / 已发布 / 待审核 / 运行记录）→ 紧凑流程（建题集 → 提交并发布 → 新建运行 → 复核与定稿）→ 工具栏（题集搜索 / 搜索 / 筛选）。搜索和状态筛选默认收进「筛选」，不再一进页面铺一排下拉框。

| 按钮 | 点下去发生什么 | 前置条件 | 注意 |
|---|---|---|---|
| ＋ 新建题集 | 建 draft 题集 + v1 草稿版本，跳详情 | 名称、用途必填 | 用途在提交审核后不可改 |
| 用示例题创建一个 | 建 acceptance 题集 + 3 道销售异议题 | — | 4 个请求非事务；示例题直接 active，不经过 AI 审核 |
| 编辑 / 保存信息 | 改名称、描述、用途（带版本乐观锁） | 仅 draft | 版本冲突 409，刷新重试 |
| 提交审核 | 校验后 draft → in_review | 仅 draft；不能有 AI 草稿题；至少 1 道 active 题；用途字段要齐 | 有草稿题会被拦：「还有 N 道 AI 草稿题未审核」 |
| 通过 / 退回 | in_review → approved / draft | 仅 in_review；退回理由必填 | 退回理由显示在详情顶部 |
| 发布 | approved → published，冻结当前版本 | 仅 approved | 发布即冻结；只统计 active 题。列表页发布无二次确认，建议在详情页发布 |
| 新版本 / 创建新版本 | 复制当前 active 题到 v+1 草稿，题集回到 draft | 仅 published | v1 仍冻结可运行，但题集会从「新建运行」的已发布下拉里**消失** |
| 复制 | 复制公共模板最新的**已发布版本** | 仅公共模板 | 后端还要求模板有已发布版本；超管复制出来仍是公共模板 |
| 版本下拉切换 | 只读查看历史版本 | 版本数 > 1 | 历史版本不能编辑 |
| 最近测试结果 | 列出该题集最近 3 次运行 | — | 快捷跳运行详情 |
| 删除题集 / 退役 | **代码未实现** | — | 不要按旧文档操作；目前只能不发布/不使用 |

### 4.2 题目与 AI 出题

| 按钮 | 点下去发生什么 | 前置条件 | 注意 |
|---|---|---|---|
| ＋ 添加题目 | 新增 active 题，orderNo 自动 +1 | 仅题集 draft | 手工题不经过 AI 待审 |
| 编辑 / 删除 | 改题 / 删题 | 仅题集 draft；删除要求未被任何运行引用 | 被引用过返回 409：请新建版本改题 |
| AI 生成候选（弹层） | 从勾选的知识/案例生成候选题 | 题集 draft，至少选 1 个来源 | 候选题是 **active**，不进 AI 待审视图；0 产出会说明重复/缺事实数量 |
| 从失败信号出题 | 按场景把真实失败题转成新题 | 题集 draft；有失败信号 | 异步任务，最多 5 道 `draft`；同题集+同场景+同日只一次；产出会阻塞提交审核，必须先审 |
| AI 题目分析 | 看难度、区分度、争议率、是否跑过 | 只读 | 没有运行数据时显示暂无 |
| 处理 AI 草稿题 | 切到「待处理」筛选并滚到题目区 | 存在 draft 题 | 有草稿题时不能提交审核；题目行有底色和行内「通过 / 丢弃」；顶部提示按钮会自动切筛选 |
| 题目筛选（全部/待处理/已生效） | 只过滤题目列表 | — | 默认「全部」；有待处理题时优先看「待处理」 |
| 题集内导入 JSON / 外部提取导入 | **代码未实现** | — | 外部提取导入只在知识/案例有 |

### 4.3 运行

| 按钮 | 点下去发生什么 | 前置条件 | 注意 |
|---|---|---|---|
| ＋ 新建运行 | 建批次 + 逐题 pending，Worker 异步答题评分 | 题集 published 且所选版本 published；个体分身已发布；有企业归属；用途仅 regression/acceptance | 双击只建一个批次；组织分身不支持；super_admin 无企业归属不能建；training 用途会 400 |
| 版本下拉 | 选要跑的冻结版本 | 只列 published 版本 | 不选时默认 `currentVersion`；刚建新版本时它是草稿版，会报「仅已发布版本可运行」 |
| 看结果 | 进运行详情 | — | 运行中也能进，页面会轮询 |
| 取消 | 标记 cancel_requested，Worker 收尾为 cancelled | 仅 queued/running | 取消后不能重试失败题；通常无法定稿 |
| 重试失败题 | 只给 `status=error` 的题新建一次 attempt，批次重新排队 | 终态且 errorItems>0，且未取消 | 低分（fail）不能靠重试刷分；只处理执行失败 |
| 逐题「看回答」 | 打开抽屉：回答、检索证据、指标、规则检查、AI 评分、复核历史 | — | 单题取最新 attempt |
| AI 评分 | 无按钮，自动执行 | Worker | 不能手动重跑 AI 评分；评分失败算 error，可重试 |
| 与上次批次对比 | 看基线→本次均分、提升/下降/翻盘、逐题变化 | 有已完成基线 | 后端默认基线**不按分身过滤**，可能拿到同题集另一个分身；要严格同分身请用「再跑一次」 |
| 再跑一次并对比基线 | 异步新建同题集/同分身批次并跳转 | 有历史批次 | 幂等键按小时分桶，1 小时内只建一个；无历史时本次作为基线 |
| 计数卡 / 检索指标 | 总题数、成功、错误、通过、未通过、未判定、均分、Recall/Precision/MRR、tokens | 只读 | 批次级检索指标要定稿后才写入；超 200 题只显示前 200 |
| 补一条知识 / 补一个案例 | 跳新建页并预填题干/异议 | 单题 fail 或 error | 只是预填，生效仍需审核 |
| 错题补知识（promote-issues） | 最多 3 道错题各生成 1 条 pending 知识草稿 | 批次有未通过/失败题 | 只生成知识，不生成案例；同批次+同日只一次 |

### 4.4 复核、定稿、报告

| 按钮 | 说明 | 注意 |
|---|---|---|
| 确认 AI 结论 | 追加一条复核记录，结论不变 | 理由必填；会把批次拉回待复核 |
| 改分 | 人工分 0-100，按 60 分阈值重新判 pass/fail | 人工分优先；原分保留；会拉回待复核 |
| 无法判断 | 结论置 undetermined | 计入未判定，不计通过/失败 |
| 提交复核 | 提交后刷新单题与批次 | 失败在抽屉内提示 |
| 复核历史 | 看动作、时间、理由、改分 | 审计用 |
| 定稿出报告 | 重算计数/均分、聚合检索指标、生成报告版本+1 | 需终态、无未完成题、`need_review` 的题都已复核；已定稿再点只返回当前报告 |
| 已定稿报告自动加载 | 刷新页面自动显示 | 没有报告不阻塞页面 |
| 导出 Markdown | 浏览器本地下载 | `report.content` 为空会导出空文件 |

## 5. 内容工厂

### 5.1 生成入口

| 按钮 | 点下去发生什么 | 注意 |
|---|---|---|
| 查看 AI 待审（主操作） | 跳 AI 待审视图 | 只列 AI 生成且待审的记录；日常主入口 |
| 知识库待审 / 案例库待审（次级） | 跳知识/案例库并带 `pending` 筛选 | 这里含人工录入的 pending，AI 待审视图只含 AI 生成 |
| 刷新（弱操作） | 同时刷新「内容需求 / 看板 / 最近任务」三块 | 没有单独的「刷新信号」按钮；处理完待审后用它恢复生成按钮 |
| 生成知识草稿 | 建异步 job，1.5s 轮询，成功产出 1 条 pending 知识草稿并跳 AI 待审 | 有 AI 知识草稿待审时按钮置灰并显示「知识待审 N 条」；后端 409。置信度 <0.3、同标题已存在会失败；同场景同信号当天已成功会 409 |
| 生成案例草稿 | 同上，产出 1 条 pending 案例草稿 | 有 AI 案例草稿待审时按钮置灰并显示「案例待审 N 条」；结果必须是 win/loss/delay；同标题已存在会失败 |
| 生成中… | 当前行按钮禁用 | 防双击；后台仍有并发去重兜底 |
| 待审提示条 | 顶部显示「还有 N 条 AI 知识/案例草稿待审」并提供「去处理」 | 处理完待审内容后回页面点「刷新」，生成按钮才恢复 |
| AI 派生（知识/案例详情） | 异步生成评测题/微练（案例另含知识卡），只弹窗展示 | 点击先确认；**不落库、不去重**，反复点会重复消耗模型；复制按钮有「已复制」反馈和粘贴位置提示 |
| 错题补知识（运行详情） | 最多 3 道错题生成知识草稿 | 只生成知识；同批次同日只一次 |

### 5.2 生成任务与去重

- 任务列表只读：类型、来源、状态、产出数、时间、失败原因；**没有详情/重试按钮**。失败后回到原场景再点一次「生成」即重试。
- 同一键当天成功过会 409；失败任务可当天重试；运行中的任务再点会 409。
- 卡住超过 30 分钟的 `running` 会在下次建任务时被自动标记失败。
- 去重键：
  - 知识/案例：`kind|场景|日期|信号指纹`
  - 考题：`eval|题集|场景|日期`
  - 错题回流：`promote|运行|日期`
  - 派生：无去重

### 5.3 看板口径（别被数字误导）

| 指标 | 实际口径 | 注意 |
|---|---|---|
| 近 30 天生成任务 | 所有生成任务行数 | 含派生、错题回流，不等于草稿数 |
| 产出草稿 | 所有任务 `producedCount` 求和 | **派生任务也算 1，但它不落草稿**，口径偏大 |
| 待审知识 / 待审案例 | 全部 status=pending | 含人工录入，与AI 待审视图「只看 AI」不同 |
| 开放知识缺口 | `knowledge_gap.status=open` 条数 | 与缺口被问次数不是同一个数 |
| 成功 / 失败 | 30 天内 done / failed 任务数 | running 两边都不算 |
| 采纳-生成 / 通过 / 丢弃 | 30 天内 AI 生成条目，按 `review_outcome` 统计 | 通过后被新版取代不算丢弃 |
| 采纳-待审 | 生成 − 通过 − 丢弃（下限 0） | 是窗口内减法，不是当前 pending |
| 通过率 | 通过 /（通过 + 丢弃） | **待审不进分母**，刚生成很多时通过率会失真 |
| 平均审核时长 | 只统计已审核样本 | 未审核不参与 |
| AI 考题数 | 接口有，前端未展示 | 看考题量请进题集详情 |

## 8. 文档与实现不一致（以本手册为准）

1. `docs/72` 写「评测中心支持手工 / AI 生成 / JSON 导入」——**题集 JSON 导入未实现**；外部提取导入只在知识/案例有。
2. `docs/72` 暗示题集可删除/退役——**代码没有题集删除、退役入口**；`retired` 只有常量和校验，运营无法到达。
3. 评测「AI 评分」不是按钮，Worker 自动执行；人工只能复核/改分，不能重跑 AI 评分。
4. 运行详情「与上次批次对比」默认基线不按分身过滤，可能拿到同题集另一个分身；严格回归用「再跑一次并对比基线」。
5. 内容工厂「产出草稿」把派生任务算进去；「待审」包含人工 pending；「通过率」不含待审。
6. 知识审核在AI 待审视图默认给 1 年有效期；列表/详情的单条审核若没有失效时间会弹日期，批量审核会保留原失效时间（可能已过期）。

## 9. 最容易踩的 12 个坑

1. 审核完立刻去问分身，发现没命中——向量还没 index 完，等索引徽标变绿。
2. 批量通过后内容直接过期——原失效时间已过；批量不会重置。
3. AI 改写后以为已生效——已生效条目会生成新草稿，还要再审核。
4. 题集建了新版本，新建运行里找不到它——题集主状态变 draft；要显式选旧发布版。
5. 题集有 AI 草稿题就提交审核——会被 400 拦住，先去AI 待审视图通过/丢弃。
6. 以为低分题可以「重试失败题」刷分——重试只处理执行 error，不处理 fail。
7. 定稿后改分，发现报告没变——复核会把批次拉回待复核，需要重新定稿生成新报告版本。
8. 反复点「AI 派生」——派生不落库、不去重，每次都消耗模型额度；知识来源不再产 FAQ。
9. 同一天重复点「生成知识」——同日同信号成功过会 409，失败才可以重试。
10. 有 AI 草稿待审还想继续生成——按钮会置灰显示「知识待审 N 条 / 案例待审 N 条」，后端也会 409；先处理待审再刷新。
11. 题集有草稿题就点提交审核——会被拦住；到题目区切「待处理」，逐题通过/丢弃。
12. 在公共 Tab 直接改公共内容——company_admin 会被 403，只能复制到本企业再改；前端也不会显示写按钮。

## 10. 日常动作清单

**知识运营（每周 30 分钟）**
1. 内容工厂 → 刷新 → 看开放缺口 Top，选 3–5 个场景「生成知识/案例草稿」。
2. AI 待审视图处理 AI 草稿：通过或丢弃（写清原因）。
3. 知识库筛选「已过期」：续期或下架；看被引用 Top10 与 0 引用高价值内容。
4. 抽查索引徽标：`failed` 的点「重建索引」。

**销售管理者（每两周）**
1. 评测中心选已发布题集新建运行，跑一次当前分身。
2. 运行详情看失败题 → 「错题补知识」或「补一个案例」。
3. 补完内容、通过并生效后，用「再跑一次并对比基线」验证是否改善。

**平台超管（每月）**
1. 公共 Tab 审核企业提交的公共候选；处理重复/过期公共内容。
2. 抽查采纳率与平均审核时长，识别长期不过审的 AI 产出。
3. 审核公共模板的复制情况，必要时更新模板并发布新版本。
