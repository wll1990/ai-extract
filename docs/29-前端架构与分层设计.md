## 三、分层架构

```
┌─────────────────────────────────────────────┐
│  页面层 (app/)                               │
│  只负责 UI 渲染 + 路由跳转                    │
│  禁止直接 fetch，禁止硬编码业务逻辑           │
└──────────────┬──────────────────────────────┘
               │ 调用
┌──────────────▼──────────────────────────────┐
│  API 层 (lib/api/)                           │
│  每个模块对应一个后端 Controller              │
│  统一通过 client.ts 发请求，自动注入 JWT      │
└──────────────┬──────────────────────────────┘
               │ 使用
┌──────────────▼──────────────────────────────┐
│  组件层 (components/)                        │
│  可复用 UI 单元，无业务逻辑                   │
│  接收 props，渲染视图                        │
└──────────────┬──────────────────────────────┘
               │ 依赖
┌──────────────▼──────────────────────────────┐
│  工具层 (lib/)                                │
│  storage/sse/logger/constants/theme.tsx      │
│  纯函数，无副作用，可被任何层使用              │
└─────────────────────────────────────────────┘
```

## 四、核心设计原则

### 4.1 页面不直接 fetch

```typescript
// ❌ 错误：页面内直接 fetch
const res = await fetch('/api/v1/skills/list');

// ✅ 正确：走 API 模块
import { listSkills } from '@/lib/api/skill';
const data = await listSkills(1, 20);
```

### 4.2 导航根据角色过滤

```typescript
// AppLayout.tsx
const NAV_ITEMS = [
  { label: '分身管理', path: '/admin/skills', roles: ['super_admin'] },
  { label: '销冠访谈', path: '/interview/create', roles: ['super_admin', 'employee'] },
];
const visibleNav = NAV_ITEMS.filter(item => item.roles.includes(role));
```

### 4.3 管理后台不隔离 Layout

所有 `/admin/*` 路由共用 `AppLayout`，权限靠后端 RBAC（403 拦截），不搞前端路由守卫。

### 4.4 API 客户端统一管理

```typescript
// lib/api/client.ts
export async function apiClient<T>(path: string, options?: RequestInit): Promise<T> {
  const token = getToken();
  const res = await fetch(`${API_BASE}${path}`, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options?.headers,
    },
  });
  const data = await res.json();
  if (data.code !== 200) throw new Error(data.message || '请求失败');
  return data.data as T;
}
```

## 五、MindSmith 设计规范

### 5.1 主题架构（Token 三层架构）

```
┌────────────────────────────────────────────────────┐
│ 第1层: globals.css CSS 变量定义                     │
│   :root / .theme-dark / .theme-claude 三套变量       │
├────────────────────────────────────────────────────┤
│ 第2层: tailwind.config.js 变量引用                  │
│   colors: { primary: 'var(--primary)', ... }       │
├────────────────────────────────────────────────────┤
│ 第3层: 页面组件使用语义 Tailwind 类                 │
│   bg-primary text-foreground border-border          │
└────────────────────────────────────────────────────┘
```

主题切换由 React Context 驱动：

```tsx
// src/lib/theme.tsx — ThemeProvider + useTheme hook
// src/components/ui/ThemeToggle.tsx — 三主题切换按钮组

// Light（默认）: :root 定义变量，不加 class
// Dark（专注）: html 上加 .theme-dark
// Claude（人文）: html 上加 .theme-claude
```

主题持久化 key：`mindsmith-theme`（localStorage）。

## 八、部署与构建

### 8.1 本地开发

```bash
cd frontend && npm run dev
```

next.config.js 中 `rewrites` 将 `/api/v1/*` 代理到 `http://localhost:8080/api/v1/*`，开发时前后端同域，无 CORS 问题。

### 8.2 API 地址配置

API 基础路径由环境变量 `NEXT_PUBLIC_API_BASE_URL` 控制，默认值为 `/api/v1`（相对路径）。

```typescript
// lib/api/client.ts
const API_BASE = process.env.NEXT_PUBLIC_API_BASE_URL || '/api/v1';
```

### 8.3 同域部署（推荐）

前后端部署在同一域名下，通过 Nginx 反向代理分流。

```
                 浏览器
                   │
            https://yourdomain.com
                   │
              ┌────┴────┐
              │  Nginx  │
              └────┬────┘
              /    │    /api/*
          前端静态   │   后端 :8080
```

| 配置项 | 值 |
|--------|-----|
| `.env.production` | `NEXT_PUBLIC_API_BASE_URL=/api/v1` |
| Nginx | `location /api/ { proxy_pass http://backend:8080/api/; }` |
| 后端 CORS | **不需要配置** |

**优点**：零 CORS 配置，无跨域问题，最安全。

### 8.4 跨域部署

前后端部署在不同域名/服务器上。

```
  浏览器 → https://app.yourdomain.com
       ↓ fetch('https://api.yourdomain.com/api/v1/...')
  浏览器 → https://api.yourdomain.com
```

| 配置项 | 值 |
|--------|-----|
| `.env.production` | `NEXT_PUBLIC_API_BASE_URL=https://api.yourdomain.com/api/v1` |
| 后端 CORS | **必须配置**（见下方） |

**后端 CORS 配置（Spring Boot）**：

```java
// SecurityConfig.java 或独立 CorsConfig.java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();
    config.setAllowedOrigins(List.of("https://app.yourdomain.com"));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
    config.setAllowedHeaders(List.of("Authorization", "Content-Type"));
    config.setAllowCredentials(true);
    // SSE 长连接需要暴露的响应头
    config.setExposedHeaders(List.of("Content-Type"));

    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", config);
    return source;
}
```

> ⚠️ 跨域部署时，`next.config.js` 中的 `rewrites` 在生产模式不生效，全靠环境变量 + 后端 CORS。

### 8.5 生产构建

```bash
cd frontend
npm run build     # Next.js 生产构建
npm start         # 启动生产服务器（默认端口 3000）
```

构建产物位于 `.next/` 目录，不可手动修改。
