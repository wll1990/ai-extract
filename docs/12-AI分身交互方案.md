# AI分身交互方案完整文档



**版本**：V1\.0

**日期**：2026年6月29日

**用途**：定义AI分身在IM端和Web端的完整交互流程、技术实现与管理配置





## 一、方案概述



### 1\.1 分身是什么



分身不是一个真人账号，而是一个**AI驱动的对话机器人**。它背后是销冠经过萃取的经验知识库\+大模型。员工可以通过飞书、企业微信、网页端与分身对话，获得基于销冠真实经验的建议。



### 1\.2 分身的三种形态



|形态|场景|交互方式|
|---|---|---|
|**飞书/企微机器人**|工作中快速求助|@分身提问，私聊或群聊|
|**Web端对话页**|深度学习|打开网页，问答或对练|
|**企业总调度**|跨销冠经验匹配|工作台综合分身输入框|



### 1\.3 分身的三种对话模式



|模式|触发方式|用户心态|分身风格|
|---|---|---|---|
|**快问快答**|直接提问（默认）|救急，要能立刻用|结论先行，150字内，留展开入口|
|**深度探讨**|/讨论 或 分析性问题|想理解逻辑，思维碰撞|案例先导，反问互动|
|**实战对练**|/对练 或 /练习|想练技能|扮演客户，逐轮评判|





## 二、IM端交互方案（以飞书为例）



### 2\.1 整体架构



```Plain Text
飞书用户
    │
    │ 私聊 / 群聊@机器人
    ↓
飞书服务器
    │
    │ POST Webhook (回调地址)
    ↓
我们的IM网关
    │
    │ 验证签名 → 解析消息 → 匹配分身 → 识别模式
    ↓
Python AI服务
    │
    │ 加载锦囊 → 组装Prompt → 调用大模型
    ↓
返回回答 → IM网关 → 飞书API发送消息 → 用户看到回复
```

### 2\.3 三种对话模式的IM交互



**模式一：快问快答（默认）**



触发：直接提问，不加前缀。



```Plain Text
员工：@周铭分身 客户说太贵了怎么回

分身：你可以这样回：
“完全理解。在聊价格之前，我想先问您——
您觉得一年后回头看，这钱花得值，标准是什么？”
这句话把战场从价格拉到价值。先说“完全理解”接住情绪。

📎 周铭·《移花接木》
💬 回复“展开”听我当时的具体案例
```



如果员工回复“展开”：



```Plain Text
员工：展开

分身：去年瑞丰银行的吴总，看到报价直接说“你们这是抢钱”。
我当时心里一紧，但马上有个念头：他让我给理由，说明有兴趣。
所以我没解释价格，反问了他那个价值标准的问题。
他想了想说“别天天给我出乱子”——那一刻我知道，他最在乎
的不是省几万块钱，是系统不出事故。
核心：恐惧驱动力大于贪婪。价格从来不是买不买的真正原因。
```



**模式二：深度探讨**



触发：以 /讨论 或 /聊聊 开头，或问题中包含“你怎么看”“为什么”。



```Plain Text
员工：@周铭分身 /讨论 我觉得做银行客户，关系比方案重要，你怎么看

分身：我部分同意。关系是敲门砖，但关系不能替你回答技术问题。
去年瑞丰银行吴总，他和竞品高管是老相识，关系够硬。但第一次见面
他上来就问“迁移时间4小时的数据依据是什么”。如果我没做功课，
关系再好也没用。
我的体会：关系决定你有没有机会开口，专业决定你开口之后能不能活下来。
银行的人怕丢乌纱帽比什么都怕，你能用专业让他觉得“选你，我晚上睡得着”，
比喝一百顿酒有用。
你怎么看？你遇到过关系特别硬但最后丢了的单子吗？
```



**模式三：实战对练**



触发：以 /对练 或 /练习 开头。



```Plain Text
员工：@周铭分身 /对练 破冰

分身：好，我来扮演客户。
场景：你是销售，我是城商行科技部负责人。我已经对比了两家竞品，
不想再花时间见新厂商。
我说：“已经有两家在谈了，不考虑新的。你简短说一下你们有什么不同。”
请开始你的回应。

员工：我们服务过七家规模相近的城商行，像长沙银行就是我们的客户

分身：⚠️ 评判：
✅ 提到了案例，不是空谈
⚠️ 但你说的是“我们”，不是“你”。没让他觉得你研究过他

💡 我会这样说：“我认真读了您在城商行论坛上的发言，关于中小银行
结算系统‘不能为了先进而牺牲稳定’的观点，我深以为然。我们给
长沙银行做迁移的时候，他们最担心的也是这个。”

再来一轮？还是换场景？
```



### 2\.4 IM消息处理流程（技术）



```Plain Text
飞书用户 @机器人 "客户说贵"
  ↓
飞书服务器 → POST Webhook → IM网关
  ↓
1. 验证签名（防伪造）
2. 解析消息：
   - 用户：张三（user_id）
   - 问题：客户说贵怎么办
   - 场景：群聊（chat_id = oc_xxx）
   - 被@的分身：周铭分身 → skillId = skill-001
3. 生成 sessionId = "feishu_group_oc_xxx_user_zhangsan"
4. 识别模式：
   - 以 /对练 或 /练习 开头 → practice
   - 以 /讨论 或 /聊聊 开头 → discuss
   - 匹配 你怎么看|为什么|你觉得 → discuss
   - 其他 → quick
5. 调用 POST /api/v1/skills/skill-001/chat
   { "message": "...", "sessionId": "...", "channel": "im", "mode": "quick" }
6. Python AI服务：
   - 加载周铭锦囊
   - 组装Prompt（基础模板 + 快问快答模式指令）
   - 从Redis加载该sessionId的历史对话
   - 调用大模型
7. 将本轮对话存入Redis（key = sessionId，过期30分钟）
8. 调用飞书API回复消息（@提问者）
```



### 2\.5 多员工同时使用的隔离机制



```Plain Text
飞书私聊：
  张三 → 私聊“周铭分身” → sessionId = feishu_private_zhangsan
  李四 → 私聊“周铭分身” → sessionId = feishu_private_lisi

飞书群聊：
  张三 @分身 → sessionId = feishu_group_xxx_user_zhangsan
  李四 @分身 → sessionId = feishu_group_xxx_user_lisi
```



每个员工在Redis中有独立的会话上下文，互不干扰。同一员工跨设备或隔30分钟以上，生成新sessionId，开启新会话。

### 3\.4 Web端会话管理



- 网页端 `sessionId` 由前端生成，存储在浏览器 localStorage 中。

- 每次打开C4页面，自动生成新的 `sessionId`。

- 同一浏览器、同一分身，多轮问答共享同一个 `sessionId`，上下文连续。

- 关闭页面后重新打开，生成新 `sessionId`，开启新会话。

- Web端问答模式默认 `mode=discuss`，对练模式默认 `mode=practice`。

    

    

## 四、需要补充的交互流程



反推整个产品流程，以下交互还需要明确：



### 4\.1 首次使用引导



**场景**：员工第一次在IM里搜索到分身，不知道能干什么。



**方案**：首次打开私聊窗口时，分身主动发送欢迎消息：



```Plain Text
周铭分身：
你好，我是周铭的AI分身！👋

我可以帮你三件事：
💬 直接提问 → 给你能立刻用的建议和话术
📖 /讨论 + 问题 → 深入聊聊方法背后的逻辑
🎯 /对练 + 场景 → 我扮演客户，陪你实战演练

试试问我：“客户说太贵了怎么回？”
```



### 4\.2 员工反馈闭环



**场景**：分身的建议有没有帮到员工？需要收集反馈来优化分身。



**方案**：在分身回答末尾，附带两个快捷反馈按钮（IM端为文字提示）：



```Plain Text
这个建议对你有用吗？👍 有用  👎 没用
```



点击后数据存入 `experience_grain` 的评分统计，影响报告的评分和分身的匹配排序。



### 4\.3 邀请销冠做萃取



**场景**：管理员在场景覆盖地图看到“转介绍”场景空白，想邀请陈婷来做萃取。



**方案**（MVP）：



```Plain Text
管理员点击“发起萃取邀请”
  → 弹窗：“邀请链接已复制”
  → 管理员通过飞书发给陈婷
  → 陈婷点击链接 → 跳转到B2创建访谈页面
  → 链接带邀请码，用于追踪来源
```



后续迭代可接入系统内通知。



### 4\.4 分身无效回答的兜底



**场景**：员工问了一个知识库完全覆盖不到的问题。



**方案**：



```Plain Text
分身：
这个问题我没有遇到过类似情况。以下是我的分析，仅供参考：
[基于通用销售逻辑的建议]

💡 建议：这类问题，你可以直接找周铭本人聊聊，
或者试试 @经验助手 看看其他销冠有没有类似经验。
```

### 4\.6 多销冠分身的IM切换



**场景**：员工在飞书里同时有周铭分身和林芳分身，想针对不同问题问不同的人。



**方案**：飞书里搜索不同分身的机器人名称即可。周铭分身和林芳分身是两个独立的飞书应用，各自独立的私聊窗口。不需要切换机制。



### 4\.7 企业总调度与个人分身在IM中的区分



**场景**：员工在群里，有时候想@具体销冠，有时候想综合参考所有销冠。



**方案**：IM中有两种机器人：



|机器人名称|类型|功能|
|---|---|---|
|@周铭分身|个人分身|用周铭的经验回答|
|@林芳分身|个人分身|用林芳的经验回答|
|@经验助手|企业总调度|综合所有销冠，匹配最优经验|



员工按需选择，不需要记忆复杂指令。
