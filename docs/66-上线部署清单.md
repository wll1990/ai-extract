# 上线部署清单（生产）

> 目标：一次把线上拉起来，启动正常、服务正常。
> 生产：`ssh mindforge` → `/opt/mindforge`。数据库只走 Flyway，仓库里其它 SQL 一律不在生产执行。

## 现状（2026-11-12 核对）

- 生产库 Flyway 最大版本 **V40**，本次启动自动补 **V45–V59**。
- 生产当前只有 ai-service 在跑，**Redis 未启动**，backend/frontend/platform/im-bridge 均未运行。
- `/opt/mindforge/config/secrets.env` 不存在，`PARTNER_AES_KEY` 缺失会让后端启动即失败。

---

## 一、上线前必做（5 项，缺一不可）

### 1. 备份数据库

```bash
ssh mindforge 'set -a; . /opt/mindforge/config/backend.env; set +a; \
  mkdir -p /opt/mindforge/backup; \
  PGPASSWORD="$PG_PASSWORD" pg_dump -h "$PG_HOST" -p "$PG_PORT" -U "$PG_USER" -Fc "$PG_DATABASE" \
  > /opt/mindforge/backup/aiextract_$(date +%F_%H%M).dump; \
  ls -lh /opt/mindforge/backup | tail -1'
```

### 2. 创建 secrets.env

```bash
ssh mindforge 'umask 077; echo "PARTNER_AES_KEY=$(openssl rand -base64 32)" \
  > /opt/mindforge/config/secrets.env; ls -l /opt/mindforge/config/secrets.env'
```

只放服务器，不进仓库。不要把 key 写进 `config/backend.env`。

> 注意：`PARTNER_AES_KEY` 一旦更换，`im_channel.secrets` 里已有的 appSecret 密文就解不开，IM 桥会报 `missing appSecret`。如果库里已有 IM 渠道，换 key 后需要在「IM 渠道配置」里重新保存一次 App Secret（会用新 key 重新加密），再重启 im-bridge。

### 3. 确认迁移文件在构建产物里

V45–V59 目前是 untracked，`V1__init.sql` 也有未提交修改。打包前先确认：

```bash
git status --porcelain backend/src/main/resources/db/migration/
cd backend && mvn clean package -DskipTests -q
unzip -l target/backend.jar | grep -E 'db/migration/V(4[5-9]|5[0-9])__' | wc -l   # 期望 15
```

### 4. 同步 prompts（deploy-all 不会做）

生产缺 9 个新 Prompt，缺了评测/培训/知识/销售复盘的 AI 调用会失败：

```bash
rsync -av prompts/ mindforge:/opt/mindforge/prompts/
```

### 5. 启动 Redis

```bash
ssh mindforge 'systemctl start redis && systemctl enable redis && systemctl is-active redis'
```

## 三、启动顺序

### 1. 只启动后端，让 Flyway 跑完迁移

```bash
ssh mindforge 'bash /opt/mindforge/scripts/start-backend.sh'
```

`start-backend.sh` 会 source `backend.env` 和 `secrets.env`。观察日志：

```bash
ssh mindforge 'tail -f /opt/mindforge/logs/backend.log'
```

看到 `Successfully applied 15 migrations` 或逐条 `Migrating schema ... to version 45..59`，再继续。

### 2. 确认迁移结果

```bash
ssh mindforge 'set -a; . /opt/mindforge/config/backend.env; set +a; \
  PGPASSWORD="$PG_PASSWORD" psql -h "$PG_HOST" -U "$PG_USER" -d "$PG_DATABASE" -tA \
  -c "select count(*) filter (where success), count(*) from flyway_schema_history where version::int >= 45;"'
```

期望 `15|15`。若有 false，先看日志，不要继续启其它服务。

### 3. 启动其余服务

```bash
ssh mindforge 'bash /opt/mindforge/scripts/start-ai-service.sh'
ssh mindforge 'bash /opt/mindforge/scripts/start-platform.sh'
ssh mindforge 'bash /opt/mindforge/scripts/start-frontend.sh'
ssh mindforge 'bash /opt/mindforge/scripts/start-im-bridge.sh'
ssh mindforge 'bash /opt/mindforge/scripts/status.sh'
```

## 五、出问题回滚

```bash
# 1. 停服务
ssh mindforge 'bash /opt/mindforge/scripts/stop-all.sh'

# 2. 恢复数据库
ssh mindforge 'set -a; . /opt/mindforge/config/backend.env; set +a; \
  PGPASSWORD="$PG_PASSWORD" pg_restore -h "$PG_HOST" -U "$PG_USER" -d "$PG_DATABASE" \
  --clean --if-exists /opt/mindforge/backup/<备份文件>.dump'

# 3. 换回上一版 backend.jar / 前端 standalone，再启服
```

**不要**为了回滚删除 `flyway_schema_history`。删除后会被当成“非空无历史”库打 V50 基线，V45–V50 全部跳过，后端直接起不来。

## 七、企业微信 / 钉钉接入（2026-11-14 起）

IM 桥从「只做飞书」升级为三渠道同进程（`im-bridge`，端口 3010）：

| 渠道 | 接入方式 | 公网要求 |
|---|---|---|
| 飞书 | 扫码授权 + WebSocket | 无 |
| 钉钉 | Stream 模式（appKey/appSecret 主动连出） | 无 |
| 企业微信 | 自建应用回调 `GET/POST /wecom/callback` | 需要公网 HTTPS |

企业微信回调已在服务器 nginx 上配好（`/etc/nginx/conf.d/mindforge.conf`，admin 443 块）：

```nginx
location /wecom/callback {
    proxy_pass http://127.0.0.1:3010;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 10s;
    client_max_body_size 1m;
}
```

回调 URL 填 `https://admin.loomforge.cn/wecom/callback`。管理端发布弹窗里填写：
`corpId / agentId / secret / token / EncodingAESKey`（后两个来自企微后台「接收消息」配置）。
发布时会先调 `gettoken` 校验凭据，失败不会落库。

> 注意：企微回调必须先能看到机器人记录，所以顺序是「先发布 → 再在企微后台点保存回调 URL」。
> 若桥重启，会自动从后端拉取已发布机器人重建状态，不需要重新保存回调。

钉钉在开放平台把应用机器人设为 Stream 模式并发布，然后在管理端填 `AppKey / AppSecret` 即可。
