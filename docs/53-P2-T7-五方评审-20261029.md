## 2. 合并后的问题与处置

### 2.1 高 / 中（全部已修）

| 问题 | 来源 | 处置 |
|---|---|---|
| 考试自动保存 dirty 竞态：保存期间继续输入会被误清 dirty，离开即丢答案 | 技术#1 | 保存前快照 `answersRef.current`，仅当引用未变才清 dirty；失败保留 dirty 供下轮重试，并把错误显示在底栏 |
| `connectSse` 流干净结束不补 `onDone`，陪练/提示永久停在「正在输入」 | 技术#2 | `finally` 兜底：未收到 done/error 时补 `onDone`；识别 `heartbeat status=timeout/done`；主动 abort 不补 |
| SSE 非 2xx 只回 `HTTP 403`，丢失后端 message；401 不跳登录 | 安全#1 / 技术#20 | 非 2xx 解析 `ApiResponse.message`；401 清凭证跳登录 |
| 逾期后前端仍放行交卷，`timeout_fail` 必 409 | UI#1 / 技术#3 / 安全#4 | `canSubmit` 只认 `allowedActions.submit` 且未逾期；逾期冻结输入、按钮改「等待系统处理」，每 5s 轮询直到扫描器落库后跳成绩页 |
| 「新建版本」条件错：当前版本已是草稿仍可点，必 409 | UI#2 | 改为 `currentVersion.status === 'published'` |
| 退役计划仍可保存/发布/新建版本/新建批次；后端 `publish` 还能把退役状态复活 | UI#3/#5 / 产品#9 | 前端统一 `detail.status !== 'retired'` 门禁；**后端 `requireEditableVersion` 与 `createVersion` 补退役 409** |
| 已结束（completed/cancelled）批次仍显示「分配学员」 | UI#4 | 条件改为 `canManage && status === 'active'`，非进行中显示原因 |
| 次数用尽后「再考一次/开始新一次陪练」仍可点，必 409；已用次数用 attemptNo 会多算 | UI#6 / 用户#3 | 任务页改用 `getRecordAttempts` 的 `used/remaining`；剩余 0 禁用并提示「联系主管补训」；考试页同步显示 |
| 陪练不读 `allowedActions`：过截止仍可输入，发送才 403 | 技术#7 / UI#7 | 输入/发送/提示/提交全部由 `send_message/hint/submit` 驱动，失去动作时显示冻结原因 |
| 陪练恢复历史失败被吞成空对话 | 安全#2 | 独立 `historyError` + 重试；不再静默置空 |
| 成绩页静默轮询失败无感知；`pending_review` 复核后不刷新 | 安全#3 / 技术#5 / 产品#7 | 轮询加入 `pending_review`（20s）；连续失败 3 次提示并给「刷新」按钮 |
| 成绩页直接打开 `in_progress` 显示「正在评分」 | 技术#17 / UI#22 | 单独渲染「本次尝试还在进行中」+「继续作答」 |
| 导师从批次详情「返回培训管理」→ 计划列表 403 死胡同；`canAccessAdmin` 因一个培训权限放开整个 /admin | 技术#4 | 返回按钮按 `canManage` 分流；`AppLayout` 改路径级 `canAccessPath`（只有 `/admin/training/cohorts*` 允许 REVIEW） |
| 导航无高亮：导师在批次页侧栏全暗 | 技术#19 | `/training` 高亮覆盖 `/admin/training/cohorts*`；`/admin/training/plans` 不再抢占批次高亮 |
| 新增任务默认 `phaseNo = max+1` 且继承阶段名 | 产品#1 / UI#21 | 默认沿用最后一个阶段（同阶段加任务不用手改编号） |
| 陪练任务展示「要点覆盖率」，后端明确拒绝（必 400） | 用户#2 | 该字段只对考试展示；提交时也只对考试携带 `minPointCoverage` |
| 考试离开无未保存提示 | 用户#4 | `beforeunload` 在有 dirty 时拦截；切路由仍尽力保存 |
| 交卷确认不体现未答题数 | 产品#2 | 确认框列出「还有 N 题未作答」 |
| 认证备注用 `window.prompt`（内嵌浏览器会拦截） | 用户#6 / UI#26 | 改为正式弹层：备注 textarea（≤1000）+ 取消/确认；复核理由加 maxLength/计数 |
| 学员/导师选择器不过滤角色与停用账号 | 产品#3/#6 / UI#13 | 过滤 `isActive` 与 employee/company_admin/super_admin；>100 人搜索归 P3 |
| 批次列表显示计划 UUID | 产品#5 / UI#14 | 拉取计划 id→name 映射，回退短 ID |
| 计划列表搜索每敲一字请求、页码不重置、慢请求覆盖新结果 | UI#10 | 输入与生效关键字分离（Enter/按钮提交），重置第 1 页，请求序号丢弃过期响应 |
| 任务展开失败「重试」实际是收起；快速连点重复请求 | UI#9 / 技术#10 | 抽出 `fetchTasks` 直接重试；in-flight Set 去重；loading 不被并发清空 |
| 抽屉尝试列表/详情失败只 toast、永久空白 | UI#16 | 独立错误态 + 重试；尝试详情乱序响应用序号丢弃；详情滚动定位 |
| 计划/批次/导师列表失败显示「假空态」 | UI#17/#18 | 失败时不再渲染空态；错误条单独展示 |
| 批量分配结果直出英文 assigned/skipped/failed | UI#15 | 中文状态字典 |
| 管理端表格窄屏被裁 | UI#12 | 表容器 `overflow-x-auto` + `min-w`，头部 `flex-wrap` |
| 认证阻断原因：缺项几乎不可达、`not_pending` 显示「—」 | UI#8 | 有 blockers 就展示「缺：…」；补 `not_pending` 文案 |
| 任务表单点遮罩即关，长表单误触丢失 | UI#20 | 有内容时二次确认 |
| 预览把草稿标成「学员视角」 | 技术#12 | 草稿时注明「学员实际看到的是已发布版本」 |
| 新接口归属单测只 mock 了 accessService | 安全#5 | `TrainingAccessServiceTest` 补 4 条：他人尝试 404 / 跨企业 404 / 本人通过 / 他人记录 404；`practiceMessages` 补会话属主不一致 404 |
| `practiceMessages` 未校验会话属主 | 安全#7 | 增加 conversation.userId == 当前用户，不一致 404 |
| `allowHints=null` 时提示接口放行但 action 不下发 | 安全#9 | 统一为「显式 true 才允许」，两处口径一致 |
| `/auth/me` 任意失败都清凭证跳登录，把服务端故障伪装成会话过期 | 安全#11 | 仅显示错误 + 重试；401 仍由 apiClient 统一处理 |
| 契约漂移：新增 `GET /me/training/attempts/{id}/messages` 未入 §9 | 技术#21 | 回填 docs/43 §9（#33） |
