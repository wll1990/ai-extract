## 第一阶段：素材上传与清洗（Phase 2）

### ① 上传素材

管理员打开分身管理页，点击「上传素材」→ 弹出对话框：
- 拖拽文件（PDF/Word/PPT/聊天记录/录音转写文本）
- 下拉选择已有分身（如「周铭」），或选「+ 新建分身」输入名称和描述
- 点击「开始上传」→ 文件存到 `/data/files/skills/{skillId}/YYYY-MM/xxx.pdf`

接口: `POST /api/v1/admin/materials/upload`

请求:
```
multipart/form-data {
  file,                              // 必填
  skillId (可选),                    // 指定已有分身
  skillName (可选),                  // 新建分身名称
  skillDescription (可选)            // 新建分身描述
}
```

校验:
- skillId 和 skillName 至少提供一个
- 同时提供 → 以 skillId 为准
- 都不提供 → 400
- skillName 与已有分身重名 → 400

### ② 三层清洗

文件上传后，Python `/parse-file` 先解析文本（PDF→文字、Word→文字等），然后进入 Java 清洗管道:

```
原始文本 → 第一层 → 第二层 → 第三层 → 纯净文本
           正则清洗   业务过滤   归一化
```

#### 第一层：格式噪声正则清洗 (MaterialNoiseCleaner)

聊天记录素材:
- 剔除时间戳: `[2024-03-15 14:32:01]`、`03-15 14:32`
- 剔除用户昵称前缀: `周铭(销售总监):`
- 剔除系统推送: `[系统消息]`、`@所有人`、`xxx加入群聊`
- 剔除表情/图片标识: `[图片]`、`[表情]`、`<msg type="sticker">`
- 剔除会话分割线: `────`、`****`、`====`
- 合并多余空行

录音转文本素材:
- 剔除口癖助词: `嗯`、`啊`、`呃`、`哦`（作为独立词时）
- 剔除口语填充: `就是`、`就是说`、`那个`、`这个`、`然后呢`、`反正`
- 剔除停顿标记: `(停顿)`、`[3秒]`、`<silence>`
- 剔除重复口误: 连续重复 3 次以上的 2-4 字词组
- 剔除识别残留乱码
- 剔除录音空白段标注: `(无内容)`、`(静音)`、`[inaudible]`

#### 第二层：冗余话术业务过滤 (BusinessNoiseFilter)

内置销售场景无效话术黑名单，五类:
1. 日常寒暄/客套问候: `你好`、`早上好`、`辛苦了`
2. 无关闲聊: `你们公司真大`、`最近股市`
3. 重复应答/无意义附和: `嗯嗯`、`好的好的`、`对`、`是的`、`OK`
4. 收尾客套话: `感谢您的时间`、`保持联系`、`有问题随时找我`
5. 无业务价值的过渡语: `我想说的是`、`说白了就是`、`说实话`

**业务关键词白名单保护** — 包含以下关键词的行**绝对不删**（宁漏勿错）:
`报价` `合同` `付款` `交付` `实施` `验收` `方案` `演示` `试用` `招标`
`痛点` `ROI` `差异化` `竞品` `决策链` `关键人` `预算` `审批`
`降本增效` `风险` `合规` `信创` `等保` `SLA` `POC`

#### 第三层：文本归一化标准化 (TextNormalizer)

- 统一 UTF-8 编码，清除零宽字符
- 合并连续换行（3 个以上 → 保留 2 个）
- 合并连续空格/tab
- 去除首尾无效字符
- 中文标点统一: `,` → `，`、`;` → `；`、`?` → `？`
- 全角数字/字母 → 半角
- 录音识别错别字修正（行业词库）: `脚夫` → `交付`、`超标` → `招标`、`似有化` → `私有化`
- 统一段落格式: 段尾补句号

素材状态流转: `uploaded` → `cleaning` → `cleaned` → `analyzing`

### ③ 候选颗粒生成

清洗后的纯净文本进入 AI 萃取:

```
纯净文本 → 智能分块 → 去重去噪 → 关键提取 → 场景归类 → 候选颗粒列表
           500-1000    embedding   LLM提取     LLM自动
           字/chunk    相似度>0.9   6字段结构   打scene_tag
           语义边界     的跳过
```

#### 智能分块 (semanticChunk)
- 先按段落分割
- 过长段落（>1000字）按语义边界二次切分
- 过短段落（<100字）与相邻段落合并
- 每个 chunk 保持 500-1000 字的黄金窗口
- 跳过页眉页脚、目录行、纯数字/符号行

#### 去重去噪 (deduplicate)
- 每个 chunk 算 embedding（临时调用，不持久化）
- 与已有颗粒库比对 cosine 相似度
- 相似度 > 0.9 → 自动跳过（高度重复）
- 相似度 0.7-0.9 → 标记为"疑似重复"，待管理员判断是更新还是合并
- 相似度 < 0.7 → 新内容，进入提取流程

#### 关键提取 (LLM 提取) — 每条候选颗粒输出 6 个字段:

| 字段 | 说明 |
|------|------|
| `scene_description` | 在什么情况下发生的？ |
| `expert_thought` | 当事人怎么想的？为什么这样做有效？ |
| `standard_script` | 说了什么原话（尽可能引用原文） |
| `common_mistakes` | 其他人遇到这种情况通常会犯什么错？ |
| `applicable_condition` | 方法在什么条件下适用？什么条件下不适用？ |
| `confidence` | 把握多大（0-1），<0.7 直接丢弃 |

**关键原则: 不要编造任何信息，所有内容必须能在原文中找到依据。**

#### 场景归类 (classifyScenes)
- LLM 为每个洞察自动分配 `scene_tag`
- 优先匹配已有标签，完全新的场景则创建标签
- 标签不超过 10 个字

### 管理员审核（候选颗粒审核页）

页面: `frontend/src/app/admin/skills/[id]/materials/[materialId]/page.tsx`

- **顶部**: 素材信息卡片（文件名、类型、大小、状态、清洗统计：`X字→Y字→Z字→W字 | 分块:N | 去重后:M | 候选颗粒:K`）
- **左侧**: 原始材料文本预览（支持搜索和高亮）
- **右侧**: AI 提取的候选颗粒列表，每条显示：
  - 场景标签（可编辑）
  - 场景描述 | 专家思考 | 标准话术 | 常见错误
  - 置信度进度条（绿 ≥ 0.85 / 黄 ≥ 0.7）
  - 如有相似颗粒：显示链接 + 相似度
- **操作**: ✅ 采纳（直接生成颗粒入库）| ✏️ 编辑后采纳 | ❌ 废弃
- **批量操作**: 全部采纳 / 按置信度筛选批量操作

## 第二阶段: 颗粒入库 + 向量化（Phase 3）

### ④ 颗粒入库

管理员采纳后:
1. 生成 `ExperienceGrain` 记录 → `experience_grain` 表
2. `status = 'active'`，`weight = 1.0`

### ⑤ 向量化（异步）

```
颗粒文本拼接 → 通义 text-embedding-v3 → 1024维向量 → pgvector
```

文本拼接逻辑 (grainToText):
```java
sceneTag + " " + sceneDescription + " " + expertThought + " " + standardScript + " " + commonMistakes
```

异步执行:
- 使用 `embeddingExecutor` 线程池（2-4 线程，CallerRunsPolicy 拒绝策略）
- 不阻塞管理员操作和报告生成流程
- 失败只记 warn 日志，不中断主流程

pgvector HNSW 索引自动维护，后续检索毫秒级响应。

### ⑥ RAG 语义检索

每次对话触发，替代原来"加载全部颗粒"的方式:

```
用户问题 → embedding → pgvector cosine距离搜索 → top-5颗粒 → 拼入 system prompt
```

检索 SQL:
```sql
SELECT g.*, (1.0 - (g.embedding <=> ?::vector)) * COALESCE(g.weight, 1.0) AS relevance
FROM experience_grain g
WHERE g.space_id = ? AND g.status = 'active' AND g.embedding IS NOT NULL
ORDER BY relevance DESC
LIMIT ?
```

按 `(1 - cosine_distance) * weight` 综合排序，权重高的颗粒优先返回。
兜底: 检索无结果时取最近 20 条颗粒。

## 第三阶段: 问答对练 + 实时分析（Phase 4）

### ⑦ 员工使用分身

**QA 问答模式**: 员工提问 → RAG 检索 top-5 颗粒 → 拼入 system prompt → 分身回答

**对练模式**: 系统扮演客户角色，员工扮演销售，多轮对话。客户角色的行为和情绪从颗粒的场景数据中驱动。

System Prompt 注入顺序:
1. 角色设定（模板 `skill_qa_system.md`）
2. 画像（`skill_profile` 表 — personality, speakingStyle, background, commonPhrases）
3. 检索结果（top-K 颗粒，按场景分组展示）
4. 模式指令（quick 150字 / discuss 300字）

### ⑧ 对练实时语义分析 (PracticeAnalyzer)

每轮员工回应后触发:

| 维度 | 检测目标 | 技术方式 | 时效 |
|------|----------|----------|------|
| 意图识别 | 破冰/探需/呈现/异议/逼单/回避 | LLM 实时分类 | 每轮 |
| 得分点命中 | 是否踩中该场景预期行为要点 | embedding 语义相似度 > 0.75 | 每轮 |
| 话术质量 | 逻辑清晰度+说服力+专业表达+客户导向 | LLM 四维评分 | 每轮 |
| 情绪感知 | 客户角色情绪变化是否被正确识别 | LLM 判断 | 异议/逼单阶段 |

SSE 流式反馈 (每轮): `event: analysis` → `{intent, hitPoints, scriptQuality, feedback, missedOpportunities}`

前端右侧实时面板展示:
- 意图标签（黄色 pill）
- 话术质量进度条（绿 ≥ 80 / 黄 ≥ 60 / 红 < 60）
- 得分点命中 ✅/❌（含相似度百分比）
- 即时反馈（蓝色提示框）
- 情绪分析（粉色提示框）
- 遗漏机会点（黄色提示框）

对练结束报告:
- 总轮次 | 整体命中率 | 平均话术质量
- 各意图类型命中率分布
- 薄弱环节高亮 + 针对性训练建议（3-5条，每条含练习方法+合格标准）
- 始终未命中的得分点清单 → 一键跳转到该场景重新对练

### ⑨ 四维评分 — AI Judge (SkillEvaluator)

对话结束后的综合质量评估:

| 维度（权重） | 对比什么 | 分数范围 |
|------|----------|----------|
| 语言风格（30%） | 分身回复 vs 真人原始访谈消息，词汇/句长/语气一致性 | 0-100 |
| 经验一致性（30%） | 分身回复 vs 相关颗粒，是否基于真实经验而非编造 | 0-100 |
| 行为模式（20%） | 客户角色情绪变化（防御→试探→接受）是否合理 | 0-100 |
| 话术复用（20%） | 分身回复中使用了多少标准话术原文或近义表达 | 0-100 |

评分自动持久化到 `skill_evaluation` 表。颗粒权重根据评分自动微调:
- 评分 ≥ 85 → 提权 ×1.05
- 评分 70-84 → 不变
- 评分 60-69 → 降权 ×0.95
- 评分 < 60 → 降权 ×0.90
- 钳制范围: [0.1, 2.0]

### ⑪ AI 自动鉴定对话

独立于人工对练的自动评估:

**流程**:
1. 系统从颗粒场景标签中提取最高频场景，自动构建客户角色
2. AI 鉴定师（客户角色）发起对话
3. 分身回复
4. AI 鉴定师追问/施压/切换场景（故意测试边界）
5. 重复 3-4，进行 12 轮（可通过 `app.evaluation.auto-evaluate-turns` 配置）
6. 对话结束后 AI 鉴定师按四维标准打分
7. 生成鉴定报告: 总分 + 各维度得分 + 亮点引用 + 翻车瞬间 + 改进建议

**SSE 端点**: `POST /api/v1/admin/skills/{id}/auto-evaluate`

事件流: `init` → `evaluator` → `avatar` → `analysis`（每轮） → `complete`

鉴定角色构建逻辑:
```
该分身的场景标签: 银行科技部破冰, 城商行砍价, 金融合规异议
该分身擅长领域: 金融科技销售, 10年经验

→ 构建客户角色: 某城商行科技部采购负责人
→ 客户背景: 已被多家 ERP 厂商坑过，预算有限，对销售天然不信任
→ 测试目标: 是否真正理解银行客户的痛点
```

鉴定结果自动写入 `skill_evaluation` 表（`mode='auto_evaluate'`），与人工对练评分独立。

### ⑫ 发布/废弃决策

**发布**:
- 检查 6 项条件
- 全部通过 → `skill.status = 'published'`，`published_at = NOW()`，`published_by = 当前用户`
- 分身出现在广场，供全员使用

**废弃**:
- `skill.status = 'discarded'`
- 30 天冷却期: 数据完整保留，分身不出现在广场
- 期间管理员可恢复
- 30 天后自动清理:

```
清理范围:
- skill 行删除（CASCADE → skill_profile, skill_material, skill_conversation, skill_message）
- skill_evaluation + skill_acceptance 删除
- experience_grain.status = 'deprecated'（只降级不物理删除，保留评分记录引用）
- pgvector 向量随 experience_grain.embedding 列，HNSW 索引 PostgreSQL 自动维护
- 磁盘素材文件删除
```

**注意**: 如果颗粒同时被其他分身引用（共享空间场景），则不删，只解除与该分身的关联。

## 状态机总览

### 素材状态机
```
uploaded → cleaning → cleaned → analyzing → analyzed → extracted
   │          │          │           │            │          │
   │     (三层清洗)  (清洗完成)  (分块+去重) (AI提取完成) (颗粒已入库)
   │          ↓          ↓           ↓            ↓
   │     失败→重试  失败→重试   失败→重试    管理员审核
   │                                                  │
   └────────────── 废弃 ───────────────────────── discarded
```

### 分身状态机
```
generating → reviewing → published
                 │           │
                 └── discarded ←──┘
```

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| `generating` | 技能生成中 | 等待颗粒萃取完成 |
| `reviewing` | 审核中（管理员评估） | 发布 → `published`，废弃 → `discarded` |
| `published` | 已发布（广场可见） | 停用 → `discarded` |
| `discarded` | 已废弃 | 管理员可重新审核 |

## 关键技术决策

| 决策 | 方案 | 原因 |
|------|------|------|
| Chat 模型 | DeepSeek v4-flash | OpenAI 兼容协议，当前已在用 |
| Embedding 模型 | 通义千问 text-embedding-v3 | 1024维，中文效果优于 OpenAI，国内低延迟 |
| 向量存储 | pgvector + HNSW | 与业务数据同一数据库，filter+search 单 SQL 完成 |
| 检索方式 | 直接 JdbcTemplate | 不用 PgVectorStore（Key-Value 模型不适合按 space_id 过滤 + weight 加权） |
| 清洗管道 | 三层递进 | 正则→业务规则→归一化，不可颠倒，每层解决不同问题 |
| 评分体系 | AI Judge 四维评分 | 风格/一致性/行为/话术，各有独立权重和评判标准 |
| 鉴定方式 | 人工 + AI 双通道 | 独立打分，互不干扰，不绑定发布决策 |
| 废弃策略 | 软删除 + 30天冷却 | 防误操作，可恢复，到期自动清理物理数据 |

## 零 Mock 原则

整个流程中**没有任何硬编码数据或假的 fallback**:

- AI 萃取失败 → 抛异常，不生成"降级颗粒"
- 报告生成失败 → 抛异常，不生成假报告
- PPT 生成 → 已删除，不是空方法
- 验收考题 → 从颗粒库动态生成，不是 8 个固定问题
- 对练场景 → 从颗粒数据构建，不是前端硬编码
- 所有状态 → 数据库真实状态，不是前端写死
