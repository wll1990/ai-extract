# 伟达商业咨询分身 · 产品需求理解

> 文档性质：产品团队（技术开发方）对需求的首次对齐输出。
> 读者：产品/技术团队、商业咨询导师（伟达/郭老师）。
> 配套文档：02_访谈文档（专家访谈卡 + 场景问题卡）、03_理论方法论、04_场景与方法论映射、05_场景与理论沟通。

---

## 0. 一句话结论

我们要做一款**前端引流型 AI 咨询产品**：用导师（商业咨询专家）本人的「提问方式」引导用户把问题说清楚，再调用导师的**理论体系**做分析，输出一份**问题诊断报告**。它卖的不是「答案」，而是「像导师一样问问题 + 像导师一样看问题」的体验，目的是为导师的真实咨询业务引流、筛选高意向客户。

---

## 1. 我们到底在做一个什么样的产品

| 维度 | 理解 |
| --- | --- |
| **产品形态** | 网页/小程序前端，用户进来先「选场景」或「描述问题」，AI 以对话方式提问 |
| **核心交互** | 苏格拉底式层层追问（不是问卷填表，不是直接给建议） |
| **知识边界** | 由「咨询场景」框定——只在导师擅长的领域里问，不发散 |
| **问题来源** | 系统会**推荐该场景下的关键问题/必问问题**（由导师方法论推导，导师正在整理） |
| **产出物** | 咨询结束后，按导师理论体系分析，输出一份**问题报告** |
| **产品目标** | 引流（前端获客）+ 顾问能力前置展示（让用户先体验「导师怎么看问题」） |
| **不是什么** | 不是通用 chatbot、不是自动给商业方案、不是替导师回答所有问题 |

## 2. 用户旅程（端到端）

```
进入产品
  └─ 选择/描述咨询场景（知识边界锁定）
       └─ AI 推荐该场景的关键问题，并基于导师风格开场提问
            └─ 苏格拉底式追问：事实 → 原因 → 证据 → 假设 → 矛盾 → 反思
                 └─ 命中「一票否决」信息缺失？→ 继续追问，不进入分析
                      └─ 达到「问够了」标准 → 转入分析
                           └─ 调用导师理论体系打分/归因
                                └─ 输出《问题诊断报告》
                                     └─ （引流闭环）引导预约导师真人咨询
```

> 关键约束（来自导师原话）：**这些回答直接决定了分析报告的准确性**——所以「问清楚」是产品成败的第一性原理，比「问得快」重要。

---

## 3. 产品的三个硬骨头（技术/设计要点）

1. **追问的「度」怎么控**
   - 既要挖到根因，又不能跑出导师专业领域、不能为了追问而追问、不能一次问太多。
   - 需要一套**追问规则引擎**：允许追问的类型（模糊→具体化、感受→事实数据、结果→原因、原因→证据、矛盾→确认、事实/判断区分）+ **红线清单**（不替用户编数字、不臆断、不过早下结论、不闲聊）。

2. **「场景 × 必问问题」从哪来**
   - 导师正在整理「每个场景下必问的关键问题」。
   - 我们的工作：把他口述/填表的内容，**提炼成结构化知识库**（场景 → 必问问题 → 追问话术 → 一票否决项 → 报告分析维度）。

3. **报告怎么「像导师」**
   - 报告不是模板填空，而是用导师的**理论体系**当分析框架（见 03/04 文档）：
     - 诊断结论（一句话定位问题）
     - 各维度打分（如七步判生意评分表、识人评分表）
     - 核心矛盾 + 错误假设排除
     - 起步动作建议
   - 同一套理论，既是「生成问题的依据」，也是「分析报告的框架」——这是产品的优雅统一点。

---

## 4. 与导师现有方法论的关系（关键认知）

导师已经有一整套成熟方法论体系（讲赢体系、七步判生意法、五看三定战略法、信任阶梯成交法、四力三问两观察识人法、六看尽调、团队搭建七步法、GROW 提问法、五阶成交提问法……）。**这些方法论就是产品的「理论内核」**：

- 每个「咨询场景」≈ 某套方法论在某一类用户身上的应用；
- 每套方法论里的「关键问题 / 红灯信号 / 一票否决 / 评分表」≈ 该场景的「必问问题库 + 报告分析框架」；
- 导师的「提问金句库 / 五阶提问法 / 七层抽屉」≈ 产品的「苏格拉底式追问风格」。

→ 所以产品落地最省力的一条路是：**把导师已有方法论「翻译」成结构化知识库**，再由导师确认/补漏洞，而不是让他从零发明问题。具体映射见 `04_场景与方法论映射.md`。

## 5. 我们还需要向导师确认的关键问题（待澄清清单）

以下问题文档一/文档二已设计，但导师尚未回填，需在推进中拿到答案：

1. **进入方式**：用户先进来先选场景（A）？还是 AI 判断（B）？还是结合（C）？——影响首页与路由设计。
2. **场景清单**：目前最重要的 3—8 个咨询场景是哪几个？——这是知识库的顶层结构。
3. **每个场景的必问问题 + 顺序是否固定 + 一票否决信息**：——这是追问引擎的核心配置。
4. **追问边界**：允许 AI 自由追问到什么程度（A 深追 / B 框内追 / C 仅补全）？红线哪几条？
5. **提问风格**：全程苏格拉底（A）/ 事实直问+决策段苏格拉底（B）/ 直接为主偶尔启发（C）/ 因场景而异（D）？
6. **AI 画像**：问卷助手 / 咨询助理 / 诊断顾问 / 教练 / 数字分身（最像谁）？——决定产品语气与「是否给建议」的策略。
7. **问够了的标准**：从提问切到分析的触发条件是什么？——决定对话何时收口并生成报告。

> 建议沟通策略见 `05_场景与理论沟通.md`：用「您已有方法论 → 我们翻译成问题+打分表 → 您只需确认/补漏」的方式降低导师填表负担。
