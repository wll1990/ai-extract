## S1 · 创业项目可行性诊断

### 元信息
- id: S1
- name: 创业项目可行性诊断
- user_profile: 想创业 / 选项目 / 做投资的人
- theory_core: [七步判生意法, 创始人六看尽调, 一针变现法]
- entry_question: 「你最近在琢磨一个什么项目？现在走到哪一步了？」

### 必问问题（must_ask）
来源：七步判生意法 7 步关键问题 + 灵魂十问 + 六看尽调（人三看/事三看）+ 一针破局/找根

| id | 问题 | 目的 | 类型 | 模糊时追问 | 一票否决 |
| --- | --- | --- | --- | --- | --- |
| q1 | 用户愿不愿意为这个问题付钱？是主动找还是你硬推？ | 判需求真伪（够痛/够频/够刚） | 事实确认 | 用户是主动找过来，还是你硬推给他？ | 是（需求假→pass） |
| q2 | 这个市场现在多大？你能切到哪块？在变大还是变小？ | 判天花板 | 事实确认 | 你能切的具体是哪类人群/场景？ | 否 |
| q3 | 你卖什么？卖给谁？怎么赚钱？凭什么你赚（护城河）？ | 判模式 | 事实确认 | 凭什么是你赚？别人为什么抢不走？ | 否 |
| q4 | 行业前三名是谁？他们做了你怎么办？ | 判竞争 | 事实确认 | 你和他们的区别到底是什么？ | 否 |
| q5 | 现在进场早还是晚？渗透率多少？ | 判阶段 | 事实确认 | 最好窗口期是不是已经过了？ | 否 |
| q6 | 不融资能活多久？每赚一块要投多少？ | 判现金流 | 事实确认 | 账上现金能撑几个月？毛利多少？ | 是（算不过账→pass） |
| q7 | 你验证过了吗？最小闭环跑通没？单位经济算得过来吗？ | 判验证 | 事实确认 | 有真实数据吗？还是全是「我觉得」？ | 否 |
| q8 | 你做过最牛的一件事？最大的坎？3年目标？ | 识人（三问） | 苏格拉底 | 具体吗？有数据吗？归因向内还是向外？ | 否 |
| q9 | 你最值钱的客户/信任资产是谁？（找根） | 找根客户 | 事实确认 | 你通讯录里最信你的 20 个人是谁？ | 否 |
| q10 | 如果只能留一件事，你留哪件？（破局） | 破局主线 | 苏格拉底 | 答不上来=没想清楚，需继续追问 | 否 |
| q11 | 你状态怎么样？这事是不是已经长在你身上？（笃定） | 六看·人 | 苏格拉底 | 被质疑时是深聊还是急跳？ | 否 |
| q12 | 你对待服务员/下属什么态度？（底色） | 六看·人品 | 观察 | 利益褪去后你怎么对人？ | 是（人品差→pass） |

### 动态追问规则（dynamic_followup）
- 澄清性：回答模糊/只说感受 → 要求具体化（数字/时间/对象/渠道）
- 缘由性：提到结果 → 追问原因与时间起点（「大概从什么时候开始的？」）
- 证据性：提到原因/判断 → 追问证据（「有什么事实支持这个判断？」）
- 矛盾性：前后矛盾 → 指出并确认
- 假设性：根据回答提新假设让导师式确认
- 反思性：引导用户自己反思「为什么觉得是 XX 问题，而不是产品本身？」

### 红线（red_lines，AI 绝不做）
- 不替用户编造数字/营收
- 不跳出商业诊断领域
- 未走完七步 + 识人三问就下结论
- 不替导师给人品下定论，只提示观察维度

### 分析框架（analysis_framework）
- dimensions / 权重：需求(20) / 天花板(15) / 模式(15) / 竞争(15) / 阶段(10) / 现金流(15) / 验证(10)
- 人三看（状态/笃定/人品）作为独立减项：任一低于 4 分 → 综合结论下调
- veto（命中即给「不建议做」）：需求假 / LTV<CAC 算不过账 / 无任何差异化 / 人品差
- output_template（一针诊断四件套）：一句话结论 / 变现主线 / 起步动作 / 降级建议

### 停止条件（stop_condition）
七步信息收集 ≥ 80% 且 识人三问完成 且 命中核心矛盾 → 进入分析

### 待导师确认
- [ ] 开场白是否用「你最近在琢磨什么项目」
- [ ] 一票否决是否加「人品差」（六看第三看）
- [ ] q8/q11/q12（识人）是否必问，还是仅「创始人」画像才问
- [ ] 报告是否同时出「七步评分表(70)」+「六看评分表(100)」两份

## S3 · 企业增长瓶颈诊断

### 元信息
- id: S3
- name: 企业增长瓶颈诊断
- user_profile: 遇到增长停滞/瓶颈的老板
- theory_core: [五看三定战略法, 一针变现法(穿线/闭环), 信任阶梯成交法]
- entry_question: 「你现在的生意，哪一块增长最让你头疼？具体卡在哪了？」

### 必问问题（must_ask）
来源：五看三定 + 一针闭环设计 7 维 + 信任阶梯（增长即复购/转介绍）

| id | 问题 | 目的 | 类型 | 模糊时追问 | 一票否决 |
| --- | --- | --- | --- | --- | --- |
| q1 | 现在整体营收/增长怎么样？哪块在掉？ | 定位瓶颈面 | 事实确认 | 具体哪个月开始掉的？掉多少？ | 否 |
| q2 | 客户是谁？画像清晰吗？决策路径是什么？ | 五看·看客户 | 事实确认 | 能说出「他叫什么、每天干嘛」吗？ | 否 |
| q3 | 行业在增长还是萎缩？渗透率多少？ | 五看·看行业 | 事实确认 | 你的细分赛道在变大还是变小？ | 否 |
| q4 | 对手是谁？你跟他们的区别是什么？ | 五看·看对手 | 事实确认 | 客户为什么选你不选他？ | 否 |
| q5 | 你的核心优势/资源是什么？短板是什么？ | 五看·看自己 | 事实确认 | 什么事你做得比对手好？ | 否 |
| q6 | 生意七个环节（入口/转化/价值/升单/推荐/交付/利润）哪一环最弱？ | 闭环定位 | 苏格拉底 | 哪个指标最低？先补哪个？ | 否 |
| q7 | 获客成本多少？复购率多少？转介绍率多少？ | 增长健康度 | 事实确认 | CAC 和 LTV 比值多少？ | 是（真实营收不清→pass） |
| q8 | 你觉得问题出在流量、转化、还是产品/团队？ | 挖核心矛盾 | 苏格拉底 | 为什么这么判断？有数据吗？ | 否 |
| q9 | 如果只解决一件事，你最想先解决什么？ | 定方向 | 事实确认 | 这个目标有时限吗？ | 否 |

### 动态追问规则（dynamic_followup）
- 同 S1 全套（澄清/缘由/证据/矛盾/假设/反思）
- 特别：用户说「流量问题」→ 必须先验证转化与产品（一针穿线思维：别急着信表面原因）

### 红线（red_lines）
- 不替用户猜数字
- 不跳出增长诊断框架
- 未定位核心矛盾就给方案
- 不否定用户判断，用追问让其自证

### 分析框架（analysis_framework）
- dimensions：行业趋势 / 客户清晰 / 对手差异 / 自身优势 / 闭环弱环 / 增长数据
- 核心输出：五看态势图 + 闭环最弱环定位 + 一针诊断四件套
- veto：找不到核心矛盾（九问后仍散） / 真实营收结构不清
- output_template：一句话结论 / 增长主线 / 起步动作 / 降级建议

### 停止条件（stop_condition）
五看信息 ≥ 70% 且 闭环 7 维至少有 1 环定位为最弱 且 核心矛盾明确 → 进入分析

### 待导师确认
- [ ] 开场白是否用「哪块增长最让你头疼」
- [ ] 一票否决是否加「真实营收不清」（防瞎分析）
- [ ] 闭环 7 维是否全问，还是只问用户自认弱的那环
- [ ] 报告是否出「五看 + 闭环弱环」双图

## S5 · 团队管理问题诊断

### 元信息
- id: S5
- name: 团队管理问题诊断
- user_profile: 带团队但执行力/人不对的创始人
- theory_core: [团队搭建七步法, 四力三问两观察识人法]
- entry_question: 「你团队现在最让你头疼的人或事，是什么？」

### 必问问题（must_ask）
来源：团队搭建七步（目标/架构/找人/规矩/方法/结果/文化）+ 识人四力三问两观察

| id | 问题 | 目的 | 类型 | 模糊时追问 | 一票否决 |
| --- | --- | --- | --- | --- | --- |
| q1 | 团队目标清晰吗？大家对齐吗？ | 七步·定目标 | 事实确认 | 目标是数字+时限吗？每个人都知道吗？ | 否 |
| q2 | 谁干什么？一件事几个负责人？ | 七步·定架构 | 事实确认 | 是不是「两个和尚没水喝」？ | 否 |
| q3 | 关键人价值观合不合？ | 七步·找对人 | 苏格拉底 | 不认同价值观的人，还在核心位吗？ | 是（价值观不合→pass） |
| q4 | 你做过最牛/最挫/3年目标是什么？（识人三问） | 四力·三问 | 苏格拉底 | 具体吗？归因向内还是向外？ | 否 |
| q5 | 核心成员认知/心力/格局/匹配怎么样？ | 四力看底色 | 苏格拉底 | 哪「力」最缺？你补还是避开？ | 否 |
| q6 | 基本规矩有吗？（目标/沟通/决策/奖惩） | 七步·立规矩 | 事实确认 | 干坏怎么罚？奖惩及时吗？ | 否 |
| q7 | 有没有 SOP/反馈/成长路径？ | 七步·给方法 | 事实确认 | 新人能直接上手吗？ | 否 |
| q8 | 拿结果了吗？复盘吗？ | 七步·拿结果 | 事实确认 | 每个阶段只有 1-2 个核心目标吗？ | 否 |
| q9 | 你活出来的样子，就是团队样子吗？ | 七步·建文化 | 苏格拉底 | 你勤奋/真诚，团队就勤奋/真诚吗？ | 否 |
| q10 | 他对服务员/弱者什么态度？（底色） | 两观察·细节 | 观察 | 利益面前先想自己还是别人？ | 是（人品差/负能量→pass） |

### 动态追问规则（dynamic_followup）
- 同 S1 全套
- 特别：用户说「执行力不行」→ 先具体化（「哪几件事没执行？」），再挖背后（目标/分工/机制），不急着贴标签

### 红线（red_lines）
- 不替用户做人事决定（开人/升迁）
- 不评价人品，只给观察维度
- 未看清「人」就下「事」的结论
- 不跳出团队诊断框架

### 分析框架（analysis_framework）
- dimensions：目标对齐 / 架构清晰 / 人岗匹配 / 规矩健全 / 方法赋能 / 结果复盘 / 文化底色
- 识人减项：四力任一项极低 + 三否决（人品/负能量/价值观不合）命中 → 综合下调
- veto：价值观严重不合 / 人品差 / 只说不做 / 浑身负能量
- output_template：一句话结论 / 团队主线 / 起步动作（先调人还是先调制度） / 降级建议

### 停止条件（stop_condition）
七步信息 ≥ 70% 且 关键人识人三问完成 且 定位「人 or 制度」主因 → 进入分析

### 待导师确认
- [ ] 开场白是否用「最头疼的人或事」
- [ ] 一票否决是否沿用识人三否决（人品/负能量/价值观）
- [ ] q5（四力）是否全问，还是仅对「关键人」问
- [ ] 报告是否出「团队七步诊断 + 识人评分表(100)」
