# 场景建设与方法论的关系 ｜ 映射与知识库结构

> 配套：01_产品需求理解、03_理论方法论分析、05_场景与理论沟通。
> 目的：回答「怎么把这些方法论和哪些场景做关联，从而构建结构化的知识库」。

---

## 0. 核心认知：理论是「一物两用」的

导师的每套方法论，在产品里同时承担两个角色：

```
        ┌─────────────────── 方法论（理论） ───────────────────┐
        │                                                     │
   作为「提问依据」                              作为「报告框架」
   • 关键问题 → 必问问题                      • 评分表 → 报告打分维度
   • 红灯信号 → 追问触发条件                  • 一票否决 → 报告结论的硬约束
   • 灵魂十问/流程卡 → 推荐问题序            • 诊断四件套 → 报告输出结构
        │                                                     │
        └──────────────┐               ┌──────────────────────┘
                       ▼               ▼
                【场景】= 方法论 在某一类用户/问题上的具体化应用
```

**所以「场景」不是凭空设计的，而是「方法论 × 用户画像」的组合**。知识库的本质 = 把方法论拆成「问题节点 + 规则节点 + 报告节点」，再按场景组装。

## 1. 顶层场景清单（建议）

综合「用户原话的 5 类诊断」+「讲赢六场景」+「识人/战略模块」，建议一级场景如下（最终由导师确认/裁剪）：

| 编号       | 场景           | 用户画像（典型来者）          | 主要理论内核                         |
| -------- | ------------ | ------------------- | ------------------------------ |
| S1       | 创业项目可行性诊断    | 想创业/选项目/做投资的人       | 七步判生意法 + 六看尽调                  |
| `**S2**` | `**商业模式梳理**` | `**有项目但说不清怎么赚钱的人**` | `**七步判生意(模式步) + 一针变现(破局/穿线)**` |
| S3       | 企业增长瓶颈诊断     | 遇到增长停滞的老板           | 五看三定 + 信任阶梯 + 一针变现(穿线)         |
| S4       | 实体店/本地经营诊断   | 线下门店经营者             | 七步判生意 + 信任资产盘点 + 闭环设计          |
| S5       | 团队管理问题诊断     | 带团队但执行力/人不对的创始人     | 团队搭建七步法 + 四力三问(识人)             |
| S6       | 创始人/合伙人评估    | 选合伙人/被评估的人          | 观微识人法 + 六看尽调                   |
| S7       | 路演/招商诊断      | 要融资/招商的人            | 路演讲赢(八步成演)                     |
| S8       | 一对一成交诊断      | 不会谈客户/成交率低的人        | 成交讲赢(七能力/提问四步)                 |
| S9       | 内容/IP 诊断     | 想做短视频/朋友圈/IP 的人     | 内容讲赢(四步公式/人设三环)                |
| S10      | 社交人脉诊断       | 想经营圈层的人             | 社交讲赢(识人三步/同频四步)                |

## 3. 知识库节点 Schema（一个场景怎么存）

建议每个场景在知识库里存为如下结构的节点（JSON/YAML 均可），这就是产品的「配置即规则」：

```yaml
scene:
  id: S1
  name: 创业项目可行性诊断
  user_profile: 想创业/选项目/做投资的人
  theory_core: [七步判生意法, 六看尽调]
  entry_question: "你最近在琢磨一个什么项目？现在走到哪一步了？"   # 开场白
  must_ask:            # 必问问题（来自方法论关键问题）
    - id: q1
      question: "如果明天这个服务消失了，用户会难过吗？"
      purpose: 判需求真伪
      ask_type: 事实确认
      is_required: true
      followup_if_vague: "用户是主动找过来，还是你硬推给他？"
      veto_if_missing: true     # 缺失则一票否决
  dynamic_followup:    # 动态追问规则（来自七层抽屉 + GROW）
    - type: 澄清性
      trigger: 用户回答模糊
      action: 要求具体化(数字/时间/对象)
    - type: 缘由性
      trigger: 提到结果
      action: 追问原因与时间起点
    - type: 假设性 / 影响性 / 质疑性 / 行动性 / 继续性
  red_lines:           # 红线（AI 绝不做）
    - 不替用户编造数字
    - 不跳出商业诊断领域
    - 不未问够就下结论
  analysis_framework:  # 报告分析框架（来自方法论评分表）
    dimensions: [需求, 天花板, 模式, 竞争, 阶段, 现金流, 验证]
    weights: {需求:20, 天花板:15, 模式:15, 竞争:15, 阶段:10, 现金流:15, 验证:10}
    veto: [需求假, 算不过账, 无差异化]
    output_template: [一句话结论, 变现主线, 起步动作, 降级建议]
  stop_condition: "七步信息收集≥80% 且 命中核心矛盾 → 进入分析"  # 问够了的标准
```

## 4. 示例：S1 创业项目可行性诊断（完整知识库条目雏形）

> 下面用导师已有的「七步判生意法」直接翻译出一个场景配置，证明「理论→场景」是可机械转换的。导师只需确认/补漏。

**开场**：「你最近在琢磨一个什么项目？现在做到了哪一步？」

**必问问题（7 步 × 关键问题，节选）**
1. 用户愿不愿意为这个问题付钱？是主动找还是你硬推？（判需求）
2. 这个市场现在多大？你能切到多少？在变大还是变小？（判天花板）
3. 你卖什么？卖给谁？怎么赚钱？凭什么你赚（护城河）？（判模式）
4. 行业前三是谁？BAT 做了你怎么办？（判竞争）
5. 现在进场早还是晚？渗透率多少？（判阶段）
6. 不融资能活多久？每赚一块投多少？（判现金流）
7. 你验证过了吗？最小闭环跑通没？单位经济算得过来吗？（判验证）

**追问风格**：先用事实确认型问清 7 步，再用苏格拉底式追问「你为什么觉得这是真需求？」「有什么证据证明用户会推荐？」

**一票否决**：需求假 / LTV<CAC / 无任何差异化 → 报告直接给「不建议做」结论。

**报告框架**：七步评分表（56+ 可做 / 42-56 想清楚差异 / <42 别做）+ 诊断四件套（一句话结论/主线/动作/降级）。

## 5. 知识边界与发散控制

- **场景 = 边界**：用户选了 S1，AI 只在「创业可行性」的问题空间内问，不跳跃到团队管理（除非用户主动提到，可标记为关联线索，但不展开）。
- **理论 = 深度上限**：AI 的追问不能超出该场景挂的方法论框架（满足文档一选项 B「围绕事先定义的分析框架追问」）。
- **兜底**：用户描述的问题不在任何场景 → 走文档一「C 两者结合」的 AI 判断分支，先归类再进对应场景；归不了类的，引导用户选最接近的场景或转人工。
