# 场景与理论的沟通策略 ｜ 如何引导导师还原场景、提炼规则

> 配套：01_产品需求理解、02_访谈文档、03_理论方法论分析、04_场景与方法论映射。
> 目的：产品团队如何向导师（伟达/郭老师）**讲清楚「场景」和「理论」的关系**，从而让他愿意、且能低成本地参与「还原场景 → 提炼规则」的共建。

---

## 0. 沟通的核心矛盾

- **导师**：脑子里是「方法论」（七步判生意、一针变现、四力三问……），习惯临场判断，讨厌填表。
- **我们（产品方）**：需要的是「场景 + 必问问题 + 追问规则 + 报告框架」的结构化配置。
- **桥梁**：**场景 = 导师的方法论，落到某一类具体用户身上**。所以我们不是让他「从零发明问题」，而是让他「认领并校准」我们已经从他方法论里翻译出来的问题。

> 一句话沟通定位：**「您的方法论我们已读透，正在把它翻译成 AI 能用的问答和报告。您只需要像平时一样，跟我们过一遍『这类人您会怎么问』，剩下的整理工作交给我们。」**

---

## 1. 给导师的「一眼看懂」关系图（建议直接发给他）

```
您的方法论（理论）          我们做成              咨询场景（用户入口）
─────────────────          ──────────          ──────────────────
七步判生意法        ──▶     问题+打分表    ──▶   S1 创业可行性诊断
一针变现法(4步)     ──▶     30分钟诊断脚本  ──▶  S2/S3 模式/增长诊断
四力三问+六看尽调   ──▶     识人问卷+红线   ──▶   S5/S6 团队/创始人评估
五看三定            ──▶     战略提问清单    ──▶   S3 增长瓶颈诊断
讲赢六场景          ──▶     6套场景话术    ──▶   S7-S10 路演/成交/内容/社交
GROW + 七层抽屉     ──▶     追问规则引擎    ──▶   （所有场景通用）
```

**给导师的旁白文案（可直接用）**：
> 「老师，您的每一套方法论，我们在产品里都会变成两样东西：① 一套问用户的问题（您的必问清单）；② 一套出报告的打分标准（您的判断逻辑）。不同的用户类型，就是不同的『场景』。您已经有了理论，我们只是帮您把理论『摆到桌面上』，让 AI 能照着问、照着判。所以您不用写新方法，只要确认我们翻译得对不对。」

---

## 2. 两条沟通路径（按「导师有没有现成方法论」分流）

### 路径 A：导师已有方法论覆盖的场景（省力，优先做）
适用于 S1/S2/S3/S5/S6/S7–S10（都有对应文档）。
- **我们做**：按 `04` 的 Schema，把方法论翻译成「场景配置草稿」（必问问题、追问规则、一票否决、报告框架）。
- **导师做**：开一次 20–30 分钟对齐会，逐场景过：
  1. 这个场景的用户画像对不对？
  2. 必问问题漏了哪条？哪条其实不重要？
  3. 追问可以到多深？（深挖 / 框内追 / 仅补全）
  4. 一票否决项齐不齐？
- **产出**：导师签字确认的 Scene Config（即知识库节点）。

### 路径 B：导师无现成方法论、或想新开的场景（用文档二补全）
适用于导师临场经验强但没写成文档的场景。
- **方式一（最推荐）**：提供一段真实咨询录音/聊天记录 → 我们拆解成问题卡。
- **方式二**：模拟咨询——产品方懂商业的人和导师聊 20 分钟，我们记录追问逻辑。
- **方式三**：只给关键词（如「营收、渠道、复购、团队、目标」），我们扩写成问题卡。
- **方式四**：导师口述，我们整理成文档再确认。

> 沟通话术：「老师，这块您还没写成文档，没关系。您挑一个印象最深的真实案例，跟我聊一遍就行——您怎么问、为什么这么问，我记下来整理成表，您再看像不像您。」

## 3. 访谈/对齐会引导脚本（用于路径 A 的对齐会）

每个场景用同一套 5 问，控制在 20 分钟内：

1. **「这类人进来，您第一句会问什么？」** → 锁定 entry_question（开场白）。
2. **「您一定会搞清楚哪几件事，才敢下判断？」** → 锁定 must_ask + 一票否决。
3. **「他答得含糊时，您会怎么逼出真话？」** → 锁定 dynamic_followup（七层抽屉映射）。
4. **「您什么时候觉得'问够了'？」** → 锁定 stop_condition（报告触发）。
5. **「您最后给他的结论长什么样？」** → 锁定 analysis_framework（报告模板）。

> 这 5 问，正好对应 `04` Schema 的 5 个字段。导师回答即配置，我们整理即知识库。

## 4. 常见顾虑与应对

| 导师可能的顾虑 | 我们的回应 |
| --- | --- |
| 「我都是临场发挥，说不清」 | 不用说清，给我们录音/聊一遍，我们拆。您的方法论文档已经够我们翻译一大半了。 |
| 「填表太累」 | 不用填表。我们先翻译好草稿，您只做判断题（对/错/补）。 |
| 「AI 问得不像我」 | 所以才要您测原型。S1 我们已经翻译成可跑的对话，您试完说哪不像，我们调。 |
| 「怕问漏关键信息」 | 我们用您方法论里的「一票否决」和「红灯信号」做硬卡点，缺了就不让出报告。 |
| 「怕 AI 瞎给建议」 | 红线已设：未问够不出结论、不替用户编数字、不跳出领域。 |

## 5. 可直接发给导师的一页纸（沟通稿模板）

> 标题：《咱们这个 AI 分身，怎么把您的本事「装」进去》

老师，跟您对齐一下我们怎么做：

1. **您已有的方法论（七步判生意、一针变现、识人六看等），我们已经读完，正在逐套翻译成 AI 能用的「问答+报告」。** 您不用重写，只需认领。
2. **每个「场景」= 您的方法论，对应一类来找您的人。** 比如「创业可行性诊断」就是七步判生意法。用户选场景，AI 就照那套问。
3. **我们要您参与的，是两件事**：① 确认场景清单（哪些人最常来找您）；② 跟我们过一遍「您会怎么问」（录音/聊天/口述都行）。
4. **您的方法论同时干两件事**：既决定 AI 问什么（必问问题），也决定报告怎么写（您的打分标准）。一套理论，两处复用。
5. **下一步**：我们先把「创业可行性 / 增长瓶颈 / 团队管理」三个场景翻译成可跑原型，您测「像不像」，不像我们就调。

您看这周三还是周四，抽 30 分钟我们对一遍这三个场景？

## 6. 沟通节奏建议（落地排期）

| 周次 | 动作 | 产出 |
| --- | --- | --- |
| W1 | 发 §5 一页纸 + 确认场景清单 | 锁定 S1–S10 范围 |
| W2 | 路径 A：翻译 S1/S3/S5 配置草稿 | 3 份 Scene Config 草稿 |
| W3 | 对齐会（§3 五问），导师校准 | 导师确认版配置 |
| W4 | 出对话原型，导师测「像不像」 | 原型验收 + 迭代 |
| 持续 | 路径 B 补全缺口场景 | 知识库逐步完整 |

---

## 7. 一句话总结给团队

**不要请导师「设计产品」，要请导师「验收翻译」。** 他的方法论是原料，我们的结构化是工厂，场景是货架。把「您写问题」变成「您看我们对不对」，导师的参与成本从「创造」降到「确认」，共建才能持续。
