## 3. 用户侧缺口（G13，已关闭）

**原缺口**：`retrieval_evidence` 与 `retrieval_expected` 都已落库，但没有代码把两者比对，报告里没有 Recall@K / Precision@K / MRR。

**已实现（2026-10-28）**：

| 层 | 实现 |
|---|---|
| 计算 | `RetrievalMetricsService`：金标条目归一化后被任一检回条目的标题/场景标签**包含**即命中；按相似度降序取排名算 MRR。**不用语义相似度**——语义匹配会让「没检回金标」的题也显示命中，指标就失去意义 |
| 单题 | Worker 执行时把指标写进 `rule_check_result.retrieval_metrics`（含 `missedExpected` 遗漏项） |
| 批次 | `finalize` 聚合写入 `evaluation_run.score_detail.retrieval`，报告新增「检索指标」段并注明口径与「K=实际检回条数」 |
| 前端 | 批次头部展示聚合指标；单题抽屉展示该题命中/遗漏项 |

**实机证据**（批次 `e6e9dc22`，2026-10-28 20:58）：

```
单题: expectedCount=1, retrievedCount=1, hitExpected=0, recall=0, mrr=0, missedExpected=["能力范围"]
批次: items=1, recallAtK=0, precisionAtK=0, mrr=0, fullyHitItems=0, itemsWithMiss=1
报告: "## 检索指标（仅统计配置了检索期望的题）" 表格 + 口径说明
```

这条链路现在能直接回答「召回有没有退步」：金标没检回就是 0 分，不再被 AI 回答质量掩盖。
