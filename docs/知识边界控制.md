# AI 分身 — 知识边界控制机制

> 生成日期: 2026-07-17
> 设计目标: AI 分身不越界、不编造、不知道的就诚实说

---

## 总体架构：三层防线

```
用户问题
     │
     ▼
┌────────────── 第一层：向量检索 ───────────────┐
│  只把最相关的 5 条颗粒注入 System Prompt       │
│  similarity ≥ 0.5 → 【核心经验·高度匹配】      │
│  0.3 ≤ sim < 0.5 → 【参考经验】               │
│  sim < 0.3       → 不标注，照常回答            │
│  无结果           → "暂无结构化经验数据"       │
│  无结果 + 回退    → 取最近 20 条颗粒兜底       │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌────────────── 第二层：Prompt 边界规则 ──────────┐
│  ① 知识域内 + 有颗粒支撑 → 引用原话和案例      │
│  ② 知识域内 + 无对应颗粒 → 诚实告知，给大致方向 │
│  ③ 知识域外(完全不在专业领域) → 拒绝+引导回域  │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌────────────── 第三层：硬约束黑名单 ──────────────┐
│  政治敏感 / 违法违规 / 医疗建议                 │
│  投资建议 / 技术实现 / 代码编写 / 通用百科       │
│  Prompt 层面直接禁止，无论 RAG 检索到什么       │
└────────────────────────────────────────────────┘
```

## 第一层：向量检索 (RAG)

**代码**: `GrainRetriever.retrieveWithScores()` + `ChatStreamService.retrieveGrainsWithScores()`

### 检索流程

```
用户消息
  → ① query_rewrite.md: LLM 改写为独立语义查询
  → ② DashScopeEmbeddingService.embed(): 1024 维向量
  → ③ pgvector HNSW 索引 ANN 检索: candidates=topK×3
  → ④ weight 重排: relevance = cosine_similarity × weight
  → ⑤ 取 topK=5
```

### 相似度分档

| 分数 | 档次 | System Prompt 标记 | 效果 |
|------|------|-------------------|------|
| ≥ 0.50 | high | `【核心经验 · 高度匹配当前问题】` | LLM 优先采用 |
| 0.30 ~ 0.50 | ref | `【参考经验】` | 辅助参考 |
| < 0.30 | — | 普通标题 | 可用但不强依赖 |
| 无结果 | — | `（暂无结构化经验数据...）` | 靠画像兜底 |

### 回退机制

向量检索 0 结果 → 从 DB 取最近 20 条颗粒兜底，不标注 tier。

## 第二层：Prompt 边界规则

**代码**: `SkillService.buildSkillSystemPrompt()` → `skill_qa_chat.md` / `skill_talk.md`

### QA 模式边界（skill_qa_chat.md 第 72-77 行）

```
1. 你只在以下领域有专业能力：{knowledge_domains}。超出拒绝
2. 禁止回答：政治敏感、违法违规、医疗、投资、技术实现、代码、通用百科
3. 不要充当客服、心理医生、情感顾问。你就是 XXX 本人
4. 绝对不编造案例、数据、客户信息。经验区没有的，就说
   "这个我没经历过，不敢乱说"
5. 被追问 3 次超出边界，坚定结束
```

### Talk 模式边界（skill_talk.md 第 64-74 行）— 更细腻的三层分级

```
① 知识域内 + 有经验颗粒支撑
   → 自然回答，引用经验区原话和案例

② 知识域内 + 无对应经验颗粒
   → 诚实告知但保留温度：
   "这个方向我有一些经验，但具体到你说的这种情况，我没有完全相同的案例，
    不敢乱给建议。大概的方向是……"

③ 知识域外（完全不在你的专业领域）
   → 礼貌拒绝 + 引导回专业领域（社交闲聊除外——正常聊）
   "写代码我不擅长，我是做传统高客单销售的。要不聊聊怎么把产品卖给技术负责人？
    这类客户我有不少经验。"
   → 被追问 3 次坚定结束："这个我真的不懂，建议你找专业的人问问。"
```

### Practice 模式

AI 扮演客户，不提"销冠话术"——边界由场景颗粒限定。客户角色只能在该场景的练习角度内提问。

---

## 第三层：硬约束黑名单

两个对话 Prompt 共享的固定禁止话题列表：

```
政治敏感 | 违法违规 | 医疗建议 | 投资建议 | 技术实现 | 代码编写 | 通用百科
```

这些不依赖 RAG 检索结果，不依赖知识域。Prompt 层面直接禁止，属于"最后一道防线"。

## 前端用户感知

### 有匹配颗粒时

AI 回复下方可展开**溯源面板**：

```
📋 溯源 · 3条
  🔗 价格谈判
  🔗 异议处理
  🔗 决策推进
  ⭐ 平均质量 4.2
  📄 潘露婷 · 经验萃取报告
```

触发条件: `msg.source` + `msg.grainCount` 均有值。

代码: `ChatStreamService.buildSourceChunkFlux()` 取 top 3 颗粒的标签 + 质量分 + 报告名，通过 SSE source event 发给前端。

### 无匹配颗粒时

前端不显示溯源面板，用户只看到纯文本回答。Talk 模式额外在回答末尾标注：

```
---
📎 来自 XXX 的访谈，相关经验：政府销售、B2B大客户
💡 核心思路：...
```

### 越界提问时

用户看到的是自然语言拒绝，不是报错——保持了对话体验。

## 改进空间（待评估）

1. **无颗粒时置信度显性化**：目前"无颗粒"和"低分颗粒"在前端表现一样——都不显示溯源。可以考虑在低分时显示"匹配度较低，仅供参考"的弱提示
2. **RAG 改写质量监控**：query_rewrite 失败时降级为原消息，可能导致检索不准。可加监控日志
3. **阈值可配置化**：当前 high=0.5, ref=0.3 硬编码在 `ChatStreamService:393`，可考虑放入领域配置
4. **Practice 模式溯源缺失**：对练模式目前不返回 source event，用户看不到引用了哪些颗粒
