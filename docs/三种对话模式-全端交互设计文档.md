> 含代码流程图、提示词体系、各模块差异化对比

## 一、代码流程图

### 1.1 QA 模式（请教/快问快答）

```
用户输入 / 点击推荐问题
    │
    ▼
┌─ ChatView/ChatEntry (前端) ──────────────────────────────────────────┐
│  ChatEntry.onQuestionClick(q) or handleSend()                        │
│    → chat.sendMessage(q, 'qa')                                       │
│    → useChat / useQaChat hook                                        │
└──────────────────────────────────────────────────────────────────────┘
    │ POST /skills/{skillId}/chat { mode: "qa"/"quick", message: "..." }
    ▼
┌─ SkillController.chat() ─────────────────────────────────────────────┐
│  extractUserId() from JWT                                             │
│  → chatStreamService.chat(skillId, request, userId, role)            │
└──────────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─ ChatStreamService.chat() ───────────────────────────────────────────┐
│                                                                       │
│  Phase 1: Setup (同步)                                                │
│  ├─ skillRepository.findById()        ← 校验分身存在/已发布            │
│  ├─ interceptGuest()                  ← C端游客5条限流                │
│  ├─ profileRepository.findBySkillId() ← 查画像完整性                  │
│  ├─ resolveMode("qa", message)        ← → "quick" 或 "discuss"        │
│  ├─ convPersistence.upsertConversation() ← 会话查找/创建+保存用户消息  │
│  ├─ ragPipelineService.buildRagHistory()    ← DB最近12条历史           │
│  ├─ ragPipelineService.rewriteQuery()       ← LLM查询改写              │
│  └─ ragPipelineService.retrieveGrainsWithScores() ← pgvector检索+tier │
│                                                                       │
│  Phase 2: Stream (异步, SSE)                                          │
│  ├─ promptAssembly.buildSkillSystemPrompt()                           │
│  │   ├─ 加载画像 (personality/background/common_phrases...)           │
│  │   ├─ 组装经验上下文 (groupGrainsByScene + tier标记)                 │
│  │   ├─ 注入模式指令 (quick=直给 / discuss=深入)                       │
│  │   └─ promptLoader.format("skill_qa_chat.md", params)               │
│  ├─ promptAssembly.buildChatMessages() ← system+历史+当前消息          │
│  ├─ chatStreamAdapter.chatStream()     ← DeepSeek LLM 流式调用        │
│  └─ convPersistence.saveAiMessage()    ← 保存AI回复+grainId+reportId  │
│                                                                       │
│  Phase 3: Post-stream                                                 │
│  ├─ buildSourceChunkFlux()             ← 溯源source event             │
│  │   └─ grainIds + grainTags + reportTitle + avgScore + avgSimilarity │
│  ├─ RAG无匹配? → grainRec.generateSuggestedQuestions()                │
│  └─ conversationStatsRepository.save() ← 统计埋点                     │
└──────────────────────────────────────────────────────────────────────┘
    │ SSE: content → source → suggested → meta → done
    ▼
┌─ 前端渲染 ───────────────────────────────────────────────────────────┐
│  ChatActive / SkillChatView / MobileChatShell                         │
│  ├─ 逐 chunk 渲染 AI 回复文本                                          │
│  ├─ onSource → MessageBubble 展示溯源面板                              │
│  │   └─ [高度匹配 85分] ▼ 溯源 · 3条                                   │
│  └─ onMeta → 更新 conversationId                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.2 Talk 模式（自由对话）

```
用户输入 (placeholder="聊聊你的想法...")
    │
    ▼  POST /skills/{skillId}/chat { mode: "talk", message: "..." }
    │
    ▼
┌─ ChatStreamService.chat() ───────────────────────────────────────────┐
│                                                                       │
│  Phase 1: Setup (同QA)                                                │
│  ├─ resolveMode("talk", message) → "talk"                             │
│  └─ 其余同QA                                                          │
│                                                                       │
│  Phase 2: Stream (关键差异)                                            │
│  ├─ promptAssembly.buildSkillSystemPrompt()                           │
│  │   ├─ template = "skill_talk.md"  ← 不同的Prompt模板!               │
│  │   │   └─ 无强制四段式结构                                          │
│  │   │   └─ 三层边界系统 (域内+有颗粒/域内+无颗粒/域外)               │
│  │   │   └─ 社交规则 (寒暄/感谢/嗯好的处理)                           │
│  │   │   └─ 话题切换确认                                             │
│  │   │   └─ 首次对话自我介绍                                         │
│  │   ├─ modeInstruction = "" (talk模式无额外指令)                      │
│  │   └─ experience_context 含tier标记 (同QA)                          │
│  └─ 其余流程同QA                                                      │
│                                                                       │
│  Phase 3: Post-stream (同QA)                                          │
└──────────────────────────────────────────────────────────────────────┘
    │ SSE → 前端渲染 (同QA，仅placeholder不同)
```

### 1.3 Practice 模式（实战对练）

```
用户点击 🎯对练
    │
    ▼
┌─ PracticeView (各端独立实现) ─────────────────────────────────────────┐
│  Phase select: 场景选择                                                │
│  ├─ fetchPracticeScenes(skillId) ← 从颗粒加载场景列表                  │
│  └─ 展示场景网格 → 用户选一个                                          │
└──────────────────────────────────────────────────────────────────────┘
    │ POST /skills/{skillId}/practice/start { scene: "价格谈判" }
    ▼
┌─ SkillService.startPractice() ───────────────────────────────────────┐
│  ├─ loadSceneByTag() → 从颗粒取场景信息                                │
│  ├─ practiceDemoService.getScenePracticeAngles() → 练习角度           │
│  ├─ 创建 Conversation (mode="practice")                                │
│  ├─ 保存首条 AI 客户消息 (role="assistant", roleLabel="客户")           │
│  └─ 返回 { practiceId, scene: { customerLine, ... }, angles }         │
└──────────────────────────────────────────────────────────────────────┘
    │ 前端收到 customerLine → phase='active'
    ▼
用户扮演销售打字回应
    │ POST /skills/{skillId}/practice/respond { message, sceneTag, ... }
    ▼
┌─ ChatStreamService.respondPractice() ─────────────────────────────────┐
│  ├─ interceptGuest()                  ← C端游客限流                    │
│  ├─ promptAssembly.buildPracticeSystemPrompt()                         │
│  │   └─ promptLoader.format("skill_practice_customer.md", params)     │
│  │       └─ AI角色: 扮演客户 (身份隐藏/真实情绪/逐轮升级)               │
│  ├─ chatStreamAdapter.chatStream()    ← LLM 流式                      │
│  └─ 保存用户消息(roleLabel="我(销冠)") + AI消息(roleLabel="客户")      │
│  └─ buildSourceChunkFlux() ← 追加场景颗粒溯源                          │
└──────────────────────────────────────────────────────────────────────┘
    │ SSE → 前端 → 逐轮对话
    │ ...多轮后用户点 "结束对练"
    ▼
┌─ 评价阶段 ───────────────────────────────────────────────────────────┐
│  POST /skills/{skillId}/practice/evaluate { conversation, scene }     │
│  ├─ promptAssembly.buildPracticeEvaluatePrompt()                       │
│  │   └─ promptLoader.format("skill_practice_evaluate.md", params)     │
│  │       └─ AI角色: 销冠本人, 第一人称复盘                             │
│  ├─ chatStreamAdapter.chatStream()                                    │
│  └─ persistEvaluation() ← 解析JSON → 写入 skill_evaluation 表         │
│      └─ score + styleScore + consistencyScore + behaviorScore         │
│      └─ strengths + improvements + demoScript                        │
└──────────────────────────────────────────────────────────────────────┘
    │ SSE → 前端展示复盘面板
    │ GET /skills/{skillId}/practice/trend → 历史趋势
```

## 四、各模块交互详解

### 4.1 开场白

| 入口 | 展示方式 | 数据来源 | 可配置 |
|------|---------|---------|--------|
| 主前端 | Talk/QA 内联渲染气泡 | `skill.openingMessage` (AI生成/手动填写) | 管理员编辑 |
| 企业端 | ChatEntry 居中气泡 | 同上 | 同上 |
| H5 | ShareLanding 卡片内展示 | 同上 | 同上 |
| 管理后台 | 审核预览 (无独立开场) | — | — |

**生成时机：** 发布时 `@Async generateOpeningMessage()` 自动生成 15-30 字自我介绍

**意义：** 降低冷启动门槛，让用户第一时间感知分身的个性和能力边界

### 4.2 推荐问题

| 入口 | 展示方式 | 生成逻辑 | 触发条件 |
|------|---------|---------|---------|
| 主前端 Talk | 精选话题按钮列表（三级淡入动画） | `fetchRecommendedQuestions(skillId)` 异步加载 | 进入即加载，无场景联动 |
| 主前端 QA | 场景标签 → 点击后加载场景专属话题 | `fetchRecommendedQuestions(skillId, sceneTag)` | 点击场景 pill 后加载 |
| 企业端 Talk | 精选话题按钮列表 | 同上 | 进入即加载，无场景联动 |
| 企业端 QA | 场景标签 → 点击后刷新场景专属话题 | `fetchRecommendedQuestions(skillId, sceneTag)` | 点击场景 pill 后加载 |
| H5 | 无 | — | — |
| 管理后台 | 无 | — | — |

**生成逻辑：**
```
按 sceneTag 分组统计颗粒数 → 取 top 3 场景
  → 取每个场景第一个颗粒的 sceneDescription
  → 转为问句格式
  → 不足 3 个用兜底: "能分享一个你最成功的案例吗？" / "遇到客户拒绝时，你会怎么处理？"
```

**RAG 无匹配时的推荐：** `ChatStreamService.chat()` 在 `grains.isEmpty()` 时通过 SSE `suggested` 事件下发推荐问题，引导用户转向分身擅长的领域

**意义：** 降低提问门槛，引导用户发现分身的价值，提高首问转化率

### 4.3 溯源展示

**数据链路：**
```
SSE source event
  ├── reportId → Report.title
  ├── grainIds → ExperienceGrain (场景描述/销冠思路/标准话术/常见误区)
  ├── grainTags (逗号分隔场景标签)
  ├── grainCount + avgScore + avgSimilarity
  └── sourceNames (素材文件名 / 访谈主题)
      │
      ▼
  MessageBubble 渲染
  ├── 匹配度徽章: avgSimilarity≥50 高度匹配(绿) / ≥30 参考匹配(黄)
  └── 展开溯源: 标签胶囊 + 条数
      │
      ▼
  TraceabilityDrawer (Phase 4 P0 待建)
  └── 侧边抽屉: 颗粒详情 + 原始对话片段 + 报告来源
```

| 入口 | 展示方式 | 交互 |
|------|---------|------|
| 主前端 | `MessageBubble` 底部匹配度徽章 + 可展开溯源面板 | 点击展开/折叠 |
| 企业端 | `MessageBubble` 自研版本, 同上有匹配度+标签 | 同 |
| H5 | `MobileChatShell` 内联 `<details>` 标签 | 原生展开/折叠 |
| 管理后台 | 审核预览无聊天模式, 不涉及 | — |

**意义：** 信任锚点 — 每句话可追溯到真实销冠的原始素材，企业采购决策者最关注的可信度指标

### 4.4 评价

| 维度 | QA/Talk | Practice |
|------|---------|----------|
| **评价方式** | 用户反馈 (👍/👎 helpful) | AI 自动四维评分 |
| **评分维度** | 单一 helpful 标记 | 风格(30%) + 一致性(30%) + 行为(20%) + 话术复用(20%) |
| **存储** | `feedback_log` 表 | `skill_evaluation` 表 |
| **展示** | 无前端展示 | PracticeView result 阶段复盘面板 |
| **趋势** | 无 | `GET /skills/{id}/practice/trend` |
| **管理看板** | 暂无 | 待建 (Phase 4 P1) |

**Practice 评价流程：**
```
LLM 输出结构化 JSON
  { score, style_score, consistency_score, behavior_score, script_reuse_score,
    strengths: [{ point, quote }], improvements: [{ point, quote, suggestion }],
    demo_script: "销冠示范话术" }
    ↓
ChatStreamService.persistEvaluation()
  ├─ 解析 JSON (防御: 提取{...}子串, 格式非法吞异常)
  └─ 写入 skill_evaluation 表
```

**意义：** 
- 用户侧：看到进步曲线，形成"练习→评价→改进→再练"的行为闭环
- 管理侧：量化培训 ROI，发现短板场景

## 五、多端交互流程（完整用户旅程）

### 5.1 QA 模式（请教/快问快答）— 逐端交互

#### 主前端 (`/skill/[skillId]`，默认 talk，切到 QA 后如下)

```
切换到 💬 经验请教
  │
  ├──① 开场
  │   顶部 header + SceneTagBar 场景 pill 条
  │   ├── 分身头像 + 姓名 + 头衔
  │   ├── openingMessage（气泡样式，AI生成的15-30字自我介绍）
  │   ├── "擅长领域" 标签 — SceneTagBar 横向滚动 pill 条
  │   │   └── 每个 pill: emoji + 场景名 + 颗粒数
  │   └── 点击 pill → 加载该场景的精选话题 + 显示场景上下文导航
  │
  ├──② 场景上下文导航
  │   选中场景后显示当前场景标签（高亮 pill）+ 上/下一场景翻页按钮
  │   ├── ← 上一场景 | 🔵 当前场景 ✕ | 下一场景 →
  │   └── 下方展示该场景的精选话题（来自 fetchRecommendedQuestions）
  │
  ├──③ 对话中
  │   SkillChatView
  │   ├── 用户消息气泡（右侧蓝色）
  │   ├── AI 回复 → MessageBubble（左侧白色卡片）
  │   │   ├── 正文: 判断逻辑→策略选择→话术→可迁移点
  │   │   ├── ━━━━━━ 分隔线 ━━━━━━
  │   │   ├── 核心思路分析（1-2句）
  │   │   └── [🏅 精准匹配] / [📎 关联匹配] / [✦ 综合画像生成]
  │   │       └── 溯源 · N条 → 点击打开 TraceabilityDrawer
  │   └── 底部 👍👎 反馈按钮
  │
  ├──④ 模式切换
  │   header 右上角 segmented control
  │   ├── 💬 经验请教 | ☕ 轻松交流
  │   └── ⚠️ 每次切换 = 新对话（清空消息 + 清空 conversationId）
  │
  └──⑤ 历史
      HistorySidebar（右侧滑入, overlay 半透明遮罩）
      ├── "+ 新对话" 按钮
      ├── 会话列表: 标题 + 模式标签 + 更新时间
      └── hover 显示删除按钮
```

#### 企业端 (`/chat/[skillId]`，默认 talk，切到 QA 后如下)

```
切换到 🔍 经验请教
```

## 六、各模块意义总结

| 模块 | 商业意义 | 用户价值 | 技术要点 |
|------|---------|---------|---------|
| **开场白** | 冷启动激活, 降低跳出率 | 感知分身个性, 知道该问什么 | `@Async` 异步生成, 已手动填写不覆盖 |
| **推荐问题** | 首问转化, 引导价值发现 | 降低提问门槛, 发现分身能力 | 按颗粒覆盖度生成, RAG无匹配时兜底 |
| **溯源展示** | 建立信任, 采购决策依据 | 验证AI回答可靠性, 看到原始素材 | grain→report→material 三表回溯 |
| **评价** | 量化培训 ROI, 数据飞轮 | 看到成长曲线, 形成练习闭环 | 复用已有 skill_evaluation 表 |
| **三种模式** | 覆盖不同使用场景, 提高留存 | QA=效率, Talk=探索, Practice=成长 | 同一后端三套 System Prompt |
| **多端部署** | 灵活交付, 降低集成成本 | 企业IM/浏览器/H5 全场景覆盖 | 共享后端, 前端独立部署 |

### 7.2 逐轮评价 API（文档 Section 1.3 补充）

`POST /skills/{skillId}/practice/evaluate-round` (JSON, 非 SSE)

请求: `{ sceneTag, customerMessage, myResponse, previousChampionAnswer?, retryCount? }`
响应: `{ championAnswer, comparison, hits, misses, technique, offTopic?, grains?, matchLevel?, fullAnswer?, isLastRetry? }`

调用时机：实战演练中每次用户回复后、客户回应前。支持重试（最多 2 次）时传入 previousChampionAnswer。
