## 2. 外键设计决策

**不使用数据库外键约束**。V5 已全部移除。

### 原因

| 问题 | 说明 |
|------|------|
| DDL 阻塞 | ALTER TABLE 触发全库 FK 校验，38 条约束放大变更风险 |
| TRUNCATE 不兼容 | PG 的 TRUNCATE 不触发 ON DELETE CASCADE，清数据需手排依赖 |
| 扩展阻碍 | 分库分表、在线 DDL（gh-ost/pt-osc）直接报错 |
| 重复校验 | Service 层 `findById().orElseThrow()` 已在检查引用完整性 |

### 替代方案

- **索引保留** — 所有外键列上的索引不变，JOIN 性能不受影响
- **引用完整性** — Service 层保证，创建关联实体前检查父记录存在
- **级联删除** — 项目几乎无物理删除操作；少量场景由 Service 显式先删子表再删父表

## 3. 核心表结构

### 3.1 组织架构

```
company (企业)
  └── user (用户)
        └── space (空间/个人专区)
              ├── interview_session ── interview_message
              ├── skill ── skill_material
              │     ├── experience_grain
              │     ├── skill_profile
              │     ├── skill_conversation ── skill_message
              │     └── report
              └── expert_skill ── expert_grain
```

### 3.2 表清单

| 表名 | 说明 | 关键列（无 FK，仅索引） |
|------|------|------------------------|
| `company` | 企业 | id, name |
| `user` | 用户 | id, company_id, role |
| `space` | 空间 | id, user_id |
| `interview_session` | 访谈会话 | id, space_id, invited_by |
| `interview_message` | 访谈消息 | id, session_id |
| `report` | 萃取报告 | id, space_id, session_id |
| `experience_grain` | 经验颗粒 | id, space_id, report_id, source_material_id, embedding |
| `skill` | AI 分身 | id, space_id, domain, status |
| `skill_material` | 分身素材 | id, skill_id, uploaded_by, material_type |
| `skill_profile` | 分身画像 | id, skill_id |
| `skill_conversation` | 对话会话 | id, skill_id, user_id |
| `skill_message` | 对话消息 | id, conversation_id |
| `skill_practice_eval` | 对练评估 | id, skill_id, conversation_id, evaluator_id |
| `skill_acceptance` | 分身验收 | id, skill_id, accepted_by |
| `skill_acceptance_item` | 验收项 | id, acceptance_id |
| `expert_skill` | 萃取师经验 | id |
| `expert_grain` | 萃取师颗粒 | id, expert_id |
| `expert_interview` | 萃取师访谈 | id, expert_id |

### 3.3 关键索引

```sql
-- JOIN 查询（保留，无 FK 依赖）
CREATE INDEX idx_user_company ON "user"(company_id);
CREATE INDEX idx_space_user ON space(user_id);
CREATE INDEX idx_session_space ON interview_session(space_id);
CREATE INDEX idx_message_session ON interview_message(session_id);
CREATE INDEX idx_report_space ON report(space_id);
CREATE INDEX idx_grain_space ON experience_grain(space_id);
CREATE INDEX idx_grain_scene ON experience_grain(scene_tag);
CREATE INDEX idx_grain_material ON experience_grain(source_material_id);
CREATE INDEX idx_skill_space ON skill(space_id);
CREATE INDEX idx_material_skill ON skill_material(skill_id);
CREATE INDEX idx_conversation_skill ON skill_conversation(skill_id);
CREATE INDEX idx_message_conversation ON skill_message(conversation_id);
```

## 4. 命名规范

- 表名：snake_case，单数（`skill` 非 `skills`）
- 列名：snake_case
- 索引：`idx_{表}_{列}`
- 约束：`ck_{表}_{列}`（check）、`uq_{表}_{列}`（unique）
- 枚举：VARCHAR + CHECK 约束，不用 ENUM 类型
- JSONB：用于 tags、metadata 等非检索字段
- 向量：`VECTOR(1024)` 用于 embedding 列
