# 访谈生命周期完整手册

> 2026-07-01（更新） · 覆盖：创建→四阶段对话→中断/恢复→完成→报告→锦囊→分身 全链路

---

## 一、两种访谈模式

| 模式 | B2 入口 | 访问角色 | System Prompt |
|---|---|---|---|
| 💼 萃取销冠经验 | "萃取销冠经验"标签 | employee, super_admin | interview_system.md + 萃取师经验 |
| 🧠 访谈萃取师 | "访谈萃取师"标签 | **仅 super_admin** | meta_interview_system.md（元萃取） |

两种模式共用同一套四阶段对话引擎，但 Prompt 不同、产出不同。

## 二、完整生命周期状态机

```
                    ┌─────────┐
            创建 ──→│ created │
                    └────┬────┘
                         │ 首次发送消息
                         ▼
                    ┌────────────┐       暂停       ┌────────┐
                    │ in_progress│ ←──────────────→ │ paused │
                    └─────┬──────┘     恢复          └────┬───┘
                          │                              │
                          │ 四阶段完成+6模块采集全true      │ 重新开始
                          ▼                              ▼
                    ┌───────────┐                  ┌───────────┐
                    │ completed │                  │ abandoned │
                    └─────┬─────┘                  └───────────┘
                          │
                          ▼
                    触发报告生成
```

**6 个状态**：`created` → `in_progress` → `paused`/`completed`/`abandoned`/`failed`

**关键文件**：
- 状态常量：`InterviewService.java:53-61`
- 状态校验：`InterviewService.java:169`（非 created/in_progress 时拒绝消息）
- 会话创建：`InterviewService.createSession()` → status=created
- 首次消息：`processMessageToWriter()` → status 从 created → in_progress
- 暂停：`pauseSession()` → status=paused
- 恢复：`resumeSessionToWriter()` → 校验 INTERRUPTIBLE_STATUSES
- 完成：`checkAndCompleteSession()` → 6 项全 true + phase=closing

## 三、四阶段对话流

### 阶段推进

```
opening（开场定调）
  → 目标：建立信任，锁定一个具体成功案例
  → 转段信号：用户说出具体客户背景 → storytelling

storytelling（故事深描）
  → 目标：追问完整成交故事，拿到 STAR 细节
  → 转段信号：能脑补整个成交过程 → modeling

modeling（模型提炼）
  → 目标：把故事变成可复制的步骤和原则
  → 转段信号：用户说出"我的方法叫XXX" → closing

closing（收网确认）
  → 目标：明确适用边界，给方法命名
  → 结束信号：全部 6 个采集模块标记完成
```

### 6 个采集模块

| 模块 | 字段 | 何时标记 |
|---|---|---|
| 案例故事 | `collect_case_story` | 第二阶段完成时 |
| 核心步骤模型 | `collect_steps` | 第三阶段提炼出步骤时 |
| 关键决策点 | `collect_decision` | 第三阶段深入追问决策时 |
| 专家心法 | `collect_mindset` | 第三阶段引出金句/比喻时 |
| 适用边界 | `collect_boundary` | 第四阶段追问边界时 |
| 行动检查清单 | `collect_checklist` | 第四阶段确认清单时 |

**标记机制**：Python AI 在流式响应末尾检测关键字（如"案例故事完成"），发射 `collect_update` 事件 → 后端 `handleSseEvent()` 更新对应字段 → 前端 `onCollectUpdate` 回调更新进度条。

## 四、中断与恢复

### 暂停

```
用户点 ⋮ → "暂停访谈"
  → POST /interviews/{id}/pause
  → pauseSession(): status = "paused"
  → 前端跳回 B2 创建页
  → B2 顶部显示黄色提示条"你有进行中的访谈「{topic}」"
  → localStorage 记录当前 sessionId
```

### 恢复

```
点"继续" → 跳回 B3
  → B3 检测 session.status ∈ {in_progress, paused}
  → 弹出 ResumeModal:
      "你有未完成的访谈"
      主题: {topic}
      当前进度: {phase}
      上次活跃: {lastActiveAt}
      [继续上次访谈]  [重新开始]

点"继续上次访谈":
  → POST /interviews/{id}/resume (SSE)
  → 注入系统消息:
      "【系统指令】访谈恢复。当前阶段：storytelling。
       已采集素材：案例故事。
       未采集素材：核心步骤模型、关键决策点、专家心法、适用边界、行动检查清单。
       最近对话摘要：ai: 请回忆...; user: 瑞丰银行...;
       请自然衔接，优先追问未采集素材。"
  → AI 自动衔接上一条上下文
```

### 重新开始

```
点"重新开始" → 二次确认红色按钮
  → POST /interviews/{id}/restart
  → restartSession(): status = "abandoned", finished_at = NOW()
  → 历史消息保留不删除
  → 跳回 B2 重新创建
```

## 五、完成 → 产出链

### 触发条件

```
AI 主动发出【建议推进】高亮提示 → 用户点击推进按钮

四阶段完成检测 (checkAndCompleteSession):
  currentPhase == "closing"
  AND collectCaseStory == true
  AND collectSteps == true
  AND collectDecision == true
  AND collectMindset == true
  AND collectBoundary == true
  AND collectChecklist == true
  → reportGenerationService.generateReport(sessionId)
```

### 产出清单

```
① Report（报告记录）
  report 表: id, title, subtitle, content_json(六章JSON), rating=4.5, file_status=synced

② 锦囊 (experience_grain)
  从 content_json 拆解:
    - scene_tag: 场景标签（破冰/异议处理/逼单/...）
    - scene_description: 场景描述
    - judgment_signal: 判断信号
    - expert_thought: 专家思维
    - standard_script: 标准话术
    - common_mistakes: 常见错误
    - applicable_condition: 适用条件
    - embedding: VECTOR(1024) 向量

③ Word 文件
  HTML 格式 .doc 文件（StringBuilder + CSS 内联样式 → .doc 扩展名）
  六章结构: 封面+案例故事+方法论+决策点+心法+避坑+清单+练习
  下载: GET /reports/{id}/download?format=word

④ PPT 文件
  单页标题幻灯片（fillPptSlides 当前为空方法，24页结构待实现）
  结构: 封面→目录→案例(4页)→方法论总览→每步骤2页→决策点(2页)→心法→避坑→清单→练习→感谢

⑤ AI 分身 Skill
  skill 表: space_id(每个空间一个), status=generating→active
  基于该空间所有 experience_grain 按场景分组
  System Prompt = skill_qa_system.md + {owner_name} + {experience_context}

⑥ 工具资料
  tool 表: 金句海报(poster)/话术卡片(card)/行动清单(checklist)/情景剧本(script)
  由前端渲染或后端 Pillow 生成
```

## 六、数据关系总图

```
一次访谈 (interview_session)
  ├─ N条消息 (interview_message)
  │   ├─ role: ai/user/system
  │   ├─ phase: opening/storytelling/modeling/closing
  │   ├─ depth: 追问深度（-1=引导消息, 0=主问题, 1+=追问）
  │   └─ stage_status: JSONB 阶段快照
  │
  ├─ 1份报告 (report)
  │   ├─ content_json: 六章 JSON
  │   ├─ word_url / ppt_url
  │   ├─ file_status: synced / pending_regenerate
  │   └─ rating / view_count
  │
  ├─ N条锦囊 (experience_grain)
  │   ├─ scene_tag: 破冰/异议处理/逼单/...
  │   ├─ expert_thought: 专家思维
  │   ├─ standard_script: 实际话术
  │   ├─ common_mistakes: 常见错误
  │   └─ embedding: VECTOR(1024)
  │
  └─ 1个分身 (skill)
      ├─ status: generating → active
      ├─ model_name: deepseek-chat
      └─ 关联 space_id (每个空间唯一)
```

## 七、涉及的 API

| 步骤 | API | 说明 |
|---|---|---|
| 创建 | `POST /interviews` | 传 spaceId + topic + expertSkillId |
| 对话 | `POST /interviews/{id}/chat` (SSE) | 5种事件: chunk/phase_change/collect_update/done/error |
| 查状态 | `GET /interviews/{id}` | 返回 phases + collectStatus + reportId |
| 消息列表 | `GET /interviews/{id}/messages` | 按时间升序 |
| 暂停 | `POST /interviews/{id}/pause` | status → paused |
| 恢复 | `POST /interviews/{id}/resume` (SSE) | 注入恢复提示词后接续 |
| 重新开始 | `POST /interviews/{id}/restart` | status → abandoned |
| 活跃检测 | `GET /interviews/active` | B2 页用，检测是否有进行中的访谈 |
| 报告生成 | 自动触发（checkAndCompleteSession 内部） | 异步生成 |
| 报告查看 | `GET /reports/{id}` | 六章详情 |
| 报告下载 | `GET /reports/{id}/download?format=word\|ppt` | 文件流 |

---

## 八、SSE 事件类型

| type | 携带字段 | 触发时机 | 前端处理 |
|---|---|---|---|
| `chunk` | content | AI 每输出一个 token | 逐字追加到气泡 |
| `phase_change` | content(阶段名) | Python 检测到阶段切换关键词 | 更新进度条 + 插入转段分隔线 |
| `collect_update` | content(模块名) | 流结束时检测到标记 | 更新采集状态 |
| `done` | reportId(可选) | 流正常结束 | 触发报告跳转 |
| `error` | message | AI 超时/异常 | 显示错误提示 |

## 九、萃取师访谈 vs 销冠访谈 的区别

| 维度 | 萃取销冠经验 | 访谈萃取师 |
|---|---|---|
| B2 入口 | 💼 萃取销冠经验 | 🧠 访谈萃取师（仅 admin 可见） |
| System Prompt | interview_system（BEI方法论+成交导向） | meta_interview_system（虚心请教姿态） |
| 对话目标 | 挖掘销冠的隐性成交经验 | 挖掘萃取师本人的实践智慧 |
| 四阶段 | 开场→深描→提炼→收网 | 开场→深描→提炼→收网（追问更"元"） |
| 产出报告 | 六章《萃取报告》（含步骤/话术/避坑） | 七章《萃取师经验报告》（含分类框架/可执行指令） |
| 生成颗粒 | experience_grain（场景颗粒） | expert_grain（7类萃取师颗粒） |
| 对分身的影响 | 生成该销冠的 AI 分身 | 增强 AI 萃取引擎的追问质量 |
