CEO/创始人分身 — 产品设计思路
先回答一个底层问题：CEO 分身到底是什么？
我们现在的销冠分身，本质上是**"话术索引器"**——你遇到一个销售场景，它告诉你销冠会怎么说、怎么做。

如果把这个逻辑直接套到 CEO 身上，做成"CEO 语录搜索引擎"，那就完全错了。因为：

销冠的价值在话术（这个场景说什么话）
CEO 的价值在判断（这个局面怎么想、怎么决策）
所以 CEO 分身不应该回答"CEO 说过什么"，而应该回答**"如果 CEO 面对你现在的局面，他会怎么思考"**。

这是一个根本性的产品定位差异，它决定了后面的所有设计。

问题一：整体上怎么去做这个东西？
参考市场上的产品，目前有几类做法：
产品类型	代表	做法	优点	短板
文档问答型	Google NotebookLM、ChatGPT 自定义 GPT	上传文档 → RAG 检索 → 回答引经据典	来源可追溯、幻觉可控	只有"事实层"，没有"人格层"和"判断层"。问答像搜数据库，不像是跟人聊
人格扮演型	Character.AI	定义人设 → 自由对话	互动感强、有趣	知识没有根基，聊深了就会露馅。CEO 讲不出自己的真实故事和原则
知识萃取型	Delphi AI	结构化访谈 → 提取知识 → 教练式对话	有结构、有深度	互动形态比较单一、通用化，没有针对 CEO 这类角色做特别设计
决策辅助型	企业内部的决策系统	规则引擎 + 决策树	一致性强	太僵硬，捕捉不到 CEO 的灵活判断和直觉权衡
这四种路线，单独用哪一个都不够。 CEO 分身需要同时做到四件事：

知道 CEO 知道什么（文档问答型的根基）
像 CEO 那样思考和表达（人格扮演型的灵魂）
知识有结构、不散乱（知识萃取型的骨架）
能帮助用户做决策、而不仅仅是回答问题（决策辅助型的价值落点）
我的核心主张："洋葱模型"三层结构
CEO 的知识不能像销冠颗粒那样打散平铺，必须是分层的：


        ┌─────────────┐
        │  人格表达层   │  ← 怎么说：语气、用词、讲故事的方式、标志性表达
        │  ┌─────────┐  │
        │  │ 决策原则层 │  │  ← 怎么想：核心价值观、决策框架、判断标准、红线
        │  │ ┌───────┐ │  │
        │  │ │ 知识事实层 │  │  ← 知道什么：具体经历、做过的事、见过的案例
        │  │ └───────┘ │  │
        │  └─────────┘  │
        └─────────────┘
**最外层（人格表达层）**决定用户的感受——"嗯，这确实像他在说话"
**中间层（决策原则层）**决定分身的智力内核——"他会怎么判断这件事"
**最内层（知识事实层）**提供具体素材和引用依据——"他为什么这么判断、有过什么经历"
每一层有不同的建设方式和质量标准，不能混在一起。

这个三层模型的每一层怎么建设：

知识事实层 → 通过"素材上传 + 人工标引"建设

来源：战略文件、全员信、演讲、董事会纪要、对外访谈
处理方式：不拆散！保留文档完整性。AI 做的是"标引"（这份文档讲的是什么领域、包含了什么决策案例），不是"打散"
质量标准：引用准确、来源可查
决策原则层 → 通过"轻访谈 + AI 提炼 + CEO 确认"建设

来源：访谈 + 从素材中 AI 提取候选原则
处理方式：AI 从素材中提取候选原则 → CEO/助理审核确认 → 形成正式原则库
质量标准：每一条原则必须是 CEO 本人认可的，不能是 AI 猜测的
人格表达层 → 通过"素材学习 + 产品配置"建设

来源：演讲、访谈、内部讲话的音频/视频/文字
处理方式：AI 学习表达风格，但不编造。需要产品提供可调整的配置项（正式程度、简洁度、反问频率等）
质量标准：用户感觉"像"，但不追求 100% 模仿（过度模仿反而会恐怖谷）
问题二：交互上是什么样的？
首先要回答：谁来用？在什么场景下用？
CEO 分身的用户和销冠分身的用户是完全不同的人群：

销冠分身	CEO 分身
核心用户	一线销售、销售主管	高管、部门负责人、战略岗
使用场景	准备见客户、复盘拜访	做决策前对齐思路、理解战略意图
使用频次	高频、碎片化	中低频、深度使用
期望产出	具体话术、可执行的操作	思考框架、判断依据、决策信心
对话深度	浅-中	中-深
这意味着交互设计需要从"轻快对话"转向"深度思考辅助"。

首页/入口设计
现有销冠分身的首页是"头像 + 开场白 + 三个模式按钮"——这对于销售场景是够用的。但 CEO 分身的首页需要让人觉得"我进入了他的思考空间"，而不是"我开始跟一个机器人聊天"。

我建议首页的核心元素是：

1. 核心主张（一句话）
直接展示 CEO 最核心的一句话理念，比如："我判断一件事的标准是：它能不能让组织在三年后更强"。这句话不是 AI 生成的，是 CEO 本人确认的。它让用户一进来就知道"这个分身的底层操作系统是什么"。

2. 思考领域地图
可视化展示 CEO 的知识覆盖范围——战略、组织、产品、资本、文化等。每个领域显示的不是"有多少条数据"，而是"CEO 在这个领域有明确的判断原则"。这帮助用户建立预期：哪些问题他一定能聊，哪些可能超出范围。

3. 标志性决策故事
展示 3-5 个 CEO 做过的关键决策和背后的思考。这不是装饰——它是建立信任的工具。用户看到"这个分身确实知道 CEO 是怎么想问题的"，才愿意认真提问。

三种交互模式重新定义
现有系统的 QA / Talk / Practice 三个模式，本质上是为销售场景设计的。对于 CEO 分身，三个模式的内涵需要完全重新定义：

模式一：请益模式（对应 QA）

用户带着一个具体问题来，希望获得 CEO 视角的判断。

和销冠 Q&A 的核心差异：

销冠：直接给答案（"你应该这么说"）
CEO：给思考框架（"这个问题CEO会这样拆解..."）
交互流程：


用户提问 → AI 匹配相关原则 → 
展示：① CEO 怎么看待这类问题（原则）
      ② 为什么这么看（背后的逻辑）
      ③ 一个类似的真实案例
      ④ 需要注意的边界情况
这不是一问一答的客服模式，而是**"思维对齐"**——让用户学会像 CEO 一样思考这个问题。

模式二：推演模式（对应 Talk）

用户想跟 CEO 深入讨论一个话题，不是要答案，是要碰撞。

关键设计：AI 不能只顺着用户说。真正的 CEO 在 1:1 时会反问、会挑战假设。所以这个模式下，AI 应该有**"苏格拉底式反问"**能力——用户说了一个想法，AI 会追问："你有没有想过反过来的情况？"、"这个假设如果错了呢？"

这会让分身感觉更真实，因为好的 CEO 本身就是善于提问的，而不是善于给答案的。

模式三：决策沙盘（对应 Practice）

这是 CEO 分身最大的差异化功能，也是最能体现"创始人特点"的模式。

流程：


1. 系统给出一个商业场景（或用户自己描述）
2. 用户先表达自己的判断：怎么做、为什么
3. AI 展示：CEO 面对这个场景会怎么思考
   - 他会先问什么问题？
   - 他会用什么框架分析？
   - 他会考虑什么别人看不到的因素？
   - 最终他的判断倾向是什么？
4. 对比：用户的思路 vs CEO 的思路，差异在哪里
这个模式的价值不在于"对答案"，而在于暴露思考层次的差异。用户说自己判断的时候只能看到一层，AI 展示 CEO 能看到三层——这就是创始人经验的传递。

问题三：怎么录入他的知识库？
这是整个产品最难、也最重要的一环。录入质量决定了分身质量。

现在市场上常见的做法及问题：
做法	问题
全自动：丢一堆文档进去，AI 自动拆解	知识散乱、没有结构；AI 分不清重要和不重要的信息
纯人工：一个一个知识点录入	不现实，CEO 没时间，助理不知道 CEO 脑子里想什么
纯访谈：像销冠那样 4 个 phase 访谈	CEO 没时间，且 CEO 的知识不适合用对话来"萃取"
我的判断：需要一条新路——"素材先导入→AI 提取候选→人工确认"三阶段流程。

第一阶段：资产盘点（人工主导，AI 辅助）
在做任何事情之前，先搞清楚：CEO 有哪些东西可以拿来用？

这一步需要 CEO 的助理或战略负责人配合，做一次"知识资产盘点"：

列清单：战略文件、年度规划、全员信、董事会纪要、对外演讲、媒体采访、社交媒体发言……全部列出来
排优先级：不是所有素材同等价值。判断标准是——"这份材料里有没有体现 CEO 的判断逻辑？"
高价值：有明确立场和判断的（全员信、战略会发言）
中价值：有信息但判断不明显的（例会纪要、项目复盘）
低价值：纯信息传递的（通知、流程文件）
标记空白：哪些 CEO 一定会涉及的领域，但目前没有对应素材？
这一步的产出： 一份待处理素材清单 + 一份知识空白清单。

这一步看似简单，但极为关键。它决定了后续所有工作的质量基线。市场上很多产品失败就是因为跳过了这一步，直接开始"上传-处理"。

第二阶段：原则提炼（AI 主导，人工审核）
这是"洋葱模型"中间层——决策原则层的建设。也是 CEO 分身和销冠分身在录入环节最根本的差异。

销冠的萃取逻辑：从对话中提取"场景+话术+思路"三元组。话术是具体可执行的，所以可以做全自动。

CEO 的萃取逻辑：从素材中识别"原则+框架+判断标准"。这些是抽象的，AI 可以做候选，但最终必须人确认。

具体做法：

AI 阅读每一份高价值素材，提取候选原则，格式是：

原则陈述（一句话）：CEO 在这件事上的核心判断准则
原文依据（一段话）：素材中哪段话提炼出来的
适用场景：这个原则在什么情况下启用
反例/边界：什么情况下不适用
每条候选原则进入"待确认"状态。CEO 或助理可以：

✅ 确认：这就是我的原则
✏️ 修改：方向对但表述不准，手动调整
❌ 删除：AI 理解错了
所有确认的原则形成"原则库"，这是分身的核心资产。

为什么这一步必须有人工确认？ 因为原则是规范性命题（"应该怎么做"），不是描述性命题（"做了什么"）。AI 可以从素材推断，但无法区分"这是 CEO 深思熟虑的原则"还是"这是 CEO 某个场合随口说的一句"。只有人知道。

第三阶段：风格校准（AI 学习 + 可调节）
这一阶段建设"洋葱模型"最外层——人格表达层。

AI 自动学习：从演讲、访谈等素材中分析 CEO 的表达特征

句式偏好（长句/短句、抽象/具体）
举例习惯（用数据说话 / 用故事说话）
语气特征（直接/委婉、乐观/审慎）
标志性表达（口头禅、常用比喻）
产品化调节：不追求 AI 完美模仿，而是提供可调节的"表达风格"配置：

正式程度：高（对外演讲风格）/ 中（内部会议风格）/ 低（日常交流风格）
简洁程度：精炼直接 / 适度展开 / 充分论述
反问倾向：多反问用户 / 平衡 / 多直接回答
故事倾向：多用故事和案例 / 多用框架和逻辑
这样的好处是：

不过度模仿（避免恐怖谷效应）
可以根据场景切换风格（对外展示 vs 内部使用）
用户可以自己调整感受
第四阶段：持续生长（发布后的迭代机制）
CEO 分身不是一次性工程。CEO 在持续思考、不断产生新内容。分身需要能跟着一起进化。

关键的持续机制：

新素材接入：CEO 发表了新演讲、写了新全员信 → 自动进入候选池 → 标记"是否需要更新原则"
对话反馈闭环：用户问的问题、AI 的回答、用户的满意度 → 标记出"这个领域大家很关心但分身回答不够好" → 提示补充素材
原则版本管理：CEO 的想法可能会变化 → 原则不是写死的，可以更新，但需要保留版本历史
总结：和现有销冠系统的核心差异
维度	销冠分身	CEO 分身
核心价值	教你怎么说	教你怎么想
知识结构	平铺的颗粒（场景 → 话术）	三层洋葱（事实 → 原则 → 人格）
知识来源	访谈为主、录音转录	文档为主、轻访谈校准
萃取方式	全自动 AI 萃取 grain	AI 候选 + 人工确认原则
首页形态	头像 + 三模式按钮	核心主张 + 领域地图 + 决策故事
QA 模式	直接给答案	给思考框架，教用户怎么想
Talk 模式	自由对话	苏格拉底式反问，深度推演
Practice 模式	销售话术对练	决策沙盘，暴露思考层次差异
人格表达	基于素材自然呈现	AI 学习 + 产品化可调节
持续机制	反馈调整 grain 权重	新素材 → 候选原则 → 版本管理
这些都是产品层面的思考，每一个设计选择都有对应的市场参照和创始人特点的考量。你看看这三个方向——整体怎么做、交互怎么做、知识怎么录入——有没有需要调整的？确认了整体方向，我们再来做具体的技术方案。
