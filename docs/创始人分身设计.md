CEO/创始人分身 — 产品设计思路
先回答一个底层问题：CEO 分身到底是什么？
我们现在的销冠分身，本质上是**"话术索引器"**——你遇到一个销售场景，它告诉你销冠会怎么说、怎么做。

如果把这个逻辑直接套到 CEO 身上，做成"CEO 语录搜索引擎"，那就完全错了。因为：

销冠的价值在话术（这个场景说什么话）
CEO 的价值在判断（这个局面怎么想、怎么决策）
所以 CEO 分身不应该回答"CEO 说过什么"，而应该回答**"如果 CEO 面对你现在的局面，他会怎么思考"**。

这是一个根本性的产品定位差异，它决定了后面的所有设计。

问题一：整体上怎么去做这个东西？
参考市场上的产品，目前有几类做法：
产品类型	代表	做法	优点	短板
文档问答型	Google NotebookLM、ChatGPT 自定义 GPT	上传文档 → RAG 检索 → 回答引经据典	来源可追溯、幻觉可控	只有"事实层"，没有"人格层"和"判断层"。问答像搜数据库，不像是跟人聊
人格扮演型	Character.AI	定义人设 → 自由对话	互动感强、有趣	知识没有根基，聊深了就会露馅。CEO 讲不出自己的真实故事和原则
知识萃取型	Delphi AI	结构化访谈 → 提取知识 → 教练式对话	有结构、有深度	互动形态比较单一、通用化，没有针对 CEO 这类角色做特别设计
决策辅助型	企业内部的决策系统	规则引擎 + 决策树	一致性强	太僵硬，捕捉不到 CEO 的灵活判断和直觉权衡
这四种路线，单独用哪一个都不够。 CEO 分身需要同时做到四件事：

知道 CEO 知道什么（文档问答型的根基）
像 CEO 那样思考和表达（人格扮演型的灵魂）
知识有结构、不散乱（知识萃取型的骨架）
能帮助用户做决策、而不仅仅是回答问题（决策辅助型的价值落点）
我的核心主张："洋葱模型"三层结构
CEO 的知识不能像销冠颗粒那样打散平铺，必须是分层的：


        ┌─────────────┐
        │  人格表达层   │  ← 怎么说：语气、用词、讲故事的方式、标志性表达
        │  ┌─────────┐  │
        │  │ 决策原则层 │  │  ← 怎么想：核心价值观、决策框架、判断标准、红线
        │  │ ┌───────┐ │  │
        │  │ │ 知识事实层 │  │  ← 知道什么：具体经历、做过的事、见过的案例
        │  │ └───────┘ │  │
        │  └─────────┘  │
        └─────────────┘
**最外层（人格表达层）**决定用户的感受——"嗯，这确实像他在说话"
**中间层（决策原则层）**决定分身的智力内核——"他会怎么判断这件事"
**最内层（知识事实层）**提供具体素材和引用依据——"他为什么这么判断、有过什么经历"
每一层有不同的建设方式和质量标准，不能混在一起。

这个三层模型的每一层怎么建设：

知识事实层 → 通过"素材上传 + 人工标引"建设

来源：战略文件、全员信、演讲、董事会纪要、对外访谈
处理方式：不拆散！保留文档完整性。AI 做的是"标引"（这份文档讲的是什么领域、包含了什么决策案例），不是"打散"
质量标准：引用准确、来源可查
决策原则层 → 通过"轻访谈 + AI 提炼 + CEO 确认"建设

来源：访谈 + 从素材中 AI 提取候选原则
处理方式：AI 从素材中提取候选原则 → CEO/助理审核确认 → 形成正式原则库
质量标准：每一条原则必须是 CEO 本人认可的，不能是 AI 猜测的
人格表达层 → 通过"素材学习 + 产品配置"建设

来源：演讲、访谈、内部讲话的音频/视频/文字
处理方式：AI 学习表达风格，但不编造。需要产品提供可调整的配置项（正式程度、简洁度、反问频率等）
质量标准：用户感觉"像"，但不追求 100% 模仿（过度模仿反而会恐怖谷）
问题二：交互上是什么样的？
首先要回答：谁来用？在什么场景下用？
CEO 分身的用户和销冠分身的用户是完全不同的人群：

销冠分身	CEO 分身
核心用户	一线销售、销售主管	高管、部门负责人、战略岗
使用场景	准备见客户、复盘拜访	做决策前对齐思路、理解战略意图
使用频次	高频、碎片化	中低频、深度使用
期望产出	具体话术、可执行的操作	思考框架、判断依据、决策信心
对话深度	浅-中	中-深
这意味着交互设计需要从"轻快对话"转向"深度思考辅助"。

首页/入口设计
现有销冠分身的首页是"头像 + 开场白 + 三个模式按钮"——这对于销售场景是够用的。但 CEO 分身的首页需要让人觉得"我进入了他的思考空间"，而不是"我开始跟一个机器人聊天"。

我建议首页的核心元素是：

1. 核心主张（一句话）
直接展示 CEO 最核心的一句话理念，比如："我判断一件事的标准是：它能不能让组织在三年后更强"。这句话不是 AI 生成的，是 CEO 本人确认的。它让用户一进来就知道"这个分身的底层操作系统是什么"。

2. 思考领域地图
可视化展示 CEO 的知识覆盖范围——战略、组织、产品、资本、文化等。每个领域显示的不是"有多少条数据"，而是"CEO 在这个领域有明确的判断原则"。这帮助用户建立预期：哪些问题他一定能聊，哪些可能超出范围。

3. 标志性决策故事
展示 3-5 个 CEO 做过的关键决策和背后的思考。这不是装饰——它是建立信任的工具。用户看到"这个分身确实知道 CEO 是怎么想问题的"，才愿意认真提问。

三种交互模式重新定义
现有系统的 QA / Talk / Practice 三个模式，本质上是为销售场景设计的。对于 CEO 分身，三个模式的内涵需要完全重新定义：

模式一：请益模式（对应 QA）

用户带着一个具体问题来，希望获得 CEO 视角的判断。

和销冠 Q&A 的核心差异：

销冠：直接给答案（"你应该这么说"）
CEO：给思考框架（"这个问题CEO会这样拆解..."）
交互流程：


用户提问 → AI 匹配相关原则 → 
展示：① CEO 怎么看待这类问题（原则）
      ② 为什么这么看（背后的逻辑）
      ③ 一个类似的真实案例
      ④ 需要注意的边界情况
这不是一问一答的客服模式，而是**"思维对齐"**——让用户学会像 CEO 一样思考这个问题。

模式二：推演模式（对应 Talk）

用户想跟 CEO 深入讨论一个话题，不是要答案，是要碰撞。

关键设计：AI 不能只顺着用户说。真正的 CEO 在 1:1 时会反问、会挑战假设。所以这个模式下，AI 应该有**"苏格拉底式反问"**能力——用户说了一个想法，AI 会追问："你有没有想过反过来的情况？"、"这个假设如果错了呢？"

这会让分身感觉更真实，因为好的 CEO 本身就是善于提问的，而不是善于给答案的。

模式三：决策沙盘（对应 Practice）

这是 CEO 分身最大的差异化功能，也是最能体现"创始人特点"的模式。

流程：


1. 系统给出一个商业场景（或用户自己描述）
2. 用户先表达自己的判断：怎么做、为什么
3. AI 展示：CEO 面对这个场景会怎么思考
   - 他会先问什么问题？
   - 他会用什么框架分析？
   - 他会考虑什么别人看不到的因素？
   - 最终他的判断倾向是什么？
4. 对比：用户的思路 vs CEO 的思路，差异在哪里
这个模式的价值不在于"对答案"，而在于暴露思考层次的差异。用户说自己判断的时候只能看到一层，AI 展示 CEO 能看到三层——这就是创始人经验的传递。

问题三：怎么录入他的知识库？
这是整个产品最难、也最重要的一环。录入质量决定了分身质量。

现在市场上常见的做法及问题：
做法	问题
全自动：丢一堆文档进去，AI 自动拆解	知识散乱、没有结构；AI 分不清重要和不重要的信息
纯人工：一个一个知识点录入	不现实，CEO 没时间，助理不知道 CEO 脑子里想什么
纯访谈：像销冠那样 4 个 phase 访谈	CEO 没时间，且 CEO 的知识不适合用对话来"萃取"
我的判断：需要一条新路——"素材先导入→AI 提取候选→人工确认"三阶段流程。

第一阶段：资产盘点（人工主导，AI 辅助）
在做任何事情之前，先搞清楚：CEO 有哪些东西可以拿来用？

这一步需要 CEO 的助理或战略负责人配合，做一次"知识资产盘点"：

列清单：战略文件、年度规划、全员信、董事会纪要、对外演讲、媒体采访、社交媒体发言……全部列出来
排优先级：不是所有素材同等价值。判断标准是——"这份材料里有没有体现 CEO 的判断逻辑？"
高价值：有明确立场和判断的（全员信、战略会发言）
中价值：有信息但判断不明显的（例会纪要、项目复盘）
低价值：纯信息传递的（通知、流程文件）
标记空白：哪些 CEO 一定会涉及的领域，但目前没有对应素材？
这一步的产出： 一份待处理素材清单 + 一份知识空白清单。

这一步看似简单，但极为关键。它决定了后续所有工作的质量基线。市场上很多产品失败就是因为跳过了这一步，直接开始"上传-处理"。

第二阶段：原则提炼（AI 主导，人工审核）
这是"洋葱模型"中间层——决策原则层的建设。也是 CEO 分身和销冠分身在录入环节最根本的差异。

销冠的萃取逻辑：从对话中提取"场景+话术+思路"三元组。话术是具体可执行的，所以可以做全自动。

CEO 的萃取逻辑：从素材中识别"原则+框架+判断标准"。这些是抽象的，AI 可以做候选，但最终必须人确认。

具体做法：

AI 阅读每一份高价值素材，提取候选原则，格式是：

原则陈述（一句话）：CEO 在这件事上的核心判断准则
原文依据（一段话）：素材中哪段话提炼出来的
适用场景：这个原则在什么情况下启用
反例/边界：什么情况下不适用
每条候选原则进入"待确认"状态。CEO 或助理可以：

✅ 确认：这就是我的原则
✏️ 修改：方向对但表述不准，手动调整
❌ 删除：AI 理解错了
所有确认的原则形成"原则库"，这是分身的核心资产。

为什么这一步必须有人工确认？ 因为原则是规范性命题（"应该怎么做"），不是描述性命题（"做了什么"）。AI 可以从素材推断，但无法区分"这是 CEO 深思熟虑的原则"还是"这是 CEO 某个场合随口说的一句"。只有人知道。

第三阶段：风格校准（AI 学习 + 可调节）
这一阶段建设"洋葱模型"最外层——人格表达层。

AI 自动学习：从演讲、访谈等素材中分析 CEO 的表达特征

句式偏好（长句/短句、抽象/具体）
举例习惯（用数据说话 / 用故事说话）
语气特征（直接/委婉、乐观/审慎）
标志性表达（口头禅、常用比喻）
产品化调节：不追求 AI 完美模仿，而是提供可调节的"表达风格"配置：

正式程度：高（对外演讲风格）/ 中（内部会议风格）/ 低（日常交流风格）
简洁程度：精炼直接 / 适度展开 / 充分论述
反问倾向：多反问用户 / 平衡 / 多直接回答
故事倾向：多用故事和案例 / 多用框架和逻辑
这样的好处是：

不过度模仿（避免恐怖谷效应）
可以根据场景切换风格（对外展示 vs 内部使用）
用户可以自己调整感受
第四阶段：持续生长（发布后的迭代机制）
CEO 分身不是一次性工程。CEO 在持续思考、不断产生新内容。分身需要能跟着一起进化。

关键的持续机制：

新素材接入：CEO 发表了新演讲、写了新全员信 → 自动进入候选池 → 标记"是否需要更新原则"
对话反馈闭环：用户问的问题、AI 的回答、用户的满意度 → 标记出"这个领域大家很关心但分身回答不够好" → 提示补充素材
原则版本管理：CEO 的想法可能会变化 → 原则不是写死的，可以更新，但需要保留版本历史
总结：和现有销冠系统的核心差异
维度	销冠分身	CEO 分身
核心价值	教你怎么说	教你怎么想
知识结构	平铺的颗粒（场景 → 话术）	三层洋葱（事实 → 原则 → 人格）
知识来源	访谈为主、录音转录	文档为主、轻访谈校准
萃取方式	全自动 AI 萃取 grain	AI 候选 + 人工确认原则
首页形态	头像 + 三模式按钮	核心主张 + 领域地图 + 决策故事
QA 模式	直接给答案	给思考框架，教用户怎么想
Talk 模式	自由对话	苏格拉底式反问，深度推演
Practice 模式	销售话术对练	决策沙盘，暴露思考层次差异
人格表达	基于素材自然呈现	AI 学习 + 产品化可调节
持续机制	反馈调整 grain 权重	新素材 → 候选原则 → 版本管理
这些都是产品层面的思考，每一个设计选择都有对应的市场参照和创始人特点的考量。你看看这三个方向——整体怎么做、交互怎么做、知识怎么录入——有没有需要调整的？确认了整体方向，我们再来做具体的技术方案。



核心判断
现有销冠系统的 RAG 是"短颗粒 + 向量相似度检索"，这套东西不能直接搬到创始人分身。原因是检索的对象变了：

维度	销冠系统	创始人分身
知识粒度	短颗粒（场景+话术）	长文档 + 结构化原则 + 立场
用户问题	场景明确的问句	模糊的、跨领域的判断请求
检索目标	找"最像的一段话术"	找"支撑判断的原则 + 证据"
答案要求	具体、可执行	有据、可追溯、有边界
如果还是拿 GrainRetriever 那套向量相似度去搜 CEO 的长文档，得到的会是**"字面上相关、判断上无关"**的碎片。

我的方案：分层检索 + 混合召回 + 重排
1. 三层索引，分别建库

层	内容	检索用途
立场层	CEO 对具体议题的明确态度（"我们要不要多元化？我的立场是..."）	用户问"CEO 怎么看 X"，直接命中立场
原则层	结构化的判断原则（原则 + 适用场景 + 边界 + 反例）	用户问"这件事该怎么判断"，命中原则
证据层	原始文档 chunk（演讲、全员信、纪要的原文段落）	给原则/立场提供引用依据
三层分开建库，回答时先定位层，再取证据，而不是一锅烩。

2. 混合召回 + Rerank（现有系统缺的一环）

现有系统只有 dense 向量 + similarity 阈值分 tier，没有 rerank。创始人分身的回答质量，很大程度取决于"召回后重排"。建议：

召回：dense（语义）+ sparse（BM25 关键词）+ 结构化过滤（按议题标签）
重排：引入 rerank 模型（BGE-reranker / Cohere Rerank），因为原则类判断的语义相似度和最终相关性偏差很大
3. 引用与置信度是底线

商业化产品，创始人敢署名认可的前提是可追溯。每条回答必须能标注：

"这是创始人 X 在 Y 场合说的"（有原文）
"这是基于创始人原则的推断"（无原文，需明确标识）
这两者必须在 UI 和数据结构上严格区分，不能混。

4. 诚实的不确定性

RAG 最大的坑是"硬答"。创始人没覆盖的领域，系统要能返回"创始人未明确表态，但可以给你相邻领域的原则参考"，而不是强行召回低分文档。这需要设定一个明确的召回置信度阈值 + 空态处理。

市场依据
Perplexity 的成功证明"引用 + 溯源"是 AI 产品建立信任的核心；Notion AI 证明企业知识库问答的落点是"找到对的那段话"而非"生成漂亮的话"。创始人分身要两者兼得，但重心在溯源和诚实。

如何支持
我负责：索引 schema 设计、chunk 策略、混合检索 + rerank 的 pipeline、召回置信度阈值、溯源字段设计、golden set 评估集建设。

二、高级产品经理
核心判断
这个产品不能免费、不能泛化、不能做成"另一个机器人"。它的商业定位是："组织决策的对齐工具 / 创始人认知的继承机制"。

我的方案
1. 一句话价值主张

"创始人在场时你问不到、不好意思问、来不及问的问题，分身替创始人回答。"

这决定了产品的调性：它不是娱乐，不是工具集，是决策参考。

2. 用户分层与权限

用户	场景	权限建议
核心高管	重大决策前对齐思路	全量知识 + 深度对话
中层管理者	理解战略意图、准备向上汇报	全量知识，部分敏感议题受限
新员工	理解公司文化、判断标准	公开原则层 + 脱敏内容
外部（投资人/合作伙伴）	了解创始人思路	仅限对外公开立场
权限分级不是技术细节，是商业化前提——同一套知识库，不同人看到不同深度的内容。

3. 商业模式

这是高端付费功能，单独定价（按分身数量 + 企业级订阅），不做免费入口
构建成本高（需要 CEO 本人时间 + 人审），价值密度高，必须收费
未来可扩展为"高管分身矩阵"（CTO/CFO/CMO），所以产品要抽象成"决策者分身"而非写死 CEO
4. 产品形态：单一对话，不设模式

用户进来就是一个对话，AI 根据问题类型自动决定回答方式。"深度/快速"是一个控制回答长度的开关，不是模式切换。 这跟你说的"不要套三模式"完全一致——创始人分身不需要用户先选"我是来请益还是来推演"，用户就自然地提问。

5. 成功指标

不是"对话数"，而是：

回答可信度（引用准确率、幻觉率）
决策对齐度（用户是否在真实决策中参考了分身）
知识覆盖率（用户高频问题中，多少是分身能答好的）
创始人认可度（创始人自己愿不愿意把这个分身推给高管用）
市场依据
Delphi AI、Personal.ai 证明"数字分身"有真实需求，但它们的短板是没有针对"决策者"这个角色做深度设计。Notion AI 证明了知识问答的价值，但它没有"人格"。创始人分身的差异化就是**"决策判断 + 人格 + 溯源"三位一体**。

如何支持
我负责：PRD、用户分层与权限模型、价值主张、商业模式、成功指标、创始人审批流程（哪些原则要创始人亲自确认）。

三、高级技术专家（系统架构）
核心判断
这个需求的架构难点不在对话，在"构建链路"。对话是现有的（复用 SSE、ChatStream），但**"如何把 CEO 的知识变成可检索的结构化资产"**是全新的。

我的方案
1. 数据模型：不能复用 ExperienceGrain

现有 ExperienceGrain（场景+话术+思路+embedding）是为销售颗粒设计的。创始人需要新实体：


素材 (Material) ──清洗──▶ 候选原则 ──人审──▶ 原则 (Principle)
                                    │
素材 (Material) ──切片──▶ 证据块 (Chunk) ──向量化──▶ 证据索引
                                    │
对话/演讲 ──风格分析──▶ 人格配置 (Persona Config)
核心新实体：

Principle（原则）：陈述 + 原文依据 + 适用场景 + 边界/反例 + 版本 + 状态(候选/已确认/已废弃)
Stance（立场）：CEO 对具体议题的明确态度，含原文引用
PersonaConfig（人格配置）：风格参数（正式度、简洁度、反问倾向等）
2. 构建 pipeline（异步，复用现有框架）


上传素材 → 清洗(复用 MaterialCleaningService) → 
AI 提取候选原则(@Async) → 人审工作台 → 确认入原则库 → 向量化
复用现有的 @Async / Scheduler / 线程池框架，但 pipeline 本身是全新的，因为提取的目标从"话术"变成了"原则"。

3. 对话编排：借鉴现有三段式，但内容重构

现有 ChatStreamService 的 setup → stream → post 三段式结构可以借鉴，但每段内容完全不同：

setup：意图识别（是问判断/立场/事实）→ 分层检索 → 组装"原则 + 证据 + 边界"
stream：带原则约束 + 风格注入的生成
post：溯源组装（区分"原文"vs"推断"）
4. 合规与隔离（商业化底线）

创始人分身涉及企业最高层敏感信息，必须：

多租户隔离（复用 TokenContext + CompanyScopeService）
完整审计日志（谁问了什么、AI 答了什么、引用了什么）
私有化部署选项（部分企业不接受云端存 CEO 思想）
5. 可扩展性：抽象成"决策者分身"

不要写死 CEO。设计成 Skill.type = 'executive' 或独立的分身类型，未来 CTO/CFO 分身复用同一套架构，只是知识域不同。

如何支持
我负责：新数据模型设计、构建 pipeline 架构、对话编排重构、权限与审计方案、与现有系统的接口边界（哪些复用、哪些新建）。

四、高级 UI 设计师
核心判断
调性错误是这个产品最容易翻车的地方。 如果创始人分身做成"圆润可爱、活泼俏皮的聊天机器人"，产品就废了。它必须给人"顾问 / 智囊 / 思想档案"的分量感。

我的方案
1. 视觉调性

维度	销冠分身	创始人分身
气质	亲切、实用	克制、权威、留白
参照	客服/教练	高端咨询、私人银行、Notion 的克制感
色彩	品牌主色	低饱和、深色为主、金色/暗金点缀
动效	活泼	沉稳、少而精准
2. 回答不是"气泡"，是"判断卡片"

创始人分身的回答更长、更有结构，传统的一条条气泡会让人读着累。建议用回答卡片分层呈现：


┌─────────────────────────────┐
│ 核心判断（一句话）            │
│ ─────────────────────────── │
│ 展开：判断依据（原则）         │
│       + 案例/证据            │
│       + 边界与反例           │
│ ─────────────────────────── │
│ 📎 引用：原文来源（可折叠）    │
│ ⚠️ 标注：AI推断/原文         │
└─────────────────────────────┘
3. 溯源交互：一键展开，不打断阅读

引用不能是"点开一个新页面"，而应该是内联展开——点一下"原文依据"，那段原文在原位置展开，读完再收起。这是信任的关键。

4. 人设页：思想档案，不是模式选择页

创始人分身的入口页应该像"思想档案 / 顾问介绍"，展示：

核心主张（一句话）
关注领域（可视化的领域覆盖）
代表性观点（3-5 条标志性判断）
没有任何"模式按钮"。用户进来就是对话。

5. 诚实的空态

CEO 没覆盖的领域，UI 要优雅呈现"创始人未明确表态"，并主动给相邻领域的参考，而不是硬挤一个错误答案。

市场依据
Notion AI 证明了"克制、留白"的界面能承载深度思考型内容；Perplexity 证明了"引用内联展开"是深度问答的最佳交互。创始人分身要把两者融合，同时拔高调性。

如何支持
我负责：设计系统扩展（新的视觉 token）、回答卡片组件、溯源交互、人设页设计、空态与不确定性呈现、移动端适配。

五、高级技术专家（AI/算法）
核心判断
创始人分身最难的算法问题不是"生成"，而是**"像创始人那样思考，同时不编造创始人没说过的话"**。这两者是矛盾的，需要在算法层面精确拿捏。

我的方案
1. 判断链（Chain of Thought 的顺序设计）

让 AI 模拟创始人的思考顺序，而不是直接给结论。生成时强制走：


先明确原则（我判断这件事的准则是什么）
→ 再分析（当前情况适用哪条原则、为什么不适用另一条）
→ 再结论（所以我的判断是...）
→ 最后边界（什么情况下这个判断不成立）
这个顺序本身，就是"创始人思维"的体现。它不是 prompt 里的一句话，是要固化的生成结构。

2. 幻觉控制：三条硬约束

创始人分身的红线是"不能替创始人说没说过的话"。三条硬约束：

约束	实现
溯源绑定	每条判断必须绑定检索到的原则/文档，无据不判断
降级机制	召回置信度不足时，明确说"创始人未表态"，不硬答
结构化输出	判断 / 依据 / 边界 强制分离，AI 不能把推断伪装成原话
3. 人格一致性：不是人设 prompt，是"原则约束 + 风格适配"

原则约束：检索到的原则作为生成时的强约束（类似 constrained decoding 的思路，但用 prompt 层实现）
风格适配：基于创始人语料做风格规则提取（句长、用词、比喻习惯、反问频率），注入生成，而不是简单一句"你要像一个 CEO 说话"
可控性：风格做成可调节参数（正式度/简洁度/反问倾向），用户可调
4. 原则提炼算法（构建侧的难点）

"从 CEO 语料中提炼原则"不是简单抽取，而是：


分段归纳 → 候选原则生成 → 相似原则聚类去重 → 人工确认 → 版本合并
需要多轮 LLM 归纳 + 相似度聚类，且必须有人工确认环节——因为 AI 无法区分"这是 CEO 深思熟虑的原则"还是"某个场合随口一说"。

5. 评估体系

商业化必须能量化：

引用准确率（回答引用的原则/文档是否真实相关）
幻觉率（回答中有多少是编造的）
风格相似度（回答风格和创始人真实语料的距离）
原则命中率（用户问题是否命中了正确的原则）
需要建 golden set（人工标注的标准问答对）+ 自动化评估 + 人工抽检。

市场依据
Character.AI 证明"人格"能极大提升 AI 产品的吸引力，但它的短板是知识无根基、聊深了露馅；Perplexity 证明"溯源 + 诚实"是知识型 AI 的信任基石。创始人分身要把"人格"和"溯源"焊在一起，这是市面上还没人做好的事。

如何支持
我负责：判断链的生成结构设计、幻觉控制策略、人格一致性的风格注入方案、原则提炼算法、评估体系与 golden set 建设。

五位角色的核心共识与分歧
✅ 共识
不能复用销售 grain 那套，需要全新的知识结构和检索架构
"诚实的不确定性"是底线——没覆盖就明说，绝不硬答
溯源与"原文 vs 推断"的区分是商业化前提
知识录入必须"AI 候选 + 人工确认"，不能全自动
调性必须是"决策顾问"，不是"聊天机器人"
⚠️ 需要创始人拍板的核心分歧
最根本的一个问题，决定一切设计方向：这个分身的"判断自由度"到哪一步？

这是贯穿所有角色的分歧：

保守派（偏 RAG 工程师视角）：分身是"创始人思想的忠实引用者"——只答有据可查的，绝不推断
激进派（偏 AI 算法视角）：分身是"创始人思维的模拟器"——基于原则敢给判断，标注"这是推断"
这两者的产品形态、技术方案、风险敞口完全不同



创始人分身 — 整体方案（定稿版）
一、产品定位（一句话）
把创始人的"判断力"做成组织可调用的资产——创始人在场时问不到、不好意思问、来不及问的问题，分身替他回答，且每个回答都能追溯到"他是怎么想的"。

这不是"CEO 语录搜索"，也不是"聊天机器人"，是决策对齐工具。

二、四条铁律（贯穿所有设计，不可妥协）
诚实优先于聪明——没覆盖的领域就明说"创始人未表态"，绝不硬答、绝不编造。
溯源是底线——每条判断必须区分"创始人原话"vs"基于原则的推断"，这是创始人敢署名的前提。
原则必须人确认——AI 只提候选，最终原则必须创始人/助理点头，AI 不能替创始人"想"。
调性是顾问，不是客服——克制、权威、有分量，不是圆润可爱的机器人。
三、知识如何录入（已确认：文档 + 轻确认）

① 资产盘点（人工主导）
   助理/战略负责人列清单：战略文件、全员信、演讲、董事会纪要、对外访谈
   排序：高价值（有明确判断）> 中价值（有信息无判断）> 低价值（纯信息）
   标记知识空白

② 原则提炼（AI 候选 + 人工确认）
   AI 阅读每份高价值素材 → 提取候选原则
   （原则陈述 + 原文依据 + 适用场景 + 边界/反例）
   → 创始人/助理逐条：✅确认 / ✏️修改 / ❌删除
   → 确认后的原则形成"原则库"（分身的核心资产）

③ 风格校准（AI 学习 + 可调节）
   从演讲/访谈学习表达特征（句长、用词、比喻、反问频率）
   做成可调节参数（正式度/简洁度/反问倾向），不追求 100% 模仿
四、分身如何回答（已确认：混合模式）
默认：忠实引用。用户提问 → 检索命中原则/立场/证据 → 按"判断链"回答：


先明确原则 → 再分析当前情况 → 再下结论 → 最后说明边界
每条判断都带溯源（哪条原则、哪份文档）。

显式推演：用户明确要求"推演/假设"时 → 基于原则做推断 → 显著标注"此为推断，非创始人原话"。

五、展示形态（不设模式）
入口页 = 思想档案（不是模式选择页）：

核心主张（创始人确认的一句话）
关注领域（可视化覆盖）
代表性观点（3-5 条标志性判断）
对话 = 单一形态：用户进来就提问，AI 根据问题类型自动决定怎么答。"深度/快速"是控制回答长度的开关，不是模式。

回答以"判断卡片"呈现（不是气泡）：


┌─────────────────────────────┐
│ 核心判断（一句话）            │
│ 判断依据（原则）+ 案例/证据   │
│ 边界与反例                   │
│ 📎 原文引用（内联可展开）     │
│ ⚠️ 标注：原话 / AI推断       │
└─────────────────────────────┘
六、商业化
高端付费，单独定价（按分身 + 企业级订阅），不做免费
权限分级：核心高管（全量+深度）> 中层（全量，部分敏感受限）> 新员工（公开原则+脱敏）> 外部（仅公开立场）
可扩展：抽象成"决策者分身"，未来 CTO/CFO/CMO 复用




"内部高管优先"已锁定，这其实让"敏感信息"这个问题变简单了——第一版只给核心高管用，本身就是一个天然的隔离层。但"没想好"说明这个问题需要拆开来看，因为它不是一个决策，是三个。

敏感信息，其实是三个独立的决策
我们常常把这三个混在一起谈，导致"没想好"：

决策点	问题	例子
① 采集端	什么内容能进知识库？	未公开的并购谈判，能不能作为素材录入？
② 输出端	什么内容能被 AI 说出来？	即使进库了，AI 回答时能不能引用薪酬、人事信息？
③ 权限端	谁能看到这些回答？	同样是内部，CEO 和 HR 和销售VP 能看的不一样吗？
"没想好"往往是因为把这三个绑在一起想了。实际上它们可以分别独立决策，而且 MPP 阶段可以先把 ② 和 ③ 做保守、把 ① 放开。

我的建议：分阶段处理
MVP（内部高管优先）阶段，采用"宽进严出"策略：

① 采集端：全收，不打标签。 素材照常录入，不设"敏感"开关。理由：第一版只有高管用，且打标签这件事（人工标注"这段敏感"）成本高、容易漏，MVP 阶段不值得投入。
② 输出端：默认拦截，白名单放行。 这是真正的底线。AI 回答时，凡是涉及薪酬、具体人事（谁离职/谁晋升）、未公开交易、法律风险的内容，默认不引用、不回答，转成"这个我建议你直接问创始人本人"。这不是技术限制，是一段系统约束（prompt 层 + 检索层双重过滤），成本很低。
③ 权限端：MVP 只做一层——"高管全量"。 因为第一版只有高管用，不需要分级。等未来扩展到全员/外部时，再引入权限分级。
这样做的好处：

采集端不打标签 → 创始人/助理录入零负担
输出端白名单拦截 → 商业合规底线守住了，且实现简单
权限端单层 → MVP 复杂度最低
代价： 敏感内容进了库但 AI 不会说出来——这意味着分身在"薪酬、人事、未公开战略"这些领域是"哑"的。但对 MVP 来说，这恰恰是对的：这些领域本来就该创始人本人亲口说，分身不该替。

这样决策的底层逻辑
创始人分身的价值在于决策判断的对齐（战略、组织、产品、资本这些"想问题的方式"），而敏感信息本质上是"事实"而非"判断"。分身的核心资产是"原则"，不是"信息"。所以敏感信息被拦截，并不削弱分身的核心价值——它只是让分身在"该创始人亲口说的事"上闭嘴，而这正是应该的。

产品方案定稿

## 新需求：创始人(CEO)分身

### 产品方案定稿（这是硬约束，不要改变）
1. **定位**：把创始人判断力做成组织资产——决策对齐工具，不是语录搜索、不是聊天机器人
2. **知识结构**：三层洋葱模型
   - 事实层：原始文档chunk（演讲、全员信、纪要），保留完整性，做标引不打散
   - 原则层：结构化判断原则（原则陈述+原文依据+适用场景+边界反例+版本+状态），这是核心资产
   - 人格层：表达风格（正式度/简洁度/反问倾向，可调节参数）
3. **录入路径**：文档+轻确认。资产盘点(人工列清单)→AI提取候选原则→创始人/助理审核(✅确认/✏️修改/❌删除)→风格校准
4. **回答方式**：混合模式。默认忠实引用+判断链(先明确原则→再分析→再结论→最后边界)；用户显式要求"推演"时才基于原则推断并显著标注"此为推断，非创始人原话"
5. **敏感信息**：宽进严出——素材照常录入不打标签，但AI输出时对薪酬/人事/未公开交易/法律风险默认拦截，转"建议直接问创始人"
6. **首发**：内部高管优先，MVP单层权限
7. **展示**：思想档案入口页(核心主张+领域地图+代表性观点)+单一对话+判断卡片(内联溯源、原话/推断标注)，不做QA/Talk/Practice三模式

3. **对话编排**：借鉴ChatStreamService的setup→stream→post三段式，但内容重构为：意图识别(判断/立场/事实)→分层检索(原则优先，文档补证据)→判断链生成→溯源组装(区分原话vs推断)。需要设计分层索引策略和混合检索+rerank
