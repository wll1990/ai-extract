# 系统说明书

> 本文说明系统是什么、怎么组织、有哪些边界。操作步骤见《操作手册》或系统内 `/help`。

## 一、系统解决什么问题

它把销冠在真实客户沟通里的判断、话术和边界，变成可以被检索、被引用、被反复使用的经验颗粒，再由分身以对话的方式提供出来。

它不替代 CRM，也不自动生成销售策略。它解决的是「经验在人脑子里、带不走」的问题。

## 二、角色与权限

- `super_admin`：平台级，建企业、发注册码、看全平台数据。
- `company_admin`：企业级，管用户、分身、素材、知识、培训。
- `employee`：员工级，用分身、传素材、做复盘、参加培训。
- 教练/学员不是独立角色，由 `TRAINING_REVIEW` / `TRAINING_LEARN` 等权限组合决定。

权限码由后端 `RolePermissions` 统一下发，前端不维护第二份角色映射。

## 三、数据关系

企业 → 用户 → 空间 → 分身 → 经验颗粒。

知识和案例按企业隔离：`company_id` 为空表示平台公共内容，非空表示租户私有。

素材是原料，颗粒是检索单元，分身是回答入口，复盘和培训是使用场景。

## 四、四条核心链路

1. **素材萃取**：上传 → 解析 → 清洗 → 提取 → 向量化 → 待审核。
2. **销冠访谈**：AI 四阶段访谈 → 六章报告 → 颗粒。
3. **分身对话**：检索颗粒/知识/案例 → 生成回答 → 附溯源。
4. **销售复盘**：对话切段 → 六区块报告 → 线索/任务。

## 五、状态字典

| 对象 | 状态 |
|---|---|
| 分身 | `generating` / `reviewing` / `published` / `discarded` / `paused` / `draft` |
| 素材 | `uploaded` / `parsed` / `cleaning` / `analyzing` / `analyzed` / `extracted` / `rejected`；失败中间态 `parse_failed` / `cleaning_failed` |
| 复盘 | `active` / `report_ready` / `converted` / `closed` |
| 报告 | `queued` / `generating` / `ready` / `failed` |
| 知识/案例 | `draft` / `pending` / `active` / `deprecated`；过期由 `expireAt` 派生为 `expired` |
| 培训计划 | `draft` / `published` / `retired` |
| 培训批次 | `active` / `completed` / `cancelled` / `archived` |
| 认证 | `pending` / `confirmed` / `remediating` / `revoked` |

## 六、能力边界

- 经验颗粒没有版本号，不能回滚；编辑后按场景标签、场景描述、适用条件重新计算向量。
- 颗粒不能合并或拆分；废弃是软删除。
- 只改专家思考或标准话术不会改变检索命中，它们仍然是回答时引用的内容。
- 教练补充单独存 `review_coach_note`，不改写 AI 报告，也不进入经验颗粒。
- 发布前有三道硬校验（活跃颗粒 ≥ 10、场景 ≥ 3、画像四字段齐全），但没有独立审批流和发布回滚。
- C 端用户发布自己的分身时没有颗粒数/场景数门槛。
- 文件支持格式以《操作手册》第 02 节为准；不支持的格式会明确拒绝。
- 检索不到依据时会拒答并记录知识缺口，不会编造经验。
- 满意度是历史累计口径，不是今日；活跃分身是近 7 天有对话的分身。
- 知识缺口不会自动消失：补颗粒时自动关闭对应缺口，没有关联到缺口的新增颗粒需要手动标记。

## 七、常见问题

完整问答见系统内 `/help` 的 FAQ。三个最容易误会的点：

1. 满意度是历史累计，不是今日。
2. 活跃分身是近 7 天有对话，不是已发布数。
3. 缺口不会自动消失，补完颗粒后由系统标记为已解决。

## 八、术语表

| 术语 | 定义 |
|---|---|
| 经验颗粒 | 一条可检索的场景化经验，含场景、思考、话术、常见错误、适用条件 |
| 分身 | 由颗粒与画像组成的对话角色 |
| 知识缺口 | 检索全部找不到依据时记录的待补问题 |
| 溯源 | 回答引用了哪些颗粒，以及颗粒对应的原文 |
| 技能场景化 | 把颗粒组织成情境、FAQ 和对练开场白 |
| 教练补充 | 教练在 AI 报告之外写的人工判断，独立存储，不改写报告 |
