## 一、认证模块



### 1\. POST /api/v1/auth/login



**实现步骤**：

1. 接收 `companyId`、`account`、`password`

2. 查询 `user` 表，匹配 `company_id` 和 `account`

3. 如果用户不存在 → 返回404

4. 验证 `password_hash`（BCrypt）

5. 如果密码错误 → 返回401

6. 检查 `is_active = true`

7. 生成JWT Token：payload包含 `userId`、`companyId`、`role`，有效期24小时

8. 返回Token和用户信息

    

---



### 2\. POST /api/v1/auth/register



**实现步骤**：

1. 接收 `companyId`、`name`、`account`、`password`、`role`

2. 查询 `user` 表，校验 `account` 在企业内唯一

3. 如果重复 → 返回400

4. 密码BCrypt加密

5. 插入 `user` 表

6. 生成JWT Token

7. 返回Token和用户信息

    

---



### 3\. GET /api/v1/auth/me



**实现步骤**：

1. 从JWT中提取 `userId`

2. 查询 `user` 表

3. 关联查询 `company` 表获取 `companyName`

4. 返回用户信息

## 二、空间模块

6. 关联查询 `report` 表统计 `reportCount`

8. 分页返回

## 三、访谈模块



### 8\. POST /api/v1/interviews



**实现步骤**：

1. 从JWT提取 `userId`

2. 查询 `space` 表，校验 `spaceId` 存在且 `user_id=当前用户`

3. 解析 `expertSkillId` 参数：

    - 不传 → 使用综合Skill

    - 传 `"none"` → 基础版，不加载萃取师经验

    - 传具体ID → 查询 `expert_skill` 表验证存在且 `status='active'`

4. 解析 `inviteCode`（如果传入，校验有效性）

5. 插入 `interview_session` 表：

    - `status='created'`

    - `current_phase='opening'`

    - 所有 `collect_*=false`

    - `expert_skill_id` = 传入值或NULL

    - `invite_code`、`invited_by`（如果适用）

6. 生成开场引导消息：

    - 判断该 `space_id` 是否有已完成访谈（`status='completed'`）

    - 首次 → 完整版引导；再次 → 简化版

    - 根据 `expertSkillId` 选择引导模板

7. 开场引导消息存入 `interview_message` 表（`role='ai'`, `phase='opening'`, `depth=-1`）

8. 返回会话信息

    

---



### 9\. GET /api/v1/interviews/\{sessionId\}



**实现步骤**：

1. 查询 `interview_session` 表

2. 校验权限（会话所属空间的所有者 or 超管）

3. 映射 `current_phase` 为中文标签

4. 映射 `collect_*` 字段为采集状态

5. 返回会话状态

    

---



### 10\. POST /api/v1/interviews/\{sessionId\}/chat（SSE核心接口）



**实现步骤**：

1. 查询 `interview_session` 表

2. 校验 `status` 为 `created` 或 `in_progress`

3. 如果 `status='created'` → 更新为 `'in_progress'`

4. 用户消息存入 `interview_message` 表

5. 构建对话上下文：

a\. 加载 `interview_system.md`（基础System Prompt）

b\. 查询 `interview_session.expert_skill_id`：

- 不为空且不为"none" → 调用Python `expert_loader.py` 加载对应MD文件 → 替换 `{expert_tacit_knowledge}`

- 为空 → `{expert_tacit_knowledge}` 替换为空字符串

c\. 从 `interview_message` 表加载最近20条历史（按 `created_at` 升序）

d\. 读取 `current_phase` 和 `collect_*` 状态，注入到上下文中

6. 调用Python AI服务（内部REST `POST /internal/chat`）：

    - 传入完整消息列表

    - `stream=true`

7. 将AI返回的文本块封装为SSE事件推送给前端：

    - `chunk` → 文本片段

    - `phase_change` → 更新 `interview_session.current_phase`

    - 采集标记 → 更新对应 `collect_*` 字段

    - `done` → 流结束

8. AI完整消息存入 `interview_message` 表

9. 如果四阶段完成 → 更新 `status='completed'` → 触发异步报告生成任务

10. 更新 `last_active_at=NOW()`

7. 作为 `role='system'` 消息注入

8. 调用大模型 → SSE流式返回衔接消息

## 九、IM集成模块



### 44\. POST /api/v1/im/\{channel\}/callback



**实现步骤**：

1. 验证签名（飞书/企微各自的验证方式）

2. 解析消息：提取 `userId`、`chatId`、`chatType`、消息文本、@的机器人

3. 匹配 `im_channel` 表 → 获取 `skillId`

4. 生成 `sessionId = "{channel}_{chatId}_{userId}"`

5. 检测首次对话：

    - Redis中无该 `sessionId` 的历史 → 返回欢迎消息 → 存入Redis

6. 识别对话模式：

    - `/对练` 或 `/练习` → `practice`

    - `/讨论` 或 `/聊聊` → `discuss`

    - 匹配 `你怎么看|为什么|你觉得` → `discuss`

    - 其他 → `quick`

6.5 检测展开关键词（追问上一轮案例详情）

    触发条件：消息内容匹配 `展开` 或 `展开案例` 或 `展开讲讲` 或 `详细说说`，
    且该 `sessionId` 在 Redis 中有历史对话记录，
    且上一轮分身回答中包含了 `[grain:uuid]` 标记。

    实现逻辑：
    1. 从 Redis 中读取该 `sessionId` 的最近一轮对话
    2. 提取上一轮分身回答中的 `grainId`（格式：`[grain:uuid]`，前端不可见）
    3. 调用 `SkillService.chat()`，传入 `message=请展开讲讲你刚才提到的案例`，
       `mode=discuss`，`context=该 grainId 对应的完整锦囊内容`
    4. 返回案例详细内容（案例先导风格）

    如果无法识别上一轮的 `grainId`，返回提示：
    "抱歉，我找不到刚才提到的具体案例了。你可以再问我一个问题，
    或者试试 /讨论 模式深入聊聊。"

7. 调用 `POST /skills/{skillId}/chat`（内部调用）

8. 转成IM消息格式（Markdown）

9. 调用IM API回复（群聊中@提问者）

10. 对话存入Redis（过期30分钟）
