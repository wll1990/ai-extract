# 试问台与对话式纠偏 · 技术设计 v2

> 状态：已按两轮评审修订（技术 + 产品/体验）· 2026-11-18
> 关联：`docs/28-素材到分身完整生命周期.md`、`docs/38-评测中心与新人培训前后端流程设计.md`

## 修订记录（v1 → v2）

| # | v1 的问题 | v2 的处理 |
|---|---|---|
| 1 | 靠 `record`/`skill.status` 推断“试问不落库” | 新增显式 `persistMode`，贯穿 Chat/RAG 全部写库点（含 `grain_retrieve_log`、`knowledge_gap`） |
| 2 | 多轮试问复用 `request.history` | 新增 TrialHistoryProvider，从 `skill_trial_message` 按 session 组装 |
| 3 | `assertSkillReadable` 不存在，`requireSkillReadable` 对 published 不做企业校验 | 改用 `canAccessSkill`（含 acting-company），跨企业返回 404 |
| 4 | 误以为 `refreshEmbedding` 是异步 | 拆成「短事务提交 → 跨 Bean 异步重建 → 可查询状态」 |
| 5 | 流式人话 + 末尾 JSON 自相矛盾 | 单次非流式 `call()` 出 JSON，SSE 结束时下发，全程跑在 boundedElastic |
| 6 | 并发 apply 静默覆盖 | `base_*` 比对 + 409；状态机补 `reverted`；写编辑历史 |
| 7 | `done{sessionId}` 前端拿不到 | 用 `meta` 与自定义 `refine` 事件，payload 放 `data` |
| 8 | DDL 在 `ddl-auto: validate` 下会失败 | JSONB 显式映射、CHECK、索引、幂等键、纳入清理任务 |

**两处产品决策同时改了**（评审结论）：

- **已发布分身不允许“直接改库”**：属主只能提交修改建议，管理员可直接改但需二次确认
- **取消“自动复测”**：改为索引就绪后由用户点「用这个问题再问一次」

## 1. 背景与现状缺口

链路：素材 → 萃取 → 审核 → **发布** → 使用 → 反馈 → 再生产。

| 缺口 | 代码现状 |
|---|---|
| 发布前无法验证 | `/admin/skills/{id}/audit` 无试问入口 |
| 发布前对话不留痕 | `ChatStreamService`：`record = "published".equals(status)` |
| 属主没有入口 | employee 无 `SKILL_MANAGE`/`DASHBOARD_VIEW`；`/skill/{id}/insights` 无任何链接 |
| 纠正只能填表单 | `GrainCorrectionService.submit` 收文字建议，无对话式修订 |
| 改完看不到效果 | 无“改完再问一遍”的闭环 |

## 2. 目标与非目标

**目标**

1. 属主与管理员在发布**前**试问，能看到本次引用哪几条经验
2. 对不满意的经验用自然语言描述，AI 落成结构化修订，红绿 diff 对照
3. 确认后写回颗粒、重建向量，**索引就绪后**可一键复测并对比
4. 试问数据与真实员工数据**零交叉**，但可回看

**非目标**：向量手工编辑；多人协同编辑合并；知识库/案例库版本机制改造；评测中心（题集跑分）改造。

**校验顺序（必须写在返回 Flux 之前）**

```java
// 1) 企业隔离：published 也必须校验（requireSkillReadable 的 published 分支直接放行，不能用）
if (!companyScopeService.isUnrestrictedDataScope()
        && !companyScopeService.canAccessSkill(skillId)) {
    throw new BusinessException(404, "分身不存在");   // 跨企业统一 404
}
// 2) 组织分身不在本期范围
if ("organization".equals(skill.getType())) throw new BusinessException(400, "组织分身暂不支持试问");
// 3) 角色/属主
if (!hasPermission(SKILL_MANAGE) && !isSpaceOwner(skill.getSpaceId(), TokenContext.get())) {
    throw new BusinessException(403, "无权试问该分身");
}
```

**路径**：全部挂在 `/skills/{skillId}/...`（`SecurityConfig` 的 `/skills/**` 已覆盖，只需 `SKILL_USE`），业务校验在 Service。

## 5. 数据模型（Flyway V105）

```sql
CREATE TABLE IF NOT EXISTS skill_trial_session (
  id            UUID PRIMARY KEY,
  skill_id      UUID NOT NULL,
  user_id       UUID NOT NULL,
  first_question VARCHAR(200),                    -- 列表摘要，不单独维护 title
  message_count INT NOT NULL DEFAULT 0,
  created_at    TIMESTAMP NOT NULL DEFAULT now(),
  updated_at    TIMESTAMP NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_trial_session_owner ON skill_trial_session(skill_id, user_id, updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_trial_session_skill ON skill_trial_session(skill_id, updated_at DESC);

CREATE TABLE IF NOT EXISTS skill_trial_message (
  id                UUID PRIMARY KEY,
  session_id        UUID NOT NULL REFERENCES skill_trial_session(id) ON DELETE CASCADE,
  skill_id          UUID NOT NULL,
  role              VARCHAR(16) NOT NULL CHECK (role IN ('user','assistant')),
  content           TEXT NOT NULL,
  meta              JSONB,                        -- {grainIds, grainTags, avgSimilarity, sourceNames, refineDraftId}
  client_message_id VARCHAR(64),                  -- 前端幂等键
  created_at        TIMESTAMP NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_trial_msg_client
  ON skill_trial_message(session_id, client_message_id) WHERE client_message_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_trial_msg ON skill_trial_message(session_id, created_at);

CREATE TABLE IF NOT EXISTS grain_refine_draft (
  id              UUID PRIMARY KEY,
  skill_id        UUID NOT NULL,
  grain_id        UUID NOT NULL,
  user_id         UUID NOT NULL,
  status          VARCHAR(16) NOT NULL DEFAULT 'draft'
                  CHECK (status IN ('draft','applied','discarded','reverted')),
  base_scene      TEXT, base_thought TEXT, base_script TEXT, base_mistake TEXT, base_condition TEXT,
  draft_scene     TEXT, draft_thought TEXT, draft_script TEXT, draft_mistake TEXT, draft_condition TEXT,
  changed_fields  JSONB NOT NULL DEFAULT '[]',    -- ["expertThought","standardScript"]
  transcript      JSONB,                          -- 多轮对话
  embedding_status VARCHAR(16) NOT NULL DEFAULT 'pending'
                  CHECK (embedding_status IN ('pending','ready','failed')),
  created_at      TIMESTAMP NOT NULL DEFAULT now(),
  applied_at      TIMESTAMP
);
CREATE INDEX IF NOT EXISTS idx_refine_grain ON grain_refine_draft(grain_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_refine_skill_status ON grain_refine_draft(skill_id, status);
```

**JPA 映射要点**（否则 `ddl-auto: validate` 启动失败）
- `meta` / `transcript` / `changed_fields`：`@JdbcTypeCode(SqlTypes.JSON)` + `columnDefinition = "JSONB"`（照 `AdminAuditLog`）
- 枚举用 `String` 字段 + 应用层校验
- 三张表纳入 `DataCleanupScheduler`（trial 会话保留 90 天，纠偏记录保留 180 天）

## 6. 接口

### 6.1 试问（SSE）

```
POST /skills/{skillId}/trial/chat
```

```json
{ "message": "客户三次改需求还改吗？", "sessionId": "uuid|null", "clientMessageId": "前端幂等键" }
```

- 忽略请求体里的 `conversationId`
- 事件沿用现有形状：`content` / `source` / `meta{sessionId,messageId}` / `error`
- **不新造 `done` 事件**（`sse.ts` 的 done 分支不透传 payload）

### 6.2 试问历史

```
GET /skills/{skillId}/trial/sessions?page=1&size=20      // 员工只看自己的；管理员看本企业
GET /skills/{skillId}/trial/sessions/{sessionId}         // 单独校验 session.userId / skillId
```

### 6.3 纠偏（SSE，内部非流式）

```
POST /skills/{skillId}/grains/{grainId}/refine
{ "draftId": "uuid|null", "message": "不是这样，我们从来先确认验收人" }
```

- 首次不传 `draftId`：**AI 成功之后**才在一个事务里插入 `base_* + draft_* + transcript`（失败不留半成品）
- 事件：`content`（AI 的 reply 全文，一次性）+ `refine{data:{draftId, fields, changed, confidence}}`
- 线程：`Flux.defer(...).subscribeOn(Schedulers.boundedElastic())`，鉴权在 Flux 外

### 6.4 应用 / 丢弃 / 回滚

```
POST .../refine/{draftId}/apply
POST .../refine/{draftId}/discard
POST .../refine/{draftId}/revert
GET  .../refine/{draftId}          // 取状态：status + embedding_status
```

`apply` 流程（不标事务）：

1. `assertCanApplyPublishedOrDraft(skill, grain)` —— 已发布分身仅管理员可 apply，且需 `{ confirm: true }`
2. `self.applyTx(draftId)`：校验 `status='draft'` → 重载 grain → **五段与 `base_*` 比对，不一致返回 409** → 写 grain 五段 → 写 `grain_edit_history` + `admin_audit_log` → draft 置 `applied`
3. 提交后调 `embeddingRefresher.refresh(grainId, draftId)`（跨 Bean `@Async("embeddingExecutor")`）
4. 返回 `{ draftId, changed, embeddingStatus: "pending" }`

`revert`：只允许**最新一条 applied**；比对当前五段与 `draft_*`，不一致 409；恢复 `base_*` 后状态置 `reverted`，再触发重建。

### 6.5 统计（并入审核 dashboard，不单独开接口）

审核 dashboard 增加：`trialCount`（session 数）、`refinedGrainCount`（distinct grain_id，`status='applied'`）、`lastTrialAt`（`max(updated_at)`）。

## 7. AI 编排

**Prompt**：`prompts/grain_refine.md`，`PromptLoader.format("grain_refine.md", vars)`

| 变量 | 说明 |
|---|---|
| `{grain_json}` | 当前五段（`PromptSecurity.wrapUntrusted` 包裹） |
| `{conversation}` | 纠偏对话（`wrapHistory`） |
| `{user_message}` | 本轮发言 |

**输出契约**（严格 JSON，允许 md fence）

```json
{
  "reply": "明白，我把专家思维和标准话术改了…",
  "fields": {"sceneDescription":"…","expertThought":"…","standardScript":"…","commonMistakes":"…","applicableCondition":"…"},
  "changed": ["expertThought","standardScript"],
  "confidence": "high"
}
```

- **`changed` 不信任模型**：服务端按 base/draft 实际差异重新计算
- 解析失败重试 1 次；仍失败发 `error`，不落草稿
- 落库前过 `PiiMasker.mask`
- 字段范围：五段 + `sceneTag`（仅在用户明确说“场景标错了”时改，2–4 字校验）

## 8. 试问链路隔离（本设计最关键的一处）

现有代码里 **6 个写库点**，不能靠状态推断：

| 写库点 | 现有行为 | trial 处理 |
|---|---|---|
| `skill_conversation` + user 消息 | `record` 控制 | 不写 |
| `skill_message`（assistant） | `record` 控制 | 不写 |
| `conversation_stats` | `doFinally` **无条件** save | 由 `persistMode` 门控 |
| `knowledge_gap` | `recordGap`（看 isTest） | 强制 false |
| `grain_retrieve_log` | **无条件**写 | 新增 `recordRetrievalLog=false` |
| `knowledge_case_retrieve_log` | `record` 控制 | 不写 |

实现：`SkillChatRequest.persistMode`（`REAL` 默认 / `TRIAL`），贯穿
`ChatStreamService.chat → chatIndividual`、`RagPipelineService.retrieve*/recordGap`、`logKcReferences`、stats 写入。

**token_usage_log 照常写**（成本核算需要），但不进入任何用户侧统计。

## 9. 事务、异步与并发

| 规则 | 落地 |
|---|---|
| HTTP 线程禁 AI | 试问/纠偏均为 SSE + `subscribeOn(boundedElastic)`；鉴权在 Flux 外 |
| 事务内禁 AI/HTTP | 纠偏 AI 调用在事务外；`applyTx` 只做 DB |
| `@Async` 不能写在事务内 | `apply` 非事务 → `self.applyTx()` → 返回后再调另一个 Bean 的 `refreshEmbeddingAsync` |
| 向量失败可观测 | draft 上 `embedding_status`，失败置 `failed`，前端给「重试」 |
| 并发 | `base_*`/`draft_*` 比对 + 409，不做合并 |
| ThreadLocal | `userId/companyId` 在返回 Flux 前捕获，回调里不读 `TokenContext` |

## 10. 前端

| 路径 | 组件 | 说明 |
|---|---|---|
| `/my/skills` | `MySkillsPage` | 复用 `GET /skills/my`；空态引导「上传素材 / 发起访谈」 |
| — | `TrialPanel` | 试问台：左侧问答、右侧引用经验 |
| — | `RefinePanel` | 纠偏：左对话、右 diff；**独立抽屉**，不混进试问消息流 |
| — | `TrialHistoryDrawer` | 试问历史 |

**交互契约**

- 试问台头部：分身头像 + `正在试问：张三的分身`；未发布时黄条
- 纠偏抽屉标题：`纠偏助手（只改经验，确认后才生效）`；打开时左侧对话冻结
- diff：按字段可单独勾选/编辑，不强制整条接受
- 应用后：toast `已更新 2 段内容` → 角标 `分身正在记住这条修改…` → `已记住`
- **索引就绪后**才点亮 `用这个问题再问一次`；结果区标题 `改前 / 改后（基于新经验）`，上方一行「引用变化：仍被引用（82% → 87%）」
- 检索为空：`本次没有引用到你的经验，回答来自通用能力` + 「查看知识缺口」，不显示「改这条」

## 11. 验收（可执行）

1. 销冠登录 → 菜单「我的分身」→ 列出未发布分身（`GET /skills/my`）
2. 试问 → 右栏出现引用经验；`/admin/grains/traceability` 改成属主可读接口后不再 403
3. **数据隔离**：试问 3 轮后，`skill_conversation / skill_message / conversation_stats / grain_retrieve_log / knowledge_gap / knowledge_case_retrieve_log` 六张表 `count(*)` 前后不变；`skill_trial_message` 增加 6 行
4. 纠偏：两轮对话 → diff 更新 → apply → 五段变化 + `grain_edit_history` + `admin_audit_log` 有记录
5. `embedding_status` 从 pending → ready；ready 前「再问一次」不可点
6. 并发：两个草稿基于同一 `base_*` 先后 apply → 第二次 409
7. 回滚：apply → revert → 五段恢复、状态 `reverted`、`refinedGrainCount` 减 1
8. 权限：员工调 trial/refine → 403；跨企业 skillId → 404；组织分身 → 400
9. 已发布分身：属主的「改这条」变成「提交修改建议」；管理员直接改需二次确认
10. 试问不出现在「对话历史」与任何看板；`Skill.conversationCount` 不变
11. 会话私有性：A 看不到 B 的 trial session；管理员看本企业全部
12. SSE 中断不产生半条消息；重复 `clientMessageId` 不重复插入

已按本文件实现，实际代码位置：

| 清理 | `DataCleanupScheduler.cleanupTrialData`（试问 90 天、纠偏 180 天） |

**与 v2 的三处实现差异**（均为收敛，不改变契约）：

1. **纠偏字段只做五段**：v2 提到的 `sceneTag` 修正需要额外的 base/draft 列，V105 未建；prompt 已同步去掉 `sceneTag` 输出，避免模型返回无法落库的字段。
2. **apply 支持逐字段应用**：前端勾选的字段通过 `{fields:{...}}` 传入，后端以 `base_*` 为底、只覆盖勾选项；应用后把实际应用的版本写回 `draft_*`，保证后续 revert 比对的是真实内容。
3. **溯源新增属主可读接口**：`GET /skills/{id}/trial/traceability?grainIds=`，与 `/admin/grains/traceability` 同形状但只允许本分身空间下的颗粒；`TraceabilityDrawer` 有 `skillId` 时走新接口，属主不再 403。
