# 修复技术方案与交互设计

> 配套文档：`docs/69-问题清单与交互优化方案.md`（问题清单）。
> 本文回答三件事：**怎么修（技术）**、**页面长什么样（UI）**、**用户怎么操作（交互）**。
> 不含排期；所有方案以“可上线、可回滚、可验证”为标准。

---

# 一、总体原则

1. **先安全，后功能**：跨租户、XSS、SSRF、越权发布不修，功能越多风险越大。
2. **防御在查询层**：所有租户数据访问默认带 `company_id/space_id` 条件，不在“查出来再判断”。
3. **状态显式化**：任何异步任务必须有 `pending/running/succeeded/failed`，失败可见、可重试。
4. **错误可行动**：每个错误给“原因 + 稳定码 + 下一步”。
5. **交互一致**：同类页面用同一套列表、详情、空态、错误、危险操作模式。
6. **渐进上线**：高风险改动（Cookie 鉴权、报告 XSS 过滤）分阶段，带开关和回滚。

# 二、总体技术方案

## 2.1 分层职责

| 层 | 职责 | 本次约束 |
|---|---|---|
| Controller | 参数校验、路由、DTO 装配 | 不写 SQL、不做归属判断、不调 AI |
| Service | 业务、事务、状态机、权限归属 | 所有写操作先过 `TenantGuard` |
| Repository | 数据访问 | 列表查询强制带租户/空间条件 |
| Scheduler/Worker | 异步任务 | 必须有租约、重试上限、失败终态 |
| Config | 安全、模型、限流 | 不写业务 |

## 2.2 租户隔离统一方案（核心）

**问题现状**：大量接口“先按 id 查，再在 Controller 里判断”，漏判即越权；异步任务/内部接口更容易漏。

**方案**：新增 `TenantGuard`（或扩展 `CompanyScopeService`），所有 Service 写操作必须调用：

```java
// 统一入口，内部按当前 TokenContext 判断；super_admin 放行
guard.requireSpace(spaceId);
guard.requireSkill(skillId);
guard.requireGrainInSpace(grainId, spaceId);
guard.requireReport(reportId);          // report -> space -> company
guard.requireExpert(expertId);          // expert.company_id
guard.requireChannel(channelId);        // channel.company_id
guard.requireUserInCompany(userId);
```

**Repository 侧兜底**：所有列表/详情查询改成显式条件：

```java
findByIdAndCompanyId(id, companyId)
findBySpaceIdIn(spaceIds)
```

**C 端特例**：`companyId == null` 时不返回全平台数据，返回“本人空间集合”或空；报告、分享、知识检索都按空间归属过滤。

**验收**：每个资源两条反例测试（跨企业、C 端无企业），必须 403/404。

## 2.3 权限与身份

- 权限码仍以 `RolePermissions.ROLE_MAP` 为唯一真相源。
- **IM 权限决策**：企业要能自助发布飞书，给 `company_admin` 增加 `IM_MANAGE`；Service 层按 `company_id` 过滤渠道/机器人，超管放行。
- **C 端发布**：`c_user` 发布必须走同一个 `PublishReadinessService`，返回 blockers；不能只改状态。
- **登录/账号**：
  - 登录统一返回“账号或密码错误”，不区分用户不存在/密码错误。
  - 失败计数：Redis `login:fail:{ip}:{account}`，5 次后要求验证码/延迟。
  - 账号唯一性：注册 `saveAndFlush` 捕获唯一冲突，返回 400 明确文案；明确 B/C 账号命名空间。
- **Token（最终方案，线上无用户，不做迁移过渡）**：
  - Web 端（B 端 / C 端 / platform）只用 `HttpOnly + Secure + SameSite=Lax` Cookie 承载 JWT，**前端不再把 token 放 localStorage**。
  - 所有请求同源自动带 Cookie；SSE 用同源连接，不再用 query token。
  - CSRF：双提交 Cookie（`csrf` 可读 Cookie + `X-CSRF-Token` 头），只对 POST/PUT/PATCH/DELETE 校验。
  - `JwtAuthFilter` 读取顺序：Cookie → Bearer（仅 API/脚本/合作方）。Bearer 保留给 QA runner、内部调用；Web 页面不发 Bearer。
  - 合作方 token 只允许在 `/internal/**`、分享/SSE 白名单路径使用，且不进日志/Referer。
  - 登出清 Cookie + 撤销 jti；改密/停用 `bumpTokenVersion`，旧 token 立即失效。
  - 由于线上没有存量用户，直接切最终态，不做双读灰度；QA 脚本改用登录接口拿 Cookie 或继续 Bearer。

## 2.4 错误码与异常

- `AiErrorMapper` 已统一模型错误；补充业务错误码规范：
  - `TENANT_FORBIDDEN`、`RESOURCE_NOT_FOUND`、`STATE_CONFLICT`、`VALIDATION_FAILED`、`TASK_FAILED`。
- 同步接口返回 `{code, subCode, message}`；SSE `error` 事件带 `code`；后台任务落 `error_code/error_message`。
- 前端统一解析：展示 message；有 code 时给对应动作（重试/去配置/联系管理员）。

## 2.5 状态机与异步任务

统一状态机组件（每个领域一张显式转移表）：

| 领域 | 状态 | 关键规则 |
|---|---|---|
| Skill | draft/generating/reviewing/published/paused/discarded | 发布必须过 readiness；未知 action 400；废弃可 restore（30 天） |
| Material | uploaded/parsing/parsed/cleaning/extracted/failed/rejected/discarded | parsed 不是终态；failed 可重试；扫描带 LIMIT |
| Interview | created/in_progress/paused/completed + extraction_status | 补采必须重跑；失败可见可重试 |
| Expert | pending/analyzing/parsed/manual_review/failed/active | 失败计数上限；analyzing 超时回收 |
| IM Channel/Bot | draft/connecting/published/failed/offline | 先 connecting，连接成功才 published |
| Training | 已有，补资源失效标记 | 发布后资源下线要能告警/替换 |

异步任务统一字段：`status/error_code/error_message/attempts/last_attempt_at/lease_owner/lease_until`。

## 2.6 安全基线

| 风险 | 方案 |
|---|---|
| SSRF（AI BaseURL） | `OutboundUrlValidator`：解析 DNS、拒绝私网/环回/链路本地/元数据地址；仅 https（dev 可 localhost）；禁止重定向；测试异步化，不回显上游错误体 |
| 存储型 XSS（报告） | 服务端：FreeMarker 模型值统一转义（`?html` 或 HtmlSanitizer）；前端：DOMPurify；CSP；报告建议独立域 |
| 分享页 XSS | `ownerName` 等用户字段用 React 文本插值，禁止拼 HTML |
| 上传 | 大小上限、magic 嗅探、扩展名白名单、UUID 文件名、落盘 `normalize` 校验、OSS 强制 Content-Type |
| 提示词注入 | 素材/知识内容用分隔标签包裹并声明“仅数据”；输出侧做策略校验 |
| 限流 | Redis 滑动窗口：登录、公开搜索、游客发证、注册码校验；只信任可信代理的 XFF |
| 内部接口 | `/internal/im/**` 按桥/租户拆分密钥，只返回本桥 bot，secret 最小化下发 |

## 2.7 可观测性

- 每个异步任务失败写 `error_code` + 告警（日志关键词 + 后台状态页）。
- 关键链路带 `traceId`；前端错误上报带 traceId。
- 新增后台“任务健康”页：排队数、失败数、最老任务、重试按钮。

# 三、第零批安全修复设计（逐项）

| 编号 | 问题 | 技术方案 | 验收 |
|---|---|---|---|
| SEC-01/ORG-01 | 组织分身跨租户注入成员 | 创建/更新时批量 `findAllById`，校验 companyId、type=individual、status=published；任一不符 400 | 企业 A 挂 B 的分身 → 400 |
| SEC-02/EX-04/05 | 专家 IDOR、无 companyId | `expert_skill` 加 `company_id` 并回填；所有写操作 guard；颗粒/文档校验 expertId | 跨企业编辑 → 403 |
| SEC-03/IM-02/07 | IM 跨企业写、appSecret 泄露 | 渠道/机器人写操作 guard；`/internal/im/{type}/active` 按 bridgeId 过滤，secret 短时下发 | 跨企业下线 → 403；响应不含他租户 secret |
| SEC-04/OPS-06 | 洞察 grain-source IDOR | 校验 `grain.spaceId == skill.spaceId` | 跨空间读取 → 403 |
| SEC-05 | AI BaseURL SSRF | `OutboundUrlValidator` + 异步测试 + 不回显错误体 | 填 127.0.0.1/内网 → 400；错误无探测信息 |
| SEC-06/12 | 上传类型/大小 | 统一 `FileUploadValidator`（magic + 白名单 + 10MB/2MB） | 传 .html/.exe → 400 |
| SEC-07/10/11 | 报告/分享 XSS | 模板转义 + DOMPurify + CSP；ownerName 文本插值 | 注入 `<img onerror>` 不执行 |
| SEC-08/14 | 提示词注入 | 分隔标签 + 系统声明 + 输出校验 | 恶意素材不能改变系统指令 |
| SEC-09/IM-08 | 默认密钥 | IM bridge 启动 fail-fast（SECRET 非空且非默认）；qrUrl 空报错 | 未配 SECRET 启动失败 |
| SEC-13 | 路径穿越 | UUID + 白名单扩展名；落盘 normalize startsWith | `../` 文件名被拒绝 |
| SEC-15/AC-11 | 限流/枚举 | 登录/公开接口 Redis 限流；统一错误文案 | 5 次失败后限速；错误不区分账号 |
| SEC-16 | Token 存储 | 分阶段 Cookie 鉴权；移除 localStorage token；CSRF | XSS 无法读取 token |
| SP-01 | 空间跨企业 | userId 必须属于当前 companyId | 跨企业读空间 → 403 |
| PC-01/02/03 | 报告越权 | report→space→company 统一 guard；分享仅属主/管理员；guest 校验 share.enabled | C 端列出他企业报告 → 空；按 UUID → 403 |
| SK-01 | C 端发布绕过门槛 | `PublishReadinessService` 共用；C 端发布返回 blockers | 0 颗粒发布 → 400 + blockers |
| GR-05 | 反馈刷分 | 校验 grain 属于 skill、用户有会话；按 message/user 去重 | 跨 skill 反馈 → 400；重复只计一次 |

**实施顺序建议**：TenantGuard/Repository 条件 → 报告与分享 → 专家/组织/IM → SSRF/XSS/上传/限流 → Token 迁移。

# 四、第一批 P0 功能修复设计

## 4.1 知识/案例索引

- 表加 `embedding_status`（pending/indexed/failed）、`indexed_at`、`index_error`。
- 审批/编辑后异步索引；失败落状态；新增 `POST /admin/{knowledge|cases}/{id}/reindex` 与批量重建。
- 列表/详情展示索引状态；前端“已生效 · 未索引”橙色提示。

## 4.2 公共内容

- **内容包**：由我提供一版通用销售知识（8–10 条）+ 案例（5 条），固定 ID、可重复执行；先导 QA 验收，再导生产。
- **三个入口都保留**：
  1. 平台运营/超管：公共 Tab 新增/上传/审批/编辑/废弃（现有能力）。
  2. 企业管理员：公共内容只读 + 复制到本企业；新增「提交到公共库」——把本企业一条知识/案例提交为公共候选。
  3. 员工：无管理入口，只通过分身检索使用。
- **提交到公共库流程**：企业管理员点「提交到公共库」→ 系统生成一条 `company_id=null、status=pending、source_company_id=本企业` 的候选 → 超管在公共 Tab 审核 → 通过后成为公共知识，企业信息只做溯源展示。
- 需要新增字段：`knowledge_entry.source_company_id`、`industry_case.source_company_id`（可空）。
- 公共 Tab 顶部说明 + 最近更新；企业复制后生成本企业 pending 副本。
- 公共更新不自动同步；后续加“公共版本有更新”提示。

## 4.3 销售文件上传

- 新建复盘支持 txt/docx/pdf；解析复用 ai-service `/internal/parse-file`。
- 上传→解析→文本预览→可编辑→提交；解析失败保留手动粘贴。
- 说话人识别失败时让用户手动标注。

## 4.4 复盘沉淀为案例/知识

- 报告详情增加「沉淀为案例」「沉淀为知识」。
- 组装：报告结论/亮点/不足 + 对话段落 + 教练补充 → pending 草稿。
- 跳转对应详情页确认；失败可重试。

## 4.5 培训资源失效

- 定时扫描已发布计划引用的资源状态；写 `training_resource_alert`。
- 计划详情红色横幅 + 替换资源；替换生成新计划版本。
- 学员端 409 给任务名和“联系管理员”。

## 4.6 访谈补采与状态

- InterviewSession 加 `extraction_status`；补采时重置虚拟 material 并重跑。
- 萃取失败可见、可重试；报告生成显式触发或异步任务。
- 报告 HTML 不在 HTTP 线程生成：未命中返回 202 + 轮询。

## 4.7 专家状态机

- `retry_count` 上限 3；超限终态 failed。
- `analyzing` 超时回收（租约 10 分钟）。
- `manual_review` 状态 + 前端补录入口。

## 4.8 IM 可用性

- 给 company_admin `IM_MANAGE`，Service 按企业过滤。
- 发布状态机 connecting→published/failed；失败可重试连接。
- 去重 key 成功后才落；桥断线重连；测试连接真实探测。
- `/internal/im/active` 按 bridgeId 过滤，secret 最小化。

## 4.9 素材状态

- 前端 `TERMINAL` 移除 parsed；新增“等待清洗”中间态。
- 扫描查询加 LIMIT/游标；素材接口改 DTO 投影。

## 4.10 发布门槛

- `PublishReadinessService` 统一 B/C/Admin 入口；阈值用配置。
- 状态机转移表；未知 action 400；废弃 restore（30 天）。

# 五、UI 设计系统

## 5.1 页面骨架（所有管理页统一）

```
┌────────────────────────────────────────────────────┐
│ 页面标题 + 一句话说明          [使用说明] [主操作]  │
├────────────────────────────────────────────────────┤
│ Tab / 搜索 / 筛选 / 批量操作（按需）                │
├────────────────────────────────────────────────────┤
│ 内容：表格 / 卡片 / 空态 / 错误态 / 加载骨架         │
├────────────────────────────────────────────────────┤
│ 分页 + 总数                                         │
└────────────────────────────────────────────────────┘
```

规则：
- 主操作只有一个（新增/创建）；次操作用描边按钮。
- 行操作超过 3 个收进「更多」菜单。
- 批量模式：勾选后底部浮出操作条（审批/废弃/重建索引）。
- 列表必须有：搜索、总数、分页、行摘要。

## 5.2 状态标签规范

**生命周期状态**与**运行状态**分开展示，不混在一个标签里：

| 类型 | 示例 | 颜色 |
|---|---|---|
| 审核状态 | 草稿/待审核/已生效/已废弃 | 灰/橙/绿/灰 |
| 索引状态 | 已索引/未索引/索引失败 | 绿/橙/红 |
| 任务状态 | 排队中/生成中/已完成/失败 | 灰/蓝/绿/红 |
| 连接状态 | 已连接/连接中/未连接/失败 | 绿/蓝/灰/红 |

## 5.3 空态 / 错误态 / 加载

| 场景 | 展示 |
|---|---|
| 空数据 | 图标 + 一句说明 + 主操作 + 次操作（下一步做什么） |
| 加载失败 | 图标 + 可读原因 + 「重试」+ 「联系管理员」 |
| 无权限 | 说明 + 「返回」/「申请权限」，不显示操作按钮 |
| 加载中 | 骨架屏（列表）/ 进度卡（AI 任务） |

## 5.4 AI 任务卡（统一组件）

```
┌────────────────────────────────────────┐
│ 正在生成复盘报告                        │
│ 排队中 · 已等待 12 秒                   │
│ [取消]                                  │
└────────────────────────────────────────┘
```

状态：排队中 → 生成中（通常 30–90 秒）→ 完成/失败。
超过 3 分钟：`仍在生成，可先离开，完成后通知你`。
失败：原因 + 错误码 + 「重试」。

## 5.5 危险操作确认（带影响面）

```
┌────────────────────────────────────────┐
│ 确认废弃这条知识？                      │
│ 影响：                                  │
│ · 3 个分身将停止引用                    │
│ · 2 个培训计划的任务资料会失效          │
│ [取消] [确认废弃]                       │
└────────────────────────────────────────┘
```

## 5.6 权限与可见性

- 无权限的入口不渲染，而不是点了才 403。
- 管理员专属操作（去模型配置/审批）只对管理员显示。
- 员工看到的失败提示统一“请联系管理员”，不暴露内部配置。

# 六、关键页面交互方案

## 6.1 知识库列表

- Tab：企业私有 / 公共知识。
- 列：标题+摘要、分类、审核状态、索引状态、版本、更新时间、操作。
- 顶部：搜索（标题/内容，后续）、分类、状态、索引状态筛选。
- 行操作：审批 / AI 整理 / 复制 / 废弃（更多菜单）。
- 公共 Tab：说明条 + 最近更新；复制后 Toast「已复制，待审核」。

## 6.2 知识详情

- 顶部固定操作条：采用 / AI 整理 / 放弃草稿 / 废弃。
- 右侧信息栏：版本时间线、索引状态、被引用、来源。
- 正文：目录 + 搜索高亮（长文档）。
- 修订横幅：`有 1 个修订版本待处理`。

## 6.3 AI 整理弹窗

- 当前内容可展开/收起，显示字数。
- 「让 AI 给建议」→ 3 条建议，每条带理由；点击填入指令。
- 常用指令 chips。
- 生成中显示“正在按你的要求改写”，可取消；失败保留输入。

## 6.4 案例库

- 与知识库一致：公共/企业 Tab、摘要、状态、AI 整理、版本 diff。
- 复盘沉淀的草稿带来源标签「来自复盘 · 客户名」。

## 6.5 培训计划详情

- 左侧任务树（阶段/任务/依赖），右侧属性面板。
- 顶部状态 + 版本 + 发布按钮；发布前展示 blockers。
- 资源失效红色横幅：「3 个任务资料失效」+「查看并替换」。
- 批次区：进行中人数、完成率、逾期人数、导出。

## 6.6 我的培训

- 顶部认证进度条 + 截止时间 + 剩余必修数。

# 七、交互体验规范（横切）

## 13.18 上传准入与书籍模式（2026-11-14）

**问题**：用户会直接把整本电子书传到知识库/案例库。原有管道按普通文档逐节抽取，一本书会产出
大量章级大块、版权页和叙事段落，检索阈值命中不了；案例管道还要求 `result`，书籍叙述根本满足不了。
同时两个库缺少准入标准，便签式知识和空壳案例可以一路审批生效，稀释检索、拉低分身回答质量。

**处理原则**：不把判断推给用户，上传即分流 + 硬门槛准入。

| 层 | 实现 |
|---|---|
| 素材分流 | 上传时选「企业自有资料 / 书籍·课程」；未选时按文本特征自动识别（≥2.5 万字且 ≥8 节，或 ≥6 万字，或含 3 个书籍版式标记）。书籍模式走专用提示词 |
| 书籍知识 | `material_knowledge_book.md`：只提炼可独立检索的观点卡片（标题=场景+观点，正文 120–280 字，结论先行 + 适用条件），丢弃版权页/目录/序言/推荐语/叙事段落；输出 `anchor`，落库 `source=《书名》· 章节`，单次上限 200 条并提示拆书 |
| 书籍案例 | `material_case_book.md`：只提取信息完整的客户故事，结果不明不输出、禁止编造原话；一律落 `draft` 并标 `origin=book`，与内部实战案例区分采信度，单次上限 100 条 |
| 知识准入 | 标题 4–60 字且不能只是章节名；正文普通 ≥10 字、书籍 60–600 字；分类合法；书籍必须带出处；正文 >1500 字阻断（防止整章粘贴） |
| 案例准入 | 标题不能是「案例一」；必须有核心异议或关键动作/话术；结果必须 win/loss/delay；书籍案例必须有出处。不达标的草稿记录 `quality_issues`，审批接口直接 400 |
| 去重 | 同任务内 + 同企业按规范化标题查重，重复项跳过并计入 `skipped_count`，页面显示跳过数量与原因 |
| 补齐闭环 | 未达标草稿可在预览里直接改标题/正文/分类/出处（`PUT /admin/knowledge/upload/{taskId}/drafts/{draftId}`），保存即重算质量分；达标后才能勾选采纳，避免「只提示不给出路」 |
| 页面 | 上传页展示「书籍模式」说明、跳过数、处理说明；草稿列表显示质量分与阻断原因，未达标条目禁用勾选并提供「补齐」；案例详情显示「书籍案例（二手）」标签与补齐入口 |

迁移：V85（任务 `source_kind/skipped_count/guide_message`、草稿 `quality_score/quality_issues/quality_warnings`、案例 `origin/quality_issues/quality_warnings`）。
新增单测：`ContentQualityGateTest`（13）、`UploadContentModeTest`（5）、REG-KNOW-12；后端 **593 单测通过**；前端 `tsc` 通过。

本地实测：
- 书籍模式上传含版权页的测试文本 → 只产出 3 张方法论卡片（每章 1 条），版权页被丢弃，`source=《书名》· 章节`，质量分 95/75/85；
- 同一文本按案例库书籍模式上传 → 0 条，任务失败并提示「没有结果明确的客户故事」，不编造；
- 人工创建正文「短」的知识 → 400「正文过短（至少 10 字）」；
- 草稿改成过短内容 → 质量分下降且记录阻断原因 → 批量采纳 `adopted: 0`（不会带着问题入库）。

**明确的取舍**：审批只拦结构性无效（空标题、超长正文、非法分类、萃取阶段记录的问题），
不拿长度下限回杀历史数据；完整标准在萃取与人工新建时执行。

## 13.28 IM 通知推送（飞书/企微/钉钉，2026-11-15）

**目标**：站内信是唯一真相，IM 只是投递通道；未绑定/渠道停用自动跳过，失败不影响业务。

**绑定（不需要企业通讯录权限）**
- `POST /me/im/bind-code`：生成 6 位绑定码（10 分钟）。
- 用户在 IM 给机器人发送「绑定 123456」→ 后端入站链路识别并建立 `im_user_binding`。
- `GET /me/im/bindings`、`DELETE /me/im/bindings/{id}` 查看/解绑。
- 同一 IM 身份改绑时覆盖旧用户；同一用户同渠道只保留最新一条。

**推送链路**
- `NotificationService` 站内信落库成功后，异步调用 `ImPushService`。
- 只外发培训闭环相关类型（每日微练、待复核、待认证、延期、补训、认证结果等），只发标题+摘要+完整站内链接。
- 后端 → im-bridge `POST /internal/push`（HMAC 与入站同密钥）→ 各渠道适配器：
  - 飞书：`channel.send(chatId, markdown)`
  - 企微：`message/send`（touser=userid）
  - 钉钉：机器人 `oToMessages/batchSend`（robotCode=appKey，userId）
- 失败只记日志；站内信不受影响。

**入站变化**
- 渠道不再强制绑分身：无分身的机器人只处理绑定命令，普通消息回复绑定指引；有分身则照常对话。
- 绑定命令优先于对话路由，避免验证码被当成业务问题。

**管理端**
- `GET /im/users/{userId}/bindings`、`POST /im/users/{userId}/test-push`（IM_MANAGE）。

**迁移**
- V94：`im_user_binding`（企业+渠道+用户唯一、渠道+外部身份唯一）与 `im_bind_code`（一次性、10 分钟）。
