## 一、三端用户体系

```
┌─────────────────────────────────────────────────────────────────┐
│                        用户体系全景                               │
├──────────────┬──────────────────┬────────────────────────────────┤
│   B 端企业版  │   C 端 H5 消费者  │   合作方 App 嵌入               │
├──────────────┼──────────────────┼────────────────────────────────┤
│ 用户表: user  │ 用户表: app_user  │ 用户表: app_user               │
│ 角色:        │ 角色:            │ 角色:                          │
│  super_admin │  c_guest (游客)   │  c_partner                     │
│  employee    │  c_user (已注册)   │                                │
│              │                  │                                │
│ 企业: company │ 企业: 无          │ 企业: 合作方 company             │
│ 空间: space   │ 空间: ❌ 暂无      │ 空间: ❌ 暂无                   │
│   (user_id)   │                  │                                │
├──────────────┼──────────────────┼────────────────────────────────┤
│ 鉴权:         │ 鉴权:             │ 鉴权:                          │
│  HttpOnly     │  localStorage    │  URL ?token= JWT               │
│  Cookie token │  c_auth Bearer   │  (PartnerJwtFilter)            │
└──────────────┴──────────────────┴────────────────────────────────┘
```

### 1.1 B 端用户（user 表）

| 字段 | 说明 |
|------|------|
| `id` | UUID |
| `company_id` | 所属企业，FK → company.id |
| `role` | super_admin / employee |
| `account` | 登录账号，同公司内唯一 |
| `password_hash` | BCrypt |

**数据链**：`company (1) → user (N) → space (1:1) → skill (1:1) → skill_share (0..1)`

### 1.2 C 端用户（app_user 表）

| 字段 | 说明 |
|------|------|
| `id` | UUID，游客→注册升级时不变 |
| `nickname` | 游客自动生成"访客XXXX" |
| `account` | 注册后填，全局唯一。游客为 null |
| `password_hash` | 注册后填，游客为 null |
| `status` | guest / registered / partner |
| `source_share_id` | 从哪个分享链接来的（归因） |

**生命周期**：
```
打开分享页 → 自动创建 guest（无账号密码）
     │
     ▼
  跟分身聊天（限 5条/天）
     │
     ▼
  条数用完 → 注册 → 原地 UPDATE 同一行
     status: guest → registered
     UUID 不变，历史聊天自动继承
```

### 1.3 合作方用户（app_user 表，status=partner）

| 字段 | 说明 |
|------|------|
| `account` | `partner:{appId}:{externalUserId}` |
| `status` | partner |

由 `PartnerJwtFilter` 首次请求时自动创建。PartnerApp 表管理合作方密钥。

## 二、功能一：分身聊天（H5 分享页）

### 2.1 涉及的数据表

| 表 | 写入时机 | 写入内容 |
|----|---------|---------|
| `app_user` | 首次打开分享页 | 新建 guest 行 |
| `analytics_event` | 打开分享页、发消息 | share_visit、guest_created 等事件 |
| `skill_conversation` | 首次发消息 | 新建对话（skill_id + user_id + mode） |
| `skill_message` | 每次发消息 | 用户消息 + AI 回复（各一行） |
| `conversation_stats` | 每次 AI 回复 | RAG 命中率、耗时、反馈统计 |

**关键设计**：`skill_conversation.user_id` 无外键约束，直接存 `app_user.id`（C端）或 `user.id`（B端）。两个用户体系在同一个字段共存，靠 JWT role 区分行为。

### 2.2 完整流程

```
用户打开 /s/{shareCode}
  │
  ▼
① GET /public/share/{shareCode}          [permitAll，无需登录]
  → ShareService.getShareInfo()
  → 写 analytics_event (share_visit)
  ← 返回：头像、名字、标签、场景、剩余条数
  │
  ▼
② 用户点 QA/Talk/Practice 模式
  │
  ▼
③ POST /public/share/{shareCode}/guest   [permitAll]
  → ShareService.createGuestSession()
  → 新用户：INSERT app_user (status=guest, nickname="访客xxxx")
  → 老用户：UPDATE last_active_at，重签 token（滑动续期）
  → 写 analytics_event (guest_created)
  ← 返回：JWT token + userId + remaining
  │
  ▼
④ 前端存 token 到 localStorage.c_auth
  │
  ▼
⑤ POST /skills/{skillId}/chat (SSE)     [authenticated，c_guest 可用]
  → QueryGate 四层审计：
    L1 参数校验 → L2 敏感词/隐私/注入检测 → L3 Redis 限流 → L4 guest 配额
  → guest 配额检查：COUNT(skill_message WHERE conversation.user_id=X AND role='user' AND created_at >= 今天0点)
  → 超限返回 {"type":"limit","used":N,"limit":N}
  → 未超限：存 user message + 流式返回 AI reply + 存 assistant message
  │
  ▼
⑥ 条数用完 → 弹出注册抽屉
  │
  ▼
⑦ POST /c/auth/register                  [hasRole(C_GUEST)]
  → CAuthService.register()
  → UPDATE app_user SET account=?, password_hash=?, status='registered'
  → 同一行、同一 UUID、历史聊天自动继承
  ← 返回新 token（role=c_user，30天有效）
  │
  ▼
⑧ 继续聊天，不受条数限制
```

### 2.3 同一用户跨 Skill 的数据隔离

```
app_user "小张" (id=xxx)
  │
  ├── 打开分享 A（skill-001）
  │     └── skill_conversation (skill_id=001, user_id=xxx)
  │           └── skill_message × N
  │
  ├── 打开分享 B（skill-002）
  │     └── skill_conversation (skill_id=002, user_id=xxx)
  │           └── skill_message × N
  │
  └── 条数限制：COUNT 所有 conversation 下的今天的 user message
      跨 Skill 合并计算，不是每个 Skill 独立 5 条
```

## 三、功能二：销冠访谈（B 端）

### 3.1 涉及的数据表

| 表 | 写入时机 | 写入内容 |
|----|---------|---------|
| `interview_session` | 创建访谈、阶段推进、暂停、完成 | 会话状态 + 四阶段 + 模块采集 JSONB |
| `interview_message` | 每次对话 | 用户回答 + AI 追问 |
| `skill` | 首次访谈时（如无则自动建 draft） | AI 分身 |
| `report` | 访谈完成时 | 萃取报告 |
| `experience_grain` | 萃取管道完成时 | 经验颗粒 + pgvector embedding |

### 3.2 完整流程

```
B 端员工进入 /interview/create
  │
  ▼
① GET /spaces + GET /interviews/active   [SUPER_ADMIN/EMPLOYEE]
  → 加载空间列表 + 检查是否有进行中/暂停的会话
  │
  ▼
② POST /interviews                       [SUPER_ADMIN/EMPLOYEE]
  → InterviewService.createSession()
  → 校验：同类型不能有进行中会话（ACTIVE_STATUSES = created/in_progress/paused）
  → 找/建 Skill（如 space 无 Skill 则自动建 draft）
  → INSERT interview_session (space_id, topic, status=created, phase=opening,
      collect_status='{}', interview_type=sales)
  ← 返回 sessionId
  │
  ▼
③ 跳转 /interview/{sessionId}
  → GET /interviews/{id} + GET /interviews/{id}/messages
  │
  ▼
④ POST /interviews/{id}/chat (SSE)       [SUPER_ADMIN/EMPLOYEE]
  → 流式 AI 访谈，逐 token 返回
  → 首次发言：status created→in_progress
  │
  ▼
⑤ 阶段推进（用户手动或 AI 建议）
  → POST /interviews/{id}/mark-phase-complete
  → markCollectForPhase() 写入对应模块的采集状态
  → 如为 closing 阶段：触发报告生成
  │
  ▼
⑥ 访谈完成
  → checkAndCompleteSession() → 生成 report
  → 萃取管道异步运行 → 生成 experience_grain + pgvector embedding
  │
  ▼
⑦ 分身广场展示
  → admin 审核 grains → 发布 skill
  → 管理员生成分享链接 → 写入 skill_share
```

### 3.3 四阶段 → 六模块映射

```
opening    → caseStory  (案例故事)
storytelling → steps    (核心步骤)
            → decision  (关键决策)
modeling   → mindset   (专家心法)
           → boundary  (适用边界)
closing    → checklist (行动清单)

collect_status JSONB:
{"caseStory":"collected","steps":"pending","decision":"pending",
 "mindset":"pending","boundary":"pending","checklist":"pending"}
```

## 四、分身分享机制

### 4.1 两种分享模式

| | 对外分享 | 对内分享 |
|------|---------|---------|
| 入口 URL | `/s/{shareCode}` | `/i/{shareCode}` |
| 谁可以访问 | 任何人（guest 也能） | 仅本公司员工 |
| 鉴权 | 无（permitAll） | B 端登录（EMPLOYEE） |
| 免费次数 | 5条/天，用完弹注册 | 无限制 |
| 注册入口 | guest → registered | 无（员工由管理员创建） |
| 用途 | 对外推广、社交传播 | 企业内部移动端使用、培训 |
| channel | `default` | `internal` |
| company_id | 必填（建码时解析） | 必填（员工登录时校验） |

同一个分身可以同时有两条链接：对外 `/s/xxx` + 对内 `/i/xxx`。

### 4.2 分享数据存在哪里

```
skill_share 表
┌──────────────────────────────────────────────────┐
│ id              UUID                              │
│ skill_id        FK → skill.id                     │
│ company_id      FK → company.id (建码时冗余存储)    │
│ share_code      VARCHAR(16) UNIQUE               │
│                 ↑ 10位 base62 随机码               │
│ channel         "default" | "internal"            │
│                 ↑ default=对外 internal=对内       │
│ enabled         BOOLEAN   ← 一键关闭分享            │
│ created_by      FK → user.id (管理员)              │
└──────────────────────────────────────────────────┘
```

- `company_id` 在建码时经 `skill → space → user → company` 两跳解析后冗余存储
- 公开端运行时不需要再 JOIN company 表
- **用 `channel` 字段区分对外/对内，不新增字段**

### 4.3 对外分享（/s/）

**创建**：同 4.2，channel='default'

**访问流程**：
```
被分享者打开 /s/{shareCode}
  │
  ▼
GET /public/share/{shareCode}             [permitAll]
  → requireEnabledShare(shareCode)：检查 enabled=true
  → requirePublishedSkill(share)：检查 skill.status IN ('published','active')
  → 任一不满足 → 404 "分享链接已失效"
  │
  ▼
后续流程同"二、分身聊天"（guest 自动创建 + 5条/天限制）
```

### 4.4 对内分享（/i/）🆕

**创建**：
```
B 端管理员在分身管理页点"内部分享"
  │
  ▼
POST /admin/skills/{skillId}/internal-share   [SUPER_ADMIN]
  │
  ▼
ShareService.getOrCreateInternalShare(skillId)
  → 查 skill_share WHERE skill_id=? AND channel='internal'
  → 已有 → 直接返回
  → 没有 → 生成 shareCode → INSERT skill_share (channel='internal')
  ← 返回 shareCode + companyName
```

**访问流程**：
```
员工手机打开 /i/abc123
  │
  ▼
① GET /i/abc123/info                        [authenticated 或 permitAll]
  → 查 skill_share WHERE share_code='abc123' AND channel='internal'
  → 返回 { skillId, companyName, ownerName, ownerTitle, avatarUrl }
  │
  ▼
② 检测登录态
  ├── 已登录且 company 匹配 → 直接进聊天页
  └── 未登录 → 显示登录页
        │
        ▼
   ┌────────────────────────────┐
   │  你正在访问 XX科技 的内部分身  │
   │                            │
   │  企业ID  XX科技（不可改）     │  ← 从 share.company_id 解析
   │  账号    [___]             │
   │  密码    [___]             │
   │                            │
   │  [登录]                    │
   │                            │
   │  没有账号？联系企业管理员     │  ← 不提供注册入口
   └────────────────────────────┘
        │
        ▼
③ POST /auth/login
  → 校验该用户 company_id == share.company_id
  → 不匹配 → 403 "非本公司员工"
  → 匹配 → 签发 B端 token
  │
  ▼
④ 进聊天页 → 无条数限制 → 后续流程同分身聊天，但不走 guest 逻辑
```

**与 /s/ 的差异**：
| | /s/ | /i/ |
|------|-----|-----|
| 页面 | 可复用聊天组件 | 可复用聊天组件 |
| auth flow | guest 自动创建 + 注册抽屉 | 企业登录，无注册 |
| 条数限制 | 5条/天 | 无限制 |
| companyId 来源 | 不校验 | 从短链拿到 + 登录时校验 |

## 五、B 端移动端销冠访谈 🆕

### 5.1 前端页面矩阵（H5 vs 桌面）

```
                    ┌─────────────┐
                    │  后端 API    │  ← 统一，不分 H5/桌面
                    └──────┬──────┘
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
     ┌──────────┐   ┌──────────┐   ┌──────────┐
     │ H5 页面   │   │ 管理后台  │   │ 平台门户  │
     │ (移动优先) │   │ (桌面)    │   │ (响应式)  │
     │ /s/ /i/   │   │ /admin/  │   │ /discover │
     │ /h5/      │   │ /interview│   │ /login    │
     └──────────┘   └──────────┘   └──────────┘
```

| 功能 | H5 (frontend /s/ /i/ /h5/) | 桌面 (frontend /interview/ /admin/) | 门户 (enterprise) |
|------|-----------|------|------|
| 对外分享聊天 | ✅ `/s/{code}` | — | ✅ 复用 |
| 对内分享聊天 | 🆕 `/i/{code}` | — | 🆕 复用 |
| C端自萃取 | 🆕 `/h5/interview/create` + `/h5/interview/[id]` | — | 🆕 复用 |
| B端桌面访谈 | — | ✅ `/interview/create` | — |
| B端移动端访谈 | 🆕 `/h5/interview/m/{inviteCode}` | — | — |
| B端管理后台 | — | ✅ `/admin/*` | — |
| 分身发现市场 | — | — | ✅ `/discover` |

  ▼

  ├── 已有 B端登录态（Cookie）→ 直接进移动端访谈页
  └── 未登录 → B端登录页 → 登录后回跳
  │

## 七、当前缺口：C 端用户不能自萃取、C 端分身不能分享

### 7.1 为什么 C 端不能自萃取？

```
POST /interviews 需要 spaceId
  │
  ▼
B 端用户：user → space → spaceId ✅
C 端用户：app_user → ❌ 没有 space，没有 spaceId
```

SecurityConfig 第 17 条规则：`anyRequest() → hasAnyRole(SUPER_ADMIN, EMPLOYEE)` 覆盖 `/interviews/**`，C 端角色直接 403。

**两个堵点**：
1. **权限**：C 端角色（c_guest/c_user）被 SecurityConfig 拦截
2. **数据**：app_user 没有 Space，createSession 找不到 spaceId

### 7.2 为什么 C 端分身不能分享？

```
skill_share.company_id 在创建时通过 skill → space → user → company 解析
  │
  ▼
C 端 skill：space.user_id = null（因为 space 还没建，或者 space 关联 app_user）
  → resolveCompanyId() 找不到 user → 没有 companyId
  → skill_share.company_id 是 NOT NULL → INSERT 失败
```

**两个堵点**：
1. **权限**：C 端用户调不了 `/admin/**` 和 `/skills/{id}/share`
2. **数据**：skill_share.company_id NOT NULL，C 端没有 company

## 八、后期加分享功能的实施方案

### 8.1 前置条件：让 C 端能自萃取

先打通 Space 链路：

```
space 表改造
┌──────────────────────────────────────┐
│ 当前：                                │
│   user_id UUID NOT NULL              │
│                                      │
│ 改为：                                │
│   owner_type VARCHAR(10) NOT NULL    │  ← 'user' / 'app_user'

│                                      │
│   CHECK: 二者互斥（一个有值另一个 null）  │

```

| 3 | `SpaceRepository.java` | 加 `findByAppUserId()` |

| 6 | `InterviewController.createInterview()` | C 端无需传 spaceId，自动创建 |
| 7 | `useInterviewCreate.ts` | C 端不调 getSpaces()，不传 spaceId |
| 8 | H5 访谈入口页 | 新建 `/c/interview/create` |

### 8.2 然后让 C 端分身能分享

| 序号 | 文件 | 改动 |
|------|------|------|
| 1 | `V25__skill_share_nullable_company.sql` | `company_id` → nullable |

## 十一、关键设计决策

1. **skill_conversation.user_id 无外键** — 同一个字段存 B 端 user.id 和 C 端 app_user.id，靠 JWT role 区分行为，不是靠数据库约束
2. **skill_message 无 user_id** — 用户身份只存在 conversation 层，message 通过 conversation_id JOIN 获取
3. **C 端注册 = 同 UUID 原地升级** — guest→registered 是 UPDATE 不是 INSERT，历史聊天自动继承
4. **分享链接 company_id 冗余存储** — 建码时一次解析，公开端查询时不再 JOIN
5. **guest 条数限制按天按用户** — `COUNT skill_message WHERE role='user' AND created_at >= 今天0点`，跨 Skill 合并计算
