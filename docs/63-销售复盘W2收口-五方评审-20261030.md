# 销售复盘 W2 收口 — 五方评审

评审对象：[docs/62](62-销售复盘W2收口-代码级设计-20261030.md)
角色：产品、架构/后端、前端、测试、安全/运维。
结论：**6 个阻塞项、8 个高优、6 个中优**。阻塞项已回写设计，未关闭前不进入开发。

---

## 一、阻塞项（必须改设计）

### B1 版本对比按要点文本精确匹配，实际不可用
**产品 / 前端**：AI 每次重写报告，措辞几乎全变；按 `point` 精确匹配会把整份报告都标成「新增/删除」，用户看到的是噪声。

**修改**：不做「新增/删除要点」的自动判定。改为：
- 左「上一版」右「当前版」两栏；
- `summary` 和每条要点做**词级 diff**（前端本地 LCS，新增词绿底、删除词红底）；
- 仅在数量变化时提示「要点 3 → 4 条」，不推断哪条是新增；
- 顶部写明「AI 改写会被标为词级变化，不代表结论变了」。

### B2 任务编辑会把逾期任务锁死
**后端**：`update` 一律校验 `dueAt >= now`。逾期任务的 `dueAt` 本来就是过去时间，用户只想改话术也会被 400。

**修改**：只有 `dueAt` 发生变化时才校验；未改截止时间允许编辑其他字段。代码：

```java
boolean dueChanged = !Objects.equals(task.getDueAt(), req.dueAt());
if (dueChanged && req.dueAt() != null && req.dueAt().isBefore(now))
    throw new BusinessException(400, "截止时间不能早于现在");
```

### B3 通知服务泛化会破坏培训侧构造器和测试
**架构**：`TrainingNotificationService` 当前构造器是 4 个参数，测试直接 `new`。直接把通用方法搬走会改构造器签名。

**修改**：
- 新增 `NotificationService`；
- `TrainingNotificationService` **保留原有 4 参构造器**，内部新增一个 `NotificationService` 字段由 Spring 注入会破坏测试；改为构造器增加第 5 参并在测试同步更新；
- 保留 `notifyLearner/notifyReviewer` 领域方法，内部委托 `notificationService.notifyUser`；
- `NotificationCenterController` 改注入 `NotificationService`；
- 更新 `TrainingNotificationServiceTest` 的构造调用，并补一条「委托给 NotificationService」的断言。

### B4 主联系人并发会 500
**后端**：两个请求同时设主联系人，都先 `clearPrimary` 再插入，唯一索引会抛 `DataIntegrityViolationException`。

**修改**：`addContact/updateContact` 捕获唯一索引冲突，转 `409 LEAD_CONTACT_PRIMARY_CONFLICT`，提示「主联系人已被其他操作修改，请刷新重试」。部分唯一索引保留兜底。

### B5 E2E 全链路没有清理方案
**测试**：链路测试会创建复盘/线索/任务/通知，跑几次开发库就脏了。

**修改**：
- 数据统一用 `E2E-链路-<runId>` 前缀；
- 新增 `scripts/sales-e2e-cleanup.sql`：按 `customer_name LIKE 'E2E-链路-%'` 删复盘及其子表、线索、任务、活动、联系人、通知；
- `frontend/package.json` 增加 `e2e:sales:chain` 脚本：跑测试后执行清理（CI 用 `psql`，本地无 psql 时打印标记）；
- 通知按 `biz_type='review_session' AND biz_id IN (...)` 删。

### B6 线索改名查重可能漏判
**后端**：`findDuplicates` 先 `LIMIT 5` 再在内存排除自己；如果自己排在前 5，真正的重复可能被截断。

**修改**：新增 SQL 排除自身：

```java
@Query(value = "SELECT * FROM lead WHERE company_id=:companyId AND id<>:excludeId AND ("
        + " name_normalized=CAST(:normalized AS text) "
        + " OR (:digits IS NOT NULL AND contact_phone_digits=CAST(:digits AS text))"
        + ") ORDER BY created_at DESC LIMIT :limit", nativeQuery = true)
List<Lead> findDuplicatesExcluding(...);
```

## 二、高优（开发前修正，不阻塞设计定稿）

### H1 任务创建的同名并发只靠预检
**后端**：预检挡不住并发，唯一索引冲突会 500。设计已补 `saveAllAndFlush` + 捕获 `DataIntegrityViolationException` 转 409；补单测模拟冲突。

### H2 `TaskView.ownerName` 会引入 N+1
**后端**：任务列表每行查负责人会 N+1。设计改为列表一次 `userRepository.findAllById(ownerIds)`，详情/转交复用。

### H3 线索详情的关联任务无上限
**后端**：一个线索多年可能上百条任务。改为最近 50 条，按 `due_at desc`；详情页只显示待办 + 最近完成 20 条，完整列表跳任务页。

### H4 线索状态流转没有写时间线
**后端**：设计只写了创建/编辑/联系人/任务，漏了状态流转。`updateStatus` 必须写 `status_changed` 活动并更新 `last_activity_at`。

### H5 存量任务的 `lead_id` 为空
**后端**：本轮之前从复盘生成的任务没有回填 `lead_id`，线索详情看不到历史任务。DDL 补：

```sql
UPDATE follow_up_task t
   SET lead_id = s.lead_id
  FROM review_session s
 WHERE t.review_id = s.id AND t.lead_id IS NULL AND s.lead_id IS NOT NULL;
```

### H6 转交目标选择器没有接口
**前端/后端**：员工没有 `USER_MANAGE`，不能复用 `/admin/users/picker`。新增：

```
GET /sales/tasks/owners?keyword=&page=1&size=20
→ PageResponse<UserOptionView(id, name, role)>
```

服务端限定本企业、active、角色 `employee/company_admin/super_admin`，`name/account` 模糊匹配；`size<=50`。

### H7 追问草稿跨用户泄露
**安全**：localStorage key 只用 reviewId，同一台电脑换账号能看到上一个人的草稿。

**修改**：key 改为 `sales:review:draft:{userId}:{reviewId}`；退出登录时清除所有 `sales:review:draft:` 前缀键；草稿不写任何客户敏感字段之外的内容（就是输入框原文）。

### H8 自动升级没有操作人，审计会跳过
**安全/后端**：`SalesAuditService.record` 在 `TokenContext` 为空时跳过。自动升级来自 Scheduler，不能写「管理员操作」审计。

**修改**：自动升级只写 `lead_activity`（`actor_id=null`，前端显示「系统」），不写 `admin_audit_log`；手动升级才写审计。设计明确区分。

## 三、中优（开发中落实）

### M1 `user_notification` 索引名与培训脚本不一致
**运维**：销售脚本若用新索引名，会多建一套重复索引。统一复用培训脚本的 `uq_un_dedupe / idx_un_user_unread / idx_un_company_created`。

### M2 主联系人角色空值
**产品**：新增联系人角色默认 `other`，前端下拉默认「其他」，不出现空角色。

### M3 任务编辑改期后提醒标志
**后端**：`dueAt` 变化时清空 `due_reminded_at/overdue_notified_at`；`escalated_at` 保留，避免已升级任务重复升级。

### M4 提醒/升级通知失败
**运维**：`NotificationService` 已吞异常并记日志；提醒标志已置位，失败不重试。接受这一点，在文档写明「站内信尽力投递」。

### M5 版本切换后的轮询
**前端**：用户停在历史版本时，后台报告 ready 不应把页面跳回最新版；只更新下拉数据，选择保持不变；用户点「最新版」才切换。

### M6 线索详情来源复盘被删
**后端**：`source_review_id` 指向的复盘不存在时，`sourceReview=null`，页面显示「来源复盘已删除」，不报 404。
