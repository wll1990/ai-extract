# 未完成项与已知边界

> 用途：把「现在没做 / 只做了一半 / 有明确边界的」单独记在这里，避免在交付说明里被忽略。
> 更新规则：做完一项就把状态改成「已完成」并写明日期与验证方式；不要直接删除条目。

## 一、脱敏与隐私

| # | 项目 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| P1 | 无后缀品牌名/公司简称 | **未覆盖**：强脱敏只识别「XX有限公司/集团/银行/医院/院校」等带后缀的机构名；只说「华为」「阿里」不会替换 | 对外内容可能残留客户/品牌可识别信息 | 接 NER（如 HanLP/LLM 实体识别）或模型二次脱敏；先对公共库内容做人工复核 |
| P2 | 多媒体原件 | **未脱敏**：录音原声、身份证/名片照片、合同扫描件、聊天截图只存不处理 | 声纹、头像、证件照属于高风险个人信息 | 上传端做原件加密与访问审计；公共库禁止上传原件；后续做 OCR 后脱敏或原件到期删除 |
| P3 | 存量数据 | **未回溯**：脱敏只作用于新写入，历史知识/案例/颗粒/素材仍可能含完整手机号、身份证 | 历史库存在合规风险 | 单独跑一次全量体检（扫描 + 脱敏 + 报告），由企业确认窗口期 |
| P4 | 对象存储原件 | **保留原文**：断点续传依赖原件，脱敏只作用于解析文本、模型上下文和库内内容 | 有权限的人拿到原件仍可看到原始信息 | 加密存储 + 签名短时效 + 访问审计；明确保留期限与删除策略 |
| P5 | 组合重识别 | **未处理**：精确时间 + 地点 + 金额 + 人物组合即使单项打码仍可能定位到具体客户 | 对外内容仍有重识别风险 | 对外内容额外做时间粗化（按月）、地点到城市级、金额区间化 |
| P6 | 商业敏感信息 | **不自动打码**：底价、成本价、毛利率、竞品报价、标底、客户名单、未公开资本动作、产品路线图、人事薪酬 | 不是个人隐私，但属于商业机密；打码会破坏知识价值 | 靠租户隔离 + 公共库人工审核 + 导出留痕；后续可加敏感标签与访问等级 |
| P7 | 脱敏方式 | **仅规则**：确定性正则，无模型兜底；生僻姓、无后缀机构名、口语化称呼识别不到 | 边界明确，但不是 100% | 规则 + NER 双通道；保留人工复核环节 |
| P8 | 公共库审核 | **无自动门禁**：提交公共库时自动强脱敏，但商业敏感内容仍需人工审核 | 误提交风险 | 公共库审核清单里增加「商业敏感信息」检查项 |
| P9 | 扫描件 / OCR | **不支持**：ai-service 只做文本抽取，没有 OCR；扫描版 PDF、图片里的文字可能解析为空 | 大量纸质资料无法直接入库 | 接 OCR（PaddleOCR/Tesseract）或在外部先转文字再上传 |

## 二、检索与内容质量

| # | 项目 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| Q1 | 查重 | **按标题精确匹配**（同任务/同企业），不是语义去重 | 同一观点换个说法仍能入库 | 上线时用 embedding 相似度去重（阈值建议 0.92），先离线评估误杀率 |
| Q2 | 质量分 | **规则计算**（数字/边界/场景），不是模型判断 | 分数高不代表内容正确 | 保留人工审批；后续可加模型质检作为提醒项 |
| Q3 | 审批口径 | **不重卡长度下限**，只拦空标题、超长正文、非法分类、已记录问题 | 历史短条目仍可生效 | 有意为之，避免卡死存量；新建/萃取时已执行完整标准 |
| Q4 | 租户配额 | **无月度配额**：只限单次上传产出（知识 200 / 案例 100） | 无法防止持续灌入低质内容 | 增加「每月上传任务数/产出条数」配额与告警 |
| Q5 | 存量质量体检 | **未做**：没有全库扫描与低质内容清单 | 历史低质内容持续稀释检索 | 做一次体检：0 引用 + 低分 + 超长/超短 + 重复标题清单 |
| Q6 | 内容生命周期 | **无自动归档**：过期只停止引用，不清理 | 库会持续变大 | 增加「过期 90 天自动归档」开关 |

## 三、功能缺口

| # | 项目 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| F1 | 模型变更自动回归 | **未做**：换模型/改提示词不会自动跑题集 | 变更后是否退化靠人工发现 | 需要触发点（模型配置保存/分身发布）+ 成本开关 + 指定回归题集，先设计再实现 |
| F2 | 对练检索知识/案例 | **未接**：Practice 只用分身提示词，不查知识/案例 | 对练场景真实性依赖分身自身颗粒 | 建议只注入案例的「客户画像/异议/原话」生成客户台词，不注入知识与话术；待产品拍板 |
| F3 | 组织分身评测 | **不支持**：评测运行只能选个体分身 | 组织总调度质量无法直接衡量 | 需要为组织分身定义评分基准与题集适用范围 |
| F4 | 评测题高级字段前端 | **未开放**：citationRequirement / scoringRule 目前只读或不展示 | 运营无法在页面上配置复杂评分口径 | 先收集真实用法，再设计表单，避免做成难用的高级配置 |
| F5 | 案例上传失败章节 | **未记录**：知识上传有 failedSections，案例没有 | 案例部分章节失败时只能看总数 | 与知识对齐，补 failed_sections 与页面提示 |
| F6 | 公共库治理 | **未做**：没有公共库批量治理、内容排行、使用热度榜 | 公共库运营效率低 | 按引用量/缺口命中做排序与批量下架 |
| F7 | 三库合并视图 | **未做**：知识/案例/评测各自独立入口 | 新人不知道先看哪个 | 用 `72-三库使用说明` 作为统一入口；后续可加总览页 |
| F8 | 文档级版本 | **未做**：同名文件重新上传不会生成「文档版本」，只按条目标题查重 | 无法回答「这份手册第 3 版改了什么」 | 需要文档实体 + 版本表；当前先用条目版本链替代 |
| F9 | 分块（chunk）管理 | **未做**：不能像 Dify 那样逐块查看、编辑、启用/禁用、重切 | 长文档某一段萃取错了只能整条改 | 在萃取草稿层已可预览/采纳/拒绝；后续加块级编辑 |
| F10 | 检索能力 | 知识/案例为纯向量 ANN（阈值 0.35/0.50，top3），**无 rerank、无元数据过滤**；经验颗粒才有 BM25 hybrid | 复杂过滤与高精度排序弱于通用 RAG 平台 | 需要引入 rerank 模型与 metadata 索引，按真实效果评估 |
| F11 | 工作流 / Agent 编排 | **不具备**：没有画布式 workflow、工具调用编排 | 不能像 Dify 一样搭多步流程 | 本产品定位是垂直销售经验系统，不做通用编排；确需时通过 API/IM 集成 |
| F12 | 外部知识库 API | **未开放**：只有站内导入导出 | 第三方系统无法直接写入/检索 | 可开放受控 API（鉴权 + 配额 + 审计） |
| F13 | 知识/案例检索的 query | **未统一**：经验颗粒用改写后的 `ragQuery`，知识/案例仍用用户原始问句 | 多轮指代（「那这个呢」）时知识/案例召回偏弱 | 统一传入 `ragQuery`，用评测集验证召回变化后再上线 |
| F14 | 参考资料原始文档库 | **不做**：系统没有原文 chunk 存储/检索；合同、制度、产品说明不进入任何上传入口 | 用户不能把参考资料当附件存进来随时查 | 分身需要回答时拆成知识卡；不需要就不上传 |

## 四、运维与部署

| # | 项目 | 现状 | 影响 | 建议 |
|---|---|---|---|---|
| O1 | 生产部署授权 | 部署脚本已就绪，但生产发布需要用户显式授权 | 代码与线上可能不同步 | 部署前确认窗口，部署后跑 `qa:release` |
| O2 | IM 历史渠道密钥 | 生产两条存量飞书渠道 `secrets.appSecret` 无法用当前 `PARTNER_AES_KEY` 解密 | 这两条渠道无法自动重连 | 重新发布渠道并录入凭据；后续做密钥轮换脚本 |
| O3 | 脱敏回溯任务 | 无运维入口 | 存量清洗需要人工写 SQL | 做成后台任务：扫描 → 预览 → 批量脱敏 → 报告 |
| O4 | 上传原件保留策略 | 无到期删除 | 存储成本与合规风险 | 明确保留天数，做定期清理与审计日志 |
| O5 | 文件存储 | **已统一 OSS**：分身素材、萃取师资料、知识/案例、复盘转录、头像、报告 HTML、培训导出。存量本地文件用 `POST /admin/storage/migrate-local` 迁移（默认 dryRun）。本地仅剩 STT 临时文件与 PPT 模板（非用户数据） | 无 | 迁移后确认 `file_url`/`html_path` 不再有 `/`、`./data/` 前缀 |
