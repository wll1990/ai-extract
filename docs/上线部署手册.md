## 三、部署步骤

### 步骤 1：数据库迁移

Flyway 已合并为单个 `V1__init.sql`。生产库如果已有 flyway_schema_history，先清理：

```sql
-- 新库跳过此步。旧库迁移过 V1-V39 的需要重置：
DROP TABLE IF EXISTS flyway_schema_history;
```

应用启动时 Flyway 自动执行 `V1__init.sql` 完成全量建表 + 初始数据。

**初始数据（仅 3 条）：**
- `company`：默认企业
- `user`：super_admin（admin / admin123）
- `company_register_code`：DEFAULT01

### 步骤 2：构建

每个服务独立的构建脚本：

```bash
bash scripts/deploy-backend.sh     # 后端 → backend/target/*.jar
bash scripts/deploy-frontend.sh    # 管理后台 → frontend/.next/
bash scripts/deploy-platform.sh    # 平台端 → platform/.next/
```

### 步骤 3：启动（按依赖顺序）

```bash
# 1. Python AI 文件解析服务
cd ai-service
nohup uvicorn main:app --host 0.0.0.0 --port 8000 > ../logs/ai-service.log 2>&1 &
echo $! > ../logs/ai-service.pid
# 验证
curl -s http://127.0.0.1:8000/health

# 2. Spring Boot 后端
cd backend
nohup java -Xms256m -Xmx512m -jar target/*.jar > ../logs/backend.log 2>&1 &
echo $! > ../logs/backend.pid
# 等待 20s，验证
sleep 20
curl -s http://127.0.0.1:8080/api/v1/public/stats

# 3. 前端管理后台
cd frontend
nohup npx next start -p 3000 > ../logs/frontend.log 2>&1 &
echo $! > ../logs/frontend.pid
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3000

# 4. 平台端
cd platform
nohup npx next start -p 3001 > ../logs/platform.log 2>&1 &
echo $! > ../logs/platform.pid
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3001
```

### 步骤 4：Nginx 反向代理

```nginx
# 管理后台（B端）
server {
    server_name admin.your-domain.com;
    listen 443 ssl;
    # ssl_certificate ...

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/v1/ {
        proxy_pass http://127.0.0.1:8080/api/v1/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;       # WebSocket 语音识别
        proxy_set_header Connection "upgrade";        # WebSocket 协议升级
        proxy_read_timeout 120s;                      # STT 长连接
        proxy_send_timeout 120s;
        client_max_body_size 100m;
    }

    location /files/ {
        proxy_pass http://127.0.0.1:8080/files/;
    }
}

# 平台端（C端）
server {
    server_name platform.your-domain.com;
    listen 443 ssl;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/v1/ {
        proxy_pass http://127.0.0.1:8080/api/v1/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;       # WebSocket 语音识别
        proxy_set_header Connection "upgrade";        # WebSocket 协议升级
        proxy_read_timeout 120s;                      # STT 长连接
        proxy_send_timeout 120s;
        client_max_body_size 100m;
    }

    location /files/ {
        proxy_pass http://127.0.0.1:8080/files/;
    }
}
```

> **WebSocket 说明**：语音识别（STT）使用 `/api/v1/ws/stt` 端点。浏览器与后端通过 WebSocket 实时传输音频流。
> Nginx 需配置 `proxy_http_version 1.1` + `Upgrade` + `Connection` 三行才能正确代理 WebSocket 升级请求。
> Caddy / Traefik 默认透传，无需额外配置。

```bash
nginx -t && systemctl reload nginx
```

## 五、日志

所有日志统一在 `logs/`：

```
logs/
├── backend.log              # Spring Boot — logback 自动滚动（50MB×30天）
├── backend-error.log         # 仅 ERROR — 20MB×60天
├── ai-service.log            # Python — RotatingFileHandler（10MB×5）
├── ai-service-error.log      # 仅 ERROR — 5MB×5
├── frontend.log              # Next.js stdout — logrotate daily×30天
├── frontend-error.log        # stderr
├── platform.log              # Next.js stdout
├── platform-error.log        # stderr
├── *.pid                     # 进程 PID
└── logrotate.conf            # Node.js 日志轮转配置
```

查看日志：
```bash
tail -f logs/backend.log
tail -f logs/platform.log
```

logrotate 配置（`scripts/logrotate.conf`），添加到 crontab：
```bash
# 每天凌晨 2:00 轮转 Node.js 日志
0 2 * * * /usr/sbin/logrotate -s /path/to/logs/logrotate.status /path/to/scripts/logrotate.conf
```

## 九、分布式部署方案（后期扩展）

> 当前阶段：单机部署（第四章）。域名备案完成后，可按本章拆分为分布式。

### 9.1 目标架构

```
                       ┌─────────────────────┐
                       │    DNS / CDN         │
                       └──────────┬──────────┘
           ┌──────────────────────┼──────────────────────┐
           ▼                      ▼                      ▼
    admin.your.com        platform.your.com        api.your.com
        机器 B                   机器 C                 机器 A
    ┌─────────────┐        ┌─────────────┐        ┌─────────────┐
    │ Nginx :443  │        │ Nginx :443  │        │ Nginx :443  │
    │   └─ :3000  │        │   └─ :3001  │        │   └─ :8080  │
    │  frontend   │        │  platform   │        │   backend   │
    └─────────────┘        └─────────────┘        └──────┬──────┘
                                                         │
                              ┌──────────────────────────┼────────────────────┐
                              ▼                          ▼                    ▼
                        机器 D :8000               机器 E :5432          机器 F :6379
                        ai-service                PostgreSQL             Redis
```

核心原则：**前端不感知后端机器，后端不感知前端机器，全都通过域名通信。**

### 9.2 单机 → 分布式变化点

| 配置项 | 单机 | 分布式 | 影响 |
|--------|------|--------|------|
| `NEXT_PUBLIC_API_BASE_URL` | `/api/v1`（相对路径） | `https://api.your.com/api/v1`（绝对 URL） | 需重新构建前端 |
| CORS | 不需要 | 必须配置前端域名 | 改 `application.yml` 重启后端 |
| `PG_HOST` | `localhost` | PostgreSQL 内网 IP | 改环境变量重启后端 |
| `REDIS_HOST` | `localhost` | Redis 内网 IP | 同上 |
| `AI_SERVICE_URL` | `localhost:8000` | ai-service 内网 IP | 同上 |
| Nginx `/api/` 代理 | 每台前端各代理一份 | 只在 backend 那台代理 | 精简 Nginx 配置 |

### 9.3 分机器部署步骤

**前置条件：** 4 台以上服务器，内网互通，域名已备案。

#### 机器 A：backend + Nginx（API 网关）

```nginx
# /etc/nginx/sites-enabled/api
server {
    listen 443 ssl;
    server_name api.your-domain.com;

    location /api/v1/ {
        proxy_pass http://127.0.0.1:8080/api/v1/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
        client_max_body_size 100m;
    }

    location /files/ {
        proxy_pass http://127.0.0.1:8080/files/;
    }
}
```

```bash
# config/backend.env
PG_HOST=10.0.1.10
REDIS_HOST=10.0.1.11
AI_SERVICE_URL=http://10.0.1.20:8000
```

```yaml
# application.yml（CORS 部分）
app:
  cors:
    allowed-origins:
      - https://admin.your-domain.com
      - https://platform.your-domain.com
```

#### 机器 B：frontend（管理后台）

```nginx
# /etc/nginx/sites-enabled/admin
server {
    listen 443 ssl;
    server_name admin.your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
# 构建时的 .env.production
NEXT_PUBLIC_API_BASE_URL=https://api.your-domain.com/api/v1
```

#### 机器 C：platform（平台端）

```nginx
server {
    listen 443 ssl;
    server_name platform.your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
# 构建时的 .env.production
NEXT_PUBLIC_API_BASE_URL=https://api.your-domain.com/api/v1
```

#### 机器 D/E/F：ai-service / PostgreSQL / Redis

纯内网服务，不对外暴露端口。仅 backend 机器通过内网 IP 连接。

### 9.4 关键注意事项

1. **`NEXT_PUBLIC_*` 是构建时变量** — 改了必须重新 `npm run build`，不能用环境变量运行时覆盖
2. **WebSocket** — `VoiceRecorder` 生产走 `window.location.host`，前后端分离后 WebSocket 也通过 API 域名走，Nginx 已配好 Upgrade 头
3. **文件上传** — 头像/素材上传的 `storage.local.path` 默认 `./data/files`，分布式时需要用共享存储（NFS/OSS）或保证文件只上传到 backend 机器
4. **Session 共享** — 目前 JWT 无状态，不需要 Session 共享。如果以后加 Session，需要 Redis 共享
5. **Flyway 迁移** — 多台 backend 实例只允许一台执行 Flyway（或提前手动执行）

## 十、本地开发 vs 生产部署 差异对照

### 10.1 环境变量

| 变量 | 本地开发 | 生产部署 | 说明 |
|------|---------|---------|------|
| `PG_HOST` | `localhost` | `127.0.0.1` | 生产不走域名 |
| `PG_USER` | `wanglei` | `pg2027` | 生产专用数据库用户 |
| `REDIS_HOST` | `localhost` | `127.0.0.1` | |
| `AI_SERVICE_URL` | `http://localhost:8000` | `http://127.0.0.1:8000` | |
| `DEEPSEEK_API_KEY` | `.env` 中的 dev key | 生产独立 key | 建议分开计费 |
| `QWEN_API_KEY` | 同上 | 同上 | |
| `JWT_SECRET` | dev 固定值 | 生产随机生成 | 泄露则所有 token 失效 |
| `PROMPTS_DIR` | **不设**（走 jar 内 classpath） | `/opt/mindforge/prompts` | 设了就走外部目录 |
| `STORAGE_LOCAL_PATH` | **不设**（`./data/files`） | `/opt/mindforge/data/files` | 绝对路径 |

### 10.2 数据库

| 项目 | 本地开发 | 生产部署 |
|------|---------|---------|
| Flyway 迁移 | 39 个增量文件（V1-V39） | 1 个合并文件（V1__init.sql） |
| 连接用户 | `wanglei` | `pg2027` |
| pgvector | 0.8.2（Homebrew） | 0.8.5（RPM） |
| 初始数据 | 开发测试数据 | 仅 3 条种子数据 |

### 10.3 前端

| 项目 | 本地开发 | 生产部署 |
|------|---------|---------|
| 启动方式 | `npm run dev` | `npm run build` → `next start -p 3xxx` |
| `NEXT_PUBLIC_API_BASE_URL` | 相对路径 `/api/v1` | 相同（Nginx 同域代理） |

### 10.4 后端

| 项目 | 本地开发 | 生产部署 |
