# 销售复盘 W2 收口 — 代码级设计

日期：2026-10-30
范围：把上一轮列出的「未落地项」全部补齐，按代码级实现。

## 0. 范围

| 编号 | 能力 | 现状 | 本轮目标 |
|---|---|---|---|
| S1 | 报告版本下拉 + 旧版只读 + 版本对比 | 后端 `GET /{id}/reports` 已通，前端只用最新版 | 详情页可选版本；旧版只读；与下一版做词级对比 |
| S2 | 生成任务时可编辑时间/渠道/话术 | 弹层只能勾选，`dueAt` 自动算 | 逐条编辑；创建校验；同名并发 409 |
| S3 | 任务编辑（已创建待办） | 无 | `PUT /sales/tasks/{id}`，仅 pending；审计 |
| S4 | 线索详情 / 客户档案 / 时间线 | 只有列表 | 线索详情页、多联系人、活动时间线、关联任务 |
| S5 | 任务提醒 / 转交 / 升级 | 无 | 到期前提醒、逾期提醒、72h 自动升级；手动转交/升级 |
| S6 | 追问草稿 | 刷新丢失 | 按复盘存 localStorage，发送成功清除 |
| S7 | 教练台账 N+1 | 每行查一次最新报告 | 批量查报告 |
| S8 | 全链路 E2E | 只覆盖页面渲染 | 复盘→报告→线索→任务→教练补充 的自动化链路 |

不在本轮：
- 线索池/认领/分配规则、销售漏斗报表。
- 客户档案的工商信息、外部 CRM 同步。
- 任务重复规则引擎（只做同名唯一 + 明确 409）。
- 飞书/邮件提醒（站内信已有底座）。

### 2.3 `SalesTaskService`

#### 创建（S2）

```java
@Transactional
public int createFromReview(UUID sessionId, List<TaskDraftRequest> drafts) {
    ReviewSession session = access.requireSession(sessionId);
    access.requireLeadManage();
    if (drafts == null || drafts.isEmpty() || drafts.size() > 3)
        throw new BusinessException(400, "请选择 1–3 条下一步");

    LocalDateTime now = LocalDateTime.now();
    Set<String> titles = new HashSet<>();
    List<FollowUpTask> tasks = new ArrayList<>();
    for (TaskDraftRequest d : drafts) {
        String title = d.title() == null ? "" : d.title().trim();
        if (title.isEmpty()) throw new BusinessException(400, "任务标题不能为空");
        if (!titles.add(title))
            throw BusinessException.conflict("TASK_DUPLICATE", "本次提交有同名任务：" + title);
        if (d.dueAt() != null && d.dueAt().isBefore(now))
            throw new BusinessException(400, "截止时间不能早于现在");
        if (taskRepository.existsByReviewIdAndTitle(sessionId, title))
            throw BusinessException.conflict("TASK_DUPLICATE", "已存在同名任务：" + title);
        tasks.add(FollowUpTask.builder()
                .id(UUID.randomUUID()).companyId(session.getCompanyId())
                .leadId(session.getLeadId()).reviewId(sessionId)
                .ownerId(session.getReviewerId())
                .title(title).channel(trimToNull(d.channel()))
                .content(trimToNull(d.content())).dueAt(d.dueAt())
                .status("pending").createdBy(TokenContext.get())
                .createdAt(now).updatedAt(now).build());
    }
    try {
        taskRepository.saveAllAndFlush(tasks);
    } catch (DataIntegrityViolationException e) {
        throw BusinessException.conflict("TASK_DUPLICATE", "任务已存在，请刷新后重试");
    }
    if (session.getLeadId() != null) {
        activityService.record(session.getLeadId(), "task_created",
                "创建 " + tasks.size() + " 条跟进任务", "review_session", sessionId);
    }
    audit.record("sales.task.create", "review_session", sessionId,
            Map.of("created", tasks.size()));
    return tasks.size();
}
```

`saveAllAndFlush` 保证唯一索引冲突在事务内抛出；捕获后转 409，不返回 500。

#### 编辑（S3）

```java
@Transactional
public TaskView update(UUID id, TaskUpdateRequest req) {
    FollowUpTask task = access.requireTask(id);
    if (!"pending".equals(task.getStatus()))
        throw BusinessException.conflict("TASK_STATE_INVALID", "已结束的任务不能编辑");
    String title = req.title().trim();
    if (title.isEmpty()) throw new BusinessException(400, "任务标题不能为空");
    if (task.getReviewId() != null
            && taskRepository.existsByReviewIdAndTitleAndIdNot(task.getReviewId(), title, id))
        throw BusinessException.conflict("TASK_DUPLICATE", "已存在同名任务：" + title);

    boolean dueChanged = !Objects.equals(task.getDueAt(), req.dueAt());
    if (dueChanged && req.dueAt() != null && req.dueAt().isBefore(LocalDateTime.now()))
        throw new BusinessException(400, "截止时间不能早于现在");
    task.setTitle(title);
    task.setChannel(trimToNull(req.channel()));
    task.setContent(trimToNull(req.content()));
    task.setDueAt(req.dueAt());
    if (dueChanged) {
        task.setDueRemindedAt(null);
        task.setOverdueNotifiedAt(null);
    }
    task.setUpdatedAt(LocalDateTime.now());
    taskRepository.save(task);
    audit.record("sales.task.update", "follow_up_task", id,
            Map.of("title", title, "dueChanged", dueChanged));
    return toView(task, ownerName(task.getOwnerId()));
}
```

```java
@Transactional
public TaskView transfer(UUID id, UUID newOwnerId) {
    FollowUpTask task = access.requireTask(id);
    access.requireLeadManage();
    if (!"pending".equals(task.getStatus()))
        throw BusinessException.conflict("TASK_STATE_INVALID", "已结束的任务不能转交");
    User target = userRepository.findById(newOwnerId)
            .filter(u -> Boolean.TRUE.equals(u.getIsActive()))
            .filter(u -> Objects.equals(u.getCompanyId(), task.getCompanyId()))
            .orElseThrow(() -> new BusinessException(400, "目标负责人不存在或不在本企业"));
    if (target.getId().equals(task.getOwnerId()))
        throw new BusinessException(400, "任务已经在该负责人名下");
    UUID from = task.getOwnerId();
    task.setOwnerId(target.getId());
    task.setUpdatedAt(LocalDateTime.now());
    taskRepository.save(task);
    notificationService.notifyUser(target.getId(), task.getCompanyId(),
            UserNotification.TYPE_SALES_TASK_TRANSFERRED,
            "你收到一条跟进任务", task.getTitle(), "/sales/tasks",
            "follow_up_task", task.getId(), "task_transfer:" + task.getId() + ":" + target.getId());
    if (task.getLeadId() != null)
        activityService.record(task.getLeadId(), "task_transferred",
                "任务「" + task.getTitle() + "」转交给 " + target.getName(),
                "follow_up_task", task.getId());
    audit.record("sales.task.transfer", "follow_up_task", id,
            Map.of("from", from.toString(), "to", target.getId().toString()));
    return toView(task, target.getName());
}
```

#### 升级（S5）

```java
@Transactional
public TaskView escalate(UUID id, String reason) {
    FollowUpTask task = access.requireTask(id);
    access.requireLeadManage();
    if (!"pending".equals(task.getStatus()))
        throw BusinessException.conflict("TASK_STATE_INVALID", "已结束的任务不能升级");
    if (task.getEscalatedAt() != null)
        throw BusinessException.conflict("TASK_ALREADY_ESCALATED", "任务已经升级过");
    task.setEscalatedAt(LocalDateTime.now());
    task.setEscalatedBy(TokenContext.get());
    task.setUpdatedAt(LocalDateTime.now());
    taskRepository.save(task);
    escalateNotify(task, reason);
    if (task.getLeadId() != null)
        activityService.record(task.getLeadId(), "task_escalated",
                "任务「" + task.getTitle() + "」已升级", "follow_up_task", task.getId());
    audit.record("sales.task.escalate", "follow_up_task", id,
            Map.of("reason", reason == null ? "" : reason));
    return toView(task, ownerName(task.getOwnerId()));
}
```

`escalateNotify` 逻辑：查本企业 active `company_admin/super_admin`，逐个 `notifyUser`，`dedupeKey = "task_escalated:" + taskId + ":" + adminId`；标题「任务已升级」，正文含任务名、负责人、截止时间、升级原因，`link=/sales/tasks`。

### 2.4 任务提醒 Scheduler（S5）

新增 `scheduler/SalesTaskReminderScheduler.java`：

```java
@Slf4j
@Component
@RequiredArgsConstructor
public class SalesTaskReminderScheduler {
    private final FollowUpTaskRepository taskRepository;
    private final SalesTaskReminderService reminderService;

    @Value("${app.sales.reminder.enabled:true}") private boolean enabled;
    @Value("${app.sales.reminder.interval-ms:600000}") private long interval;
    @Value("${app.sales.reminder.batch-size:200}") private int batchSize;

    @Scheduled(fixedDelayString = "${app.sales.reminder.interval-ms:600000}",
               initialDelayString = "${app.sales.reminder.initial-delay-ms:60000}")
    public void tick() {
        if (!enabled) return;
        LocalDateTime now = LocalDateTime.now();
        for (UUID id : taskRepository.findDueSoonIds(now, now.plusHours(24), batchSize))
            reminderService.remindDueSoon(id);
        for (UUID id : taskRepository.findOverdueIds(now, batchSize))
            reminderService.remindOverdue(id);
        for (UUID id : taskRepository.findEscalationCandidates(now.minusHours(72), batchSize))
            reminderService.autoEscalate(id);
    }
}
```


`ReportVersionDiff` 规则（不做「新增/删除要点」判定）：
- 左右两栏：左「当前查看的 vN」，右「下一版 vM」。
- `summary` 与每条要点的文本做**词级 LCS diff**：新增词绿底、删除词红底；相同文本不高亮。
- 只说数量变化：`做得好的 3 → 4 条`，不推断哪条是新增。
- 客户信号按 `field` 并排显示；值不同标「有变化」。
- 顶部固定说明：「AI 每次会改写措辞，词级变化不代表结论改变」。

```tsx
function diffWords(before: string, after: string): Array<{ text: string; kind: 'same' | 'add' | 'del' }> {

  // 返回按 after 顺序排列的片段，del 片段插在对应位置
```

## 4. 权限与边界

| 操作 | 规则 |
|---|---|
| 线索详情/联系人/备注/编辑 | `access.requireLead`：本人或 `SALES_REVIEW_VIEW_ALL`；写操作再要求 `SALES_LEAD_MANAGE` |
| 任务编辑/转交/升级 | `access.requireTask` + `SALES_LEAD_MANAGE`；员工只能操作自己的，管理员可操作全公司 |
| 转交目标 | 同企业、active、B 端角色；不能转给自己 |
| 报告历史版本 | `access.requireSession`；历史版本只读，不能转线索/生成任务 |
| 提醒/升级通知 | 只发给本企业用户；去重键防重复 |
| 跨企业 | 一律 404，不泄露存在性 |

### 8.3 与设计的偏差

1. **版本对比方向**：设计写「与上一版」，实际实现为「与下一版」——只有两个版本时，选中 v1 没有上一版；对比 v1→v2 才有意义。文案已改为「当前查看 / 下一版」。
2. **任务负责人选择器**：复用现有 `UserRepository.searchForPicker`，没有新增 native SQL；行为一致（本企业、active、B 端角色、关键字搜索）。
3. **提醒的实机验证**：调度间隔 10 分钟，本轮只做单测覆盖（抢占幂等、通知去重、自动升级），未等待真实调度窗口；上线前可在测试环境把 `app.sales.reminder.interval-ms` 调小跑一次。
4. **全链路 E2E 的数据清理**：Playwright 不直连 DB，清理由 `npm run e2e:sales:chain` 末尾的 psql 完成；CI 无 psql 时保留数据并打印标记。

### 8.4 已知残留

- 站内信去重冲突仍会打印一次 WARN 堆栈（`uq_un_dedupe`），不影响主流程；后续可先查后插降低噪声。
- 自动升级没有管理员时不会通知任何人（本企业无 `company_admin/super_admin` 的边界情况），只写活动；是否需要回退通知平台管理员需产品确认。
