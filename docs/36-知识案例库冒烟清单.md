# 知识库 + 案例库 冒烟清单（T1–T16 运行时验证）

> 本清单覆盖「编译已验证、但需真实 PostgreSQL(pgvector) + 真实服务才能确认」的运行时行为。
> 属既定边界：`KnowledgeCaseRetriever` / `updateEmbedding` / 上传任务进度等 native SQL 均未在单测覆盖，靠本清单兜底。

## 前置条件

- PostgreSQL 已启用 `vector` 扩展，Flyway 已跑到 **V44**（`upload_task_progress_resume`）
- `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` / `JWT_SECRET` 已注入，backend 启动无 Flyway 错误
- ai-service（`/internal/parse-file`）经预签名 URL 下载 OSS 文件解析（backend 与 ai-service 可分离部署，不再要求同机共享本地磁盘）
- 已准备：super_admin、company A 与 company B 各一个 `company_admin`、一个 `employee`

## 环境变量与登录

```bash
BASE=http://localhost:8080/api/v1

# 登录（companyCode 优先；响应 data.token）
TOKEN=$(curl -s -X POST $BASE/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"companyCode":"ABC12345","account":"admin","password":"你的密码"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

AUTH="Authorization: Bearer $TOKEN"
```

> 换企业/角色时重新登录取对应 `$TOKEN`。

## B. 知识 CRUD + embedding 生命周期

```bash
# B1 创建（company_admin）
curl -s -X POST $BASE/admin/knowledge -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"title":"BANT 四问法","category":"methodology","sourceType":"tenant","content":"预算、权限、需求、时间四个维度。","expireAt":"2027-01-01T00:00:00"}'
# → data.status = "pending"，记下 data.id = $KID
```

| # | 操作 | 预期 / 验证 |
|---|------|------|
| B1 | 上一条 create | `status=pending` |
| B2 | `SELECT embedding IS NULL FROM knowledge_entry WHERE id='$KID';` | `t`（pending 无向量） |
| B3 | `curl -X POST "$BASE/admin/knowledge/$KID/approve?expireAt=2027-01-01T00:00:00" -H "$AUTH"` | `status=active` |
| B4 | `SELECT status, embedding IS NOT NULL AS has_vec FROM knowledge_entry WHERE id='$KID';` | `active / true`（**审批即写向量**） |
| B5 | 对无失效时间的 pending 条目 `approve` 不带 expireAt | 400「失效时间必填」 |
| B6 | `curl -X POST $BASE/admin/knowledge/$KID/suggest-revision -H "$AUTH" -H 'Content-Type: application/json' -d '{"instruction":"补充时间维度示例"}'` | 旧条→`deprecated`，新条 `draft` 且 `version+1` |
| B7 | `curl -X POST $BASE/admin/knowledge/$KID/deprecate -H "$AUTH"` | `status=deprecated` |
| B8 | `curl -X POST $BASE/admin/knowledge/$PUBLIC_KID/copy -H "$AUTH"`（公共知识复制到企业） | 副本 `companyId=本企业`、`status=pending`、`embedding IS NULL`（审批时才写向量，与 B2 一致；向量不丢，approve 时 re-embed） |
| B9 | create 带 `"category":"foo"` | 400 或 DB CHECK 拦截，不落库 |

## D. 文档萃取 + 进度/续传

```bash
# D1 上传（含「第1章 / 1.1 …」结构的书）
curl -s -X POST $BASE/admin/knowledge/upload -H "$AUTH" -F 'file=@/path/to/book.txt'
# → 立即返回 data.taskId = $TID（异步）
```

| # | 操作 | 预期 |
|---|------|------|
| D1 | 上传 | 立即返回 `taskId`（不阻塞） |
| D2 | 轮询 `curl -s $BASE/admin/knowledge/upload/$TID -H "$AUTH"` | 先 `extracting`，`totalSections>0`，`processedSections` 逐节递增 |
| D3 | 轮询至 `done` | `producedCount>0`，产出 `pending`、`source` 带「章·节」链 |
| D4 | 上传含「超标」文档，检查产出正文 | 保持「**超标**」，**不被改成「招标」** |
| D5 | 上传空文件/图片 | `failed` 且 `errorMessage` 有原因 |
| D6 | **断点续传**：上传大书，中途 kill backend → 重启 → 查 `$TID` | 仍 `extracting`（卡住待续传） |
| D7 | `curl -X POST $BASE/admin/knowledge/upload/$TID/retry -H "$AUTH"` → 轮询 | 从 `processedSections` 续传，**不重复落库已完成章节** |
| D8 | 对已 `done` 任务再 retry | 400「任务已完成，无需重试」 |

## E. Phase B 检索 + 溯源（核心边界）

| # | 操作 | 预期 |
|---|------|------|
| E1 | 审批一条知识（B4）后，用 company A 用户对已发布分身提问命中该知识的话题 | SSE 出现 `{"type":"source","sourceType":"knowledge","sourceTitle":...}` |
| E2 | 无任何 active 知识/案例时提问 | **无** knowledge/case 溯源事件（`hasAnyActive` 预检跳过嵌入） |
| E3 | 建一条 `expire_at` 已过去（active）的知识 → 提问 | **不被召回** |
| E4 | 建公共知识 + company A 私有知识 → company A 提问 | 两条都召回 |
| E5 | company B 用户（或 C 端游客）提问同一话题 | 只召回**公共**，私有不可见 |
| E6 | 阈值直查：`SELECT title, 1.0-(embedding <=> '...'::vector) AS sim FROM knowledge_entry WHERE status='active' AND embedding IS NOT NULL ORDER BY embedding <=> '...'::vector LIMIT 3;` | 仅 `sim >= 0.30` 会被 retriever 返回 |
| E7 | 分身对话里看溯源 chips | B 端 + C 端均显示 📖/🎞️，**grain 溯源零回退** |

| # | 操作 | 预期 |
|---|------|------|
| G1 | `GET /admin/company/practice-kc`（company_admin） | `enabled=false, defaultEnabled=false` |

| G6 | 向量恢复后重新发布 | 发布成功；`generating→published` 同样受门槛约束 |
| G7 | 对已发布分身再调 publish | 幂等：`{passed:true, alreadyPublished:true}`，不重复生成开场白 |

## 通过判据

- **B4 / B8**：审批后 `embedding IS NOT NULL`、复制后向量未丢（否则 E1 永远召不回）。
- **D4**：「超标」不被改「招标」——知识管道不复用错别字修正的回归红线。
- **E3 / E5**：时效过滤 + 企业隔离在真实 pgvector 上生效。
- **E7**：三类溯源独立展示，grain 溯源零回退。
- 全流程**零 500 / 无吞异常**（失败必有 `errorMessage` 落到任务或日志）。
