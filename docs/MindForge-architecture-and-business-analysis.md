## 二、经验生产管线（供给侧）

系统有 **两条独立的萃取管道**，分别服务不同场景。加上自动发现引擎，共三条 AI 流水线。

### 2.1 Pipeline A：技能分身萃取管道（Skill Material Pipeline）

**入口**：素材上传 + 专家访谈转录（InterviewTranscriptExtractor）
**产出**：`ExperienceGrain`（技能颗粒）→ 入库 → DashScope 向量化 → RAG 可召回

**触发链**：
```
用户上传素材 → MaterialCleaningScheduler(30s轮询)
    → scanAndParse: Python AI 服务解析文本
    → preCheck: 准入检查+重复检测 (rule-based)
    → scanAndClean → processMaterial()
    → MaterialCleaningService.clean() ← 核心管道
```

**13 层管道（`MaterialCleaningService.clean()`）**：

| 层级 | 名称 | 做什么 | AI调用 |
|------|------|--------|--------|
| Gate 0a | 准入预检 | 检查文本是否与领域相关，拒绝无关内容 | 否（规则） |
| Gate 0b | 质量预检 | 估算颗粒数、检测场景、评估质量 | 否（规则） |
| L0 | 上下文标注 | 标注购买阶段、决策角色、竞争环境、客单价、行业 | ✅ 1 次 |
| L1-L3 | 文本清洗 | 格式噪声清理 + 业务噪声过滤 + 文本规范化 | 否 |
| L4 | 语义分块 | 按句子边界智能切块（目标800字，上限1500字） | 否 |
| L4b | 去重 | Jaccard 3-gram 与空间内已有颗粒比对（阈值0.7） | 否 |
| L4c | AI 洞察提取 | 逐块调用 AI 提取销售经验（首块含上下文，后续轻量 prompt） | ✅ 1次/块 |
| L5 | 场景分类 | 批量分类所有提取洞察到场景标签 | ✅ 1 次 |
| L6 | 对抗验证 | 每批10条，AI 五维评分（特异性/可复现性/因果性/差异性/可证伪性），低分淘汰 | ✅ 1次/批 |
| L7 | 同标签合并 | 合并同场景重叠颗粒（仅候选>10时触发） | ✅ 1次/组 |
| L8 | 模式发现 | 识别核心习惯、差异点、方法论命名（仅≥8候选时触发） | ✅ 1 次 |
| L9 | FAQ 提取 | 从原文提取客户异议+销售回应 | ✅ 1 次 |
| L10 | 叙事复现 | AI 重写完整叙事并交叉引用颗粒 | ✅ 1 次 |
| L11 | 画像生成 | 异步生成 SkillProfile（个性、话风、高频短语） | ✅ 异步 1 次 |

**小素材优化**：≤3 个候选颗粒时跳过 L9/L10/L11，省 3 次 AI 调用。

**管道产出后**：
1. `saveGrains()` → 写入 `ExperienceGrain`（status=active）
2. `embedGrains()` → DashScope batch embed → pgvector
3. 素材状态：`analyzed` → `extracted`
4. 分身状态：`generating` → `reviewing`（首次产颗粒）
5. `markReportDirty()` → Redis Set → `generateDirtyReports()`（2分钟周期）→ 生成萃取报告

**锁定机制**：
- 素材级乐观锁：`UPDATE WHERE locked_by IS NULL`（REQUIRES_NEW 短事务）
- 分身级 Redis 锁：`SETNX skill:clean:{skillId}` TTL 600s（同分身串行处理）

### 2.2 Pipeline B：萃取师经验管道（Expert Skill Pipeline）

> **术语**：萃取师 = 专门从专家身上提取方法论的人。元萃取师访谈 = 萃取师通过结构化访谈向专家提问，AI 从访谈记录中提炼 7 类方法论颗粒。

**入口**：萃取师文档上传 + 元萃取师访谈（ExpertInterviewProcessor）
**产出**：`ExpertGrain`（7 类方法论颗粒）→ 管理员激活 → 进入 RAG

**触发链**：
```
萃取师上传文档 → ExpertAnalysisScheduler(30s轮询)
    → 解析文档 → 分析 → 生成报告 → 提取颗粒 → 管理员激活

元萃取师访谈 → ExpertInterviewProcessor
    → 创建 ExpertSkill(status=pending) → 进入同上管道
```

**9 步管道（`ExpertService.analyzeMaterials()`）**：

| 步骤 | 做什么 | AI调用 |
|------|--------|--------|
| 1 | 状态设为 `analyzing`（短事务） | 否 |
| 2a | 文档解析：Python `/internal/parse-file`，失败抛异常（不造假） | 否 |
| 2b | 访谈路径：直接读 `sourceContent`（头/中/尾三段采样，上限4万字） | 否 |
| 3 | AI 生成萃取报告（prompt：`expert_document_extraction.md`） | ✅ 1 次 |
| 4 | AI 结构化报告为 6 章 JSON（prompt：`expert_structure_report.md`） | ✅ 1 次 |
| 5 | 创建 `Report` 行（content_json=结构化报告） | 否 |
| 6 | 状态设为 `extracting` | 否 |
| 7 | 自动触发颗粒提取 | 否 |
| 8 | AI 提取 7 类颗粒：打法方法/判断直觉/心智模型/失败教训/验证方法/隐喻框架/节奏感知 | ✅ 1 次 |
| 9 | 删除旧非活跃颗粒、更新计数 | 否 |

**总计 AI 调用：3 次**（报告生成 + 结构化 + 颗粒提取）

管理员通过 UI 审核 → `activateExpert()` → 颗粒 status→active → 进入 RAG

### 2.3 Pipeline C：自动发现引擎（Auto-Insight Discovery）

**触发**：每天凌晨 3:00（cron）
**输入**：`knowledge_gap` + `feedback_log` + `conversation_stats` + `grain_retrieve_log`
**产出**：`auto_insight` + `candidate_grain`（管理员审核通过 → 写入 `ExperienceGrain`）

| 步骤 | 做什么 |
|------|--------|
| 1 | 扫描未向量化的 knowledge_gap → DashScope embed → 写 pgvector |
| 2 | 贪心聚类（attempt≥5, cosine distance<0.15）→ LLM 命名簇 → 生成 auto_insight |
| 3 | new_pattern 型 → LLM 生成结构化候选颗粒 → status=pending_review |

**三条管道的关系**：
- Pipeline A 和 Pipeline B **完全独立**，不同表（`ExperienceGrain` vs `ExpertGrain`）、不同 prompt、不同领域结构
- Pipeline C 从 Pipeline A/B 的消费数据（缺口、反馈、检索日志）中**反向发现**新知识
- 专家访谈转录 → Pipeline A（产生技能颗粒）；元萃取师访谈 → Pipeline B（产生方法论颗粒）

### 2.4 审核流水线

```
┌─ 四步审核 ────────────────────────────────────────────────┐
│                                                           │
│  Step 1: 显性校验 (ExplicitStep)                            │
│  "AI 说的话对不对？有没有明显错误？"                           │
│                                                           │
│  Step 2: 分身校验 (SkillStep)                               │
│  "这段话术风格像不像张伟本人？语气、用词、思路都对吗？"           │
│                                                           │
│  Step 3: 场景校验 (SceneStep)                               │
│  "这个颗粒归到'报价场景'对吗？适用条件写清楚了吗？"              │
│                                                           │
│  Step 4: 产品校验 (ProductStep)                             │
│  "涉及产品的话术，产品名称、参数、优势都对吗？"                  │
│                                                           │
│  → 通过: status=active → DashScope embed → RAG              │
│  → 拒绝: 记录原因 → 回炉重炼                                   │
└───────────────────────────────────────────────────────────┘
```

### 3.2 RAG 检索链路

```
用户提问
    ↓
Query Rewrite (LLM 改写, 可选)
    ↓
DashScope text-embedding-v4 → query vector (1024维)
    ↓
pgvector HNSW ANN (cosine distance, topK×3 候选)
    ↓
Weight re-rank (cosine_similarity × grain.weight)
    ↓
Tier: high / ref / none
    ↓
LLM 生成回答 (system prompt + top grains as context)
    ↓
grain_retrieve_log + conversation_stats (每轮统计)
    ↓
none → writeKnowledgeGap → Pipeline C 消费
```

## 四、LLM 算力 + 数据 = 自己发现规律

### 4.1 不是告警，是知识生成

传统 BI 只告诉你"满意率降了 18%"。MindForge 输出的是：

> **一条新的候选颗粒**：
> 场景: 报价-ROI锚定
> 专家思考: "高效销售面对价格异议时，先算ROI建信任锚点再谈价格。直接回应价格的对话满意率低 31%"
> 标准话术: "王总，咱们先不谈价格。我帮您算一笔账——按你们目前的人工处理量..."
> 证据: 47 个正面样本 / 32 个负面样本 / +31% 满意率差异

### 4.2 五个数据源

```
knowledge_gap    → "用户问了但颗粒库里没有" —— 缺什么
feedback_log     → "哪些颗粒被赞、哪些被踩" —— 好不好
conversation_stats → "每轮命中率、耗时、错误率" —— 运行状态
grain_retrieve_log → "每条颗粒被检索频率和相似度" —— 热度变化
candidate_grain  → "AI 已经发现了什么、审核通过了吗" —— 进化速度
```

### 4.3 AI 自进化飞轮

```
用户提问 → RAG 检索 → 未命中 → knowledge_gap
    ↓
积累到阈值(≥5次) → Pipeline C 每天 3:00 运行
    ↓
pgvector 聚类 → LLM 生成 auto_insight + candidate_grain
    ↓
管理员审核通过 → 写入 ExperienceGrain + DashScope embed
    ↓
下次同类问题 → RAG 命中 → 满意率提升
    ↓
更多使用 → 更多缺口 → 更多候选颗粒 → 分身越来越聪明
    ↑                                               │
    └────────── 正面飞轮：越用越聪明 ─────────────────┘
```

## 六、用户路径 & 转化漏斗

### 6.1 四条典型用户旅程

```
旅程 1: 员工 → 学习消费
─────────────────────────
落地页 → 发现页浏览AI分身 → 想聊天 → 登录 → 注册(员工) → 回到发现页 → 聊天 → 对练 → 分享

旅程 2: 专家 → 创建分身
─────────────────────────
落地页 → "我是专家" → 注册 → 进入 System A → 上传素材/做访谈 → AI 萃取 → 审核发布 → 生成分享链接

旅程 3: H5 访客 → 注册转化
─────────────────────────
微信点链接 → H5 页 → 免费聊 5 条 → 额度用完 → 注册 → System B → 继续聊 → 发现更多分身

旅程 4: 管理员 → 管理+调优
─────────────────────────
Admin 直登 → 数据看板 → 发现异常 → 调优 → 审核候选颗粒(Pipeline C) → 管理用户
```

## 八、分身飞轮

### 8.1 五个飞轮

```
飞轮 1: 数据飞轮（供给侧）
  更多素材/访谈 → Pipeline A/B 萃取更多颗粒 → AI分身更聪明
  → 员工用得更频繁 → 更多对话数据 → 更多缺口
  → Pipeline C 发现新知识 → 分身持续进化

飞轮 2: 用户飞轮（需求侧）
  更多人用 → 更多反馈(赞/踩) → 系统知道哪些颗粒好
  → Pipeline C 识别差评颗粒 → 提示专家修改
  → 颗粒质量提升 → 满意率提升 → 更多人用

飞轮 3: 增长飞轮（分享侧）
  员工用得好 → 分享 H5 链接 → 外部访客体验
  → 免费 5 条 → 注册转化 → 新用户进入 System B
  → 新用户中有专家 → 引导创建分身 → AI分身库扩大

飞轮 4: 供给飞轮（专家侧）
  专家创建分身 → 员工使用 → 数据看板显示使用量
  → 专家获得成就感("我的经验帮了 200 人")
  → 专家更愿贡献 → 更多素材/访谈 → 颗粒更多更准

飞轮 5: AI 自进化飞轮（系统侧）
  提问 → RAG 检索 → 未命中 → knowledge_gap
  → 聚类 → LLM 生成 candidate_grain → 管理员审核
  → 入库 + 向量化 → 下次命中 → 越用越聪明
```

### 8.2 飞轮度量

| 飞轮 | 核心指标 | 数据源 | 健康阈值 |
|------|---------|--------|---------|
| 数据飞轮 | 周新增颗粒数 / 周对话量 | experience_grain, conversation_stats | > 0.1 |
| 用户飞轮 | 满意率 | feedback_log | > 80% |
| 增长飞轮 | H5 注册转化率 | app_user | > 10% |
| 供给飞轮 | 周活分身比例 | skill, conversation_stats | > 60% |
| AI 飞轮 | 候选颗粒审核通过率 | candidate_grain | > 50% |

## 九、竞争壁垒

> 壁垒不是"我们有 AI"，而是"竞争对手需要花多长时间、多少钱才能追到这个水平"。

### 9.1 壁垒总览

```
                            ┌──────────────────────────┐
                            │     MindForge 壁垒体系     │
                            └──────────────────────────┘
                                         │
        ┌────────────┬──────────┬────────┼────────┬──────────┐
        │            │          │        │        │          │
   ┌────▼───┐  ┌─────▼────┐ ┌──▼──┐ ┌──▼───┐ ┌──▼──┐ ┌─────▼────┐
   │ 数据壁垒 │  │ 工程壁垒  │ │领域 │ │飞轮  │ │质量 │ │ 平台效应  │
   │  Data  │  │Engineer │ │Domain│ │Flywl │ │Qual │ │Platform │
   └────────┘  └─────────┘ └─────┘ └──────┘ └─────┘ └─────────┘
```

### 9.2 壁垒详解

**壁垒一：萃取管道工程复杂度**

竞争对手最容易做的事情是"用 GPT 套壳做一个 AI 聊天"。最难复制的是 MindForge 的三条 AI 流水线：

| 壁垒要素 | 具体内容 | 追平成本估算 |
|---------|---------|------------|
| Pipeline A | 13 层清洗管道：从原始对话到结构化颗粒，含上下文标注、语义分块、Jaccard去重、对抗验证(五维评分)、同标签合并、FAQ提取、叙事复现。仅 AI prompt 模板就有 12+ 个，每个都经过反复调优 | 6-12 个月工程 + 领域专家标注 |
| Pipeline B | 萃取师知识提取：7 类方法论颗粒（打法/直觉/心智模型/失败教训/验证/隐喻/节奏），三层采样+6章报告结构化 | 3-6 个月工程 + 资深萃取师参与 |
| Pipeline C | 自进化引擎：pgvector 聚类 → LLM 候选颗粒生成 → 管理员审核 → 入库形成闭环。每天凌晨自动运行，越用越聪明 | 2-4 个月工程 |
| 锁定+重试机制 | 素材级 DB 乐观锁 + 分身级 Redis 串行锁 + 3 次重试 + extraction_drop_log 全链路可审计 | 1-2 个月工程 |
| 向量化基础设施 | DashScope text-embedding-v4 + pgvector HNSW 索引(m=16, ef_construction=200) + 权重重排序 + 批量嵌入更新 | 已有基础设施，但集成成本高 |

**追平总成本估算**：12-18 个月 + 3-5 人核心工程团队 + 领域专家参与。

**壁垒二：领域知识编码**

不是"写一个 prompt 就能回答销售问题"。MindForge 的领域知识沉淀在：

- `prompts/domain/sales/` 和 `prompts/domain/finance/` 下的 30+ 个 prompt 模板
- DomainConfig 体系：`{domain.role_label}`、`{domain.counterparty_label}`、`{domain.name}` 等变量注入
- `MaterialPreChecker` 的规则引擎——每个领域的准入标准（什么叫"相关"、什么叫"合格"）不同
- 审核流水线的四步校验——不是 AI 说了算，是有业务逻辑的校验

**这意味着**：不是加一个领域 = 改一行 prompt。每个新领域需要定义：角色体系、对手方体系、场景标签体系、准入规则、质量评分标准、审核校验规则。

**壁垒三：数据飞轮**

```
阶段 1: 刚上线 → 0 条颗粒 → RAG 命中率 ~30% → 体验一般
阶段 2: 1个月  → 200 条颗粒 → RAG 命中率 ~55% → 开始好用
阶段 3: 3个月  → 800 条颗粒 + Pipeline C 自进化 → RAG 命中率 ~75%
阶段 4: 6个月  → 2000+ 条颗粒 + 持续进化 → RAG 命中率 ~85%+ → 极难替代
```

**先发优势的量化**：如果一个客户已经积累了 2000 条经验颗粒、500 轮对话反馈、30 个已激活专家分身，切换到竞品的代价 = 从零开始重建所有数据 + 重新训练所有 AI 分身 + 员工重新适应。切换成本 > 订阅成本。

**壁垒四：飞轮叠加效应**

五个飞轮不是并行运行，是**串行加速**：

```
Pipeline A/B 产生颗粒 → 员工使用 → 产生反馈数据
    → Pipeline C 从反馈中发现新知识 → 候选颗粒 → 审核入库
    → 更多颗粒 → 分身更聪明 → 更多员工使用
    → H5 分享 → 外部访客注册 → 其中有人是专家 → 更多分身
    → 专家看到使用数据 → 更愿意贡献 → 更多素材/访谈 → Pipeline A/B 再运行
```

**每个节点都在为正反馈做贡献**。竞品可以复制一个环节（比如做一个 AI 聊天），但无法复制整个飞轮——因为飞轮的启动需要时间，每个节点的加速需要前一个节点的积累。

**壁垒五：平台效应（双边市场）**

```
供给侧 (专家)                    需求侧 (员工)
    │                               │
    │  更多专家 → 分身库更丰富        │  更多员工 → 使用量更大
    │  分身质量更高                  │  反馈数据更多
    │                               │
    └──────────┬────────────────────┘
               │
        平台价值增长
        (交易成本降低、匹配效率提升)
```

MindForge 本质上是一个**知识交易市场**：专家提供经验（供给），员工消费经验（需求）。平台价值 ∝ (专家数 × 分身质量) × (员工数 × 活跃度)。这是典型的双边网络效应。
