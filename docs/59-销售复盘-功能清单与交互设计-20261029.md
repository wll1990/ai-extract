## 一、优先级原则

- **P0**：能形成一个真实业务闭环，且可以拿去试点/演示。做完就能回答「销售用完到底得到什么」。
- **P1**：让闭环可规模化、可管理，补齐商业化与团队协作能力。
- **P2**：生态与深度运营（完整 CRM、集成、计费、排名等）。

> 并行不等于同优先级：Sales（W2）与 Training（W4）可以两条线同时推进，但第一批交付以销售闭环为主。

### 优先级总览

| 工作流 | P0（试点闭环） | P1（对外交付/获客） | P2（规模化） |
|---|---|---|---|
| W1 企业模型与凭证 | 平台 Key 可用 + 向量固定 | 企业 DeepSeek Key、回退、掩码/测试/轮换、用量 | 配额/限流/账单口径 |
| W2 销售复盘闭环 | 复盘 + 追问 + 报告 + 线索最小 + 任务 + 台账 | 音频/三方转写、主管批注、评分 | 质量校准、趋势 |
| W3 线索/客户/商机 | — | 线索完整管理、客户/联系人、商机简版 | 商机完整、预测 |
| W4 培训深化 | — | 主管看板、评测集管理 | 能力矩阵、成长报告 |
| W5 官网门户 | — | 站点 + 可点击 Demo + 效果样例 + 留资 | SEO/多语言/客户案例视频 |
| W6 操作手册与多媒体 | 帮助中心/图文手册（随 P0 上线） | 核心流程动画、guided tour、视频中心 | 全量教程、多语言字幕 |
| W7 集成与治理 | — | — | CRM/企微/飞书、SSO、保留/删除、计费 |

## 二、功能清单

### W1 企业模型与凭证（商业化基座）

| 编号 | 功能 | 用户价值 | 优先级 | 依赖 |
|---|---|---|---|---|
| F1.1 | 企业 DeepSeek 配置：Key/base-url、模型名只读（`deepseek-chat`）、启用/停用 | 企业可用自己的额度，成本可隔离 | **P0（若首个试点用平台 Key，可后移到 P1）** | 无 |
| F1.2 | 平台默认 + 企业回退：企业没配/失效时按策略回退平台 Key | 不配置也能用，降低接入门槛 | P0 | F1.1 |
| F1.3 | Key 安全：AES-GCM 加密存储、页面掩码、不回显/不落日志、测试连通、轮换（新旧双钥过渡）、删除 | 凭证不泄露、可运维 | P1 | F1.1 |
| F1.4 | 用途路由：对话/萃取/复盘/评测走企业 Chat 配置；Embedding/STT 平台统一 | 同一企业不同用途可分别计费/排障 | P1 | F1.1 |
| F1.5 | 企业/用途用量统计、配额、超额告警、限流 | 成本可解释，避免单企业打爆平台 | P1（统计）/P2（配额） | F1.4 |
| F1.6 | 向量模型固定 + 空间版本：单一 embedding 模型，记录 `space/version`；换模型全量重建，禁止混检 | 检索结果稳定、可解释 | **P0（固定）** / P1（重建工具） | 无 |
| F1.7 | 故障诊断：Key 失效/余额不足/限流对应稳定子码与提示；回退开关可配 | 出问题能定位、不阻断业务 | P1 | F1.2 |
| F1.8 | 变更权限与审计：仅 `company_admin`/`super_admin` 可改；测试/轮换/停用写审计 | 防止凭证被误改/滥用 | P1 | F1.3 |
| F1.9 | Provider 抽象：当前 DeepSeek 固定，后续接千问只加 provider 适配与配置 | 不被单一厂商锁死 | P2 | F1.4 |

**约束**：企业不覆盖 Embedding 模型；Chat 模型固定 DeepSeek（后期接千问时只加 provider，不改业务代码）。

## 三、P0 的三类用户与关键旅程

### 3.1 销售（复盘发起人）

1. 进入「销售复盘」列表 → 点「新建复盘」。
2. 搜索并选择一位销冠分身（本企业、已发布、个人）。
3. 粘贴今天与客户的对话，填客户名/主题，选择是否允许教练看原文。
4. 创建后在详情页等待报告（异步，页面显示进度），期间可先和销冠分身追问。
5. 报告出来后逐条看：做得好、不足、风险、客户信号、下一步；点引用定位原文。
6. 点「转线索」：确认 AI 草稿字段 → 系统查重 → 创建线索。
7. 点「生成任务」：从下一步里选 1–3 条，改时间/渠道/话术 → 落到「我的跟进」。
8. 后续在「我的跟进」里完成任务；下次对话再回来复盘。

### 3.2 教练（分身所有者）

1. 进入「我的分身 → 被复盘记录」。
2. 看到：谁、什么时候、哪个客户/主题、报告摘要、是否已转线索。
3. 默认看不到原文；销售勾选共享后，出现「查看原文」。
4. （P1）可对复盘补充一句「我的看法」，不覆盖 AI 原报告。

### 3.3 企业管理员

1. 进入「销售复盘」，切换到「全公司」。
2. 按人/客户/状态筛选，查看报告与线索/任务产出。
3. 能看到谁在用、哪些复盘转成了线索，评估落地效果。

## 四、页面与交互（P0 八个页面）

### 4.1 `/sales/reviews` 复盘列表

```
┌─────────────────────────────────────────────────────────────┐
│ 销售复盘                                    [+ 新建复盘]     │
│ [我的] [全公司(管理员)]   状态[全部▾]                         │
├─────────────────────────────────────────────────────────────┤
│ 客户       主题        教练     状态       报告      时间     │
│ 华星科技   首次需求    张伟     已出报告   v1       10-29    │
│ 云海集团   异议处理    李娜     生成中     —        10-29    │
└─────────────────────────────────────────────────────────────┘
```

- 空态：「还没有复盘，选一位销冠，把今天的对话带回来」+ 新建按钮。
- 生成中行显示进度/可点进去看；失败显示原因与「重新生成」。
- 全公司切换仅 `VIEW_ALL` 可见。

### 4.2 `/sales/reviews/new` 新建复盘

```
选择销冠分身 *   [搜索姓名/擅长领域…………]  → 结果列表（企业内已发布个人分身）
客户            [华星科技]
主题            [首次需求沟通]
对话文本 *
┌─────────────────────────────────────────────────────────────┐
│ 客户：我们预算大概 30 万，主要想解决多门店会员……            │
│ 销售：明白，那现在这块是怎么做的？                          │
└─────────────────────────────────────────────────────────────┘
0/30000   提示：支持「客户：」「销售：」前缀；建议先去掉无关寒暄
[ ] 允许教练查看本次原文
[取消] [开始复盘]
```

交互：

- 教练选择器服务端搜索（本企业 + individual + published），显示姓名/头衔/擅长场景。
- 文本实时字数；超 30000 字禁用提交并提示分段。
- 提交后跳详情页，报告异步生成；失败可重试，不丢原文。
- 未选教练、文本为空 → 行内错误，不只 toast。

### 4.3 `/sales/reviews/[id]` 复盘详情（核心页）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ← 销售复盘   华星科技 · 首次需求沟通 · 教练：张伟      [重新生成]     │
├───────────────────────────────┬──────────────────────────────────────┤
│ 与销冠分身对话                 │ 复盘报告 v1     [转线索] [生成任务]  │
│ ┌───────────────────────────┐ │ 结论：需求挖掘到位，预算/决策链未确认 │
│ │ 我：客户说太贵了怎么回？   │ │                                      │
│ │ 张伟：先别降价，先问…      │ │ ✅ 做得好 (3)                        │
│ └───────────────────────────┘ │  · 先确认现状再介绍产品  「引用」     │
│ [输入框……………………] [发送]       │ ⚠ 不足 (2)                           │
│                               │  · 未确认预算  「引用」               │
│                               │ 🚩 风险 (1)                          │
│                               │ 📌 客户信号：需求/预算/决策链/时间线  │
│                               │ ➡ 下一步 (3)  [勾选生成任务]         │
│                               ├──────────────────────────────────────┤
│                               │ 真人教练补充        [请教练补充]      │
│                               │ 张伟：预算那条 AI 判断偏保守，客户…   │
└───────────────────────────────┴──────────────────────────────────────┘
```

- 右侧报告区按「结论 → 做得好 → 不足 → 风险 → 客户信号 → 下一步 → 真人教练补充」排列；每条结论都有「引用」。
- 真人教练补充独立成块（紫色边），和 AI 报告视觉分离；未请求时显示一句话引导，不占大块空间。

交互细节：

- 报告生成中：右侧骨架屏 + 「正在分析，可先在左侧追问」；生成失败显示原因 + 重试。
- 每条结论右侧「引用」展开原文段落（高亮），可关闭。
- 客户信号用标签：`客户原话` / `销售转述` / `AI 推断` / `未知`；未知字段灰显「未提及」，不填值。
- 报告版本下拉：v1/v2…；旧版本只读。
- 「转线索」弹层：预填客户名/联系人/需求 → 查重命中列出候选（同电话/同名）→ 可「仍要新建」。
- 「生成任务」弹层：列出 nextSteps，勾选 ≤3 条，可改时间/渠道/话术 → 确认后按钮变「已生成 3 条任务」。
- 追问：Enter 发送、Shift+Enter 换行；流式输出；失败保留输入；每会话有额度（40 条）。
- 关闭页面再回来：报告与消息都在；生成中状态由轮询恢复。

## 六、W1 / W5 / W6 的交互与后端能力（P1 概要）

### 6.1 API Key 企业隔离（W1）

**页面：管理员 → 设置 → AI 模型**

```
企业 AI 模型
平台默认：DeepSeek · deepseek-chat（模型名只读）
[ ] 使用企业自己的 Key
API Key   [••••••••••••]   [测试连通]  [轮换]  [停用]
Base URL  [https://api.deepseek.com/v1]
状态：已启用 · 最近测试 10-30 09:12 成功
用量：本月 1.2M tokens（对话 0.9M / 复盘 0.2M / 评测 0.1M）
[保存]
```

交互：

- Key 永远掩码显示，保存后不回显；只允许整段替换，不支持查看原值。
- 「测试连通」用最小请求验证 Key/base-url，返回成功/失败原因（无效 Key、余额不足、限流、网络）。
- 「轮换」立即用新 Key 覆盖旧密文，不保留旧 Key；审计只记录旧 Key 末 4 位（`previousKeyLast4`）与 `previousKeyRetained=false`。「停用」后按策略回退平台 Key。
- 保存/轮换/停用都写审计；只有 `company_admin/super_admin` 可操作。
- 无企业配置时页面显示「当前使用平台 Key」，不展示平台 Key 本身。

后端能力：

- `company_model_config`：企业 + 用途 + provider + base_url + 加密 Key + 状态 + 回退开关。
- `ModelResolver`：按「企业配置 → 平台默认 → 报错」解析 Chat 配置；Embedding/STT 固定平台。
- `CryptoService`：复用 PartnerApp 的 AES-256-GCM；日志脱敏。
- 用量：`TokenUsageLog` 增加 `company_id/purpose` 维度。
- API：`GET/PUT /admin/settings/ai-model`、`POST …/test`、`POST …/rotate`、`POST …/disable`。

### 6.2 官网门户（W5）

**信息架构**

```
/            首页：一句话价值 + 场景入口 + 能力三段故事 + 效果证据 + 留资
/product     产品：萃取 / 分身 / 陪练 / 考试认证 / 真实复盘 / 主管看板
/solutions   解决方案：新人上岗 / 团队辅导 / 行业打法
/demo        可点击 Demo：切换销售/新人/主管，预置场景
/customers   客户案例（经授权）
/security    安全与隔离：企业隔离、Key、审计、数据保留
/resources   资源中心：手册、视频、更新日志
/about       关于我们
```

交互原则：

- 首屏不是大图，而是「选一个角色/场景 → 直接试」；Demo 用合成数据，页面打「演示数据」水印。
- 每个能力页都有「看效果」入口：报告样例、评分对比、认证记录、看板截图/动效。
- 使用动画嵌在对应模块，不单独堆一个视频页；主视频 2–3 分钟，模块短片 30–60 秒。
- 留资表单：姓名、公司、角色、手机/邮箱、想解决的问题；提交后进线索表并通知负责人。
- 移动端可完整浏览；首屏不做重型 3D/自动播放视频。

后端能力：

- 内容页优先静态生成（MDX/静态数据），不依赖登录；Demo 使用只读 Demo 租户和受限 token。
- 留资：`POST /public/leads`（限流 + 验证码/蜜罐）→ 写 `lead`（source=portal）→ 通知。
- 事件：页面访问、Demo 使用、留资转化（P2）。
- 安全：公开接口不暴露任何企业真实数据；Demo 数据夜间重置。

### 6.3 操作手册与多媒体（W6）

**产品内帮助中心**

- 每个页面右上角 `?`：打开侧边帮助面板，显示当前页的操作步骤 + 30–60 秒动画 + 常见错误。
- 支持搜索、FAQ、跳转完整手册；首次进入关键页面可触发一次 guided tour（可跳过、可重看）。
- 动画三种载体：录屏视频（真实、最快）、guided tour（可交互）、Lottie（15–30 秒概念解释）。
- 多媒体素材统一存放（OSS/视频平台），带封面、字幕、版本；门户与产品内共用。

**分角色手册**

- 销售：新建复盘、转线索、跟进任务。
- 新人：学习任务、陪练、考试、认证。
- 主管：看板、复核、补训、复盘查看。
- 管理员：成员/权限、企业模型 Key、内容审核、导出。

后端能力：

- 帮助内容：静态 MDX/JSON + 版本号，随前端发布；或轻量内容 API（P2）。
- 动画/视频：对象存储 + CDN；播放事件（开始/完成）用于优化（P2）。
- 新手引导状态：前端 localStorage（P0/P1），需要跨设备时再落用户偏好表。
