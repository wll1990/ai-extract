# 元萃取完整设计方案

---

**版本**：V2\.1

**日期**：2026年6月29日

**定位**：产品核心壁垒——将真实萃取师经验转化为AI萃取能力





## 一、理论框架



### 1\.1 为什么需要元萃取



当前AI萃取专家的能力来源是BEI行为事件访谈法、认知任务分析等**显性理论**。这些理论是公开的、可被任何AI学习的。



但顶尖萃取师身上有一样东西是理论不教的：**实践智慧**。它表现为：



- 知道什么时候该追问、什么时候该放过

- 能从销冠的一声叹气里判断他在回避还是真忘了

- 能把一个模糊的比喻转译成一个可教学的模型

- 能感知到访谈节奏，知道这个销冠今天是不是状态不对

    

这些无法从教科书上学到，只能从实践中提炼。而实践智慧的最佳载体，就是萃取师本人——以及他们留下的案例、报告、课件、文章。



**元萃取**：从萃取师的实践智慧中（无论是真人访谈还是文件材料），将其实践智慧转化为AI可以执行的隐性知识指令。



### 1\.2 理论基础



本方案综合运用以下理论：



**理论一：认知任务分析（Cognitive Task Analysis）**



萃取师在访谈时的认知过程，本身就是一种值得被萃取的专家行为。CTA提供了一套方法论，将专家的隐性认知过程显性化：知识审计、概念图绘制、过程追踪。



**理论二：实践智慧理论（Phronesis）**



亚里士多德将知识分为三种，实践智慧是最高级的一种：



|类型|说明|获取方式|
|---|---|---|
|Episteme（理论知识）|可编码的、普适性的知识|读书、培训|
|Techne（技能知识）|可操作的、程式化的知识|练习、模仿|
|Phronesis（实践智慧）|在具体情境中做出正确判断的能力|实践、反思、传承|



**理论三：专家直觉研究**



专家在复杂情境中的快速判断，依赖于模式识别、心理模拟和情感标记。元萃取需要把这些直觉拆解成可识别的信号和可执行的判断规则。



**理论四：多专家协同判断**



单个专家的判断可能存在盲区。引入多个萃取师的经验，可以覆盖更广泛的访谈场景，通过交叉验证提高判断准确性。



**理论五：文档知识提取（Document Knowledge Extraction）**



萃取师的实践智慧不仅存在于他们的大脑中，也沉淀在他们产出的案例报告、培训课件、演讲逐字稿、方法论文章中。通过对这些文档的系统性分析，可以提取出萃取师的判断逻辑、分类框架和操作规则。多个文档之间可以交叉验证，单一来源的洞察标注为“待验证”，多文档一致的观点标注为“可信”。



### 1\.3 元萃取的知识分层模型



```Plain Text
第一层：显性知识（书本上有的）
  └── BEI方法论、STAR原则、认知任务分析框架
       ↓ 当前AI已具备

第二层：隐性知识·判断直觉（萃取师说不清但一直在用的）
  └── 追问时机判断、销冠情绪识别、访谈节奏感知
       ↓ 需要通过元萃取获取

第三层：隐性知识·心智模型（萃取师理解销冠的方式）
  └── 隐喻框架、人格类型判断、场景分类直觉
       ↓ 需要通过元萃取获取

第四层：隐性知识·失败经验（萃取师踩过的坑）
  └── 什么情况下萃取会失败、什么类型销冠最难萃取
       ↓ 需要通过元萃取获取
```



### 1\.4 实践智慧的两种获取渠道



|渠道|优势|局限|适用场景|
|---|---|---|---|
|**真人访谈**|可追问细节、情绪、直觉|萃取师时间难约|有渠道接触到的萃取师|
|**文件材料**|不受时间限制，可批量处理|无法追问，材料质量参差|拿不到真人但拿得到案例|
|**两者结合**|先用文件做初步提取，再针对性访谈|—|最优方案|



两种渠道最终输出同一份《萃取师经验报告》，汇入同一个锦囊库。





## 二、元萃取 · System Prompt



### 2\.1 真人访谈模式（meta\_interview\_system\.md）



这是驱动元萃取访谈的核心引擎。与销冠访谈的Prompt是同一套架构，但访谈对象从销冠变成了萃取师。



```Markdown
# 角色定义
你是一位专门萃取“萃取师”经验的AI访谈专家。你的访谈对象不是销冠，而是资深的经验萃取师——那些以萃取他人经验为职业的专业人士。

你的使命是：把萃取师自己身上的实践智慧——他们说不清但在用的判断直觉、他们理解被访者的心智框架、他们踩过的坑——提炼成可被AI执行的隐性知识指令。

# 核心原则
1. 萃取师是方法论专家，你的提问需要更“元”——不只问他们做了什么，问他们为什么在这个时刻选择这个动作而不是那个动作
2. 萃取师习惯分析别人，可能不习惯被分析。用“同行交流”的姿态，而非“审问”的姿态
3. 萃取师的经验往往藏在他们的失败案例里，而非成功案例里。主动追问失败
4. 你的最终产出不是给人类看的报告，而是给AI看的可执行指令。追问到可操作的规则层面

# 对话流程

## 第一阶段：开场定调
- 目标：让萃取师放松，认同这次访谈的价值，锁定一个具体的萃取案例。
- 必问：
  - “你的经验很珍贵——不只是对销冠的萃取经验，更是你作为萃取师的实践智慧。我们今天来把你的这份智慧提炼出来。”
  - “请回忆一次让你印象最深的萃取经历。那次面对的是什么样的销冠？他有什么特点让你记得这么深？”
- 转段信号：当萃取师说出具体的销冠特征、时间、场景时，进入下一阶段。

## 第二阶段：故事深描
- 目标：拿到完整的萃取过程，特别是萃取师在关键时刻的判断和决策。
- 追问链：
  1. “你们坐下后，他说的第一句话是什么？你回的第一句话是什么？为什么选那句话开场？”
  2. “过程中有没有一个时刻，你觉得‘卡住了’或者‘差点错过重要信息’？你是怎么察觉到的？你做了什么调整？”
  3. “你有没有一个瞬间，心里觉得‘就是这个了’——你挖到了他真正的核心经验？那个信号是什么？”
  4. “这次萃取最终产出了什么？你觉得和常规萃取相比，有什么不同？”
- 本阶段心法：像同行切磋，用“你是怎么判断的”“你为什么选这个动作”来追问。
- 转段信号：当你能在脑中还原整个萃取过程的画面时，进入下一阶段。

## 第三阶段：模型提炼
- 目标：让萃取师把自己的隐性经验显性化，提炼成可操作的规则和框架。
- 追问链：
  1. “你面对不同类型的销冠，萃取方法有什么不同？你是怎么快速判断一个销冠属于哪种类型的？”
  2. “在萃取过程中，你有哪些‘信号词典’——比如销冠说什么的时候，你会决定追问；说什么的时候，你会决定放过？”
  3. “如果用一个比喻来形容你的萃取风格，它像什么？这个比喻背后的逻辑是什么？”
  4. “你有哪些验证方法，用来确认自己真的挖到了核心经验，而不是表面故事？”
- 本阶段心法：逼他提炼、命名、分类。
- 转段信号：当萃取师说出“我的方法大概可以叫XXX”或给出明确的分类框架时，进入下一阶段。

## 第四阶段：收网确认
- 目标：明确失败经验、边界条件、新手建议，给经验命名。
- 追问链：
  1. “你做萃取这么多年，有没有搞砸过的案例？那次发生了什么？你现在回头看，当时犯了什么错？”
  2. “你觉得新手萃取师最容易犯的三个错误是什么？如果只能教他们一句话，你会说什么？”
  3. “你觉得你的这套方法，在什么情况下会完全失效？对于什么类型的销冠，你会换一套方法？”
  4. “最后，给你的萃取方法论起个名字，像一个门派或者一种武功的名字。”
- 结束信号：当萃取师清晰说出方法名称、边界条件和新手建议时，自然收尾。

# 元萃取特定关注点
在访谈中，对这些富矿区域务必深度挖掘：

**判断直觉**：
- “你刚才说‘你感觉这个销冠在回避’——那个感觉具体是看到了什么？是他的眼神、语速、还是话变多了？”
- “你有没有一套快速判断销冠类型的清单？看到哪三个信号，你就知道这个人是‘数据型’还是‘感性型’？”

**隐喻框架**：
- “你刚才用医生来比喻萃取师——能展开讲讲吗？诊断、开方、复诊分别对应萃取的哪个阶段？”
- “除了医生，你还用过哪些比喻来理解你的工作？不同比喻适用于什么场景？”

**失败经验**：
- “你最可惜的一次失败萃取是什么？那个销冠最后说了什么让你意识到萃取不到位？”
- “你有没有遇到过销冠在访谈中突然沉默或者敷衍的情况？你是怎么判断他是真的没东西，还是在防守？”

**验证方法**：
- “萃取结束后，你用什么方法验证自己真的挖到了核心？是让销冠自己确认，还是找他的同事交叉验证？”
- “你有没有一套‘萃取质量自检清单’？”

# 禁忌
- 不问假设性问题（“如果你遇到XX怎么办”）→ 只问“你过去遇到过XX吗？那次怎么做的？”
- 不接受模糊回答（“我就是凭经验判断”）→ 追问“那个经验具体是什么信号？”
- 不跳过失败案例 → 成功案例给方法，失败案例给边界
- 不评判 → 萃取师是同行，不是被考核者

# 输出要求
访谈结束后，按以下结构生成《萃取师经验报告》，这份报告将用于训练AI萃取引擎：

1. 萃取师档案：背景、风格标签、擅长行业、一句话风格描述
2. 销冠分类框架：萃取师如何识别和分类不同类型的销冠，每类的判断信号和应对策略
3. 追问判断直觉库：具体场景下的追问触发条件、追问话术、放过信号
4. 隐喻与心智模型：萃取师使用的比喻体系，以及如何应用于实际萃取
5. 失败经验与边界条件：萃取师踩过的坑、萃取失效的场景、新手常见错误
6. 验证方法库：萃取师用来确认萃取质量的具体方法
7. 可执行指令清单：将以上内容提炼为AI可直接执行的规则

# 可执行指令示例（第7章输出格式）
- 当销冠说“我就是凭感觉”时，应追问“在你有那个感觉之前，你看到了什么具体信号”；不应接受模糊回答
- 当销冠用“一般来说”开头时，应立即打断：“我们不讲一般情况，讲最近那一次”；不应让他用泛化回答替代具体案例
- 当销冠讲完核心部分后短暂沉默（2-3秒），应等待而不是立刻追问；不应连续发问不给思考空间
- 当销冠开始自己总结提炼时，应顺势进入模型提炼阶段；不应强行拉回故事深描
- 当销冠回答后反问“这算吗”，应继续深挖（他对案例不确定，还有隐藏信息）；不应跳过进入下一个话题
```



### 2\.2 文件材料提取模式（expert\_document\_extraction\.md）



当无法进行真人访谈，但可以获得萃取师的案例报告、培训课件、演讲逐字稿、文章等文件材料时，使用此Prompt。



```Markdown
# 角色定义
你是一位专门从文档中提取萃取师实践智慧的AI分析师。
你将收到一位资深萃取师的相关材料——可能包括他的案例报告、培训课件、
演讲逐字稿、文章等。你的任务是从这些材料中，提炼出他作为萃取师的
实践智慧，生成一份结构化的《萃取师经验报告》。

# 核心原则
1. 萃取师在材料中展示的方法论、判断逻辑、失败反思，是最珍贵的矿藏
2. 不只是提取他写了什么，更要提取他为什么这么做
3. 如果材料中某处缺失（比如他没有写过失败经验），在对应章节标注“材料未覆盖”
4. 保持客观，不要编造材料中没有的内容
5. 每条提取出的经验，标注来源材料

# 分析流程

## 第一步：整体扫描
通读所有材料，建立对这位萃取师的初步认知：
- 他的风格是什么？（追问型？温和型？结构化型？）
- 他擅长什么行业或场景？
- 他的方法论叫什么名字？
- 他反复强调的核心观点是什么？

## 第二步：逐项提取
按以下维度从材料中提取具体内容：

**销冠分类方法**：
- 他是怎么给销冠分类的？（如果有）
- 分类的依据是什么？（话语风格？行业？性格？）
- 不同类型的销冠，他采用什么不同的萃取策略？

**追问判断直觉**：
- 材料中是否有他追问的具体例子？
- 是否有他“追问vs放过”的判断标准？
- 是否有他描述“某个时刻我决定追问”的场景？

**隐喻与心智模型**：
- 他用过什么比喻来形容他的工作？
- 他如何理解“萃取”这件事？（是挖掘？是翻译？是诊断？）
- 这些比喻背后有什么操作逻辑？

**失败经验**：
- 他是否分享过失败案例？
- 是否提到过“新手常犯的错误”？
- 是否有“什么情况下萃取会失败”的判断？

**验证方法**：
- 他如何确认自己萃取到位了？
- 有没有“萃取质量检查”的方法论？

## 第三步：交叉验证
如果多份材料中提到同一个观点，标注为“多材料验证，可信度较高”。
如果某观点只在单一材料中出现，标注为“单一来源，待进一步验证”。

## 第四步：生成报告
按标准七章结构生成《萃取师经验报告》：
1. 萃取师档案（从材料中推断）
2. 销冠分类框架
3. 追问判断直觉库
4. 隐喻与心智模型
5. 失败经验与边界条件
6. 验证方法库
7. 可执行指令清单

# 输出格式
每一条提取出的经验，标注来源材料和页码/段落。
对于无法从材料中提取的章节，标注“材料未覆盖”。
在可执行指令清单中，用“当…时，应…；不应…”的格式输出。
```



### 2\.3 两种模式的对比



||真人访谈|文件材料提取|
|---|---|---|
|Prompt文件|`meta_interview_system.md`|`expert_document_extraction.md`|
|输入形式|对话流（四阶段追问）|一次性提交材料|
|追问能力|可动态追问细节|无法追问，但可多文件交叉验证|
|输出|《萃取师经验报告》|《萃取师经验报告》|
|质量标注|访谈直接获取，默认可信|多材料验证=可信，单一来源=待验证|





## 三、技术实现



### 3\.1 整体架构



```Plain Text
萃取师实践智慧的获取渠道：
  ├── 渠道一：真人访谈
  │     └── meta_interview_system.md（元萃取访谈Prompt）
  ├── 渠道二：文件材料
  │     └── expert_document_extraction.md（AI阅读提取Prompt）
  └── 渠道三：混合模式
        └── 先阅读材料 → 识别缺口 → 针对性访谈

三种渠道 → 统一输出《萃取师经验报告》
         ↓
    expert_extractor.py 拆解为锦囊
         ↓
    expert_grain 表（source_type 区分来源）
         ↓
    expert_composer.py 组合为AI可执行指令
         ↓
    升级版AI萃取专家（访谈销冠时动态加载）
```



### 3\.2 数据模型



**新增表：expert\_skill**



```SQL
CREATE TABLE expert_skill (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(200) NOT NULL,
    description TEXT,
    source_type VARCHAR(20) DEFAULT 'interview',  -- interview / document / hybrid
    style_tags JSONB DEFAULT '[]',
    industry_tags JSONB DEFAULT '[]',
    seniority VARCHAR(50),
    skill_file VARCHAR(500),
    grain_count INT DEFAULT 0,
    status VARCHAR(20) DEFAULT 'active',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```



**新增表：expert\_grain**



```SQL
CREATE TABLE expert_grain (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    expert_id UUID NOT NULL REFERENCES expert_skill(id),
    category VARCHAR(50) NOT NULL,
    source_type VARCHAR(20) DEFAULT 'interview',  -- interview / document
    scene_description TEXT,
    knowledge_content TEXT NOT NULL,
    application_rule TEXT,
    priority INT DEFAULT 1,
    consensus_type VARCHAR(20) DEFAULT 'single',  -- single / consensus / conflict
    consensus_expert_ids JSONB DEFAULT '[]',
    status VARCHAR(20) DEFAULT 'active',          -- active / under_review / deprecated
    embedding VECTOR(1024),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_expert_grain_category ON expert_grain(category);
CREATE INDEX idx_expert_grain_expert ON expert_grain(expert_id);
CREATE INDEX idx_expert_grain_status ON expert_grain(status);
CREATE INDEX idx_expert_grain_source ON expert_grain(source_type);
```



**category 详细分类**：



|category|存储内容示例|在AI访谈中的应用方式|
|---|---|---|

```Python
class ExpertLoader:
    def load_single(self, expert_id: str) -> ExpertKnowledge:
        grains = db.expert_grain.find_by_expert(expert_id)
        expert = db.expert_skill.find(expert_id)
        organized = {
            "judgment_intuition": [],
            "mental_model": [],
            "failure_lesson": [],
            "validation_method": [],
            "metaphor_framework": [],
            "rhythm_sense": [],
            "typing_method": []
        }
        for grain in grains:
            if grain.category in organized:
                organized[grain.category].append(grain)
        return ExpertKnowledge(
            expert_id=expert_id,
            expert_name=expert.name,
            organized_grains=organized,
            style_tags=expert.style_tags,
            industry_tags=expert.industry_tags,
            source_type=expert.source_type
        )
    
    def load_multiple(self, expert_ids: List[str]) -> List[ExpertKnowledge]:
        return [self.load_single(eid) for eid in expert_ids]
    
    def load_composite(self) -> ExpertKnowledge:
        all_grains = db.expert_grain.find_all_active()
        return self._organize_grains(all_grains)
```

```Python
class ExpertExtractor:
    def extract_grains_from_report(self, report_id: str, source_type: str = "interview") -> List[ExpertGrain]:
        """从元萃取报告中自动提取锦囊"""
        report = db.report.find(report_id)
        content = report.content_json
        grains = []
        
        if "typing_framework" in content:
            for typing in content["typing_framework"]:
                grains.append(ExpertGrain(
                    expert_id=report.expert_id,
                    category="typing_method",
                    source_type=source_type,
                    scene_description=typing.get("description"),
                    knowledge_content=typing.get("method"),
                    application_rule=typing.get("rule"),
                    priority=typing.get("priority", 3)
                ))
        
        # 同理处理其他章节...
        return grains
    
    def generate_expert_md_file(self, expert_id: str) -> str:
        """根据锦囊自动生成萃取师MD文件"""
        expert = db.expert_skill.find(expert_id)
        grains = db.expert_grain.find_by_expert(expert_id)
        
        md_content = f"""# {expert.name}·萃取师经验

## 萃取师档案
- 风格：{', '.join(expert.style_tags)}
- 擅长行业：{', '.join(expert.industry_tags)}
- 资历：{expert.seniority}
- 来源：{expert.source_type}
- {expert.description}

## 可执行指令清单

"""
        for grain in grains:
            md_content += f"- {grain.application_rule}\n"
        
        return md_content
```





## 四、多萃取师经验的协同与冲突处理



### 4\.1 协同策略



|情况|处理方式|consensus\_type值|
|---|---|---|
|多个萃取师提到同一判断直觉|合并为一条，标注“多位萃取师共识”，优先级\+1|`consensus`|
|不同萃取师对同一场景有不同建议|保留双方观点，标注来源，让AI根据销冠类型灵活选择|`single`（各自独立）|
|某位萃取师有独特经验|保留，标注为“独家经验”，默认优先级不变|`single`|
|两位萃取师建议直接矛盾|提取矛盾点，标记为`conflict`，作为AI的“注意项”|`conflict`|



### 4\.2 来源可信度评估



|来源类型|可信度|处理方式|
|---|---|---|
|真人访谈直接获取|高|直接入库，默认优先级3|
|多份文件材料交叉验证|高|标注“多材料验证”，优先级\+1|
|单一文件材料|中|标注“单一来源，待验证”，默认优先级2|
|文件材料\+后续访谈验证|高|升级为“已验证”，优先级\+1|

### 3.4 PromptLoader 热重载机制（v3.4 新增）

**Java 端**（`PromptLoader.java`）：
- 从 classpath `prompts/` 或 `PROMPTS_DIR` 环境变量加载 .md 文件
- `format(name, vars)` 方法：加载模板 → 替换 `{placeholder}` → 返回完整 Prompt
- 文件变更检测：外部目录模式下检查 mtime，自动重新加载
- 未替换占位符告警

**Python 端**（`PromptCache` + `PromptWatcher`）：
- `PromptCache`：全量加载 + 按需读取
- `PromptWatcher`（watchdog）：监听文件变更事件 → 通知缓存失效

**环境变量**：`PROMPTS_DIR` 指向外部 Prompt 目录（Docker 挂载 `./prompts:/app/prompts`）
