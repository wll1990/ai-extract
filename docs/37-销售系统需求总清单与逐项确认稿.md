# 销冠数字分身销售系统：需求总清单与逐项确认稿

- 版本：V0.1，待逐项确认；2026-10-27。
- 用途：产品讨论、PRD 拆解、开发任务与验收追踪。
- 本文是需求候选全集，不代表全部进入首版，也不是上线能力声明。
- 现状依据：当前工作区静态代码阅读，包含尚未提交的知识库、案例库代码；未进行完整运行验收。
- 本轮仅新增需求文档，不修改现有业务实现。

## 1. 产品目标与边界

将销冠经验转化为可使用、可训练、可验证的企业销售能力，贯通：

1. 销售业务：发现线索 → 筛选 → 建立客户关系 → 推进商机 → 成交/失单 → 回访/复购。
2. 新人成长：能力测评 → 学习计划 → 知识学习 → 场景陪练 → 考试认证 → 实战复盘 → 补训。
3. 经验生产：素材/访谈/真实对话 → 审核 → 场景、技能、案例、知识 → 分身应用 → 反馈迭代。
4. 企业交付：门户留资 → 演示 → 试点开通 → 企业配置 → 评测验收 → 使用辅导 → 续费。

待确认：以 B2B 企业销售为首版主场景；现有 C 端能力保留，但是否持续扩展另行确认。
轻量客户管理与对接既有 CRM 是可选路径；不得未经确认扩展成完整 CRM、ERP、合同或财务系统。

## 2. 需求阅读和确认方法

现状标签：已有基础 / 部分实现 / 未见完整实现 / 需运行验证。
优先级建议：P0=首批试点必需，P1=完善日常闭环，P2=规模化运营；最终由用户确认。
需求状态：候选 → 已确认 → 已设计 → 开发中 → 待验收 → 已验收；另有延期、取消。

每个模块确认：用户与场景、首版范围、输入输出、页面、数据归属、状态流转、AI规则、权限、异常、验收。
确认后的单项需求补齐：

| 字段 | 内容 |
|---|---|
| ID / 名称 / 状态 | 使用本文稳定 ID，记录确认日期 |
| 用户故事 | 谁在什么情况下完成什么工作 |
| 输入与前置条件 | 数据来源、权限、必填信息 |
| 正常流程 | 用户动作、系统响应、状态变化 |
| AI边界 | 引用、置信度、人工确认、禁止行为 |
| 页面与接口 | 页面位置、API契约、SSE事件、错误码 |
| 数据与隔离 | 表、索引、归属、可见范围、生命周期 |
| 失败与恢复 | 超时、重试、断点、幂等、取消 |
| 验收 | Given/When/Then 正常、异常、越权场景 |
| 实施 | 迁移、后端、前端、测试、上线与回退任务 |

## 3. 模块需求全集

### M01 产品结构与角色工作台

现状：已有企业后台、C端平台、基础角色权限；业务角色与工作台尚不完整。建议 P0。

- M01-01 明确企业业务端、平台运营端、对外门户、演示环境边界及入口。
- M01-02 明确平台运营、企业管理员、主管、萃取师、销冠、销售、新人、客户成功、访客的任务与数据范围；业务身份可兼任，是否独立权限角色待定。
- M01-03 销售首页展示今日跟进、逾期任务、重点商机、训练任务及分身快捷入口。
- M01-04 主管首页展示团队商机、风险、复盘待审、培训进度和辅导待办。
- M01-05 管理员首页展示初始化进度、成员、内容审核、模型配置、资源使用。
- M01-06 按权限和已开通模块下发导航；没有权限的模块不可通过直接URL或API访问。

### M02 企业、组织、成员与权限

现状：Company、统一用户、角色权限和企业归属校验已有；部门团队未见完整模型。P0基础/P1组织。

- M02-01 企业开通、品牌信息、行业、管理员、合作状态；区分企业档案与试用/套餐状态。
- M02-02 部门、团队、区域与负责人；首版采用哪种组织层级待定。
- M02-03 成员邀请、导入、入职、转岗、停用、离职交接；客户/商机/任务归属交接。
- M02-04 角色授权与本人、团队、企业、平台等数据范围；明确主管跨团队查看规则。
- M02-05 内容与分身授权到企业/团队/指定成员；公开分享与内部授权分别配置。
- M02-06 平台运维访问企业数据的授权和审计；不能把超管权限作为客户安全承诺的替代。
- M02-07 关键操作审计：操作者、企业、资源、动作、前后变化、时间、结果。
- M02-08 企业停用、数据导出、保留期、删除、恢复；SSO按客户需求进入后续范围。

### M03 企业模型与凭证隔离

现状：统一ChatClient及全局向量配置，不具备完整企业凭证路由。P0。

- M03-01 企业配置服务商、模型、接口地址、用途及凭证；平台公共任务使用明确的平台配置。
- M03-02 对话、萃取、复盘、评测、向量、语音分别配置或继承企业默认值。
- M03-03 Key后端加密保存、页面掩码、禁止明文回读/日志输出；支持测试、轮换、停用。
- M03-04 同步请求、SSE、异步任务、定时器和重试均使用确定的企业配置，禁止跨请求修改全局Key。
- M03-05 企业明确选择是否允许平台Key回退；Key失效、余额不足、限流须可诊断。
- M03-06 企业/用途维度的额度、并发与调用统计；区分实际账单、供应商用量和估算成本。
- M03-07 向量模型更换检查维度、语义兼容与重建索引；避免新旧向量直接混检。
- M03-08 测试自定义接口可达性与允许范围，凭证管理与业务使用分权。

### M04 线索发现与管理

现状：未见完整销售线索实体和流程。P0手工/导入，P2外部发现。

- M04-01 理想客户画像：行业、规模、地区、职位、需求信号、排除条件。
- M04-02 手工录入、表格导入、门户留资、既有CRM同步；外部线索数据源单独确认。
- M04-03 记录来源、联系人、联系渠道、负责人、分配时间、最近动作及下次动作。
- M04-04 去重、合并、批量分配、领取与回收；是否需要公海池待定。
- M04-05 资格判断与优先级建议：展示理由、证据和缺失信息，允许人工修正。
- M04-06 线索状态：新建、待联系、联系中、合格、转商机、培育、无效；具体枚举待确认。
- M04-07 合格线索转客户/联系人/商机，保留来源及活动历史。

### M05 客户与联系人

现状：系统用户与企业表不能替代销售客户档案。P0。

- M05-01 客户公司档案、标签、行业、来源、负责人、所属团队和关联商机。
- M05-02 多联系人与岗位、决策角色、关系状态；支持决策人、使用者、采购等角色。
- M05-03 客户时间线聚合联系记录、会议、文档、复盘、承诺与待办。
- M05-04 联系记录与客户事实支持人工确认，区分客户原话、销售记录、AI推断。
- M05-05 档案去重合并、权限转移、导入导出、归档与删除。
- M05-06 客户长期未跟进、关键人缺失等提醒；触发阈值由企业配置。

### M06 商机与销售过程

现状：案例有漏斗阶段，未见真实商机全过程。P0简版/P1扩展。

- M06-01 商机关联客户、联系人、负责人、金额、产品、预计时间与阶段。
- M06-02 企业可配置销售阶段、阶段目标、必备信息、检查清单和推进条件。
- M06-03 需求、预算、决策链、时间线、竞争对手及风险结构化记录；未知字段保持未知。
- M06-04 商机列表/看板、阶段变更、停滞提醒和历史轨迹。
- M06-05 关联方案、报价附件、产品知识及审批结果；完整报价/合同系统暂不默认纳入。
- M06-06 记录赢单/失单/延期及理由；成果回填作为业务指标来源。
- M06-07 成交后回访、续购、增购、转介绍任务；范围与交付系统边界待确认。

### M07 跟进任务与追单助手

现状：分身可给建议，未见持久化客户跟进任务闭环。P0/P1。

- M07-01 待办支持负责人、客户/商机、到期时间、优先级、状态与完成结果。
- M07-02 从复盘提取双方承诺，销售确认后生成任务；记录承诺人和原话证据。
- M07-03 追单建议包含理由、时间、渠道、话术、应补问信息与停止跟进条件。
- M07-04 基于历史生成谈前简报、会谈提纲和会后跟进草稿。
- M07-05 任务提醒、延期、取消、转交和逾期升级；通知渠道和频率待确认。
- M07-06 默认人工确认后执行外部发送；自动发送需独立授权、审计及撤销机制。
- M07-07 记录话术采纳、修改、任务执行和客户响应，避免只统计生成次数。

### M08 真实销售对话复盘

现状：已有模拟对练评价，真实销售复盘未见完整实现。P0文字/P1音频。

- M08-01 输入聊天记录、转录文本、会议纪要；关联客户、商机、销售与场景。
- M08-02 音频转写、角色确认、分段与时间戳；原文与校订稿分别保留。
- M08-03 提取阶段、需求、异议、决策链、承诺、未解决问题和下一步。
- M08-04 对照技能给出做得好、遗漏、风险表达和改进建议；每条判断引用原文位置。
- M08-05 按场景rubric评分；信息不足、纪要不完整或说话人不清时降低置信或不评分。
- M08-06 给出销冠判断、推荐追问/话术、相关知识/案例及下一步任务草稿。
- M08-07 主管批注、纠正、销售异议与复核；保留AI原结果和人工修订。
- M08-08 报告查看/分享/导出；敏感客户信息和团队范围受控。
- M08-09 经审核转成案例、经验候选、评测题，记录来源和授权，禁止自动公开。
- M08-10 异步任务进度、失败重试、取消和耗时目标；“10分钟内”须定义输入上限与服务条件。

### M09 新人培训计划与学习

现状：有知识、案例、问答和陪练；缺计划、分配、学习记录体系。P0首个计划/P1完整。

- M09-01 岗位/产品/行业训练模板与企业定制计划，支持入职批次与导师。
- M09-02 入职基线测评，识别已有能力与弱项，推荐不同学习任务。
- M09-03 课程单元关联知识、案例、技能、视频或说明；记录内容版本。
- M09-04 任务类型：阅读、测验、陪练、作业、真实对话复盘、主管面评。
- M09-05 必修/选修、前置条件、截止时间、通过标准、重考及补训规则。
- M09-06 按个人/团队/批次分配计划，展示今日任务、进度和逾期提醒。
- M09-07 新人可向分身提问，回答引用指定企业内容；问题沉淀为培训内容缺口。
- M09-08 计划变更后的在学人员迁移策略；内容更新不得悄然覆盖历史成绩依据。

### M10 场景陪练、考试与上岗认证

现状：有场景陪练、逐轮反馈、重试及复盘；训练绑定和标准化考试不足。P0/P1。

- M10-01 场景绑定销售阶段、能力点、难度、客户画像、目标与关联技能。
- M10-02 学习模式允许提示、重试、示范；考试模式限制提示并保留完整过程。
- M10-03 行为锚定评分，每场景4—6维、1—5分；具体标准经业务专家确认。
- M10-04 评分附原话、依据、未观察项和置信度，支持主管复核。
- M10-05 多轮对话一致性、离题、事实错误与合规边界评价。
- M10-06 考试题版本、次数、通过条件、补考和主管签核。
- M10-07 上岗认证关联岗位和技能；认证有效期与复认证是否首版支持待定。
- M10-08 相同能力的历次成绩趋势，区分不同题目难度与评分版本。

### M11 主管培训与业务表现看板

现状：有使用/颗粒/对练统计基础，未见完整人员训练与商机看板。P1，首版保留必要视图。

- M11-01 新人/团队/批次进度、逾期、考试、认证和导师待办。
- M11-02 能力矩阵：产品知识、需求挖掘、异议处理、推进能力、事实与合规。
- M11-03 区分学习完成、模拟能力、真实业务表现，禁止用在线时长替代专业能力。
- M11-04 查看原始作业、对话证据、评分变化，人工布置辅导和补训。
- M11-05 业务指标：联系、有效沟通、商机推进、成交/失单；定义口径、时间窗和数据来源。
- M11-06 团队风险与重点商机、超期任务；按主管组织范围过滤。
- M11-07 个人成长报告与团队周/月报；避免小样本排名和无依据的因果结论。

### M12 场景、技能、经验与萃取

现状：已有访谈、素材处理、经验颗粒、画像、场景覆盖和萃取师方法。P0修补/P1标准化。

- M12-01 标准场景目录与稳定ID，映射现有sceneTag；优先首触、需求、异议、追单。
- M12-02 技能卡：触发条件、目标、判断规则、步骤、话术、边界、检查清单及证据。
- M12-03 场景—技能—经验颗粒—案例—知识—题目多对多关系与覆盖缺口。
- M12-04 文件/访谈/实战对话来源统一溯源；内容归属和人工审核。
- M12-05 访谈阶段、采集状态、AI回复持久化、恢复和上下文角色一致性运行验收与修补。
- M12-06 素材任务进度、失败重试、幂等、质量淘汰原因与人工补充。
- M12-07 技能发布/停用/版本记录；技能与已发布分身版本关联。
- M12-08 萃取师方法库与销冠经验分层管理，不混淆“如何萃取”和“如何销售”。

### M13 知识库、案例库与时效治理

现状：已有新模块CRUD、文档萃取、审核、章节续传、向量检索及来源输出，待运行验收。P0验收/P1治理。

- M13-01 公共/企业知识与案例管理；保持已实现的结构化字段，不重复新建存储。
- M13-02 文档章节分块、出处、进度、断点重试、候选审核与批量操作。
- M13-03 来源可信级别、适用行业/产品/地区、生效时间、失效时间、维护人。
- M13-04 明确未来生效、过期、停用在列表和检索中的一致规则。
- M13-05 版本链、差异、修订、审核、回退及历史引用追踪；字段存在不等于完整治理。
- M13-06 冲突处理：事实按权威来源、适用范围和时效裁决；经验与案例须匹配情境。
- M13-07 知识无法确认时提示缺口/请求澄清，不凭个人经验覆盖产品价格或政策。
- M13-08 公共模板授权、复制到企业、更新提示；企业内容跨租户复用须脱敏并授权。
- M13-09 临期提醒、不能用反馈、负责人复核和关联评测回归。
- M13-10 区分有功能与有优质内容，明确首批行业内容的来源、审核人及维护责任。

### M14 数字分身与销售AI助手

现状：个体/组织分身、问答、讨论、对练、检索与溯源已有。P0复用/P1增强。

- M14-01 发布质量门禁、画像、能力范围、推荐问题与场景入口。
- M14-02 组织分身成员授权、检索范围、撤发布后的更新；组织分身不替代部门组织模型。
- M14-03 回答过程识别情境、选择技能、检索案例知识、给行动建议；允许澄清和拒答。
- M14-04 客户/商机上下文在授权后接入；不自动把客户私有信息加入公共分身知识。
- M14-05 谈前简报、异议建议、追单草稿及后续动作，共用销售对象和任务。
- M14-06 答案来源可定位原条目及版本；保留会话和引用的历史一致性。
- M14-07 反馈、纠错、知识缺口与人工处理结果闭环。
- M14-08 直接聊天、飞书等入口使用一致权限、企业凭证、限额与会话归属。

### M15 评测集、评分校准与发布验收

现状：有AI Judge、对练评价和RAG评估工具；未见完整可管理验收集。P0。

## 5. 建议逐项讨论顺序

1. 产品边界与目标客户：轻量CRM还是对接CRM；B端/C端；首批行业与交付场景。
2. 角色、组织与数据范围。
3. 企业Key、模型用途、预算与回退。
4. 销售对象：线索、客户、联系人、商机、任务。
5. 一次真实跟进与谈后复盘的完整流程。
6. 新人训练计划、评分、考试及主管验收。
7. 场景技能、知识案例、分身及标准评测。
8. 演示、使用说明、门户与企业试点。
9. 数据指标、集成、运营、计费和激励。

## 7. 从需求到代码的交付约定

每次只推进已确认模块，不根据本清单自动实现全部候选需求。
实施前确认数据关系、权限矩阵、状态机、API和验收示例；复用既有Company、User、Space、Skill及知识案例能力。
一项开发任务应有明确前后端产物、数据库迁移、必要测试、演示步骤和上线影响；不以页面完成替代业务闭环完成。
现有未提交修改保持原样，实施前再次核对工作区；不覆盖其他正在进行的工作。
