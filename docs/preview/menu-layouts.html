侧栏布局方案对比

同一套权限与路由，四种导航组织方式。线框仅示意结构，细节沿用现有视觉。

方案 A · 分组折叠侧栏 改动最小

一个侧栏，6 个可折叠分组。参考 Linear、Notion、Stripe 后台。

方案 B · 顶栏分区 + 侧栏二级 推荐

顶栏放 5 个业务域，侧栏只显示当前域，一屏永远 ≤7 项。参考飞书管理后台、阿里云控制台、HubSpot。

方案首屏可见项新手上手菜单继续增长改动成本对现有导览/文档
A 分组折叠5–6（其余折叠）好一般，组会越来越长低几乎不影响
B 顶栏分区≤7（每域）好好，加域不加长中文案里提到菜单名要改
C 图标轨道≤6（二级）一般，图标要记好中高截图要重拍
D 对象优先8偏难，入口变少好高，路由重构导览章节要重编
建议走 B。它真正解决「太多」——同一时刻只出现一个业务域的 5–7 项，而不是把 28 项折叠起来； 顶栏 5 个标签本身就是系统地图，新用户第一次就能建立「用 → 卖 → 造 → 管」的心智。 改动集中在 AppLayout + /config/nav，路由、权限、数据接口都不动；员工只会看到「日常」「销售」两个标签。 如果更看重上线速度，选 A，我可以直接按上一张效果图落地。
