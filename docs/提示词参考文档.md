## 阶段 1: 素材预检

**调用服务**: `MaterialCleaningService`
**目的**: 用户上传销售对话后，分块做结构化标注和质量过滤

### material_context_tag.md

- **作用**: 读懂对话的"背景信息"
- **输入**: `{text}` — 原始对话文本
- **输出**: 结构化 JSON — 购买阶段、对话角色、竞争态势、交易规模提示、行业信号
- **领域感知**: 是（根目录有通用版，领域目录可覆盖）

### material_verify.md

- **作用**: 质量审核——过滤"正确的废话"
- **输入**: `{candidates_json}` — 候选颗粒列表
- **输出**: 每条颗粒 5 维打分：（具体性、可复现性、因果性、差异性、可证伪性），低于阈值就扔
- **领域感知**: 是

### material_merge.md

- **作用**: 合并同类项——同一场景标签下多条颗粒合并为 1 条不重复的完整颗粒
- **输入**: `{grains_json}` — 待合并的颗粒列表
- **输出**: 合并后的单条高质量颗粒
- **领域感知**: 是

### material_pattern.md

- **作用**: 从多条颗粒中提炼行为模式
- **输入**: `{grain_block}` — 同一位销冠的所有颗粒
- **输出**: 3 个核心习惯 + 3 个关键差异点 + 方法论名称 + 核心竞争力概括
- **领域感知**: 是

### classify_scenes.md

- **作用**: 给颗粒打场景标签（≤10 字）
- **输入**: `{domain_name}`, `{existing_tags}`, `{scenes_block}`
- **输出**: JSON 数组 `[{"index":0,"tag":"价格谈判"}, ...]`
- **领域感知**: 否

## 阶段 2: 颗粒萃取

**调用服务**: `MaterialCleaningService`
**目的**: 从对话中提取 5 维技能颗粒——这是整个系统的核心产出

### material_extract_full.md

- **作用**: 从第一段对话提取颗粒（带上下文）
- **输入**: `{context_prefix}` — 购买阶段/角色/竞对等上下文, `{material_content}` — 对话文本
- **输出**: `[{scene_description, expert_thought, standard_script, common_mistakes, applicable_condition}]`
- **领域感知**: 是（仅领域版，根目录无通用版。现有 `sales.b2b_enterprise` 和 `finance.secondary_market` 两个版本）

### material_extract_short.md

- **作用**: 从后续段落继续提取（沿用第一段建立的上下文）
- **输入**: `{material_content}` — 对话文本
- **输出**: 同 `material_extract_full.md`
- **领域感知**: 是（仅领域版）

> 这 5 个字段后续会直接拼入对话 System Prompt：
> ```
> - 我的思考：{expert_thought}
> - 我说过的话："{standard_script}"
> - 我见过的坑：{common_mistakes}
> ```

## 阶段 3: 深度加工

**调用服务**: `MaterialCleaningService`
**目的**: 颗粒出来后再加工成三种可用资产

### material_profile.md

- **作用**: 生成 AI 分身画像配置
- **输入**: `{grains_block}`, `{habits}`, `{diffs}`, `{industry}`, `{persona}`
- **输出**: `{personality, speaking_style, background, common_phrases, knowledge_domains, communication_preferences}`
- **领域感知**: 是

### material_faq.md

- **作用**: 从对话中提取客户异议 + 销冠回应，生成 FAQ 问答对
- **输入**: `{dialogue_text}` — 原始对话
- **输出**: FAQ 问答对列表
- **领域感知**: 是

### material_narrative.md

- **作用**: 把颗粒和模式编成结构化案例故事（给人类阅读）
- **输入**: `{grains_block}`, `{patterns_str}`
- **输出**: 4-6 阶段的叙事文本
- **领域感知**: 是

## 阶段 4: 报告生成

**调用服务**: `ExtractionReportService` + `ExpertService`

### extraction_report_part1.md

- **作用**: 报告第 1 部分——案例摘要（交易标的、客户画像、决策链、关键人物）
- **输入**: `{source_text}` — 源文本
- **领域感知**: 是

### extraction_report_part2.md

- **作用**: 报告第 2 部分——方法论（策略、战术、FAQ、禁忌）
- **输入**: `{grain_text}` — 颗粒文本
- **领域感知**: 是

### expert_document_extraction.md

- **作用**: Expert 模式——从萃取师上传的文档提取 7 章经验报告
- **输入**: `{expert_name}`, `{expert_description}`, `{file_contents}` 等
- **领域感知**: 否

### expert_grain_extraction.md

- **作用**: Expert 模式——从报告中提取结构化颗粒
- **输入**: `{report_json}`
- **领域感知**: 否

### expert_structure_report.md

- **作用**: Expert 模式——格式化原始经验为标准化 6 章结构
- **输入**: `{raw_content}`
- **领域感知**: 否

## 阶段 5: 分身对话

**调用服务**: `ChatStreamService` + `SkillService`

### skill_qa_chat.md

- **作用**: QA 问答 + 深度讨论模式的 System Prompt
- **输入**: `{owner_name}`, `{background}`, `{personality}`, `{speaking_style}`, `{common_phrases}`, `{knowledge_domains}`, `{skill_tags}`, `{target_scenarios}`, `{communication_preferences}`, `{experience_context}`, `{mode_instruction}`
- **回答结构**: 判断逻辑 → 策略选择 → 具体话术 → 可迁移点
- **领域感知**: 是

### skill_talk.md

- **作用**: 自由对话模式的 System Prompt——"茶水间碰到销冠"风格
- **输入**: 同 skill_qa_chat.md
- **特点**: 含社交情感处理（感谢后收尾、闲聊正常回应）+ `---` 分隔内部思考
- **领域感知**: 是

### enterprise_system.md

- **作用**: 企业多分身聚合——"调度员"角色汇总多位销冠经验
- **输入**: `{experience_context}`
- **特点**: 意见分歧时呈现双方观点，诚实面对知识差距，标注来源
- **领域感知**: 是

### query_rewrite.md

- **作用**: 查询改写——将口语对话补全为独立语义查询，用于 RAG 检索
- **输入**: `{history}` — 最近 12 条历史消息, `{message}` — 当前用户消息
- **示例**: "继续说说吧" → "客户不信任时销售如何调整心态继续跟进"
- **领域感知**: 是

### skill_evaluator.md

- **作用**: 分身质量四维评分
- **输入**: `{real_samples}`, `{grains_text}`, `{scripts}`, `{conversation}`
- **评分维度**: 语言风格 30% + 经验一致性 30% + 行为模式 20% + 话术复用 20%
- **领域感知**: 否

## 阶段 6: 实战对练

**调用服务**: `PracticeDemoService` + `SkillService`

### skill_practice_customer.md

- **作用**: AI 客户的 System Prompt——双重角色（真实客户 + 训练教练）
- **输入**: `{scene_context}`, `{practice_angles}`, `{round_number}`, `{total_angles}`, `{history}`, `{last_message}`
- **特点**: 情感节奏——防御 → 认可 → 被说服
- **领域感知**: 是（仅领域版）

### skill_practice_angles.md

- **作用**: 从场景颗粒生成 3-5 个练习角度
- **输入**: `{scene_tag}`, `{grain_info}`
- **领域感知**: 是（仅领域版）

### skill_practice_opening.md

- **作用**: 生成 AI 客户开场白——直击压力点，逼练习者用技能
- **输入**: `{name}`, `{scene_tag}`, `{grain_ctx}`
- **领域感知**: 是（仅领域版）

### skill_practice_evaluate_response.md

- **作用**: 评估每轮回答——对照标准技法，检测跑题
- **输入**: `{scene_tag}`, `{skill_baseline}`, `{ref_section}`, `{customer_message}`, `{my_response}`
- **输出**: 冠军级回答作为标准答案 + 命中和遗漏的技法点
- **领域感知**: 是（仅领域版）

### skill_practice_full_answer.md

- **作用**: 生成"完整答案"——覆盖所有角度的 150-250 字理想回答
- **输入**: `{scene_tag}`, `{customer_message}`, `{grain_ref}`
- **领域感知**: 是（仅领域版）

### skill_practice_evaluate.md

- **作用**: 对练结束复盘——评分 + 优缺点（附原文引用）+ 示范话术
- **输入**: `{owner_name}`, `{conversation}`, `{scene}`, `{source_context}`
- **领域感知**: 是

### skill_practice_summary.md

- **作用**: 对练总结——2-3 条"下次试试"、一句总体建议
- **输入**: `{tech_summary}`, `{total_rounds}`, `{retry_count}`
- **领域感知**: 否

### demo_simulate.md

- **作用**: 自动演练——AI 同时扮客户和销售，生成完整示例对话
- **输入**: `{role_description}`, `{scene_tag}`, `{scene_desc}`, `{skill_info}`, `{constraint}`, `{history}`, `{customer_message}`, `{analysis_instruction}`
- **两种模式**: `with_skill`（使用销冠技巧）vs `without_skill`（模拟新手）
- **领域感知**: 是

## 领域感知说明

- **共用**（24 个）: 根目录有通用版，`domain/{domain}/` 可覆盖。加载时优先领域版，不存在则回退根目录
- **领域专属**（8 个，硬依赖）: 根目录无通用版，领域目录**必须有**，否则 NPE：
  - `material_extract_full.md` / `material_extract_short.md`（颗粒萃取）
  - `interview_system.md` / `meta_interview_system.md`（AI 访谈）
  - `skill_practice_customer.md` / `skill_practice_angles.md` / `skill_practice_opening.md` / `skill_practice_evaluate_response.md` / `skill_practice_full_answer.md`（对练链路）

## 变量注入机制

`PromptLoader.format(name, vars, domain)` 支持两层变量注入：

1. **领域变量**（自动注入）: `{domain.id}`, `{domain.name}`, `{domain.role_label}`, `{domain.counterparty_label}`, `{domain.skill_label}`, `{domain.knowledge_unit}`, `{domain.knowledge_unit_plural}`
2. **业务变量**（调用方传入）: 每个 prompt 声明的特定变量，如 `{text}`, `{grains_json}` 等

两层变量以 HashMap 合并，业务变量优先级高于领域变量。
