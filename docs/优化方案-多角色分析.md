# 三个待优化问题 — 四角色交叉分析

> 日期: 2026-07-17
> 问题: 无颗粒回退质量 / RAG 改写监控 / 知识域前台展示

---

## 问题一：无颗粒回退质量

### 现状
RAG 检索 0 结果 → 取最近 20 条颗粒兜底。完全不考虑这 20 条跟当前问题是否相关。

### 商业运营视角

**这是留存风险点。** 客户上传了素材、配置了分身，期待的是"有问必答"。颗粒覆盖不全 = 分身"选择性失忆"。

- 每次无匹配对话就是一次"次优体验"，累积影响续费率
- 应该最大化利用已有资产——不是"给 20 条了事"，而是"在已有的里面找最接近的"
- 长期看，这也是**素材上传的激励点**：系统告诉管理员"还有 X 个场景没覆盖到，上传相关素材可以提升回答质量"

**建议**: L1→L2→L3 递进式回退，每层都让用户感知到"系统在努力匹配"

### 高级产品经理视角

本质是"冷启动覆盖"和"长尾覆盖"问题。分层策略：

| 层级 | 策略 | 触发条件 | 复杂度 |
|------|------|----------|--------|
| L1 | **同场景回退** | RAG=0，但同场景标签下有其他颗粒 | 低 |
| L2 | **跨场景关键词匹配** | L1 也无结果，按问题中的关键词模糊匹配 | 中 |
| L3 | **用户反馈闭环** | L1+L2 都无结果，引导用户提交需求 | 低 |

L1 成本最低收益最大——场景标签已经在 DB 里，直接按 `sceneTag` 查即可。L3 是长期价值——把"不知道"变成"需求池"。

**优先级**: L1 > L3 > L2

### 用户视角

"我问了一个销售问题，它完全不懂？连个大概方向都不给？"

用户心理：
- 问对了领域但没匹配到 → 期望"虽然没完全一样的案例，但类似的情况我是这么处理的..."
- 完全问错了领域 → 期望"我不太懂这个，但我擅长 XXX，要不要试试？"

关键洞察：**"不知道"比"瞎编"好一百倍**。用户宁愿听到诚实的"我不会"，也不愿意得到一份看似专业实则错误的话术。

### 高级 UI 设计师视角

无颗粒回答的视觉语言应该与有颗粒回答**明确区分**：

- 有颗粒：正常气泡 + 🟢高匹配标签 + 可展开溯源
- 无颗粒(L1回退)：正常气泡 + 🟠"近似匹配"标签 + 溯源展开显示的是"近似场景"
- 无颗粒(L2回退)：气泡底部加一条分割线 + "📌 系统根据关键词匹配了相关经验，可能不完全适用"
- L3 兜底：气泡内嵌快捷操作——"💡 我目前对这类问题了解有限。要不试试问我这些问题？" + 3 个推荐问题按钮

**移动端**: 推荐问题用横向滑动的 Chip 组件

### 综合决策

**立即做 L1**: 同场景回退替代"最近 20 条"。改动量极小——把 `findBySpaceId` 改成 `findBySpaceIdAndSceneTag`。
**同步做 L3**: 无颗粒时前端展示快捷入口，给用户一个出口。
**L2 暂缓**: 需要语义匹配，成本高收益有限。

## 问题二：RAG 改写监控

### 现状

`query_rewrite.md` 调用 DeepSeek 改写用户查询。改写失败 → 降级为原始消息。但没有任何监控——不知道改写率、命中率提升、失败率。

### 商业运营视角

改写质量是"看不见的体验"——用户不知道有这个步骤，但它的效果直接决定了搜索结果质量。

**需要回答的商业问题**:
1. 有多少用户的"口语化简略表达"被正确补全了？
2. 改写后检索命中率是否有显著提升？（A/B 对比数据）
3. 改写服务挂了多久了？影响了多少用户？

**量化目标**: 改写后检索分数 ≥ 原消息检索分数的比例 > 80%

### 产品经理视角

三个核心指标，两级告警：

| 指标 | 计算方式 | 正常 | 告警 |
|------|----------|------|------|
| 改写覆盖率 | 触发改写的请求 / 总请求 | > 60% | < 40% |
| 改写有效率 | 改写后 score ≥ 原消息 score | > 80% | < 60% |
| 改写降级率 | LLM 调用失败回退 | < 3% | > 5% |

监控数据建议用**结构化日志**输出（JSON 格式），后续接入 Prometheus/Grafana 即可可视化。当前阶段不建全套监控系统——先记日志，Admin 后台做一个简单的"RAG 健康度"面板就够了。

### 用户视角

用户无感，但能"感觉到"——改写不准的后果是：
- 说"继续"→ 切到无关话题 → 用户困惑
- 说"上次那个客户最后怎么签的"→ 检索不到 → AI 回答偏了

本质是"AI 能不能听懂人话"。用户不关心实现，只关心结果。

### UI 设计师视角

监控数据不暴露给终端用户。Admin 后台设计一个轻量面板：

```
┌─────────────────────────────────────────┐
│  RAG 改写健康度（最近 24h）              │
│                                         │
│  改写覆盖率    ████████████ 72%          │
│  改写有效率    ████████████████ 91%      │
│  改写降级率    ██ 2.1%                  │
│                                         │
│  热门改写 Top5:                          │
│  1. "继续吧" → "销售如何跟进已经在讨论的客户"│
│  2. "然后呢" → "客户签约后的下一步流程"    │
│  ...                                    │
└─────────────────────────────────────────┘
```

### 综合决策

**立即做**: 在 `rewriteQuery` 方法里加结构化日志（改写前/改写后/耗时/是否命中提升）。
**下一步**: Admin 后台加"RAG 健康度"卡片。
**未来**: 接入 Prometheus metrics。

## 问题三：知识域前台展示

### 现状

用户打开分身页面，只有三种模式的入口。分身"能做什么"藏在 System Prompt 里，用户看不到。

### 商业运营视角

**知识域是获客转化点。** 用户进页面第一眼就要判断"这个分身对我有没有用"。

- 清晰的知识域 = 降低用户决策成本 = 提高首次对话率
- 竞品差异点：别人的 AI 是黑盒，我们的是**透明 AI**——明确告诉你"我能做什么、不能做什么"
- 展示知识域也是**对内容质量的倒逼**——颗粒少的领域显示空白，刺激管理员完善素材

### 产品经理视角

三种模式需要不同的展示策略：

**QA 模式**:
- 顶部场景标签云（3-5 个），点击直接生成该领域的问题
- 标签旁显示该场景颗粒数，给用户"这个领域我有多少经验"的直观感受
- 示例问题区：每个场景自动生成 1-2 个推荐问题

**Talk 模式**:
- 分身自我介绍卡片（已有开场白，但不够结构化）
- 展示 2-3 个最擅长的领域 + 一句特色描述
- "你可以跟我聊：政府客户怎么搞定 / 大单子怎么推进 / 价格谈判怎么守住底线"

**Practice 模式**:
- 场景选择页已有，但缺少"练完你能掌握什么"
- 每个场景卡片加技能点列表：✅ 异议处理 ✅ 价格锚定 ✅ 逼单节奏

### 用户视角

打开分身页面的心理活动：

1. "这是什么？" → 需要一句话定位（已有 ownerName + ownerTitle）
2. "能帮我吗？" → 需要看到知识域覆盖范围
3. "怎么开始？" → 需要明确的操作引导

**场景一**：用户有明确问题 → 直接打字，知识域展示作为"话题提示"
**场景二**：用户没有明确问题 → 点推荐问题，快速上手
**场景三**：用户想练习 → 看场景列表，选感兴趣的

### 高级 UI 设计师视角

**设计原则**: 知识域不是"标签列表"，是"可交互的对话起点"

**PC 端**:

```
┌─────────────────────────────────────────────┐
│  👤 潘露婷 · 10年高客单销售                 │
│  💬 我能帮你搞定                             │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐    │
│  │ 🏛 政府销售│ │ 💰 价格谈判│ │ 🤝 异议处理│    │
│  │  12 条经验 │ │   8 条经验 │ │  15 条经验 │    │
│  └──────────┘ └──────────┘ └──────────┘    │
│  ┌──────────┐ ┌──────────┐                 │
│  │ 📋 决策推进│ │ 🔍 需求挖掘│                │
│  │   6 条经验 │ │  10 条经验 │                │
│  └──────────┘ └──────────┘                 │
│                                             │
│  💡 试试问我：                               │
│  "政府客户怎么找到关键决策人？"               │
│  "客户说太贵了我该怎么回？"                   │
└─────────────────────────────────────────────┘
```

**Mobile 端**: 标签横向滑动，推荐问题列表

**交互细节**:
- 点标签 → 自动切换 QA 模式 + 输入框预填"关于 [场景] ，能分享一下你的经验吗？"
- 已经有对话历史 → 标签区折叠为一行，节省空间
- Talk 模式的末尾 `📎` 来源标注就是一个迷你不要的知识域展示——**这个可以更显眼**

### 综合决策

**先做最简单的**: 对话页顶部加场景标签横条（复用已有 `grainDistribution` 数据），点击可快速提问。
**再做推荐问题**: 取每个场景的前 2 条颗粒问题作为推荐——不需要 AI 生成，直接从 DB 取。
**最后做场景卡片**: Practice 模式已有，QA/Talk 暂时用标签替代。

## 优先级共识

| 优先级 | 事项 | 理由 |
|--------|------|------|
| **P0** | L1 同场景回退 | 一行 SQL 改动，效果立竿见影 |
| **P0** | RAG 结构化日志 | 不改业务逻辑，只加 log |
| **P1** | L3 无颗粒快捷入口 | 给用户出口，产品闭环 |
| **P1** | 知识域标签横条 | 复用已有数据，零后端改动 |
| **P2** | Admin RAG 健康度面板 | 需要前端新页面 |
| **P2** | 推荐问题自动生成 | 需要新逻辑 |
| **P3** | L2 跨场景匹配 | 需要语义匹配引擎 |
