## 3. 阻塞 / 高危（已修）

### 3.1 补考通过后永远拿不到通过（产品 + 技术 + 用户共同命中）

`TrainingProgressService.applyRecordResult`：

- 原：`if (TERMINAL.contains(from)) return;` —— `failed` 在终态集合里，补考提交永远不会写入 `passed`；
- 原：`passedDelta = (!wasTerminal && passed) ? 1 : 0` —— 即使状态迁移了，`failed→passed` 也不补记通过；
- 原：`promoteIfRequiredPassed` 读 `assignment.requiredPassed`，此时内存里还是旧值，最后一个必修通过后不推进 `pending_certification`。

修复：
1. 只有 `passed` / `waived` 视为不可再变；`failed` 允许迁到 `passed`；
2. `passedDelta = passed && from != passed`，`completedDelta` 仍只在首次出结论时 +1；
3. 认证推进改为从 `task_record`（本次状态已同步到内存）+ 冻结任务表现算必修通过数，不读冗余计数。

测试：新增 `applyRecordResult_retakePassedAfterFailure_countsPassedOnce`（断言 `addCounters(id,0,1,1)` 且进入待认证）。

### 3.2 前端会渲染一个没有接口的「交卷」按钮（UI）

`TrainingAttemptService.toView` 去掉了 `submit` 动作。T5 实现 `POST /me/training/attempts/{id}/submit` 时再加回。

## 5. 遗留（已确认不修，写清理由）

| 事项 | 理由 | 归属 |
|---|---|---|
| 409 语义重载（已结束/次数用尽/重复分配/并发冲突） | 前端可用 message 区分；加 subCode 属接口改造，T5 会新增大量 409，届时统一设计 | T5 |

| 阶段不设闸门 | 阶段是分组与排序；门禁由前置任务表达（docs/43 §3） | 设计语义 |

| 题面快照带金标、多次重考各存一份 | T5 评分需要金标；清理任务属运维 | P3 |
