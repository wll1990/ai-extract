# AI 经验萃取平台 — 系统使用说明书

## 一、产品概述

### 1.1 这是什么

AI 经验萃取平台是一套**将销冠经验数字化、可对话化**的系统。核心流程：

```
上传素材 → AI 自动萃取经验颗粒 → 构建 AI 分身 → 员工随时对话学习
```

**解决的问题**：销冠的经验只在他脑子里。人离职经验就没了。新人培训靠传帮带，周期长、效果差。

**解决方案**：把销冠的对话录音/文档/访谈记录上传，AI 自动提取其中的话术、思路、踩坑经验，构建成一个可以对话的 AI 分身。员工随时向分身请教，获得基于真实销冠经验的回答。

### 1.2 核心概念

| 概念 | 业务含义 | 技术对应 |
|------|------|------|
| **分身（Skill）** | 一个销冠的 AI 化身。包含他的所有经验，可以对话 | `skill` 表 |
| **颗粒（Grain）** | 从素材中提取的最小经验单元。一条话术、一个思路 | `experience_grain` 表 |
| **素材（Material）** | 原始资料：对话录音、文档、访谈记录 | `skill_material` 表 |
| **空间（Space）** | 一个用户的数据容器。分身和颗粒都属于某个空间 | `space` 表 |
| **知识缺口** | 用户问了但分身答不出来的问题 | `knowledge_gap` 表 |
| **萃取** | AI 自动从素材中识别、提取、结构化经验的过程 | 异步 pipeline |

### 1.3 用户角色总览

| 角色 | 用户表 | 一句话定位 | 核心能力 |
|------|------|------|------|
| **超级管理员** | `user` | 平台运营方 | 全平台管理、企业合作、Partner 管理 |
| **企业管理员** | `user` | 企业管理方 | 本企业用户管理、分身管理、数据看板 |
| **员工** | `user` | 企业普通成员 | 使用分身对话、创建自己的分身 |
| **C 端用户** | `app_user` | 个人消费者 | 通过分享链接访问、对话聊天 |
| **C 端游客** | `app_user` | 未注册访问者 | 分享链接即开即用，每日 25 条限制 |
| **合作方用户** | `app_user` | 第三方嵌入者 | 通过 app 系统嵌入使用 |

#### 🤖 分身广场 `/skills`

**功能**：浏览可用的 AI 分身。QA 问答、自由对话、实战对练三种模式的入口。

**打开后的界面**：
- 搜索栏：按关键词搜索分身
- 分身上下文卡片网格：每个卡片显示头像、姓名、职级、颗粒数、标签
- 点击卡片进入分身对话页

**具体操作**：

| 操作 | 步骤 | 说明 |
|------|------|------|
| 搜索分身 | 在搜索框输入关键词 → 回车 | 按名称、职级模糊搜索 |
| 开始 QA 问答 | 点击分身卡片 → 默认 QA 模式 → 输入问题 → 发送 | AI 引用颗粒回答，带溯源信息 |
| 切换对话模式 | 对话页顶部切换 Tab：QA / Talk / Practice | Talk 自由交流，Practice AI 扮演客户 |
| 对练实战 | 选择 Practice → AI 扮演客户说开场白 → 你回复 → AI 打分 | 模拟真实销售场景 |
| 查看溯源 | 回答底部点击"查看来源" | 展开引用了哪些颗粒、匹配分数 |

#### 📈 数据看板 `/admin/insights`

**功能**：所有分身的健康度一览 + AI 自动发现异常。

**页面结构**：两个 Tab — "全局看板" + "自动发现"

**全局看板 Tab**：
- **KPI 卡片**：本周对话、满意率、活跃用户、待处理缺口
- **分身卡片网格**：每个已发布分身一张健康度卡片
  - 告警标签：🔴 缺口爆发(≥10) / 🟡 不活跃 / 🟡 满意率低(<60%) / 🟡 命中率低(<50%)
  - 4 个迷你指标：对话数 / 满意率 / 命中率 / 颗粒数
- **平台概览卡片**：知识命中率 + 颗粒总数
- **分身总数卡片**：已发布分身总数 + 告警汇总 chips
  - 红色 chip 显示异常分身和告警原因，点击跳转到该分身详情

**自动发现 Tab**：
- **筛选条**：全部 / 🔴 严重 / 🟡 警告 / 🔵 提示（带计数）
- **洞察卡片网格**：每条显示
  - 左 severity 色条 + 类型标签（缺口爆发/满意率骤降/命中率下降/新场景/不活跃）
  - 标题 + 描述 + 数据摘要
  - 操作按钮：[展开证据] [已处理] [忽略]
  - 展开后：证据详情（键值对）+ AI 生成的候选颗粒审核区
    - 候选颗粒 4 字段网格：专家思考/标准话术/常见错误/适用条件
    - 审核按钮：[拒绝] [审核通过·入库]（入库即写 experience_grain + 向量化）

**具体操作**：

| 操作 | 步骤 | 说明 |
|------|------|------|
| 进入单分身详情 | 全局看板 → 点击 SkillCard | 看该分身的图表+排行+缺口 |
| 处理 AI 洞察 | 自动发现Tab → 点击[已处理] | 标记 resolved，卡片消失 |
| 忽略洞察 | 自动发现Tab → 点击[忽略] | 标记 ignored |
| 审核候选颗粒 | 展开洞察 → 点击[审核通过·入库] | AI 自动写颗粒 + 向量化 |
| 拒绝候选颗粒 | 展开洞察 → 点击[拒绝] | 标记 rejected |
| 按严重度筛选 | 点击筛选按钮（严重/警告/提示） | 只看该级别的洞察 |

#### 🎯 分身调优 `/admin/tuning`

**功能**：选一个分身，深入管理颗粒、处理知识缺口、审查反馈。

**打开后的界面**：
- **分身选择器**：圆角 pill，带头像首字母，选中高亮
- **三个 Tab**：📦 颗粒管理 / 🔴 知识缺口 / 📋 反馈审查

**颗粒管理 Tab**：
- 双栏：⭐ 最佳颗粒（👍最多）+ ⚠️ 待优化颗粒（👎最多）
- 每个排行榜 Top 5，表格列：颗粒描述 / 👍 / 👎
- 点击颗粒行 → 进入颗粒诊断页

**知识缺口 Tab**：
- 缺口列表：每条显示用户问了什么、出现次数、场景标签
- 匹配质量标签：🟡 RAG低匹配 · 最佳 XX%（低分匹配缺口）
- 三个操作按钮：[补充颗粒] [已解决] [忽略]
- 点击补充颗粒 → 跳转到创建颗粒页（预填场景标签和 skillId）

**反馈审查 Tab**：
- 最近 5 条反馈，每条显示：👍/👎 + 用户提问 + 颗粒链接 + 日期
- 顶部"查看全部 →"链接到完整反馈审查页

**具体操作**：

| 操作 | 步骤 | 说明 |
|------|------|------|
| 选择分身 | 点击分身 pill | 切换要调优的分身 |
| 查看颗粒详情 | 点击排行榜中的颗粒行 | 进入诊断页 |
| 处理缺口 | 缺口列表 → 点击[已解决] | 缺口从列表消失 |
| 忽略缺口 | 缺口列表 → 点击[忽略] | 非业务问题，不再提醒 |
| 补充颗粒 | 缺口列表 → 点击[补充颗粒] | 跳转创建页，预填场景 |
| 查看完整反馈 | 反馈Tab → 点击"查看全部 →" | 进入反馈审查页 |

## 三、核心数据流程

### 2.1 分身创建全流程

```
┌─ 1. 创建分身 ──────────────────────────────────────────────────────┐
│  销冠（或管理员）在平台端/管理后台创建一个 Skill                     │
│  状态: draft（草稿）                                                │
│  需要: 填写分身名称、领域、开场白等基本信息                          │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─ 2. 上传素材 ──────────────────────────────────────────────────────┐
│  上传销冠的对话录音、培训文档、经验总结等                            │
│  状态: uploaded（已上传）                                           │
│  支持格式: 音频（转文字）、文本、Word/PDF                           │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─ 3. AI 萃取（异步 pipeline）────────────────────────────────────────┐
│  自动执行:                                                          │
│    ① 素材清洗（去噪、分段、识别说话人）                             │
│    ② 场景识别（这条对话是什么场景：价格异议？产品介绍？）            │
│    ③ 颗粒提取（专家思考 → 标准话术 → 常见错误 → 适用条件）          │
│    ④ 向量化（写入 pgvector，供 RAG 检索）                          │
│  状态流: uploaded → cleaning → analyzing → analyzed → extracted     │
│  也可以被拒绝（rejected）或丢弃（discarded）                        │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─ 4. 审核发布 ──────────────────────────────────────────────────────┐
│  管理员审核萃取结果：                                                │
│    · 审核颗粒内容是否准确                                            │
│    · 编辑不合适的颗粒                                                │
│    · 废弃质量差的颗粒                                                │
│    · 标记缺失场景，补充更多素材                                      │
│  审核通过 → 分身状态: published（已发布）                           │
└─────────────────────────────────────────────────────────────────────┘
                                    ↓
┌─ 5. 对外使用 ──────────────────────────────────────────────────────┐
│  已发布的分身可以：                                                  │
│    · 在分身广场供员工选择                                            │
│    · 生成分享链接（对外 /s/{code} / 对内 /i/{code}）                │
│    · C 端用户通过分享链接直接对话                                    │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 一次对话的 RAG 检索流程

用户每次向分身提问，背后发生的事情：

```
用户提问: "客户说价格太贵怎么回？"
    │
    ▼
① 查询改写（RagPipelineService）
   多轮对话时，把"那这个呢"改写为"竞品对比话术怎么回"
    │
    ▼
② 文本向量化（DashScope Embedding）
   将改写后的文字转为 1024 维向量
    │
    ▼
③ pgvector 语义检索（GrainRetriever）
   SQL: SELECT * FROM experience_grain
        ORDER BY embedding <=> query_vector
        LIMIT topK
    │
    ├─ 有结果 → 按相似度分层:
    │    ≥0.50 → tier="high"  (高匹配，质量可靠)
    │    ≥0.30 → tier="ref"   (参考，需要 AI 判断)
    │    <0.30 → tier=null    (低匹配，可能不相关)
    │    全部 <0.30 → 自动记录知识缺口
    │
    └─ 零结果 → 记录知识缺口（knowledge_gap）
    │
    ▼
④ LLM 生成回答（ChatStreamService）
   将检索到的颗粒内容塞入 prompt → AI 基于颗粒生成回答
   带溯源信息（这个回答引用了哪些颗粒）
    │
    ▼
⑤ SSE 流式推送给用户
   打字机效果逐字展示
   同时写 ConversationStats（对话统计）
    │
    ▼
⑥ 用户打分（👍/👎）
   写入 FeedbackLog（反馈日志）
   关联 grainId（引用了哪个颗粒）
   记录 ragScore（本次 RAG 平均相似度）
```

### 2.3 知识缺口闭环

```
用户提问 → RAG 零结果或全部低匹配
    │
    ▼
自动记录 knowledge_gap:
  · query: 用户问的原文
  · sceneTag: AI 推测的场景标签
  · attemptedQueryCount: 累计出现次数
  · status: open
    │
    ▼
管理员在"分身调优"页看到缺口列表:
  · 🟡 低匹配缺口（相似度 <0.30，标注最佳匹配分数）
  · 🔴 零结果缺口（完全没匹配到）
    │
    ├─ 补充颗粒: 跳转到创建新颗粒页，预填场景标签
    │
    ├─ 已解决: 标记 resolved → 缺口从列表消失
    │
    └─ 忽略: 标记 ignored（非业务问题，不管）
```

② 查看工作台

③ 创建自己的分身（创建者角色）

④ 销冠访谈

### 3.4 C 端用户 — 消费者

**登录**：平台端 `:3001/login` → 个人 Tab → 账号+密码

**典型工作流**：

```
① 探索发现
   发现专家 → 浏览所有已发布分身 → 按话题筛选
   点击进入 → QA/Talk/Practice

   收到分享链接 /s/{code} → 打开 → 看到分身介绍
   → 点击开始对话 → 自动获取游客身份
   → 对话（每日 25 条限制）
   → 额度用完 → 注册 → 升级为正式用户

③ 我的分身
   平台端 → 我的分身 → 自己创建的（如有）
```

**C 端 vs B 端员工的核心区别**：

| 维度 | B 端员工 | C 端用户 |
|------|------|------|
| 看分身范围（广场） | 本企业所有 | 全平台公开 |
| 创建分身 | ✅ | ✅ |
| 管理后台 | ✅ | ❌ |
| 销冠访谈 | ✅ | ❌ |
| Token 存储 | HttpOnly Cookie | localStorage Bearer |
| 从分享链接进入 | 需切换到对内分享 /i/ | 对外分享 /s/ 即可 |

### 3.5 C 端游客 — 即开即用

**无需登录**。通过对外分享链接 `/s/{shareCode}` 进入。

```
打开链接 → GET /public/share/{code}（公开，无需认证）
    → 看到: 分身名称 + 企业名 + 专家介绍
    → 点击模式按钮
    → POST /public/share/{code}/guest → 自动获得临时 token
    → 开始对话

限制:
  · 每日 25 条消息
  · 每分钟 6 条
  · 同一 IP 每小时最多创建 20 个游客
  · Token 7 天有效（每次访问滑动续期）

注册升级:
  · 对话中弹出注册提示
  · 注册后同一 UUID 升级为 c_user
  · 历史对话完整保留
```

### 3.6 合作方 — 第三方系统嵌入

**凭据获取**：超级管理员在合作方管理创建，获取 appId + SK

**嵌入方式**：

```
合作方服务端:
  ① 生成 JWT:
    Header: { alg: "HS256" }
    Payload: { appId, userId, userName, companyId, exp }
    签名: HMAC-SHA256(header.payload, SK)

  ② 拼接 URL:
    https://域名/h5/interview/m/{inviteCode}?token={jwt}
    或
    https://域名/skill/{skillId}?token={jwt}

  ③ 嵌入到 IM 消息/WebView/iframe

平台后端处理:
  ④ JwtAuthFilter → PartnerJwtFilter
     → 解析 JWT → 校验签名 → 自动创建/更新 app_user
     → 角色: c_partner
     → 设置 Spring Security 上下文

  ⑤ 后续请求都携带此身份
```

**IM 渠道回调**：飞书/企微/钉钉等在对应平台配置 Webhook URL：`POST /im/{channel}/callback`

## 五、重点功能详解

### 4.1 数据看板 — 运营指挥中心

**意义**：不要让管理员凭感觉判断"分身好不好用"。用数据说话。

**三个关键指标**：

| 指标 | 含义 | 健康值 |
|------|------|:--:|
| **满意率** | 用户打分 👍/(👍+👎) | ≥80% 良好 |
| **知识命中率** | RAG 检索命中次数/总检索次数 | ≥70% 良好 |
| **活跃度** | 本周对话次数 >0 | 0 不活跃 |

**使用路径**：

```
工作台（运营指挥中心）
  └─ KPI 卡片 → 今日对话/用户/满意率/活跃分身
  └─ 7天趋势 → 对话量走势
  └─ 分身健康度卡片 → 每个分身的 4 个关键指标
  └─ 萃取管道 → 素材处理各阶段数量
  └─ 活跃用户 TOP 10

数据看板
  └─ 全局 KPI
  └─ 分身健康度网格（带告警标签）
     · 🔴 缺口爆发: ≥10 个待处理缺口
     · 🟡 不活跃: 本周 0 对话
     · 🟡 满意率低: <60%
     · 🟡 命中率低: <50%
  └─ 点击卡片 → 单分身详情
     · SceneBarChart: 哪些场景提问最多
     · RagPieChart: RAG 匹配分布（高匹配/参考/无匹配）
     · GrainRankTable: 👍最多 / 👎最多的颗粒
     · KnowledgeGapPanel: 待处理知识缺口

自动发现 Tab
  └─ AI 自动扫描异常 → 生成洞察卡片
     · gap_burst: 某场景缺口突然增加
     · satisfaction_drop: 满意率骤降
     · hit_rate_drop: 命中率持续下降
     · inactive: 分身长期无人使用
  └─ 每条洞察可展开证据 → [已处理] [忽略]
  └─ 候选颗粒 → [审核通过·入库] [拒绝]
```

### 4.2 颗粒诊断页 — 精准定位问题

**意义**：看到 👎5 的颗粒，不只是知道"它被 5 个人差评了"，而是知道"为什么被差评"。

**入口**：数据看板/分身调优 → GrainRankTable → 点击颗粒

**页面结构**：

```
┌─ 左栏: 颗粒内容 ───────────┬─ 右栏: 诊断指标 ──────────────┐
│ 🧠 专家思考: ...            │ 被检索: 89次  平均相似度: 73%  │
│ 💬 标准话术: ...            │ 👍12  👎5  满意率: 70%        │
│ ⚠️ 常见错误: ...            │                               │
│ 📌 适用条件: ...            │                               │
├────────────────────────────┴───────────────────────────────┤
│ 💬 检索历史（最近 20 次）                                    │
│ 时间 | 用户提问原文 | 相似度 | 匹配级别                     │
│ → 相似度 <30% 标记为 🟡 低匹配                              │
│ → 相似度 ≥50% 标记为 🟢 高匹配                              │
├────────────────────────────────────────────────────────────┤
│ 👎 差评反馈（最近 10 条）                                    │
│ Q: "竞品价格更低怎么办"                                     │
│ A: "我们的优势在于服务体验..."   RAG: 45%                    │
│ → 查看完整对话                                              │
│ → 基于反馈 → 补充颗粒 → 预填场景标签                        │
└────────────────────────────────────────────────────────────┘
```

**从诊断到行动的闭环**：

```
发现问题颗粒 → 查看差评上下文 → 理解为什么差评
    │
    ├─ 颗粒内容不对 → [编辑颗粒] → 修改话术/思路
    ├─ 缺少对应颗粒 → [补充颗粒] → 创建新颗粒
    └─ 用户问题不合理 → [忽略缺口]
```

### 4.3 三种对话模式

| 模式 | 适用场景 | 交互方式 |
|------|------|------|
| **QA 问答** | 有具体问题要问 | 用户提问 → AI 回答（引用颗粒+溯源） |
| **Talk 对话** | 自由交流学习 | 多轮对话，AI 保持上下文 |
| **Practice 对练** | 模拟实战训练 | AI 扮演客户，用户扮演销售。AI 给出评分 |

## 六、分享体系完整说明

### 5.1 对外分享 vs 对内分享

| 维度 | 对外分享 | 对内分享 |
|------|------|------|
| **URL** | `/s/{shareCode}` | `/i/{shareCode}` |
| **谁可以访问** | 任何人（无需登录） | 企业成员（需登录） |
| **游客模式** | ✅ 自动获取临时 token | ❌ |
| **消息限制** | 游客 25 条/天 | 无限 |
| **注册引导** | 弹出注册提示 | 无 |
| **生成位置** | 分身管理 → 分享管理 → 选择 public | 分身管理 → 生成内部分享码 |
| **适用场景** | 微信/朋友圈/二维码 营销 | 企业内部知识库 |

### 6.2 访谈邀请

**与分身的区别**：

| 维度 | 分身对话 | 销冠访谈 |
|------|------|------|
| **目的** | 学习已有经验 | 萃取新经验 |
| **AI 角色** | 回答者（基于已有颗粒） | 提问者（引导你分享经验） |
| **产出** | 对话记录 | 萃取报告 + 新颗粒 |
| **谁用** | 团队成员 | 销冠本人 |
| **邀请方式** | 分享链接 /s/{code} | 访谈链接 /h5/interview/m/{code} |

**两种邀请类型**：

| | 企业邀请（enterprise） | 个人邀请（personal） |
|------|------|------|
| **发起者** | B 端管理员 | 平台端 C 端用户 |
| **生成入口** | B 端 → 销冠访谈 → 生成邀请码 | 平台端 → 邀请专家 |
| **API** | `POST /admin/invite` | `POST /interviews/invite` |

## 八、萃取管线详解（Material Pipeline）

这是系统最核心的引擎。素材上传后经过 **12 层 AI + 规则混合管线**，最终产出结构化的经验颗粒。

### 7.1 管线全景

```
素材上传 (uploaded)
    │
    ▼
Gate 0: 接受度预检 ── 不合格 → rejected（终止）
    │ 检查: 领域相关性、重复检测、预估颗粒数、文本质量评分
    │
    ▼
Layer 0: 上下文标签 ── AI 分析：采购阶段、买家画像、竞争态势、行业信号
    │
    ▼
Layer 1-3: 规则清洗（零 AI 调用）
    · MaterialNoiseCleaner: 去除格式噪音（时间戳、系统消息）
    · BusinessNoiseFilter: 过滤无关内容（寒暄、闲聊）
    · TextNormalizer: 文本规范化
    │  状态: cleaning
    ▼
Layer 4-5: AI 萃取 + 场景分类
    · 对话按说话人分块 / 文档按语义分块（~800字，50字重叠窗口）
    · 每批 5 个块并行调 AI → 提取结构化 ExtractedInsight:
      sceneDescription / expertThought / standardScript / commonMistakes / applicableCondition
    · 单次批量 AI 调用做场景标签归类（复用空间已有标签）
    │  状态: analyzing → analyzed
    ▼
Layer 6: 对抗验证 ── 每批 10 个候选颗粒，二次 AI 验证
    · 5 维度打分: 具体性 / 可复现性 / 因果性 / 差异性 / 可证伪性
    · 综合分 < 3.5 或具体性 < 3 → 拒绝 → 记录到 ExtractionDropLog
    │
    ▼
Layer 7: 重叠合并 ── 同一场景 >10 个候选 → AI 去重合并
    │
    ▼
Layer 8: 模式发现 ── ≥8 个通过验证 → AI 提取跨场景模式
    · 核心习惯 / 差异化打法 / 方法论名称 / 一句话总结
    │
    ▼
Layer 9: FAQ 提取 ── AI 提取客户异议→回应对
    │
    ▼
Layer 10: 叙事回放 ── AI 构建策略模式与颗粒引用的关联叙事
    │
    ▼
Layer 11: 画像生成 (异步) ── @Async
    · 生成 SkillProfile: 性格 / 说话风格 / 背景 / 常用语 / 知识领域 / 沟通偏好
    │  状态: extracted
    ▼
持久化:
    · 颗粒入库 → 向量化 (DashScope 1024维) → pgvector
    · 语义去重: cosine >0.95 的重复颗粒自动标记 deprecated
    · 分身状态: generating → reviewing
    · Report 标记 dirty → 定时重新生成
```

### 7.2 调度机制

- **扫描频率**：每 30 秒一次
- **并发控制**：素材级乐观锁 + Redis 分身级锁（集群安全）
- **文件解析**：`scanAndParse()` — 音频转文字、PDF 解析
- **清洗萃取**：`scanAndClean()` — 12 层管线驱动
- **报告生成**：每 2 分钟扫描 dirty 标记，满足阈值（≥10颗粒 + ≥3场景）则重新生成

## 九、发布审核流程

### 8.1 审核面板

管理员进入"分身管理" → 点击分身 → 审核页，可看到：

```
审核仪表盘 (GET /admin/skills/{id}/audit-dashboard)
  ├─ 分身基本信息 + 自动生成画像
  ├─ 颗粒总览: 总数/活跃/废弃 + 场景覆盖 + 5维度均分 + 质量分布(高/中/低)
  ├─ 场景分组颗粒: 按 sceneTag 分组 + 全文展示
  ├─ 素材列表: 上下文/模式/FAQ/叙事 + 验证/拒绝数
  ├─ 历史评估分数
  └─ 补充信息: 名称/职位/标签/限制/备注
```

### 8.2 发布三校验

`PUT /admin/skills/{id}/publish` — 任一不通过则返回 `{passed: false, blockers: [...]}`：

| 校验项 | 阈值 | 说明 |
|------|:--:|------|
| 活跃颗粒数 | ≥10 | 经验太少无法支撑对话 |
| 场景覆盖 | ≥3 个不同 sceneTag | 场景单一则实用性差 |
| 画像完整性 | ownerName + personality + background + knowledgeDomains 全部不为空 | 没有画像的分身像机器人 |

### 8.3 发布后自动生成

三个 `@Async` 任务在发布时自动触发：

1. **开场白** — AI 生成 3 段式开场（标题/正文/结尾邀请）
2. **推荐问题** — 从 Top 场景颗粒描述生成 6-8 个自然语言问题
3. **对练开场** — 每个场景生成 AI 扮演客户的对话开头

## 十、Chat/RAG 全链路技术细节

### 9.1 请求处理阶段

```
① Gate 拦截 (QueryGate.audit)
   · 敏感词过滤 → 4xx
   · 频率限制 (每分钟 6 条) → 429
   · 游客配额检查 (每日 25 条) → 429
   · 内容安全检查

② 游客拦截
   · C 端游客限流 + 免费额度检查

③ 模式解析
   · 根据消息内容 + 显式 mode 参数 → quick | discuss | talk | practice

④ 对话持久化
   · 已发布分身 → 持久化 conversation + message
   · 未发布分身 → 临时 UUID

⑤ 查询改写 (RagPipelineService)
   · 多轮对话: "那这个呢" → "竞品对比话术怎么回"
   · 最近 12 轮对话作为上下文
   · 改写失败回退原消息（不阻塞对话）
```

### 9.2 RAG 检索

```
⑥ pgvector 语义检索 (GrainRetriever)
   输入: 改写后的查询 → DashScope Embedding → 1024维向量
   SQL: SELECT *, 1.0 - (embedding <=> query) AS similarity
        FROM experience_grain WHERE space_id = ? AND status = 'active'
        ORDER BY embedding <=> query LIMIT topK*3
   重排: similarity × weight → topK

⑦ 分层标记
   ≥0.50 → tier="high"  (高匹配，直接给 LLM)
   ≥0.30 → tier="ref"   (参考，LLM 自行判断)
   <0.25 (app.rag.min-similarity) → 硬拦截过滤，不进 LLM
   全部被拦截 → 记录知识缺口 + 触发兜底回答
   全部 <0.30 → 记录知识缺口 (低匹配类型)

⑧ 多空间检索 (组织分身)
   逐 space 独立检索 → 合并去重 → 全局 weight 重排
```

### 9.3 LLM 生成与后处理

```
⑨ Prompt 组装 (PromptAssemblyService)
   系统 prompt = 分身画像 + 模式指令 + RAG 颗粒(按场景分组) + 回答要求

⑩ SSE 流式输出 (ChatStreamAdapter)
   120 秒超时 → 打字机效果推送给前端

⑪ 后处理
   · 持久化 AI 回答 (SkillMessage)
   · 发射溯源信息 (source chunk: 用了哪些颗粒、相似度)
   · 写 ConversationStats (ragHighCount/ragRefCount/ragNoneCount/avgSim/llmDuration)
   · RAG 零结果 → 生成推荐追问
```

### 9.4 Hybrid Search (可选)

配置 `app.rag.hybrid-search.enabled=true` 开启 Dense(向量) + Sparse(BM25) → RRF 融合排序，提升召回率。

## 十一、关键阈值速查

| 参数 | 默认值 | 说明 |
|------|:--:|------|
| RAG 高匹配阈值 | 0.50 | 相似度 ≥ 此值标记为 high |
| RAG 参考阈值 | 0.30 | 相似度 ≥ 此值标记为 ref |
| RAG 硬拦截阈值 | 0.25 | 相似度 < 此值不进 LLM |
| 语义去重阈值 | 0.95 | cosine > 此值的颗粒自动废弃 |
| 对抗验证最低分 | 3.5/5 | 综合分 < 此值的候选颗粒被拒绝 |
| 发布最小颗粒数 | 10 | 颗粒不足不允许发布 |
| 发布最小场景数 | 3 | 场景太单一不允许发布 |
| 游客每日消息 | 25 | 超出需注册 |
| 游客每分钟消息 | 6 | 防刷 |
| 游客 token 有效期 | 7 天 | 滑动续期 |
| C 端免费萃取次数 | 3 | 访谈限制 |

## 十二、检索引擎健康度指标

管理员在数据看板看到的关键百分比是怎么算出来的：

| 指标 | 计算公式 | 含义 |
|------|------|------|
| **知识命中率** | (high + ref) / (high + ref + none) | RAG 检索的有效匹配比例 |
| **满意率** | 👍 / (👍 + 👎) | 用户对 AI 回答的满意比例 |
| **颗粒平均相似度** | avg(similarity) | 所有检索命中的平均余弦相似度 |
| **颗粒质量分** | 5 维度综合 (0-5) | 对抗验证阶段的 AI 评分 |
