# 多模式对话逻辑详解

> 最后更新: 2026-07-14

## 1. 模式总览

```
                         ┌─────────────────────┐
                         │  ChatStreamService   │ ← 协议无关核心
                         │  Flux<ChatChunk>     │
                         └──────────┬──────────┘
                                    │
        ┌───────────────┬───────────┼───────────┬───────────────┐
        ▼               ▼           ▼           ▼               ▼
   分身问答(Q&A)    对练回应    企业总调度   对练评价         审核对练
   /skills/{id}    /practice   /enterprise  /practice      /admin/skills
   /chat           /respond    /chat        /evaluate      /{id}/auto-demo
        │               │           │           │               │
        ▼               ▼           ▼           ▼               ▼
   RAG向量检索     场景Prompt   关键词匹配   AI评价打分     PracticeDemoService
   +LLM流式       AI扮演客户   跨空间Top20  +溯源颗粒       SSE Raw格式流式

                         ┌──────────────────────────┐
                         │  InterviewService        │ ← 访谈引擎(独立)
                         │  Flux<ChatChunk>         │
                         └──────────┬───────────────┘
                                    │
                ┌───────────────────┼───────────────────┐
                ▼                   ▼                   ▼
           访谈对话              中断恢复            阶段完成推进
     /interviews/{id}/chat  /interviews/{id}/  /interviews/{id}/
                            resume             mark-phase-complete
                │                   │                   │
                ▼                   ▼                   ▼
           AI萃取引擎            AI萃取引擎          AI萃取引擎
           四阶段推进            四阶段推进          四阶段推进
```

## 2. 分身问答（Q&A）

```
端点: POST /api/v1/skills/{skillId}/chat
场景: 员工向 AI 分身请教销售问题
前端: 分身广场 SkillPage、审核页 ProductDemoModal
协议: event:message\ndata:{"type":"content","content":"..."}\n\n
```

### Phase 1: Setup（同步，HTTP 线程）

**① 校验 Skill 状态**
- 管理员(isAdmin=true) 可测试未发布分身
- 普通用户必须 active，否则 → emit error chunk

**② 画像完整性检查**
- personality/background 为空 → emit warning chunk（不阻断）

**③ 会话与消息持久化**
- 已发布分身(published): 创建/查找 SkillConversation，用户消息写入 skill_message 表
- 未发布分身: convId=UUID.randomUUID()，不记录

**④ 对话模式解析 (resolveMode)**
- quick(默认): 简洁回答
- discuss: 消息含"你怎么看""为什么""觉得"等关键词 → 苏格拉底式追问
- 显式命令: /讨论、/聊聊 → discuss

**⑤ RAG 语义检索**
```
request.getMessage()
  → DashScope.embed() → float[1024]
  → pgvector: embedding <=> query_vector (cosine_distance)
  → HNSW 索引 → TopK×3 候选 → weight 重排 → Top5
  → 无结果时回退取最近 20 条活跃颗粒
```

**⑥ Prompt 组装**
- PromptLoader.format("skill_qa_chat.md")
- 注入: 分身画像 + RAG 颗粒(experience_context) + 模式指令(mode_instruction)
- buildChatMessages: system prompt + 最近 10 轮(20 条)历史 + 当前消息

### Phase 2: AI 流式（异步，Reactor 线程）

```
ChatStreamAdapter.chatStream(messages, context)
  → 消息列表拼接为单 prompt + "助手："
  → ChatClient.prompt().user(fullPrompt).stream().chatResponse()
  → Spring AI → DeepSeek API (deepseek-chat, temp=0.7)
  → 逐 token → Map.of("type","content","content",token)
  → SseEmitter.event("message").data(json) 推送到前端
  → timeout 120s
  → doOnComplete: AI 回复写入 skill_message 表
     └─ role="assistant", roleLabel="销冠" / "客户"
```

### Phase 3: Post-stream

- meta chunk: {conversationId} → 前端记录会话 ID
- source chunk: {reportId, grainIds, grainTags, avgScore} → 溯源引用

## 3. 审核页（Admin Audit）

```
入口: GET /admin/skills/{skillId}/audit-dashboard
```

### 路径 A: 审核问答（ProductDemoModal）

复用 `POST /skills/{skillId}/chat` — 与分身问答完全同端点。

差异：
- ChatStreamService.chat() 中 isAdmin=true，跳过状态校验
- 管理员可在分身未发布时提前测试对话质量
- 使用 connectSseAsync（Promise 包装版）

### 路径 B: 审核对练场景（PracticeScenarioModal）

```
POST /admin/skills/{skillId}/practice-scenario (SSE)
  → connectRawSse (Format B: event:chunk\ndata:...)
  → PracticeDemoService 逐轮推进客户对话
  → 每轮结束后 evaluate-demo 评分
```

### 路径 C: 自动演示对练（autoDemo）

```
POST /admin/skills/{skillId}/auto-demo (SSE)
  → mode: "full"(完整演示) / "single"(单轮)
  → PracticeDemoService.autoDemo() 自动生成多轮对话
  → SSE event: customer | avatar | done | error
```

### 审核辅助接口

| 端点 | 用途 |
|------|------|
| audit-dashboard | 审核仪表盘（分身状态、颗粒数、画像完整性） |
| supplement | 补充信息（标签、场景、局限、发布备注） |
| report-history | 报告生成历史 |
| grain-source | 颗粒→素材溯源 |
| match-grains | 问答/对练后查询 RAG 匹配结果 |
| evaluate-demo | AI 评分对练质量（5 维） |
| practice-evaluate | 对练综合评价 |
| qa-summary | 知识点覆盖总结（已覆盖+未覆盖场景标签） |
| practice-opening | 生成对练开场白 |
| practice-angles | 对练角度列表 |

## 4. 分身对练（Practice）

```
端点: POST /api/v1/skills/{skillId}/practice/respond
场景: AI 扮演客户，员工模拟销售对话
前端: 分身广场 PracticeView
```

### 流程

**① 构建场景 Prompt**
- PromptLoader.format("skill_practice_customer.md")
- 注入: scene_context + practiceAngles + roundNumber + totalAngles

**② AI 扮演客户**
- ChatStreamAdapter.chatStream(messages, {mode:"practice"})
- System Prompt 指令: 隐藏训练伙伴身份，通过真实客户行为引导
- 按 practiceAngles 逐角度推进
- 覆盖完所有角度后自然收尾

**③ 每轮结束后评价 (evaluatePracticeRound)**
- PracticeDemoService.evaluatePracticeResponse()
- 销冠模式答案 + 对比分析 + 5 维技法拆解
- 命中/遗漏技巧 + 可提升方向
- 溯源颗粒（sceneTag, qualityScore, matchLevel）
- 最多 2 次重试机会

## 5. 企业总调度（Enterprise）

```
端点: POST /api/v1/skills/enterprise/chat
场景: 跨所有分身搜索，回答任意销售问题
```

### 与 Q&A chat() 的差异

| 维度 | Q&A chat() | Enterprise |
|------|-----------|------------|
| 检索方式 | RAG 向量 | 关键词评分 |
| 范围 | 指定分身 spaceId | 全公司所有 spaceId |
| 结果数 | Top5 | Top20 |
| 分身绑定 | 是 | 否(跨分身综合) |

### 流程

```
① 加载公司内所有空间颗粒 → LIMIT 500
② relevanceScore() 关键词匹配打分
   ├─ sceneTag 匹配 → +5
   ├─ expertThought 匹配 → +4
   ├─ sceneDescription 匹配 → +3
   ├─ standardScript 匹配 → +2
   └─ 单字拆分匹配 → +1
③ 取 Top20 → PromptLoader.format("enterprise_system.md")
④ ChatStreamAdapter.chatStream() 流式输出
```

## 6. 访谈（Interview）— 四阶段引擎

```
端点: POST /api/v1/interviews/{sessionId}/chat
场景: AI 萃取师引导销冠，将隐性经验结构化为报告
```

### 四阶段流程

```
opening (开场定调)
  → 建立信任，确定萃取主题，询问基本信息
  → 收集: collectCaseStory

storytelling (故事深描)
  → 深挖案例，追问原话、当时想法、关键决策
  → 收集: collectSteps + collectDecision

modeling (模型提炼)
  → 总结模式，命名方法论，提炼可复制步骤
  → 收集: collectMindset

closing (收网确认)
  → 确认边界条件，整理检查清单，生成知识资产
  → 收集: collectBoundary + collectChecklist
```

### Session 状态机

```
created → in_progress → completed
                      → paused
                      → abandoned
                      → failed
```

### 阶段切换机制
- AI 检测关键特征词自动推进（_detectPhaseChange）
- 用户手动标记 markPhaseComplete
- 暂停/恢复/强制完成

### 萃取师经验注入（元萃取）

若有 expertSkillId：
```
ExpertGrain 7 大类按 category 分组注入 System Prompt:
  ├─ judgment_intuition   (判断直觉)
  ├─ mental_model         (心智模型)
  ├─ failure_lesson       (失败教训)
  ├─ validation_method    (验证方法)
  ├─ metaphor_framework   (隐喻框架)
  ├─ rhythm_sense         (节奏感知)
  └─ typing_method        (类型化方法)
```

## 8. SSE 事件协议

两种格式，前端 `sse.ts` 统一处理：

```
Format A (JSON):  event:message\ndata:{"type":"chunk","content":"你好"}\n\n
Format B (Raw):   event:chunk\ndata:你好\n\n
```

| type | 含义 | 使用端 |
|------|------|--------|
| content | AI 文本 chunk | Q&A / 对练 / 企业 / 访谈 / 审核 |
| done | 流结束标记 | 全部 |
| error | 异常信息 | 全部 |
| meta | 会话 ID | Q&A |
| source | 溯源报告+颗粒 | Q&A |
| warning | 画像不完善提醒 | Q&A |
| phase_change | 阶段切换 | 访谈 |
| collect_update | 采集状态更新 | 访谈 |
| heartbeat | 连接确认 | SseAdapter 自动发送 |

## 9. 日志追踪

每个请求 `X-Trace-Id` 串联全链路：

```
[tr-MMDDHHmmss-skillId-random]
  ChatStreamService / SkillService : 业务日志
  GrainRetriever                  : RAG 检索、相似度分布
  PromptLoader                    : Prompt 格式化
  ChatStreamAdapter               : LLM chunks / chars / preview
  DashScopeEmbeddingService       : 向量模型耗时
```
