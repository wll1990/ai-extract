## 一、整体流水线

```
HTTP 请求
  │
  ▼
┌──────────────────────────────────────────────────┐
│ JwtAuthFilter (OncePerRequestFilter)              │
│                                                    │
│ 1. extractToken()  — header → cookie → ?token=    │
│ 2. 标准 JWT 验证  — HMAC-SHA256 签名校验           │
│ 3. 合作方 JWT      — ?token= 含 appId → 独立验证   │
│ 4. setAuthentication() → SecurityContext + TokenContext │
└──────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────┐
│ SecurityConfig (authorizeHttpRequests)             │
│                                                    │
│ 路径 × 方法 × hasAuthority(权限码)                  │
│ permitAll() / authenticated() / hasAuthority()     │
└──────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────┐
│ Controller / Service                              │
│                                                    │
│ CompanyScopeService 做企业级数据隔离               │
│ super_admin 跳过，其他角色校验企业归属             │
└──────────────────────────────────────────────────┘
```

## 三、Token 提取优先级

`JwtAuthFilter.extractToken()`

| 优先级 | 来源 | 场景 |
|--------|------|------|
| 1 | `Authorization: Bearer xxx` | API 调用（fetch/curl） |
| 2 | Cookie `token` (HttpOnly) | 页面加载、同域请求 |
| 3 | `?token=` query param | SSE/WebSocket（无法设 header） |

## 四、双认证体系

### 4.1 标准 JWT（B 端 + C 端）

**生成**：`JwtUtil.generateToken()`

```
Header:  { alg: "HS256" }
Payload: { userId, companyId?, role, sub, iat, exp }
```

| 字段 | B 端 | C 端 |
|------|------|------|
| `companyId` | 有值 | null（平台级用户，无企业归属） |
| `role` | super_admin / company_admin / employee | c_guest / c_user / c_partner |
| 签发方式 | `/auth/login` → HttpOnly Cookie | `/c/auth/login` → JSON body |
| 有效期 | `jwt.expiration`（默认 24h） | `app.share.c-user-token-ttl-days`（30天） |

**JWT payload 示例**（B 端 super_admin）：

```json
{
  "userId": "00000000-0000-0000-0000-000000000001",
  "companyId": "c0000000-0000-0000-0000-000000000001",
  "role": "super_admin",
  "sub": "00000000-0000-0000-0000-000000000001",
  "iat": 1785399755,
  "exp": 1785486155
}
```

### 4.2 合作方 JWT（外部系统嵌入）

**验证**：`PartnerJwtFilter.authenticate()`

```
Header:  { alg: "HS256" }
Payload: { appId, userId, userName }
```

- **独立密钥体系**：每个合作方有独立 SK，存在 `partner_app.secret_key`（AES 加密存储）
- **独立用户体系**：存入 `app_user` 表，account = `partner:{appId}:{externalUserId}`
- **角色固定**：统一映射为 `c_partner`
- **appId 即 companyId**：`appId` 直接作为 `app_user.company_id`，无需冗余字段

**与标准 JWT 的区分**：通过 payload 中的 `appId` 字段。标准 JWT 无此字段，`JwtAuthFilter.hasAppIdClaim()` 不解签名快速判断。

**执行顺序**：标准 JWT 优先（覆盖 99% 流量），仅标准 JWT 验签失败时才尝试合作方验证。

## 五、角色→权限码映射

`RolePermissions.java` — 单一真相源，三个消费点共享：

1. `JwtAuthFilter` — 登录时查映射表，设为 Spring Security GrantedAuthority
2. `AuthService.getCurrentUser` — `/auth/me` 返回 permissions 字段给前端
3. 业务代码 — `RolePermissions.hasPermission(role, permission)` 替代硬编码

```
super_admin    → [COMPANY_MANAGE, PARTNER_MANAGE, IM_MANAGE, TOKEN_VIEW_ALL,
                   DASHBOARD_VIEW, USER_MANAGE, SKILL_MANAGE, SKILL_TUNING,
                   MATERIAL_MANAGE, CONVERSATION_VIEW, SCENE_COVERAGE,
                   EXPERT_MANAGE, GRAIN_MANAGE, TOKEN_VIEW_COMPANY,
                   ORG_SKILL_MANAGE, SKILL_USE, SPACE_OWN]

company_admin  → [DASHBOARD_VIEW, USER_MANAGE, SKILL_MANAGE, SKILL_TUNING,
                   MATERIAL_MANAGE, CONVERSATION_VIEW, SCENE_COVERAGE,
                   EXPERT_MANAGE, GRAIN_MANAGE, TOKEN_VIEW_COMPANY,
                   ORG_SKILL_MANAGE, SKILL_USE, SPACE_OWN]

employee       → [SKILL_USE, SPACE_OWN]

c_guest        → [SKILL_USE]
c_user         → [SKILL_USE]
c_partner      → [SKILL_USE]
```

**设计要点**：

- `super_admin` 比 `company_admin` **仅多 4 个 Platform 级权限码**
- C 端三个角色权限码完全相同，实际差异在业务配置层（免费额度、消息限制等）——见 `application.yml` 的 `app.share.*` 和 `app.interview.*`
- 修改权限只需改 `ROLE_MAP`，JwtAuthFilter + `/auth/me` + 前端导航全部自动生效

## 六、权限码分级

`Permission.java` — 18 个权限码，三级：

### Platform 级（仅 super_admin 拥有）

| 权限码 | 说明 |
|--------|------|
| `COMPANY_MANAGE` | 企业管理 + 注册码生成 |
| `PARTNER_MANAGE` | 合作方 + API 密钥管理 |
| `IM_MANAGE` | IM 渠道配置（飞书/钉钉/企微） |
| `TOKEN_VIEW_ALL` | 全局 Token 消耗统计 |

### Company 级（super_admin + company_admin 拥有）

| 权限码 | 说明 |
|--------|------|
| `DASHBOARD_VIEW` | 工作台 + 数据看板 |
| `USER_MANAGE` | 本企业用户管理 |
| `SKILL_MANAGE` | 分身审核/上下架 |
| `SKILL_TUNING` | 分身调优 + 数据洞察 |
| `MATERIAL_MANAGE` | 素材管理 |
| `CONVERSATION_VIEW` | 对话历史查看 |
| `SCENE_COVERAGE` | 场景覆盖分析 |
| `EXPERT_MANAGE` | 萃取师经验库管理 |
| `GRAIN_MANAGE` | 颗粒管理（CRUD/废弃/恢复） |
| `TOKEN_VIEW_COMPANY` | 本企业 Token 消耗统计 |
| `ORG_SKILL_MANAGE` | 组织/综合分身管理 |

### Basic 级（所有 B 端用户拥有）

| 权限码 | 说明 |
|--------|------|
| `SKILL_USE` | 使用分身（QA/Talk/Practice） |
| `SPACE_OWN` | 个人空间 |

## 七、SecurityConfig URL 规则

三层控制粒度：

| 层级 | 示例 | 说明 |
|------|------|------|
| **permitAll** | `/public/**`, `/auth/login`, `/ws/**` | 无需认证 |
| **hasAuthority(权限码)** | `/admin/companies/**` → `COMPANY_MANAGE` | 需特定权限 |
| **hasAuthority(角色)** | `/interviews/**` → `c_user` | 按角色放行 |

完整规则矩阵：

```
/auth/login               POST   permitAll
/auth/register            POST   permitAll
/auth/register/with-code  POST   permitAll
/auth/me                  GET    authenticated
/auth/logout              POST   authenticated
/public/**                        permitAll
/c/auth/login             POST   permitAll
/c/auth/register          POST   hasAuthority(c_guest)
/c/auth/register/new      POST   permitAll
/c/auth/me                GET    authenticated
/ws/**                            permitAll（认证由 handler 完成）
/im/*/callback                    permitAll
/i/*/info                 GET    permitAll
/i/**                             authenticated
/admin/companies/**               hasAuthority(COMPANY_MANAGE)
/admin/partners/**                hasAuthority(PARTNER_MANAGE)
/admin/im/**                      hasAuthority(IM_MANAGE)
/admin/**                         hasAuthority(DASHBOARD_VIEW)
/interviews/**                    hasAnyAuthority(super_admin, company_admin, employee, c_user, c_partner)
/grains/**                        authenticated
/skills/*/status          PUT    hasAnyAuthority(SKILL_MANAGE, c_user)
/skills/list              GET    hasAuthority(SKILL_USE)
/skills/enterprise/chat   POST   hasAnyAuthority(super_admin, company_admin, employee)
/skills/**                        hasAuthority(SKILL_USE)
/reports/*                GET    authenticated
/reports/by-session/**    GET    authenticated
其余所有接口                      hasAnyAuthority(super_admin, company_admin, employee)
                                  ⚠️ C 端接口必须在上方显式声明，否则被 catch-all 拦截
```

## 八、企业数据隔离

`CompanyScopeService.java`

- **触发时机**：Controller/Service 层调用 `assertSkillOwnership()` / `assertGrainOwnership()`
- **数据链路**：`companyId → users → spaces → skills/grains`
- **请求级缓存**：`ThreadLocal<Map<UUID, Set<UUID>>>` — 同一请求内只查一次 DB
- **super_admin 例外**：`isSuperAdmin()` 检查 `COMPANY_MANAGE` 权限码 → 有一律跳过，可访问全平台数据

## 九、TokenContext — 请求上下文

`TokenContext.java`

```
Filter 层: TokenContext.set(userId, companyId)
Service层: TokenContext.get() / TokenContext.getCompanyId()
@Async 层: Decorator 把父线程上下文传递给子线程
Filter 层: finally { TokenContext.clear() }
```

用于 Token 消耗统计、企业数据查询等横切场景。

## 十、登录/注册端点汇总

| 端点 | 方法 | 角色 | Token 下发方式 |
|------|------|------|--------------|
| `/auth/login` | POST | B 端全员 | HttpOnly Cookie |
| `/auth/register` | POST | B 端管理员创建用户 | 仅新用户无 cookie 时下发 |
| `/auth/register/with-code` | POST | 新员工扫码注册 | HttpOnly Cookie |
| `/auth/logout` | POST | B 端 | 清除 Cookie |
| `/c/auth/login` | POST | C 端注册用户 | JSON body |
| `/c/auth/register` | POST | 游客→注册升级 | JSON body |
| `/c/auth/register/new` | POST | 平台直接注册 | JSON body |

**Cookie 配置**：

| 属性 | 值 | 来源 |
|------|-----|------|
| HttpOnly | true | 硬编码（防 XSS） |
| Secure | `jwt.cookie-secure` | 配置项，生产 true |
| Path | `/` | 硬编码 |
| MaxAge | `jwt.expiration / 1000` | 与 JWT 有效期同步 |
| SameSite | Strict | 硬编码 |

## 十一、合作方接入指引

### 合作方 JWT 格式

```json
// Header
{ "alg": "HS256" }

// Payload
{
  "appId": "合作方标识（UUID）",
  "userId": "合作方系统的用户 ID",
  "userName": "用户昵称"
}
```

签名密钥由平台分配（`partner_app.secret_key`，AES 加密存储）。

### 请求方式

所有 API 请求 URL 携带 `?token=<JWT>` 参数：

```
GET /api/v1/skills/list?token=eyJhbG...
POST /api/v1/interviews?token=eyJhbG...
```

认证成功后自动创建或匹配 `app_user` 记录，角色固定为 `c_partner`，拥有 `SKILL_USE` 权限。

## 十二、设计约束 & 注意事项

1. **新增 C 端接口**：必须在 `SecurityConfig` 显式加 `.requestMatchers()`，否则被 `.anyRequest()` 拦截（仅放行 B 端角色）
2. **新增角色**：只需在 `RolePermissions.ROLE_MAP` 加一行，JwtAuthFilter + `/auth/me` + 前端导航全部自动生效
3. **修改 Cookie 有效期**：`jwt.expiration` 修改后，Cookie MaxAge 自动同步（`ms/1000`）
4. **super_admin 注册保护**：仅已认证的 super_admin 可创建新 super_admin，自注册会被拒绝
5. **注册码角色限制**：`REGISTRABLE_ROLES` 仅含 `company_admin` 和 `employee`，无法通过注册码创建 super_admin
