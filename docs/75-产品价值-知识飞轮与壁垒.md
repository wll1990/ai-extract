# 产品价值、知识飞轮与壁垒

> 用途：内部统一认识、销售/交付对客沟通、试点方案设计。
> 原则：只写系统里真实存在的能力；不编造客户案例，不承诺未经验证的 ROI 数字。

---

## 一、一句话定位

**把销冠脑子里的判断，变成团队当天能查、能练、能考核、能追溯的组织资产；每一次使用，又反过来补充这份资产。**

它不是“又一个 AI 问答”，也不是“把文档丢给大模型”。它解决的是三件事同时发生：

1. 经验从人脑里被结构化地取出来；
2. 取出来的经验能在真实工作现场被调用；
3. 调用过程留下的问题，能回到经验库继续补。

---

## 二、不同角色的痛点

| 角色 | 表面问题 | 真正的问题 | 系统对应能力 |
|---|---|---|---|
| 销售负责人 | 新人成长慢 | Top Sales 的判断无法复制，带教靠个人时间 | 分身问答、销售复盘、线索与跟进任务 |
| 培训 / 赋能 | 课程没人看、讲完就忘 | 不知道新人到底会不会，培训和实战两张皮 | 知识库、案例库、评测中心、培训计划与批次 |
| 教练 / 主管 | 天天被问同样的问题 | 带教无法规模化，看不到谁卡在哪 | 教练台账、实战对练、评测结果、知识缺口 |
| 管理层 | 人走了经验就没了 | 经验是个人资产，不是组织资产；投入无法证明 | 经验颗粒、覆盖率、使用与转化指标 |
| IT / 安全 | 客户对话不能外流 | 权限、隔离、审计、部署形态 | 多租户隔离、企业 Key、IM 渠道、审计日志 |

一句话概括痛点：

> **经验在生产端高度集中，在使用端高度分散；培训在课堂上，问题在客户现场。**

## 三、知识飞轮

### 3.1 五段闭环

```text
① 采集
   录音 / 文档 / 访谈 / 真实客户对话（销售复盘）
        │
        ▼
② 结构化
   AI 萃取「经验颗粒」：场景、判断逻辑、标准话术、常见错误、适用边界
   → 人工审核 → 向量索引 → 分身可检索
        │
        ▼
③ 使用
   分身广场问答 / 自由对话 / 实战对练 / IM（飞书、企微、钉钉）
   设计上：回答尽量带原文出处；超出依据范围时明说不知道
        │
        ▼
④ 反馈
   好评 / 差评、检索命中日志、知识缺口、评测失败、
   实战未通过、销售复盘报告
        │
        ▼
⑤ 再生产
   内容工厂生成考题 / 场景微练 / 知识卡
   教练补充与认证
   销售复盘沉淀新案例 / 新知识
   缺口补录成新颗粒
        │
        └──────────────► 回到 ②，资产变厚
```

### 3.2 每一段的输入、产物和证据

| 阶段 | 输入 | 产物 | 系统里可查的证据 |
|---|---|---|---|
| ① 采集 | 素材文件、访谈记录、客户对话 | 待清洗素材、对话分段 | 素材列表、访谈记录、复盘会话 |
| ② 结构化 | 素材 / 对话 | 经验颗粒、知识条目、案例 | 颗粒列表、质量分、审核状态、索引状态 |
| ③ 使用 | 问题、对练场景 | 回答、对练评分、引用来源 | 对话记录、检索日志、溯源信息 |
| ④ 反馈 | 使用过程 | 好评差评、缺口、评测结果、复盘报告 | 反馈日志、知识缺口、评测运行、复盘报告 |
| ⑤ 再生产 | 缺口与失败信号 | 新题、微练、知识卡、新颗粒 | 内容工厂任务、派生结果、审核队列 |

### 3.3 飞轮真正转起来的前提

不是“有 AI”，而是**第 ④ 步必须留下结构化反馈**。

如果使用过程只产生聊天记录，飞轮就是断的；现在系统已经把反馈拆成可处理的对象：

- 用户点“有帮助 / 没帮助” → 影响颗粒权重与排序
- 检索没命中 → 记知识缺口
- 评测答错 → 形成补课与出题信号
- 实战对练不过 → 形成训练任务
- 销售复盘 → 形成案例、知识草稿、线索和跟进任务

### 3.4 当前最容易断的三个点

1. **采集成本**：访谈和素材整理仍然重，需要模板、教练参与和明确的采集节奏。
2. **审核瓶颈**：颗粒、知识、案例都要人审；审核不及时，飞轮停在第 ② 步。
3. **结果归因**：使用率不等于业务结果，必须把“复盘 → 下一步 → 线索/任务 → 成交”串起来看。

这三条也是产品下一阶段最值得投入的地方。

## 四、价值

### 4.1 价值主张（从客户语言出发）

- 新人遇到客户问题，先问销冠的分身，而不是等销冠有空。
- 每条回答尽量回到原话，销售敢用、主管敢查。
- 聊完直接生成复盘、线索和跟进任务，不停留在“知道了”。
- 答不上来的问题会被记成缺口，补充后回到经验库，而不是消失。
- 培训不只看课时，看评测通过率和实战对练结果。

### 4.2 可量化指标

对外不承诺拍脑袋的 ROI，直接定义“客户自己能查”的指标：

| 维度 | 指标 | 数据来源 |
|---|---|---|
| 上手速度 | 新人从入职到独立拜访 / 独立跟进的时间 | 培训批次、任务完成、主管记录 |
| 答疑负担 | 同一个问题重复问人的次数 | 分身对话、群消息 / 工单（需客户配合） |
| 执行落地 | 复盘覆盖率、复盘后“下一步”按时完成率 | 销售复盘、跟进任务 |
| 知识健康 | 知识缺口数量与关闭率、颗粒覆盖率 | 知识缺口、颗粒列表 |
| 学习效果 | 评测通过率、实战对练通过率 | 评测运行、对练记录 |
| 回答质量 | 引用命中率、答不上来的比例、好评率 | 检索日志、反馈日志 |
| 业务结果 | 复盘转线索率、线索转成交率 | 线索、复盘、成交状态 |

### 4.3 不适合承诺的说法

- “用了就能提升 30% 业绩” —— 没有对照实验，不要讲。
- “AI 可以替代销冠” —— 当前定位是放大销冠，不是替代。
- “所有问题都能回答” —— 超出依据范围必须承认不知道，这是可信度的一部分。

## 五、壁垒

### 5.1 先说不是什么壁垒

- **模型**：通用大模型是商品，谁都能接。
- **提示词**：可复制，且会随模型迭代贬值。
- **功能清单**：单点功能很容易被模仿。

### 5.2 真正会变厚的五层

```text
第 5 层  组织习惯与切换成本
         复盘、带教、评测、认证都长在同一个系统里
        ▲
第 4 层  交付与合规
         多租户隔离、企业 Key、IM 接入、审计、私有化
        ▲
第 3 层  工作流嵌入
         复盘 → 线索 → 任务 → 培训 → 评测 → 认证
        ▲
第 2 层  领域化检索与评测
         销售场景分类、颗粒质量、评分规则、对练评判
        ▲
第 1 层  企业私有经验资产
         颗粒、案例、知识、反馈、缺口，越用越厚且搬不走
```

1. **企业私有经验资产**：数据是客户自己的，使用越多越完整；换系统带不走。
2. **领域化检索与评测基准**：不是通用问答，而是按销售场景组织、按业务标准评分。
3. **工作流嵌入**：系统进入日常动作，而不是一个可替代的聊天框。
4. **可信度**：能溯源、有边界、答不上来会承认；这是销售愿不愿意用的分水岭。
5. **交付与合规**：企业隔离、权限、审计、IM 接入和部署形态，决定能不能进大客户。

一句话：

> **壁垒 = 私有数据密度 × 使用频率 × 结果可证明性。**
> 三者缺一，都容易被替代。

### 5.3 诚实的阶段性判断

当前阶段，壁垒还在形成期：

- 数据密度取决于客户是否持续采集和审核；
- 使用频率取决于是否嵌入日常动作；
- 结果可证明性取决于能否把指标串成漏斗。

所以销售不能只讲“我们有 AI”，要讲“我们帮你把这三件事跑起来”。

## 六、对客沟通

### 6.1 30 秒版本

> 新人问客户问题，最后还是去问销冠；销冠一天被问很多次，经验还在他脑子里。
> 我们把这部分判断做成可问的分身：回答尽量回到原话，答不上来的问题自动记缺口；
> 真实客户对话还能直接复盘，生成下一步、线索和跟进任务。
> 一个团队先跑 30 天，看三件事：少问了几次人、复盘后有没有可执行的下一步、缺口有没有被补上。

### 6.2 三分钟版本（问题 → 方案 → 证据 → 试点）

1. **问题**：经验集中在少数人身上，培训在课堂、问题在客户现场。
2. **方案**：采集 → 颗粒 → 分身 → 反馈 → 再生产，形成闭环。
3. **证据**：每条回答可溯源；答不上来会记缺口；复盘能转成线索和任务。
4. **试点**：一个团队、一条产品线、30 天，先跑通一条链路，再决定是否推广。

### 6.3 按角色换重点

| 对象 | 他关心什么 | 先讲什么 |
|---|---|---|
| 销售负责人 | 新人上手、复盘落地、下一步执行 | 复盘 → 任务 → 线索这条链 |
| 培训负责人 | 课程更新、评测、带教人力 | 知识/案例 → 评测 → 培训批次 |
| 管理层 | 经验留存、标准化、可复制 | 组织资产与指标看板 |
| IT / 安全 | 数据不出企业、权限、审计 | 多租户、企业 Key、审计、部署形态 |

### 6.4 常见异议

**“这和 ChatGPT / 企业知识库有什么区别？”**

> 通用模型不知道你们销冠怎么判断，也不会为“答不上来”负责。
> 我们的回答来自你们审核过的经验颗粒，尽量带原文出处；没有依据时会明说，并记成缺口。
> 而且它不是停在聊天：复盘、线索、任务、评测、培训是同一条链。

**“我们数据很敏感，不能上云。”**

> 支持企业级隔离和私有化部署形态；企业可以配置自己的模型 Key；所有管理动作有审计。
> 具体部署边界按你们的合规要求评估。

**“我们还没有内容，冷启动怎么办？”**

> 先从 3–5 位销冠的访谈和真实对话开始，不做全量知识库。
> 先覆盖高频、高价值的 20–30 个客户场景，跑通闭环后再扩。

**“怎么证明有效？”**

> 不只看使用率。看四个可查的指标：重复答疑次数、复盘后下一步完成率、知识缺口关闭率、评测/对练通过率。
> 试点前先记录基线，试点后用同一口径对比。

## 七、主要链路与功能地图

```text
A. 经验生产
   素材上传 / 访谈 → 解析清洗 → AI 萃取颗粒 → 审核 → 发布分身

B. 分身使用
   分身广场 → 问答 / 自由对话 / 实战对练 → 溯源、反馈、知识缺口
   IM（飞书 / 企微 / 钉钉）内直接提问

C. 销售执行
   销售复盘 → 结构化报告 → 转线索 → 生成跟进任务 → 线索跟进 → 教练台账

D. 学习与认证
   知识库 / 案例库 → 评测题集与运行 → 培训计划 → 批次分配 → 学习任务 → 认证

E. 内容运营
   知识缺口 / 评测失败 / 实战未通过 → 内容工厂 → AI 草稿 → 审核 → 回库

F. 管理与治理
   企业 / 空间 / 用户 / 权限、多租户隔离、企业 Key、用量、审计、IM 渠道
```

## 八、30 天试点设计

### 8.1 范围

- 一个团队（10–20 人）
- 一条产品线或一类客户场景
- 3–5 位销冠参与经验采集
- 只跑一条主链路：**问分身 → 真实对话复盘 → 转下一步（线索/任务）**

### 8.2 试点前先记录基线

- 新人独立跟进需要多久
- 每周重复答疑次数（估算口径写清楚）
- 复盘频率、复盘后是否形成书面下一步
- 当前评测 / 带教通过率

### 8.3 试点期动作

| 节奏 | 动作 |
|---|---|
| 第 1 周 | 采集 3–5 位销冠的高频场景；完成审核与发布 |
| 第 2 周 | 团队开始问分身；每周挑 3 个真实对话做复盘 |
| 第 3 周 | 复盘转线索/任务；处理知识缺口；做一次评测或对练 |
| 第 4 周 | 用同一口径对比基线；决定扩展、调整或停止 |

### 8.4 试点成功的判断

不是“大家觉得好用”，而是：

1. 重复答疑次数有可解释的下降；
2. 复盘后形成的下一步，有明确的完成记录；
3. 答不上来的问题被记录并至少关闭一部分；
4. 团队愿意在试点结束后继续用。

## 九、当前短板与下一步

| 短板 | 影响 | 下一步 |
|---|---|---|
| 飞轮指标分散在各页 | 难以向管理层证明结果 | 做一个按团队/批次下钻的飞轮看板 |
| 审核依赖人工 | 内容一多就堵 | 审核辅助：重复检测、质量分、风险提示 |
| 采集仍偏重 | 冷启动慢 | 场景模板、访谈提纲、批量导入 |
| 业务结果链路未完全打通 | 只能证明“用了”，难证明“有效” | 复盘 → 任务 → 线索 → 成交的漏斗查询 |
| 对练与评测的评分标准需持续校准 | 结果可信度受影响 | 用真实通过/未通过样本回归评分规则 |

## 十、一页话术

> 我们不是卖一个 AI 聊天框。
> 我们帮企业把销冠的判断取出来、审过去、用起来，再让使用过程反过来补充它。
> 新人问得到、销售敢用、主管查得到、培训考得了。
> 先从一个团队、一条链路跑 30 天，用四个指标判断值不值得推广。
