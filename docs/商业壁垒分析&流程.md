# 经验萃取平台 — 商业壁垒分析 & 流程全览

---

## 一、商业壁垒分析

### 1.1 三层壁垒模型

```
第一层：数据壁垒
  销冠访谈的颗粒 + 素材上传的颗粒 = 企业专属知识库
  → 每个甲方部署后沉淀的颗粒都是独一无二的
  → 竞品可以复制 UI，复制不了数据

第二层：方法壁垒
  萃取师元访谈 → ExpertSkill → 注入 AI System Prompt
  → AI 萃取师学会了甲方培训专家的访谈方法论
  → 竞品可以复制四阶段流程，复制不了"这个专家怎么追问"的方法

第三层：领域壁垒
  YAML 配置 + 11 个 Prompt 文件 + 领域专属场景分类
  → 每进入一个新行业，就多一道护城河
  → 销售、金融、医疗、法律……每个领域的知识体系都是壁垒
```

### 1.2 为什么叫"飞轮"而不是"功能"

```
一次部署：
  Day 1:   素材上传 → 15个颗粒
  Week 1:  销冠访谈 → 28个颗粒（更深，有心法和决策逻辑）
  Month 1: 萃取师访谈 → 20个 ExpertGrain → AI 追问质量↑
  Month 2: 新销冠访谈 → 35个颗粒（AI 更会追问了）
  Month 3: 第二场萃取师访谈 → 15个新 ExpertGrain → AI 追问质量↑↑
  ...
```

用的人越多、用的时间越长 → 颗粒池越深、AI 萃取师越聪明 → **切换成本指数增长**。

### 1.3 壁垒在代码中的体现

| 壁垒层 | 代码体现 | 竞品复制难度 |
|--------|---------|------------|
| 数据 | `experience_grain` 表，按 `space_id` 隔离 | 无法复制（甲方独占数据） |
| 方法 | `ExpertSkill/ExpertGrain` → `loadExpertKnowledge()` → `interview_system.md` 第14行 | 极高（需甲方培训专家配合） |
| 领域 | `domain/*.yml` + `prompts/domain/*/` 11 个文件 | 高（每领域需领域专家精调） |

### 1.4 竞品对比

| | 通用 AI 访谈工具 | 本平台 |
|---|---|---|
| 访谈流程 | 自由对话 | 四阶段结构化 CTA 方法论 |
| 领域适配 | 一段 prompt | YAML 配置 + 11 个精调 prompt + 场景分类 |
| 产出 | 对话记录 | 结构化颗粒 + HTML/PPT/Word 报告 |
| 知识沉淀 | 无 | 颗粒池 + 对练可用 |
| AI 进化 | 模型更新 | 萃取师经验注入 → 越用越聪明 |
| 切换成本 | 低 | 高（颗粒数据 + 专家方法论无法迁移） |

## 三、三条管道详细流程

### 3.1 素材上传管道（已打通 ✅）

```
用户上传文件
  │
  ├── MaterialCleaningService.uploadMaterialToSpace()
  │   ├── 解析 spaceId → skillId
  │   ├── 解析 domain（从 skill，必须解析成功）
  │   └── 保存文件 + 创建 SkillMaterial(status=uploaded)
  │
  ├── parseFile() — 文件解析
  │   ├── Python 服务: PDF/DOCX/XLSX/图片/音频 → 纯文本
  │   ├── 去重检查: Jaccard 5-gram vs 同 skill 存量素材 + 同 space 存量颗粒
  │   └── 写入 material.parsedContent
  │
  ├── MaterialCleaningScheduler（30s 定时扫描）
  │   ├── 查找 status=uploaded AND parsed_content IS NOT NULL，LIMIT 20
  │   ├── Redis 锁: skill:clean:{skillId}（同人串行，不同人并行）
  │   └── 调用 MaterialCleaningService.clean(materialId)
  │
  └── clean() — 11 层清洗管道
      │
      ├── [准入检查] preChecker.checkAcceptance(text, domain)
      │   【关键】domain 决定验收规则：销售域验"客户/成交"，金融域验"估值/行业"
      │   【关键】不通过 → material.status=rejected，不再进入管道
      │
      ├── Layer 0: tagContext(text, domain) — 一次 AI 调用
      │   【关键】加载 domain/material_context_tag.md
      │   【关键】销售域产出 buyingStage/buyerPersona，金融域产出 assetClass/researchType
      │   【关键】失败不阻断管道
      │
      ├── Layer 1-3: 规则清洗（零 AI 调用，0 幻觉风险）
      │   Layer 1: NoiseCleaner — 去时间戳、页码、HTML标签
      │   Layer 2: BusinessFilter — 去问候语、客套话、签名档
      │   【关键】domain 参数加载领域专用 noise_patterns
      │   Layer 3: Normalizer — 全角半角、多余空格、重复标点
      │
      ├── Layer 4: semanticChunk(text) — 800字目标，句子边界切分
      │
      ├── Layer 5: deduplicate(chunks, spaceId)
      │   【关键】Jaccard 3-gram vs 同 space 全部存量颗粒
      │   【关键】阈值 0.7，≥70% 相似就跳过该 chunk
      │   【关键】不区分来源：文件的颗粒和访谈的颗粒在同一去重池
      │
      ├── Layer 6: extractInsights + classifyScenesBatch — AI 提取 + 场景归类
      │   【关键】domain 决定场景分类 taxonomy
      │   【关键】销售域: 初次破冰/价格异议/竞品打压...
      │   【关键】金融域: 行业研究/公司分析/估值定价/交易决策/风险控制/宏观判断
      │
      ├── Layer 7: verifyGrains — 对抗验证，10条/批
      │   五维评分: specificity(0.25)+repeatability(0.2)+causality(0.2)
      │            +distinctiveness(0.2)+falsifiability(0.15)
      │   【关键】失败不回退，整批保留
      │
      ├── Layer 8: mergeOverlapping — 同标签相似颗粒合并
      │
      ├── Layer 9: discoverPatterns — 模式发现（方法论名称/核心习惯/差异优势）
      │
      ├── Layer 10: extractFaq + generateNarrative — FAQ提取 + 叙事重放
      │
      ├── Layer 11: generateProfile — 自动提炼销冠/研究员画像
      │
      └── MaterialCleaningScheduler.saveGrains()
          【关键】status="active"（自动激活，无需审核）
          【关键】source_type="file_upload"
```

```

  │   │   【修复】session.setDomain(domain) ← 新增
  │   ├── 加载 System Prompt: loadInterviewSystemPrompt(session)
  │   │   【修复】domain 从 session.domain 读取，不再硬编码
  │   │   【修复】interviewType 从 session.getInterviewType() 读取
  │   ├── 注入 ExpertKnowledge: loadExpertKnowledge(expertSkillId, domain)
  │   │   【修复】只加载匹配 domain 的 ExpertSkill
  │   │   → 注入到 interview_system.md 第14行 "萃取师实战经验"
  │   └── 开场白: generateOpeningMessage(domain)
  │       【修复】domain.name → 销售域"B2B大客户销售" / 金融域"二级市场研究"
  │
  ├── 四阶段结构化访谈（SSE 流式）
  │   │
  │   ├── Phase 1: 开场定调 — 建立信任 + 锁定案例
  │   │   销售域: "你最近搞定的大客户是哪个行业的？"
  │   │   金融域: "你最近一次做出与市场共识相反的判断是什么时候？"
  │   │   采集: 无（热身）
  │   │
  │   ├── Phase 2: 故事深描 — STAR 事件还原
  │   │   销售域: 第一次接触到最终成交的全过程
  │   │   金融域: 信号发现→验证→建仓→退出的全流程
  │   │   采集: case_story
  │   │
  │   ├── Phase 3: 模型提炼 — 抽象可复制方法论
  │   │   销售域: 步骤模型 + 关键决策 + 专家心法
  │   │   金融域: 分析框架 + 可证伪条件 + 判断逻辑
  │   │   采集: steps + decision + mindset
  │   │
  │   └── Phase 4: 收网确认 — 边界条件 + 避坑清单
  │       销售域: "这招什么情况下不灵？新手最容易犯什么错？"
  │       金融域: "什么市场环境这个框架失效？什么公司类型不适用？"
  │       采集: boundary + checklist
  │
  ├── 四阶段全部完成 → checkAndCompleteSession()
  │   │
  │   ├── session.status = "completed"
  │   │
  │   └── 【新增】触发异步颗粒萃取
  │       InterviewTranscriptExtractor.extractFromInterview(sessionId)
  │       │
  │       ├── 拼接转录文本: [萃取师]: ... / [受访者]: ...
  │       │   【关键】roleLabel 用 domain 变量：销售域"销冠" / 金融域"研究员"
  │       │
  │       ├── 创建虚拟 SkillMaterial(status=uploaded)
  │       │   【关键】parsedContent = 转录文本
  │       │   【关键】复用 MaterialCleaningService.clean() 全部11层管道
  │       │   【关键】clean() 不知道也不关心文本来自文件还是访谈
  │       │   【关键】deduplicate() 自动与同 space 存量颗粒去重
  │       │
  │       ├── 标记来源: grain.source_type = "interview"
  │       │              grain.source_interview_id = sessionId
  │       │
  │       ├── 报告重新生成: reportGenerationService.generateAsync(skillId)
  │       │   【关键】此时报告包含文件+访谈的全部颗粒
  │       │
  │       └── 失败处理: material.status = "failed"，转录文本保留不丢
  │
  └── 用户体验
      ├── 访谈结束 → "报告生成中，预计3-5分钟"
      ├── 5分钟后刷新 → "本次访谈产出 23 个经验颗粒" + 报告可查看
      └── 颗粒列表中新增 source=interview 的颗粒，与文件颗粒混排
```

## 四、领域隔离全览

### 4.1 两条管道的领域隔离对比

| 环节 | 销售域 | 金融域 | 实现方式 |
|------|--------|--------|---------|
| 素材验收 | "客户/成交/销冠"关键词 | "估值/行业/研报"关键词 | `domain/*.yml` → `acceptance.business_whitelist` |
| 场景分类 | 初次破冰/价格异议/竞品打压… | 行业研究/公司分析/估值定价… | `domain/*.yml` → `pipeline.scene_taxonomy` |
| AI Prompt | `sales.b2b_enterprise/` 下 11 个文件 | `finance.secondary_market/` 下 11 个文件 | `PromptLoader.load(name, domain)` 三级回退 |
| 角色称谓 | 销冠/客户/销售技巧/锦囊 | 研究员/投资经理/分析框架/投资洞察 | `domain/*.yml` → `domain.role_label` 等变量 |
| 访谈 System Prompt | 角色=销售萃取师，对象=销冠 | 角色=研究萃取师，对象=研究员 | `domain/{id}/interview_system.md` |
| 去重 | 同 space 存量颗粒去重 | 同 space 存量颗粒去重 | Jaccard 3-gram，不区分来源 |

```
│  萃取师元访谈                                                     │
│    ↓                                                             │
│  ExpertSkill (status=pending → analyzing → extracting)           │
│    ↓                                                             │
│  ExpertGrain × N (status=under_review)                           │
│    ↓ 人工审核                                                     │
│  ExpertGrain × N (status=active)                                 │
│    ↓                                                             │
│  loadExpertKnowledge(expertSkillId, domain)                      │
│    ↓                                                             │
│  注入 interview_system.md 第14行 "# 萃取师实战经验"                │
│    ↓                                                             │
│  下一场销冠访谈 — AI 萃取师现在具备了:                              │
│    - "当销冠说'我也不知道'时，这是最值得追问的时刻"                   │
│    - "每个销冠都有一个'核心隐喻'，找到它就找到了方法论的名字"           │
│    - "关系型销冠和技巧型销冠的提问策略完全不同"                       │
│    ↓                                                             │
│  访谈质量↑ → 颗粒更深 → 报告更有价值 → 甲方更离不开                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 七类 ExpertGrain 在访谈中的作用

| 类别 | 含义 | 如何影响 AI 访谈行为 |
|------|------|-------------------|
| `judgment_intuition` | 追问判断直觉 | AI 学会识别"什么时候该追问、什么时候该换话题" |
| `mental_model` | 心智模型 | AI 学会帮销冠抽象他们的隐形方法论 |
| `failure_lesson` | 失败经验教训 | AI 避免常见错误："别让销冠进入培训师模式" |
| `validation_method` | 验证方法 | AI 学会用反例验证方法论的有效性 |
| `metaphor_framework` | 隐喻框架 | AI 学会用行业比喻帮销冠理解抽象概念 |
| `rhythm_sense` | 对话节奏 | AI 学会控制四阶段的节奏，在该慢的时候慢下来 |
| `typing_method` | 类型化方法 | AI 学会识别销冠类型，调整提问策略 |
